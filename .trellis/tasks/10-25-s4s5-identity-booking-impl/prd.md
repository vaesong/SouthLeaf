# S4/S5：客户身份与档期预约确认成单实现

## 目标

依 P02/P03 为 M4（身份档期可靠）与 M5（不留半成功状态）实现后端业务能力：客户主体与关系模型、固定时段与开放/封档、预约申请、原子确认即成单、取消与改期、订单不可变快照与修订。本任务交付**领域与应用层及其 JDBC 适配器**，不包含后台 HTTP 接线、admin-web 页面、真实 MySQL 事务验收与生产授权。

## 范围

- **客户主体（S4）**：内部 customer 主体、外部身份绑定、联系点、关系记录、关联申请。默认不自动关联；同手机号/姓名不得自动合并。
- **档期（S4）**：固定时段物化、UTC instant 存储 + 业务时区标识、容量默认 1、开放/封档状态、时段列表只读可用性提示。
- **预约申请（S5）**：`PENDING_CONFIRMATION` 状态机、48 小时基线失效、pending 不占硬档。
- **原子确认即成单（S5）**：单一事务内完成 reservation 确认、唯一 slot 占档、唯一订单与不可变快照、审计与通知 outbox。
- **取消与改期（S6 最小能力）**：取消释放占用并追加订单修订；改期原子换档，失败保留旧档。
- **订单快照与修订**：已确认快照不可变，纠正只追加 revision；不引入 payment/deposit/refund/delivery 状态。

## 设计交付

- D-304（客户与身份）、D-305（预约与档期）、D-306（订单与履约）为本任务领域输入。
- D-106 §4–§9 提供流程、锁顺序与幂等口径；D-703 §7–§8 提供 RES-01..06 / REV-01..02 验收矩阵。
- 新增 `backend/admin-booking` Maven 模块：domain / port / application / adapter(jdbc) 分层，domain 与 port 不依赖 Spring、Web、JDBC 或文件系统实现。
- 新增 admin schema `V6__admin_identity_booking.sql`；新增精确 grants 策略 `AdminBookingGrantPolicy`。
- Trellis task 保存 PRD/design/implement/check/verification。

## 验收标准

1. 客户主体、档期、预约、订单各有唯一 owner；预约不直接写订单表，订单不直接改预约表。
2. 每个写命令列出 actor/capability、幂等键与请求摘要、预期版本、事务边界、失败类别与未知提交复查方式。
3. 排他占档依赖数据库唯一约束，不是先查后写；锁顺序全局统一为 idempotency → reservation → slot → occupancy → order → audit/outbox。
4. 确认事务内任一写入失败全部回滚，不存在"档期已锁但预约仍 pending"或"已确认但无订单"。
5. pending 申请永不持有硬档占用；过期与确认竞态恰好一个状态转移。
6. 订单快照不可变，修订 append-only 且 revision 连续；套餐变更不影响历史订单显示。
7. 不出现 payment/deposit/refund/delivery 状态、字段、端点或按钮。
8. 单元测试覆盖状态机、幂等、快照不可变、越权与失败回滚语义；真实 MySQL 事务/唯一约束/锁序证据留给后续隔离验收，不以 mock 冒充。

## 硬边界

- 只实现**能力**不写死**经营数值**：营业时区、营业日、服务时长、缓冲、节假日、提前量、容量规则、取消政策属 Q04，由调用方以配置形式提供；不在代码中猜测默认值。
- Q02：阶段二无支付能力，不实现定金计时、定金到期释放或比例定金；申请失效沿用 P02 的 48 小时基线且明确"自创建时间起算"；**不改写**既有 24 小时定金基线文档。
- Q05：默认**不自动关联**；同手机号/同微信/姓名相似只作候选提示；不启用手机号自动合并、家庭共享或历史订单自动认领。
- Q06：不新增真实后台角色或默认管理员，只复用既有 capability 词汇（RESERVATION_READ/CONFIRM/CANCEL/RESCHEDULE、ORDER_READ）。
- 不触碰生产、真实客户资料、真实预约、通知 provider、默认管理员、原公开服务、C2 fixture、原 3306 服务；不创建数据库/账号/grants/测试身份；不提交/推送。
