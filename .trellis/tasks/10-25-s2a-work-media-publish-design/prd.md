# S2-A：单作品媒体发布闭环设计

## 目标

依 P02/P03 为 S2-B 冻结一个可编码、可测试、范围受控的 2A 纵向切片：上传合成媒体、校验/生成衍生图、建立作品草稿、通过测试授权门、预览、发布到现有小程序读取链路并撤回。此任务只交付 G1 设计与决策，不包含 S2-B 产品实现或运行验收。

## 范围

- 明确媒体入口、JPEG/PNG 校验、大小/像素限制、隐私重编码、私有对象存储与状态机。
- 明确单作品草稿/修订、媒体绑定、授权只读判定、发布/撤回与公开 DTO 兼容。
- 明确后台 API、capability、Idempotency-Key、If-Match、错误契约和 admin-web 单作品流程。
- 明确 admin schema V5/public V2 表级 owner、最小 grants、跨 schema 同实例事务、锁序、自然到期 fail-closed、未知提交复查与 GET/HEAD 撤回边界。
- 比较 public V1 原地改写、完整 V2 catalog 与按作品 overlay；记录 S2 有限工程决策及其限制。
- 建立可映射到 HTTP、双 schema MySQL/InnoDB、浏览器与小程序的 S2 测试矩阵。

## 设计交付

- D-205 §13、D-302 §12、D-403 §8、D-507 §12、D-106 §13、D-607 §1–3/9–10、D-703 §10。
- ADR-005：按作品 public V2 overlay 仅用于 S2 首个作品切片；不延伸锁定 S3/2B 的全部内容模型。
- Trellis task 中保存 PRD/design/implement/check/verification 与关联文件。

## 验收标准

1. P02/P03 的 S2 目标与非目标准确；S2 完成不得被 S1-D、页面 mock 或设计状态代替。
2. 授权权威事实、证据、业务写模型、发布命令和公开投影各有唯一 owner；公开数据不含 PII/证据引用。
3. public V1 表和 Reader 行为保持；S2 的 V2 overlay 资格来源显式，缺行/异常不回退 V1。
4. 每个写命令列出身份/capability、请求摘要幂等、预期版本、事务、错误与未知提交复核。
5. D-507 给出逐表运行 grants、同实例 InnoDB 限制和统一锁序，并包含到期、撤回、媒体访问与缓存边界。
6. D-703 的矩阵明确是测试计划而不是已执行证据；S2-B 必须使用隔离合成资料和真实技术链路。
7. 文档检查、链接检查、差异检查及编辑器诊断完成后才关闭 S2-A 设计任务。

## 硬边界

不触碰生产、真实作品/人物/授权证据、客户或通知；不操作默认管理员、原公开服务、C2 fixture、原 3306 服务；不创建数据库/账号/grants/测试身份、不执行 SQL、不启动服务；不提交/推送。S2-B 的数据库身份/fixture 授权另行按 P03 门禁处理。

## 明确非目标

S3 全部内容运营、品牌/成员/套餐、客户/档期/预约/订单、真实 A15 授权录入、2B 对象存储/平台/域名/CDN/真机/UAT、生产发布及完整阶段二验收。
