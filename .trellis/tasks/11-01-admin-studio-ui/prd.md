# 后台前端按 v2 设计稿落地（子任务 A）

## 目标

只使用**现有**后端接口，把 `admin-web` 的全部页面按 `docs/设计笔记集/后台界面设计稿-v2.html` 重做。设计稿是视觉和交互的唯一模板；设计稿里的示例数据要换成真实接口数据。

## 范围

页面：登录、今日工作台、首页布置、关于我们、业务与套餐、作品集（含作品编辑）、图片库、预约处理、档期安排（只读）、消息通知、发布记录；外加全局外壳（侧边栏、顶栏、账号菜单、退出确认、发布确认）。

不在范围：后端改动；轮播独立配置、档期开放/关闭、预约规则编辑（属于子任务 B）。

## 硬性要求

1. 全部界面文字为简体中文，不得出现繁体字或英文界面文案（品牌英文名这类用户数据除外）。
2. 视觉还原设计稿：色板、衬线标题、按钮体系（主 / 强调 / 次 / 文字 / 危险 / 图标按钮）、卡片、开关、分段控件、标签编辑器、抽屉、弹窗、状态标签。不允许出现浏览器默认样式的按钮或输入框。
3. 小程序目录草稿 `CatalogDraftInput` 的**每一个字段**都必须有编辑入口（字段到页面的映射见 design.md）。
4. **不准编造数据**：接口没有提供的信息，不显示，或按 design.md 的降级规则处理。设计稿里的“说明”黄框只能用于写明真实存在的限制。
5. 保留现有安全与并发行为：CSRF、If-Match/ETag 修订号、Idempotency-Key（同一次操作的重试复用同一个键）、`credentials: same-origin`、409/412 冲突提示。不得改动 `*/api.ts` 的传输与校验逻辑，只允许增加纯函数辅助。
6. 退出登录只在账号菜单里，点击后弹出确认框。
7. 1280px 宽度下布局不溢出；≥1440px 时显示右侧手机预览，更窄时隐藏预览。

## 验收标准

- `npm run typecheck`、`npm test`、`npm run build`、`npm run format:check` 在 `admin-web` 下全部通过。
- 现有单元测试保留并按新文案更新；新增测试覆盖：目录草稿各页面编辑后能正确合并成一次 `saveCatalog` 请求、精选业务/套餐最多 3 个、退出确认流程、未发布状态提示的判断。
- `admin-web/e2e/*.mjs` 中的选择器与文案同步更新（无法在本地跑完整栈时，至少保证脚本与新页面文案一致，并在交付说明里写明未运行）。
- `rg` 在 `admin-web/src` 中搜不到设计稿示例数据（如“南叶摄影”“林小满”“138 0000 0000”）被硬编码进业务页面。
- 交付说明列出：每个页面用了哪些接口；哪些设计稿元素因接口缺失被降级或省略。
