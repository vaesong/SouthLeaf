# 图片上传与选择

## 边界

改动停在后台配图：`admin-web` 的选择和图片库、`admin-runtime` 的上传入口、`admin-content` 的处理与列表、管理库的下一号迁移。公开接口、小程序页面、公开库的变体上限、对象键规则都不改。

用户选中的文件只在内存里解码。写盘的仍然只有 `thumbnail` 和 `preview`。不新增 `original` 变体，不返回原图地址。

## 两套大小

| 限制 | 值 | 作用 |
|---|---|---|
| 上传文件 | 30MB（31457280 字节） | 用户选中的 JPEG/PNG，处理后丢弃 |
| 请求体 | 30MB + 64KB | multipart 开销，`AdminOriginFilter` 与 Tomcat multipart 共用 |
| 落盘衍生图 | 4MB | 缩略图和预览图；公开库和 `FileMediaObjectStore` 已有同一上限 |
| 边长 | 8192 | 保持 |
| 像素 | 24000000 | 保持 |
| 衍生图边长 | 缩略图 480，预览图 1600 | 保持 |

`ContentRules` 拆成 `MAX_UPLOAD_BYTES` 和 `MAX_STORED_OBJECT_BYTES`。上传闸用前者。`ImageIoProcessor` 的衍生图大小和 `FileMediaObjectWriter.read` 用后者。这样 30MB 的文件不会被当成可保存对象。

`V5` 的 `ck_admin_media_size` 把 `source_byte_length` 限制在 4194304。追加 `V14`，只放宽这条检查到 31457280，并增加可空的 `source_file_name VARCHAR(120)`。不改 `ck_admin_media_variant_size`，不改 `V5` 文件。变体表的 4MB 检查保持。旧行的文件名为 NULL。

## 文件名

从上传部分的文件名取最后一段，去掉路径分隔符和控制字符，截断到 120。空结果存 NULL。文件名只用于后台搜索和显示，不参与对象键，不进入公开 DTO。

`GET /api/admin/v1/media`：没有 `q` 时仍返回最近 50 张。`q` 非空时按文件名做不区分大小写的包含匹配，转义 `%` 和 `_`，最多 50 条。前端再并入当前目录草稿里描述匹配的图片；缺的缩略图用已有的单张读取补齐，同样最多 50 条。作品抽屉里的描述用当前作品表单里的描述，不把作品描述写进图片库。

## 选择与多张上传

`MediaField` 在没有图片时，点击空位打开现有抽屉。列表里的安静占位不打开抽屉。

文件框增加 `multiple`，仍然 `accept="image/jpeg,image/png"`。抽屉和图片库把选中的文件逐张上传，每张使用自己的幂等键，沿用 `POST /media/uploads` 的单文件契约。一张失败就停在这一张并报告文件名，已经成功的留在列表里。不并行上传，避免同时解码多张大图。

作品编辑在每张成功后按现有规则加入，满 9 张后不再加入，并说明上限。单张选择的封面和描述行为不变。

文案：`MEDIA_TOO_LARGE` 改为「图片超过 30MB。」图片库说明改为单张不超过 30MB、只接受 JPEG 或 PNG。

## 兼容与回滚

- 旧图片没有文件名，文件名搜索找不到它们。最近列表和描述搜索仍可用。
- 公开快照里的变体字节不变。已发布内容不需要重发。
- 已部署的管理库要执行 `V14` 之后，超过 4MB 的上传才能写入。未迁移时数据库会拒绝这些行。
- 图片上传走管理后台。部署说明里 `admin.seekway.xyz` 的 `client_max_body_size` 是 `32m`。公开接口仍是 `12m`。线上后台 nginx 不改的话，默认约 1MB，大图到不了应用。
- 回滚代码时，若 `V14` 已执行，旧代码仍能读新列；它写不了超过 4MB 的行，因为应用自己会先拒绝。不要删除 `source_file_name`，除非同时确认没有新代码在读它。

## 取舍

顺序上传比并行慢，但失败边界和内存占用都清楚。搜索最多 50 条，和现在的列表上限一致，避免一次把整个库画出来。像素上限不放宽：30MB 解决的是同一尺寸下精修 JPEG 过大，不是把 4000 万像素以上的底片放进后台。
