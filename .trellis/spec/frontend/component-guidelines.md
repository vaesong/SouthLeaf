# Frontend Component Guidelines

- Keep the approved four tabs and two details; no stage-one booking/order/payment/admin/private-delivery expansion.
- Shared DemoNotice reflects server data mode. Pages consume validated public view objects, not raw SQL/HTTP details or hardcoded business arrays.
- Preserve curated three-service home, vertical services and team, compact anchored sort and direct independent layout cycles. No layout-selection menu, team specialty tags or detail contact CTA.
- Use loading/empty/error/unavailable states without fake business content. Optional portrait may use the approved initial mark, not an unapproved photograph.
- Do not reintroduce deleted modal/waterfall/footer/vendor components simply because they remain in old Git history.
- Shared presentation helpers must not perform network access, qualification or authorization decisions.
