## 1. 设计目标

- 让有既存后台 capability 的受控操作员，在 S2 2A 本地隔离环境完成一个合成作品的上传、编辑、预览、发布、公开读取与撤回闭环。
- 管理 UI 是 `admin-web` 的真实认证后页面，调用同源 `/api/admin/v1`；继续使用 S1-D session、Origin/CSRF 及服务端 capability 检查。隐藏按钮、路由守卫或客户端状态不是安全边界。
- 页面只展示服务端判定后的最小状态，不提供授权事实/证据管理，不扩展未经 Q06 确认的生产角色。发布成功必须来自服务端事务终态，不能用乐观 UI 或静态 mock 替代。
- 本节是 S2 首个纵向切片，不是完整 CMS、真实授权审查系统、2B 平台上线或生产运营批准。

## 2. 内容、作品、业务和套餐维护

S2 页面仅提供作品列表、建立空草稿、单作品详情/修订编辑、单图上传及衍生状态、封面选择/排序、只读预览、发布与撤回。字段按 D-302 的公开白名单收敛到标题、简介、分类码与媒体绑定；不含价格、套餐、客户、档期、订单、联系信息或批量导入。

上传状态明确显示 `RECEIVING / PROCESSING / READY / REJECTED / FAILED_RETRYABLE / WITHDRAWN`。只有服务端确认 `READY` 的 `thumbnail`、`preview` 才可绑定；页面不接收外部图片 URL，不显示原图直链、对象 key 或签名地址。草稿编辑使用强 If-Match 修订 ETag；冲突须提示刷新/复核，不覆盖他人新修订。创建/上传/发布/撤回按 D-403 使用命令幂等键。

所有 2A 画面和对象均使用合成资料及专用可销毁测试目录；不得用真实客户作品、儿童/家庭/婚纱素材或授权证据填充演示。

## 3. 公开授权资格与发布阻断

页面以只读门禁摘要呈现 `VALID / INVALID / UNKNOWN / EXPIRED` 与必要的 scope/purpose/channel/有效期类别。只显示明确可供操作员决策的安全状态，不显示证据文件、主体姓名/联系方式、授权原文、私下说明、法律撤回原因或内部对象地址。

发布按钮可按已知状态禁用以改善体验，但服务端在每次发布、预览媒体及公开读取时都必须重新检查当前权威授权版本、媒体范围和时间窗。`UNKNOWN`、依赖故障、缺行、已到期、scope 不匹配均 fail-closed；UI 不能把失败映射成“已授权”。S2 synthetic profile 的演示判定必须显式标注 `TEST_SYNTHETIC`；生产配置不得加载它。

后台没有“授权/批准/补证/法律撤回”按钮。A15 权威撤回由独立责任边界处理；不能以作品业务下架按钮冒充法律授权撤回。作品撤回后 UI 显示服务端终态及命令 ID，公共列表/媒体路由应已拒绝新读取。

## 8. 通知、审计和异常

S2 仅记录最小后台操作审计和命令终态；不发送任何真实通知。权限/授权未知、存储/数据库异常、版本冲突均显示可行动的安全错误类别，不在 UI、普通日志或错误堆栈暴露密钥、对象 key、证据或敏感资料。完整通知/补偿由后续 S6/2B 另行设计。

## 9. 测试和验收

验收必须走真实后台 session/CSRF、管理 HTTP API、图片解码/衍生、双 schema MySQL/InnoDB 和真实 public-api/小程序作品页请求，不能只跑页面 mock。基本路径为：合成图片上传并校验 → `READY` 和两种衍生图 → 建草稿并预览 → 装载明确标记的 synthetic 授权判定 → 发布 → public 列表/详情与同源媒体读取 → 撤回 → 新的公开 JSON、GET/HEAD 与旧游标均拒绝/失效。

负向检查含伪装/损坏/超限图片、版本冲突、重复与同键异 payload、媒体不 READY、授权缺失/错误 scope/自然到期/依赖不可用、发布事务回滚、未知提交复查、媒体撤回后复读、对象 root 隔离及清理。保留不含秘密/真实资料的可复现证据，列出数据库版本、身份/grants、浏览器/API 测试数、退出码及清理状态。该验收只证明 S2 合成 2A 切片，不覆盖 2B、真实授权、真机或生产。
