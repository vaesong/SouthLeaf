## 1. 目标、入口与技术边界

首个交付只解决“工作人员能安全登录、知道当前身份与权限、退出且旧会话失效”。不以假订单/假收入/假待办填充仪表盘，不为尚未实现的模块放可点击空壳入口。

新增独立 `admin-web/`，Vue 3 + TypeScript + Vite + Vue Router + Element Plus；不改原生微信 `frontend/` 的运行依赖。数据流为 HTTP client → auth/application composable → route/view；组件不读写 Cookie token、不直接访问数据库。S1 用组合函数管理内存身份，无必要不加全局状态库。

UI 与 API 生产同源 HTTPS；开发经本地受信 HTTPS 代理，浏览器请求相对 `/api/admin/v1/...`。不在页面代码写本机回环地址、真实域名或秘密，不靠禁用 Secure/CSRF 来调通。

## 2. 页面与路由

| 路由 | 内容 | 前置与结果 |
|---|---|---|
| `/login` | 账号标识、密码、提交状态、稳定错误、requestId | 匿名可见；已有会话转受保护首页 |
| `/` | 今天要处理的预约、目录和通知；账号与退出在侧栏 | 已登录才显示；数量来自真实接口，读失败显示「—」，不填假数字 |
| `/forbidden` | 权限不足说明、返回可访问入口 | 不清除有效会话，不循环转登录 |
| 未知路径 | 明确 404 和首页入口 | 不把任意路径当作未来功能存在 |

后续内容/预约/订单/失败任务各自作为 feature 模块接入统一布局、权限反馈和请求封装，不把全部业务装进 auth store。角色名称/工作台分组在 Q06 确认后映射；当前仅展示服务端返回的 capability，不发明“超级管理员”角色。

## 3. 会话状态机

`UNKNOWN → CHECKING → AUTHENTICATED | ANONYMOUS | UNAVAILABLE`。

- 页面启动先 GET session；检查完成前不闪现受保护内容。
- 200 进入 AUTHENTICATED，身份只保存在内存；401 进入 ANONYMOUS；503/网络失败进入 UNAVAILABLE，不把依赖故障判成退出或密码错误。
- 受保护业务请求返回 401，立即清身份/敏感页面缓存并转登录；403 保持身份，显示权限或 CSRF 反馈；429 展示等待；503 留在可重试状态。
- expiresAt 只用于到期提示，不用于客户端授权；服务端仍逐请求判断。浏览器后台恢复/重新获得焦点时重新校验，不用本地时钟续期。
- 多 tab 可通过 BroadcastChannel 广播不含秘密的“会话已变化”提示；接收者重新 GET session，不信任广播携带的身份/权限。

## 4. 登录流程与表单

1. 获取 CSRF token，仅保存内存；准备失败时禁用提交并提供显式重试。
2. 账号标识原值提交，密码不 trim/归一化；字段绑定 label、明确 required、密码控件允许粘贴和密码管理器，autocomplete 分别为 username/current-password。
3. 提交时禁用按钮与重复 Enter；不在 URL、localStorage、sessionStorage、埋点或日志记录密码/令牌。
4. 成功后清密码、更新内存身份、重新获取轮换后的 CSRF token，再进入安全返回路径。
5. 401 使用统一“账号或密码不正确，或账号当前不可用”；不显示不存在/禁用细节。429 按 Retry-After 提示，网络恢复不自动重发登录。
6. 登录超时先查询 session 复核：有效则正常进入；401 让用户再次提交；503 显示“登录结果暂无法确认”，不在后台循环重试。

返回路径只接受应用内受支持相对路径，拒绝 scheme、`//`、反斜线和编码绕过；默认 `/`。不接受外站 redirect URL；未来表单重登录不自动重放尚未确认的写命令。

## 5. 退出与异常恢复

退出为带 Origin/CSRF 的 POST。204 后清身份/缓存并广播变化，转登录；先清 UI 再忽略服务端失败不算退出成功。503 或网络失败显示“服务端退出尚未确认，请重试”，不隐藏可能仍有效的会话事实，不自动刷新为成功。

CSRF 失效时获取新 token 并让用户重新点击；不自动重放带业务副作用的命令。会话失效时 S1 仅清登录密码；以后内容表单草稿是否保留需各 feature 按数据敏感度设计，不默认把客户/授权信息存浏览器。

## 6. 工作台与待办的扩展协议

| 批次 | 增量工作台能力 | 状态来源 |
|---|---|---|
| S2 | 上传处理、草稿、发布/撤回、处理失败 | 实际媒体/发布 API，不能用前端乐观成功冒充完成 |

## 7. 可访问性、隐私与测试

键盘可完成登录/退出，焦点进入首个错误字段；异步错误使用可读状态提示，不仅靠颜色。支持窄窗口和 200% 缩放，密码显示切换有明确名称；系统忙/空/错/权限不足均有不同文案。表单错误不回显密码，示例使用虚构账号标识。

单元/组件测试使用 Vitest + Vue Test Utils；浏览器用 Playwright。须验证 UNKNOWN 闪屏、401/403/429/503、重复提交、网络超时复核、退出失败、多 tab、开放重定向防护和键盘流程。组件 mock 测试单独标识；至少一组实际 HTTPS → 管理 API → 独立测试 MySQL 的登录/退出/禁用 E2E 才能验收 S1-D。

截图/trace/HAR 不得包含密码、Cookie、CSRF 值或真实人员信息；认证网络体不得默认录入附件。静态构建通过不等于真实会话闭环通过。运行环境/依赖版本/浏览器与限制按 P03 证据格式记录。
