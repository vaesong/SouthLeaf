## 1. 设计目标

小程序的公开浏览必须让客户区分“正在加载”“没有公开内容”“内容已不可用”“网络失败”和“服务端暂时不可用”。接口消费层负责把公开查询响应转换为稳定的客户端展示模型，页面不直接依赖后端持久化字段，也不自行推断发布状态、授权资格或价格事实。

阶段一消费范围：品牌/首页、作品、摄影业务、套餐和公开媒体读取。预约、订单、支付、退款、私密交付和客户身份状态不进入本阶段实现。

## 2. 接口响应与客户端模型

### 2.1 统一响应草案

具体 JSON 字段在 D-401 评审后锁定，当前建议所有公开查询使用统一外层：

```json
{
  "requestId": "req_xxx",
  "code": "OK",
  "message": "",
  "data": {},
  "meta": {
    "serverTime": "2026-10-06T10:00:00Z",
    "contentVersion": "public-version-xxx"
  }
}
```

约束：

- `requestId` 用于客户反馈和服务端日志关联，不向客户解释内部堆栈；
- `code` 是稳定机器可读代码，页面不根据 `message` 做分支；
- 成功时 `data` 可以为空列表或空区块，但不使用错误码伪装空数据；
- 错误时不返回草稿、内部授权原因、客户信息、内部媒体地址或数据库异常；
- `meta.contentVersion` 只表达公开版本，用于刷新和缓存判断，不表达内部表版本。

### 2.2 客户端展示模型

建议在 API 适配层转换为以下展示模型，字段名称统一，不沿用原型中 `images`、`imageSrc` 等混用字段：

- `HomeViewModel`：品牌摘要、精选作品、业务摘要、套餐摘要、联系摘要；
- `WorkListItemViewModel`：`id`、`title`、`coverMedia`、`businessLabels`、`publishedAt`；
- `WorkDetailViewModel`：作品摘要、公开说明、媒体列表、关联业务/套餐、联系摘要；
- `BusinessViewModel`：`id`、`name`、`summary`、`coverMedia`、`hasPublishedPackages`；
- `PackageListItemViewModel`：`id`、`name`、`businessId`、`summary`、`displayPrice`、`coverMedia`；
- `PackageDetailViewModel`：套餐信息、服务项、适用人群、时长、价格说明、注意事项和联系摘要；
- `AboutViewModel`：品牌资料、地址、工作时间、电话、微信联系方式；
- `MediaViewModel`：SouthLeaf 受控媒体网关引用、缩略图/预览尺寸、替代文本和资格确认/加载状态。

`MediaViewModel` 中的 URL 只能消费 D-401 `PublicMediaDTO` 返回的 SouthLeaf 受控媒体网关引用。客户端不得接收、持久化或自行拼接供应商直链、永久签名地址、公共桶地址或原始 key，也不得把 URL 存在视为作品仍有公开资格。

展示模型不得包含 `authorizationId`、客户姓名、内部备注、草稿状态、原始存储 key、后台角色或未发布字段。

### 2.3 页面数据状态

页面状态建议按资源独立维护：

```text
idle
  → loading
  → success(nonEmpty)
  → success(empty)
  → unavailable
  → error(retryable / nonRetryable)
```

媒体子项另行维护 `hiddenPendingEligibility / loading / loaded / failed`。首页、列表、详情、从后台恢复和分享入口中的作品媒体默认进入 `hiddenPendingEligibility`，只有当前资格二次确认及网关读取成功后才进入 `loaded`；待确认期间不得展示旧图。单个可选媒体失败不应自动把仍可用的主资源判为整体失败。

## 3. 加载、空状态和骨架状态

### 3.1 首次加载

- 首次进入页面显示稳定尺寸的骨架或加载指示，避免内容跳动；
- 加载期间不把上一资源的标题、价格或图片冒充当前资源；同一页面/资源的普通品牌、业务和套餐文字投影可按第 7 节短时缓存规则继续展示，但作品媒体仍隐藏至当前资格二次确认完成；
- 详情页参数无效时无需发起请求，直接进入参数错误的公开提示和返回操作；
- 页面卸载或请求被新请求替代时，旧响应不能覆盖新状态。

### 3.2 空状态

空状态只表示查询成功但当前没有可公开展示的结果：

- 作品暂无公开内容：提示“暂时没有可展示的作品”，提供返回首页/切换业务；
- 某业务暂无已发布套餐：显示业务说明和电话/微信咨询入口，不显示测试数据；
- 首页某一区块为空：隐藏该区块或展示简短空态，不阻塞其他区块；
- 关于资料未完整配置：只展示已确认字段，不能用错误的默认地址、电话或价格补齐。

空状态不是错误，不应反复自动重试。

## 4. 处理中、明确失败和未知结果

阶段一公开查询只有读操作，客户端重点处理以下结果：

| 结果 | 客户侧表现 | 是否重试 |
|---|---|---|
| 成功有数据 | 展示内容 | 用户刷新或进入页面时按策略刷新 |
| 成功无数据 | 空状态 | 不自动循环 |
| 资源不可用 | 统一不可用提示和返回 | 允许用户返回；不重复请求同一失效资源 |
| 网络失败 | 网络不可用提示、重试 | 用户主动重试，必要时退避 |
| 服务暂不可用 | 服务繁忙提示、requestId、重试 | 允许重试，避免高频 |
| 响应格式错误 | 通用异常提示、requestId | 记录客户端诊断，不泄露细节 |
| 媒体单项失败 | 主资源仍可用时保留文字和已确认媒体，缺失可选媒体并标记图片不可用 | 可单项重试 |

`PUBLIC_MEDIA_UNAVAILABLE` 固定按 HTTP 503 处理，表示作品资格已确认但本次媒体网关读取失败；`PUBLIC_RESPONSE_INVALID` 固定按 HTTP 500 处理。聚合 JSON 中部分媒体失败但主资源仍可用时，外层保持 `OK`/200，并消费可选媒体字段缺失或 D-401 既有契约表达，不把同一结果同时解释为 200 和 503。资源级授权/资格未知不属于媒体读取失败，必须 fail-closed 并进入统一资源不可用路径；授权依赖整体故障导致无法可信计算列表时，消费 `PUBLIC_SERVICE_UNAVAILABLE`/503 并展示服务暂不可用，不解释为成功空列表，也不回退旧许可。

客户端不得把“请求发出”视为发布成功，也不得在公开读取失败时回退到生产环境内置的历史示例内容或旧作品图片。

## 5. 冲突、无权限、下架、失效和到期

阶段一匿名公开页面不返回客户业务权限。以下服务端原因在客户端统一映射为公开资源不可用：

- 资源不存在；
- 尚未发布或已下架；
- A15 授权未核验、资格未知、撤回或资格失效；
- 公开版本已被新版本替换；
- 公开媒体引用失效。

页面提示不区分上述内部原因，不显示“因某客户撤回授权”等敏感细节。列表接口应在查询时过滤不合格资源；详情接口仍必须再次校验，防止旧链接或缓存绕过列表过滤。

如果资源在列表加载后变为不可用，点击详情时以详情查询结果为准，并清理对应本地缓存项。

## 6. requestId、重试和联系客服

- 每次服务端请求保留 `requestId`；同一页面重试生成新的请求，不能复用旧 requestId 作为幂等凭证；
- 客户提示优先给出可行动建议：检查网络、稍后重试、返回上一页、电话/微信咨询；
- 仅在客户需要向工作室反馈异常时展示简短 requestId，不展示堆栈、URL、签名和内部服务名称；
- 重试按钮有稳定尺寸和防重复点击状态；
- 网络失败采用短暂退避，禁止页面在失败时无限自动刷新；
- 联系工作室属于外部联系动作，不把“联系客服”记录为预约或售后工单。

### 6.1 前端编码适配边界

阶段一实现先固定页面和 API 适配层边界，接口字段最终以 D-401 联合评审为准：

- 页面只接收 `HomeViewModel`、`WorkListItemViewModel`、`WorkDetailViewModel`、`BusinessViewModel`、`PackageListItemViewModel`、`PackageDetailViewModel` 和 `AboutViewModel`，不直接读取持久化实体字段。
- `frontend/api/` 负责请求、统一响应解析、错误映射和展示模型转换；页面不再维护历史示例作品、套餐价格或活动日期。
- 公开接口未接通或返回空数据时，页面显示加载、空状态、不可用或重试状态，不回退到旧硬编码数据。
- `PackageDetailViewModel` 的 `serviceItems`、`tips`、`notices` 为详情页三段内容来源；缺失字段按安全空态或“以最终确认资料为准”展示。
- 轮播使用 `HomeViewModel.heroItems` 的配置数量，不在页面写死三张或五张，也不展示数字计数。

阶段一公开错误码：

| 错误码 | HTTP | 含义 | 客户提示 |
|---|---:|---|---|
| `OK` | 200 | 成功 | 无 |
| `PUBLIC_RESOURCE_UNAVAILABLE` | 404 | 资源不再公开；资格未知按 fail-closed 处理 | 内容暂不可用 |
| `PUBLIC_QUERY_INVALID` | 400 | 查询参数无效 | 请求内容有误，请返回重试 |
| `PUBLIC_SERVICE_UNAVAILABLE` | 503 | 必需公开查询依赖暂不可用 | 服务暂时繁忙，请稍后重试 |
| `PUBLIC_MEDIA_UNAVAILABLE` | 503 | 资格已确认但媒体网关读取失败 | 部分图片暂时无法显示 |
| `PUBLIC_RESPONSE_INVALID` | 500 | 服务端响应转换失败 | 页面加载异常，请重试 |

以上六个稳定码及本节的 HTTP 映射以 D-401 为准；具体响应字段、文案和 API 前缀仍待联合评审。

## 7. 本地缓存、刷新和过期数据

- 仅允许短时缓存普通品牌、业务和套餐公开文字投影，不缓存作品媒体、客户资料、授权凭证、订单、私密媒体、供应商直链、永久签名地址或原始 key；
- 普通文字投影缓存必须带 `contentVersion`、获取时间和资源标识；TTL 与 ETag/版本协商具体数值仍待环境验证，不在客户端写死未经评审的值；
- 首页、列表和详情可以在刷新期间展示最近一次成功的普通品牌/业务/套餐文字投影，但作品媒体必须独立处理：展示前通过 SouthLeaf 受控媒体网关完成当前发布、绑定和授权/资格二次确认，待确认时隐藏旧图；
- 上述作品媒体规则同样适用于首次进入、下拉刷新、重新进入、Tab 返回、从后台恢复和分享/扫码入口；不得先显示旧媒体缓存再异步校验；
- 作品媒体响应按 `no-store` 消费，不以 304、Range、本地文件命中、旧 URL 或缓存元数据作为资格确认；
- 授权/资格读取超时、未知或无法证明时 fail-closed；服务端返回不可用后清理对应资源及媒体状态，弱网或刷新失败不得恢复旧作品图片；
- 缓存失效、投影重建或通知任务失败只影响后续补偿，不改变当前拒绝结果，也不能恢复公开；
- 普通文字投影也不能覆盖服务端已确认的下架/替换结果；详情版本不一致时以当前服务端结果为准。

## 8. 网络异常和重复操作

- 无网络：保留当前页面结构和返回操作，显示网络提示及重试；首次加载无缓存时显示空白内容区而非错误数据；
- 超时：显示服务暂不可用，可重试；旧请求结束后不得覆盖新请求；
- 弱网重复点击：按钮进入提交中/禁用状态，查询请求按页面和参数合并，避免同一资源并发刷新；
- 切换 Tab：取消或忽略不再可见页面的旧请求，避免返回后产生内容闪烁；
- 小程序从后台恢复：普通文字投影按页面类型和缓存年龄决定刷新，不能无条件高频请求；所有可见作品媒体先隐藏，再完成当前资格二次确认和网关读取；
- 联系动作重复触发：由系统能力和页面锁定状态防止重复拨号/复制操作，但不产生业务记录。

## 9. 测试和验收

1. 成功、有数据和成功、无数据分别呈现，不用假数据填充空态。
2. 首次加载、网络失败、超时、服务不可用和响应格式错误都有明确提示、返回或重试路径。
3. 作品/套餐已下架、授权撤回、旧链接和不存在资源均进入统一不可用状态，不泄露内部原因。
4. 列表过滤和详情二次校验同时生效；授权/资格未知 fail-closed，旧缓存和失效任务失败不能恢复已下架或撤回资源。
5. 首页、列表、详情、后台恢复和分享入口中的作品媒体，在当前资格二次确认前隐藏旧图；304、Range、本地缓存和旧 URL 均不能绕过确认。
6. 一个可选媒体加载失败不阻塞其余文本和可用媒体；主资源仍可用时按 `OK`/200 中的可选媒体缺失或既有契约表达，单项网关失败按 `PUBLIC_MEDIA_UNAVAILABLE`/503 重试。
7. `PUBLIC_RESPONSE_INVALID` 固定映射 HTTP 500，响应解析失败进入同名本地异常状态，不与 503 混用。
8. 重试生成新的 requestId，旧请求不能覆盖新请求，快速点击不造成重复加载风暴。
9. 切换设备、清除缓存和从后台恢复后，展示结果仍以当前公开数据为准。
10. 客户端日志不含授权凭证、客户资料、内部存储 key、签名地址和完整服务端错误。
11. 阶段一不触发登录、预约、订单、支付、退款和私密交付接口。
12. 所有页面状态在真机网络条件下可操作，不以控制台日志代替用户反馈。
13. 套餐详情的套餐内容、温馨提示和拍摄须知均来自 `PackageDetailViewModel`，缺失时不显示旧原型内容。
14. 页面源码和打包产物中不出现历史测试价格、活动日期、测试客服号码或旧示例详情作为公开回退数据。

## 10. 当前实现与验证边界

前端源码已按本文件的适配边界完成首批实现。`frontend/api/` 不再向页面暴露持久化实体字段，公开请求成功时保留 `data`、`meta` 和 `requestId`，失败时使用稳定错误码；页面根据资源状态区分加载、成功空数据、内容不可用和可重试错误。作品/套餐列表使用公开业务 ID 查询并保留游标，详情页按公开 ID 二次查询。

当前实现为原生微信 App/Page/Component，唯一源码 frontend。公开数据与媒体通过真实数据库和受控网关读取；列表、详情、隐藏/恢复、分页、失效游标和迟到响应隔离由 Node/集成/实际接口测试覆盖，微信编译和单次六路 UI 回归单独执行。

构建命令为显式 SOUTHLEAF_API_ORIGIN 配置后的 npm run build:demo；release 读取结构化 config/release.json，拒绝未配置的正式身份。旧 run-uni/HBuilder/uni-app 命令和 unpackage 产物已退出当前运行链。

阶段一验收演示内容工程，不代表真机系统行为、真实授权或正式上线通过。真实资料、权属/客户授权材料、后台与正式平台/生产配置在阶段二交付；资格规则与 production 守卫保留。当前证据以[收敛交付记录](../../../开发与演示/阶段一收敛交付记录.md)为准。

## 11. 待确认问题

- 普通公开文字投影的缓存 TTL、ETag/版本协商具体取值；作品媒体 `no-store` 和展示前资格复核不属于待确认项；
- 首页区块是否允许部分成功及其最终视觉降级方式；主资源仍可用的部分媒体失败继续使用 `OK`/200 内的可选媒体缺失或既有契约表达；
- 公开媒体失败时的安全占位视觉和替代文本；待资格确认时必须隐藏旧图；
- requestId 是否需要提供给工作室运营人员，以及反馈渠道；
- 正式 HTTPS 域名、合法域名和发布环境的错误响应约束。

## 12. 历史演示实现检查点（旧批次，不作当前技术栈/计数依据）

用户允许展示资料后，公开 API 现在返回 demo 数据及 `meta.dataMode`。六页有演示提示；网关相对 URL 只解析到已配置 API 主机；详情以首个返回媒体作为封面回退；价格枚举按当前 API 归一。新增真实分享路径和微信号确认/复制，空电话不产生拨号入口。生命周期辅助器在 onHide 隐藏媒体并递增请求版本，返回前台重查；首页/详情也加入陈旧响应隔离，六页支持下拉刷新。

本次前端 8 项 Node 测试及 `build:demo` 通过，后端为 32 项测试。当前 JSON/媒体均 no-store，没有实现普通文字短时缓存。release 构建要求 HTTPS/AppID，release 客户端拒绝非 production 元数据。源码和编译验证不替代微信分享、复制/拨号、图片缓存、后台恢复及弱网真机验收。
