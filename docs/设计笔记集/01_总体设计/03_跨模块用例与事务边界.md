# 跨模块用例与事务边界

> 文档编号：D-103
> 文档状态：评审中（阶段一公开展示事务草案）
> 适用范围：阶段一为主；阶段二、阶段三保留扩展边界
> 更新日期：2026-10-08
> 上游需求：A04、A05-A08、A15-A16
> 上游架构：AT04、AT05、AT06、AT07、AT08、AT09
> 关联计划：P01

## 1. 设计目标

本文定义阶段一“小程序公开展示”涉及的跨模块用例、事实归属、只读协作和事务边界，确保 D-401 公开查询、D-501 数据归属、D-601 路由、D-602 状态消费和 D-702 验收场景可以在编码前形成一致约束。

阶段一只开放匿名、只读、可缓存、可撤回的公开浏览：品牌与首页编排、作品/案例、六类摄影业务、已发布套餐、公开媒体和已确认联系方式。阶段一不包含管理后台、客户登录、预约、订单、支付、私密成片交付和客户私密资料。

## 2. 责任边界与事实归属

### 2.1 模块职责

| 模块 | 持有或负责的事实 | 阶段一跨模块动作 | 明确不负责 |
|---|---|---|---|
| `content` / A05 | 品牌资料、公开内容版本、首页区块和公开编排、联系方式 | 读取作品/业务/套餐公开摘要，组装 `PublicHomeDTO` | 作品授权、套餐价格规则、订单和交付 |
| `works` / A06 | 作品案例、作品分类/标签、媒体业务关联、作品公开资格派生结果 | 消费 A15 授权结果，判断可公开作品并提供公开摘要 | 创建/撤回授权事实、私密交付、订单 |
| `catalog` / A07 | 六类摄影业务、套餐、服务项、价格表达和公开版本 | 提供已发布业务/套餐公开摘要和详情 | 预约、订单、支付、定金支付事实 |
| `delivery` / A15 | 公开授权主体、范围、用途、渠道、期限、证据和撤回事实 | 向 A06 提供授权结果或资格查询端口 | 作品分类、首页编排、公开 DTO、阶段一后台 |
| `media` / storage | 媒体登记、处理状态、公开读取引用 | 提供经过资格过滤的受控公开媒体 | 业务授权、客户归属、私密交付访问 |
| `public-query` | 安全公开投影和查询编排 | 执行 D-401 查询、分页、DTO 和统一错误映射 | 写入领域事实、修改发布/授权状态 |

A15 持有公开授权事实；A06 消费授权结果并计算公开资格；A05/content 负责公开编排。任何模块都不能通过客户端字段、缓存标志或直接改表绕过这个归属关系。

### 2.2 阶段一唯一数据路径

```text
A15 公开授权事实
  → A06 授权结果消费与 PublicEligibility 派生
  → A05/content 公开编排（首页引用）
  → PublicProjectionReader
  → D-401 公开查询 DTO
  → D-601 路由与 D-602 展示状态
```

`PublicProjectionReader` 只返回已经发布、当前有效且经过安全过滤的公开投影。公开查询层不能先读取全量数据再把过滤责任交给小程序。

## 3. 跨模块用例目录

| 用例 | 发起方 | 主要模块 | 关键结果 |
|---|---|---|---|
| 读取首页公开编排 | 匿名访客 | `content` + `works` + `catalog` + `public-query` | 返回品牌、精选作品、业务/套餐摘要、已确认联系摘要 |
| 读取品牌资料 | 匿名访客 | `content` + `public-query` | 返回已发布品牌、工作室和联系资料 |
| 浏览公开作品列表 | 匿名访客 | `works` + `delivery` + `media` + `public-query` | 只返回发布状态有效且 `PublicEligibility=eligible` 的案例 |
| 读取作品详情 | 匿名访客/分享入口 | `works` + `delivery` + `media` + `public-query` | 按 `workId` 二次校验后返回公开详情或统一不可用 |
| 浏览摄影业务列表 | 匿名访客 | `catalog` + `public-query` | 六类业务均可表达；没有套餐时保留真实业务空状态 |
| 读取套餐列表/详情 | 匿名访客 | `catalog` + `media` + `public-query` | 返回已发布版本、服务项和已确认价格表达 |
| 生成首页公开投影 | 发布/撤回后任务或受控导入 | `content` + 相关公开摘要端口 | 重新计算编排结果并使旧版本失效 |
| 处理公开资格变化 | A15 事实变化/媒体失效 | `delivery` → `works` → `content`/`public-query` | 重新计算资格、移除失效引用、触发缓存失效 |
| 受控导入公开媒体登记 | 受控导入流程 | `media` + 目标业务模块 | 登记、校验并进入待发布/可引用状态，不开放客户端上传 |

电话、微信、地址和地图操作只产生外部联系动作，不产生预约、订单、支付或客户身份事实。

## 4. 对象、状态和不变量

### 4.1 跨模块对象

| 对象 | 状态摘要 | 阶段一公开条件 |
|---|---|---|
| `PublicContentVersion` | draft、preview、published、withdrawn、expired | 仅 `published` |
| `WorkCase` | draft、review、published、withdrawn、repairing、archived | `published` 且公开资格有效 |
| `PublicAuthorizationFact` | unverified、valid、withdrawn、expired、unclear | 仅 `valid` 参与资格判断 |
| `PublicEligibility` | eligible、ineligible、unknown | 仅 `eligible` |
| `PhotoBusiness` / `Package` | draft、published、withdrawn、expired、archived | 仅当前 `published` 版本 |
| `MediaAsset` | registered、validating、readable、unavailable、withdrawn | 仅受控可读的公开引用 |
| `PublicProjection` | building、current、superseded、invalid | 仅 `current` 且服务端重新校验 |

`unknown`、`unverified`、`withdrawn`、`expired` 和 `ineligible` 默认按不公开处理。公开接口将不存在、未发布、下架、授权撤回和资格失效统一映射为 `PUBLIC_RESOURCE_UNAVAILABLE`，不暴露内部原因。

### 4.2 必须保持的不变量

1. A15 是公开授权事实唯一归属；A06 不创建第二套同意/撤回记录。
2. A06 的公开资格必须同时考虑作品发布状态、图片可用性、授权范围和公开文案/关联完整性。
3. A05 只能编排当前有效公开对象，不能复制作品、套餐或授权事实。
4. 详情接口必须重新检查资格，旧链接和客户端缓存不能绕过下架或撤回。
5. 公开 DTO 不包含客户资料、授权证据、内部备注、原始对象 key、私密媒体或后台角色。
6. 未确认价格、联系方式、地址和地图资料不得由历史原型、默认值或客户端补齐。
7. 六类业务必须可表达：儿童、亲子全家福、婚纱、写真、孕照、证件照；业务存在不等于存在套餐。

## 5. 输入、输出、接口与内部端口

### 5.1 用例输入

公开查询输入仅包括：公开资源 ID、已公开业务筛选、标签筛选、游标/页码、数量限制和可选来源上下文。输入均由入口层校验长度、格式、范围和枚举值。

客户端不得传入或决定 `published`、`authorized`、`visible`、价格、媒体地址、授权 ID 或内部状态。路由参数只作为查询条件，不作为权限凭证。

### 5.2 对外接口

实现路径、版本和统一响应以 D-401 为准，阶段一接口草案包括：

- `GET /api/v1/public/home`
- `GET /api/v1/public/brand`
- `GET /api/v1/public/works`
- `GET /api/v1/public/works/{workId}`
- `GET /api/v1/public/businesses`
- `GET /api/v1/public/businesses/{businessId}`
- `GET /api/v1/public/packages`
- `GET /api/v1/public/packages/{packageId}`

成功输出使用 `requestId`、稳定 `code`、`data` 和 `meta.contentVersion`。列表/详情返回 D-401 定义的 `PublicWork*DTO`、`PublicBusiness*DTO`、`PublicPackage*DTO` 和 `PublicMediaDTO`。接口不返回数据库实体。

### 5.3 内部端口

建议只定义语义端口，不锁定类名、数据库表或供应商：

| 端口 | 提供方 | 消费方 | 允许内容 |
|---|---|---|---|
| `PublishedContentReader` | A05 | `public-query` | 品牌、联系、首页编排公开摘要 |
| `PublicWorkReader` | A06 | A05、`public-query` | 已公开作品摘要/详情和资格结果 |
| `PublicCatalogReader` | A07 | A05、`public-query` | 六类业务和已发布套餐公开摘要/详情 |
| `PublicAuthorizationReader` | A15 | A06 | 授权范围、有效期和撤回结果的业务判断 |
| `PublicMediaReader` | media | A05/A06/A07、`public-query` | 受控公开媒体引用和可读状态 |
| `PublicProjectionReader` | 查询投影层 | D-401 adapter | 已过滤的安全公开投影 |
| `PublicCacheInvalidator` | 查询/任务层 | 发布、撤回、媒体状态变化方 | 资源/版本缓存失效任务 |

端口不得允许调用方修改提供方事实。跨模块不直接读对方表，不直接调用对象存储或供应商 SDK。

## 6. 本地事务、外部调用、并发与幂等

### 6.1 本地事务范围

阶段一公开读取不修改业务事实，单次查询事务只需保证一个公开版本和其关联摘要的一致读取；不能在查询事务中写入发布、授权、价格或客户数据。

发布或受控导入流程的本地事务只覆盖本模块事实、版本记录、引用关系、审计摘要和任务/outbox 记录。首页投影、资格刷新和缓存失效不要求与对象存储或其他模块共享分布式事务。

### 6.2 版本与并发

- 公开版本使用服务端版本号或等价不可变标识；发布失败保持旧的 `current` 版本。
- A15 授权变化与 A06 资格重算按资源版本或事件版本处理，旧任务不得覆盖较新的资格结果。
- 首页编排更新和作品/套餐下架并发时，公开查询必须优先按当前资格过滤，不能因旧投影继续暴露失效对象。
- 列表采用稳定排序和受限分页；详情不依赖列表缓存。

### 6.3 幂等与重复请求

- 匿名读取可重复执行；同一 `resourceId + contentVersion + query` 应得到语义一致结果。
- 发布、撤回、资格重算、投影重建和缓存失效任务使用资源版本/动作版本作为幂等键。
- 同一请求重试不产生新授权、新业务版本或重复媒体登记。
- `requestId` 用于诊断关联，不作为公开查询幂等凭证。

## 7. 失败、缓存、任务与补偿

### 7.1 失败映射

| 失败场景 | 服务端结果 | 客户端/内部处理 |
|---|---|---|
| 参数非法或超限 | `PUBLIC_QUERY_INVALID` | 不查询内部数据，提示返回/重试 |
| 资源不存在或不可公开 | `PUBLIC_RESOURCE_UNAVAILABLE` | 统一不可用态，不泄露原因 |
| 公开查询依赖暂不可用 | `PUBLIC_SERVICE_UNAVAILABLE` | 短暂退避后主动重试 |
| 单个公开媒体不可用 | `PUBLIC_MEDIA_UNAVAILABLE` 或部分媒体失败 | 保留文字/其他媒体，记录异常 |
| 投影/响应转换失败 | `PUBLIC_RESPONSE_INVALID` | 通用异常态，日志关联 requestId |
| 发布/撤回任务失败 | 旧公开版本或安全隐藏策略 | 有限重试，失败进入人工补偿 |

### 7.2 缓存规则

- 首页、列表和公开媒体引用可短时缓存，并携带 `contentVersion` 或等价版本。
- 详情和媒体访问必须在服务端重新校验资格，缓存不能恢复已下架或已撤回内容。
- A15 撤回、A06 资格失效、A05 下架和媒体撤回都应触发相关资源、首页精选和引用缓存失效。
- 缓存失效传播未完成时，查询层仍以当前资格为准；不能以缓存失败为由继续公开已知不合格作品。
- 不缓存授权证据、客户数据、私密媒体、原始存储 key 或永久签名地址。

TTL、ETag、CDN 和外部搜索缓存的具体数值仍待评审，不在本文假定供应商能力。

### 7.3 任务和人工补偿

任务至少记录幂等键、对象范围、版本、状态、重试次数、最后错误、requestId/taskId 和人工处理结果。补偿动作必须重新读取当前发布状态、授权结果和媒体状态，不能直接把 `published` 或 `authorized` 改成成功。

通知、缓存失效和投影重建失败不回滚已确认的授权或内容事实；若安全性无法证明，则公开端按不可公开处理并转人工复核。

## 8. 安全、隐私、审计与可观测性

- 公开接口匿名可读但必须使用 HTTPS、合法域名、参数限制、响应大小限制、基础限流和异常监控。
- ID 使用不透明公开标识，错误响应统一，防止通过枚举和差异推断草稿、授权撤回、客户和内部状态。
- DTO、缓存和客户端日志不得包含客户姓名/联系方式、授权证据、内部备注、永久签名 URL、供应商凭证或对象 key。
- A15 授权事实、A06 资格变化、A05 发布/下架、媒体替换和缓存/补偿任务记录脱敏审计。
- 普通运行日志至少关联 `requestId`、资源摘要、版本和结果；不记录原始授权文本、私密地址或完整查询敏感参数。
- 指标至少观察公开查询成功率、不可用率、响应延迟、媒体失败率、缓存命中/失效、资格重算积压和补偿失败数。

## 9. 阶段开放范围

| 能力 | 阶段一 | 阶段二 | 阶段三 |
|---|---|---|---|
| 匿名公开查询 | 开放，只读 | 继承 | 继承 |
| 首页/品牌/作品/业务/套餐公开投影 | 开放 | 继承 | 继承 |
| A15 授权事实维护 | 受控前置事实/导入结果，不交付后台 | 可纳入运营后台 | 完整授权执行和撤回 |
| 公开媒体读取 | 开放，受控引用 | 继承 | 继承 |
| 公开媒体客户端上传 | 不开放 | 按后台设计 | 按交付设计 |
| 管理后台和内容 CRUD | 不开放本阶段交付 | 开放 | 继承 |
| 客户登录、预约、订单 | 不开放 | 开放相应业务 | 继承 |
| 支付、私密交付 | 不开放 | 不开放 | 开放 |

## 10. 测试与验收输入

至少覆盖 D-702 场景：四 Tab 可达、首页深链、六类业务、业务无套餐、合格/不合格/撤回作品、套餐价格状态、旧链接、分页和非法参数、缓存版本、网络/5xx、部分媒体失败以及阶段外接口未被调用。

跨模块关键断言：

1. A15 授权有效是作品公开的必要输入，不是客户端字段。
2. A06 资格失效后，作品列表、首页、详情、相关引用和媒体入口均按当前结果处理。
3. A05 只编排有效公开对象，不复制对象事实。
4. 价格、联系方式、地址或地图未确认时，不出现历史原型值或默认值。
5. 公开读取不会创建登录、预约、订单、支付或私密交付事实。

## 11. 设计假设与待确认问题

### 11.1 设计假设

- 阶段一通过受控数据源或导入流程准备公开事实，具体维护工具可后续确定。
- 初期可使用同库任务表或事务性 outbox 管理投影重建与缓存失效。
- `PublicProjection` 可以实时查询或按版本构建，最终是否独立持久化不影响公开资格必须由服务端重新校验。

### 11.2 待确认问题

- 阶段一公开数据的权威维护来源、受控导入人、审核人和发布责任。
- A15 向 A06 提供授权结果的内部端口、查询时效、授权粒度和撤回通知机制。
- A06 公开资格重算的具体触发方式、单图/整案撤回策略和安全默认时限。
- A05 首页编排版本、失效引用处理和跨端共享方式。
- D-401 的正式 API 前缀、错误码锁定、公开媒体引用生成、ETag/TTL 和撤回传播目标。
- 六类业务的首批真实资料、套餐价格表达、地址、电话、微信和地图资料。

> 本文禁止在阶段一引入预约、订单、支付、客户登录、管理后台或私密交付实现；这些能力仅保留跨阶段边界和测试输入。
