## 1. 目标与范围

D-104 已给出推荐的模块图和依赖方向；本文继续把它细化为“当前源文件、资源、测试、脚本分别归属哪里”，并规定 Maven 聚合构建、公开启动、显式管理迁移和后续管理运行时的验证边界。目标是在移动代码后仍保持公开 API 的功能、main class、数据库权限和启动脚本语义不变，同时能从依赖图和产物内容证明管理 Writer 不在公开 API 产物中。

本文只形成迁移设计，不移动源文件、不改 POM/脚本、不运行构建或测试、不连接数据库、不创建账号或凭据。所有 `backend/*` 模块名和目标包名均为推荐结构，不代表已经创建。

## 2. 当前构建与验证事实

- `backend/pom.xml` 当前是单模块 Spring Boot jar，坐标 `cn.zhinan:uniapp-api:0.1.0-SNAPSHOT`；Boot 插件默认 main class 是 `cn.zhinan.uniapp.UniappApiApplication`。构建输出当前位于 `backend/target/`。
- `backend/scripts/Start-PublicApi.ps1` 从 `backend/` 调用 `mvnw.cmd spring-boot:run`，只注入 Reader 的 `SOUTHLEAF_DB_*` 与公开媒体根。
- `Test-StartupGuards.ps1` 直接检查 `backend/target/uniapp-api-0.1.0-SNAPSHOT.jar`；这些负向启动检查针对公开 API 的 Reader 守卫。
- `Test-DatabaseIntegration.ps1` 显式提供 `southleaf_public` Reader 与 `southleaf_public_it` 测试身份，然后执行 Maven `verify`。`AdminSessionStoreIT` 当前在共用 `southleaf_public_it` 测试 schema 验证管理表事务；这是测试实现验证，不证明正式 Reader/Writer 跨 schema 隔离。
- 当前 `AdminSecurityArchitectureTest` 按旧 `src/main/java/cn/zhinan/uniapp/adminsecurity` 文件路径扫描 import。模块拆分后不能只改路径字符串；应改为对 Maven 模块依赖、包依赖和最终 jar 内容作结构性断言。
- `AdminDatabaseMigrationMainTest` 当前测试显式迁移动作、schema、TLS 与 JDBC URL 参数策略；迁移工具和 `db/admin-migration` 资源目前仍与公开源树处于同一模块。

目前 build/test 的 `target` 共享问题已在阶段二跟踪中记录。多模块后，各模块自然有独立 `target`，但聚合构建仍需串行执行会占用 MySQL fixture 或运行服务的测试；不能为了模块拆分而对共享数据库测试并发。

| 新增管理 main、配置绑定、独立 DataSource、启动账号/grants 守卫、verified wrapper | `admin-runtime` | 新建 `cn.zhinan.adminruntime.*`；不导入公开配置；初期非 Web |

## 4. 测试迁移与边界证明

| 当前测试 | 目标归属 | 后续需要强化的证明 |
|---|---|---|
| `AdminSecurityDomainTest`、`AdminSessionServiceTest` | `admin-security-core` | 纯 Java 领域/用例规则；不加载 Spring context |
| `SecureSessionTokenCodecTest` | `admin-runtime` 的 crypto 适配器测试 | 验证随机 token 与摘要实现；不把具体 codec 实现塞回 core |
| `AdminSessionStoreIT` | `admin-security-jdbc` | 保留真实 MySQL 事务和审计原子性测试；现有 `southleaf_public_it` 结果仍标注为共库测试 |
| `AdminSecurityArchitectureTest` | 拆分到 core、public-api 与 admin-runtime 的架构测试 | core 无 framework 依赖；public-api 不依赖 admin；admin runtime 不扫描 public config；测试不依赖旧源码路径字符串 |
| `AdminDatabaseMigrationMainTest` | `admin-db-policy` / `admin-migration-cli` | 纯 URL/schema 规则进 policy 单测；CLI 动作、Flyway 历史与显式入口在 CLI 测试中验证 |
| `ArchitectureTest`、`RuntimeAccountVerifierTest`、`DatabasePublicApiIT`、`CatalogFixture` 及其他公开用例 | `public-api` | 保持原 Reader 守卫、公开查询和 V1 测试范围；不要求 admin 环境变量 |

建议分四层建立独立门禁：

1. **core 门禁**：Maven 依赖检查和包架构测试证明 `admin-security-core` 只有 JDK 依赖；端口向内、适配器向外。
2. **公开产物门禁**：检查 public jar 不含 `cn/zhinan/adminsecurity`、`cn/zhinan/adminruntime`、`AdminDatabaseMigrationMain` 或管理 V2 迁移资源；公开启动不读取 `SOUTHLEAF_ADMIN_*`。
3. **管理启动门禁**：模拟错误配置、错误 schema/账号、弱 TLS 和过量 grants 均在 Store 暴露/服务就绪前拒绝；初期非 Web，无监听端口。
4. **真实库门禁**：保留现有 `southleaf_public_it` 的 adapter 事务验证并准确标明其共库局限；另设 `southleaf_admin_it` 一类隔离管理测试库/身份，专门验证实际隔离与 grants。没有该测试环境时不 skip 后宣称通过，也不拿生产库替代。

## 5. Maven reactor 与可执行产物

| 模块 | 推荐 artifact | 是否 Spring Boot 可执行包 | 主类/责任 |
|---|---|---|---|
| 聚合父 POM | `southleaf-backend-parent`（名称可随版本治理统一） | 否 | 只聚合模块与管理依赖/插件版本，不放应用代码 |
| `public-api` | 保留现有 `uniapp-api` 坐标以减少发布兼容变化 | 是 | `cn.zhinan.uniapp.UniappApiApplication` |
| `admin-security-core` | `admin-security-core` | 否 | 纯 Java 领域、应用与端口 |
| `admin-security-jdbc` | `admin-security-jdbc` | 否 | JDBC Store adapter；无默认 main |
| `admin-db-policy` | `admin-db-policy` | 否 | 纯函数数据库配置策略 |
| `admin-runtime` | `admin-runtime` | 是 | `cn.zhinan.adminruntime.AdminRuntimeApplication` |
| `admin-migration-cli` | `admin-migration-cli` | 否（普通 CLI jar） | 显式 `AdminDatabaseMigrationMain`；使用独立 dependency classpath/受控启动脚本 |

父 POM 保留 `backend/mvnw`/`mvnw.cmd` 与统一 `dependencyManagement`，但不把 Spring Boot `repackage` 或 `spring-boot:run` 默认绑定到所有子模块。只有 `public-api` 与 `admin-runtime` 配置 Boot 可执行包及各自 main class；core、JDBC adapter、DB policy 是普通库；迁移 CLI 只带 Flyway、MySQL Connector 与其当前所需的最小 JDBC 支持，不依赖 Boot runtime。

`backend/pom.xml` 聚合之后，构建和运行脚本必须显式选择目标模块。`Start-PublicApi.ps1` 仍只注入 Reader 与媒体配置，启动 `public-api`；管理启动（未来另设）只注入 `SOUTHLEAF_ADMIN_DB_*`。迁移脚本只调用 `admin-migration-cli` 的显式动作。不要在聚合父目录含糊调用所有模块的 `spring-boot:run`，也不要通过修改 public main class 来选择管理应用。

|---|---|

| `Test-StartupGuards.ps1` | 仍只针对 public-api jar 与 Reader startup guards；jar 路径改到 public module 输出目录；不以公开守卫测试替代 admin guard 测试 |
| `Test-DatabaseIntegration.ps1` | 继续显式设置 `southleaf_public` 与 `southleaf_public_it`；验证公开链及已有 adapter IT；结果中明确共库局限 |
| `Invoke-DatabaseMigration.ps1` | 继续管理公开 V1/公开 schema；不能调用管理 V2 |
| 新的管理迁移启动入口（未来） | 单独脚本/命令启动 `admin-migration-cli`，只接受 `--validate` / `--migrate`；只读取 `SOUTHLEAF_ADMIN_MIGRATION_*`，绝不复用 runtime 或 Reader 凭据 |
| 新的管理隔离集成入口（未来） | 仅在明确提供隔离 admin test schema/identity 时运行；缺少变量直接失败；不触碰正式管理库 |

## 7. 可逆迁移顺序与行为兼容

为降低一次性改动风险，后续实现可以按以下可独立验证的切片进行；任何一阶段都不得以中间态发布含糊的公开 jar：

1. **建立 reactor 外壳**：保持 backend wrapper 与 `backend/pom.xml` 入口，形成 aggregator 和 `public-api` 子模块；先迁移公开源/资源/测试，确认 public artifact 与默认 main class 行为一致。
2. **抽离核心**：移动 domain/application/port 到 `admin-security-core`，用模块依赖测试替代旧源码路径扫描；public-api 在最终发布前删除管理核心副本。
3. **抽离适配器**：把 JDBC Store 迁入 `admin-security-jdbc`；将 JDK token codec 作为 runtime 提供的 adapter；现有 MySQL 事务测试归位，独立 schema 验证仍单独标记。
4. **拆分策略与迁移 CLI**：提取 `admin-db-policy`；把管理迁移 main 和 V2 SQL 移到 `admin-migration-cli`，用旧/新策略的回归测试证明拒绝集不变。
5. **建立管理运行时**：新建 `admin-runtime` 组合根、专属配置与 Writer guard；先以非 Web 模式验证，未配置管理库时启动失败且不回退 public reader。
6. **固定脚本/产物门禁**：更新脚本、CI 和文档；检查 public/admin/CLI jar 内容，分别构建与测试。任何 Maven integration tests 使用共享 MySQL 时串行运行；不得对正在服务的公开实例使用会清理共享输出的 `clean`。
7. **后续登录闭环**：只有密码核验、限流、HTTP/Cookie/CSRF 与访问控制用例各自设计并实现后，才启用管理 Web 适配器；后台 UI、实际 schema 授权及生产接入另行门禁。

## 8. 当前阶段边界

本设计基于现有源树、测试和 PowerShell 入口做文件/模块归属分析；当前只更新文档，不改 POM、包名、测试路径、资源、启动脚本、凭据或服务，不运行构建/测试，不操作数据库。推荐模块图和迁移顺序用于后续设计与实施拆解；实施期间必须保留公开 Reader 的行为/权限基线，并将“架构隔离通过”“测试库事务通过”“正式管理授权通过”分成不同证据，不能互相代替。

## 9. S1-A 实施前基线与可执行拆分清单

> 本节为 2026-10-18 的计划增补；前文是现状/目标说明。工程方向按 [ADR-004](../08_决策记录/ADR-004_阶段二分批交付与后台安全闭环.md) 确认，S1-A 执行边界按 [P03](../../计划/P03_阶段二分批交付与编码执行计划.md)；尚未移动文件或修改构建。

### 9.1 明确 A/B 分界

S1-A 完成六模块、现有功能归位与构建/产物证明；`admin-runtime` 在 A 中仅承接 token codec、独立非 Web 配置和明确拒绝启动的入口，不产生 DataSource/Store，不打开端口。不做一个看似启动成功但其实无功能的管理服务。S1-B 才提供经过守卫的真实运行组合根，替换明确拒绝状态；两者均不得意外启动 Web。

父 POM 管理 JDK 21、现有 Boot/BOM 及插件版本；不借迁移同时升级依赖。父层用 pluginManagement 管理 Boot 插件；仅实际应用模块声明 repackage/main class，普通库/CLI 不被误打为 Boot fat jar。core 的“JDK only”指 main 编译/运行依赖，JUnit/AssertJ 等 test-scoped 依赖允许且单列。

### 9.2 测试图必须避免隐藏环

当前 `AdminSessionStoreIT` 直接 imports `SecureSessionTokenCodec`。该 codec 目标在 admin-runtime，runtime 又依赖 admin-security-jdbc；因此不能让 JDBC 测试反向依赖 runtime，否则 Maven reactor 即使是 test scope 也形成环。

决定：JDBC IT 使用 test source 中明确命名的 `TestSessionTokenCodec`，只提供符合端口格式的确定性/唯一测试 token 与摘要；不复制生产安全算法实现、不进入主 jar。生产 SecureRandom codec 及其向量/随机性边界测试留在 admin-runtime。JDBC IT 继续验证数据库事务、格式约束、摘要绑定和竞争，不声称它验证生产随机数质量。

现有 Flyway IT 需要管理迁移 SQL：`admin-security-jdbc` 仅以 test scope 依赖普通 `admin-migration-cli` jar 获取唯一的迁移资源，Flyway/MySQL 的测试依赖显式声明；不能复制一份 V2 到 test/resources。CLI 仅依赖 policy/维护库，不依赖 JDBC adapter/core/runtime，故测试图无环。最终 runtime 包不得因此携带 test-only CLI/SQL；产物测试必须证明。

预期主依赖图：

```text
public-api → 无 admin
admin-security-core → JDK
admin-db-policy → JDK
admin-migration-cli → admin-db-policy + 最小 Flyway/MySQL/JDBC
admin-security-jdbc → admin-security-core + Spring JDBC
admin-runtime → admin-security-core + admin-security-jdbc + admin-db-policy + Boot
admin-security-jdbc --test-only--> admin-migration-cli（资源）
```

迁移工具测试按纯策略/CLI 动作分开；旧源码路径扫描不只替换字符串，应由依赖白名单、类依赖/架构规则和 jar 扫描共同替代。迁移前列出实际类/方法，迁移后对照 discovered tests，不能仅拿总数大于旧数证明无遗漏。

### 9.3 文件和脚本执行顺序

| 步骤 | 改动 | 本步检查/回退点 |
|---|---|---|
| A0 | 记录 git 状态、本批文件内容/哈希、V1/V2 原始字节、测试清单和运行命令；准备隔离候选目录 | 未提交/未跟踪文件不丢失，不复制凭据/日志/生成物，不运行 git clean/reset |

| A2 | core/policy/JDBC/CLI/codec 归位，更新包和 import；处理上节 IT 依赖 | reactor 无环、旧包不残留、迁移资源只保留一个权威副本 |

需要逐一检查的入口：`Start-PublicApi.ps1`、`Test-StartupGuards.ps1`、`Test-DatabaseIntegration.ps1`、`Invoke-DatabaseMigration.ps1`、公开 smoke/backup 脚本、工具中的源路径和 README 命令。`Local-Credentials.ps1` 只作为现有接口使用，不改凭据项/秘密。历史冻结清单不得改写成新候选证据。

聚合入口执行生命周期 `test/package/verify`；启动必须定位实际模块，不能在父或带 `-am` 的多模块选择上直接执行所有模块的 `spring-boot:run`。公开模块无 admin 依赖，可由 wrapper 指定 `-f public-api/pom.xml spring-boot:run`；实际参数与 Windows 引号在编码时验证。CLI 单独准备自身依赖 classpath，不从 public/admin Boot jar 抽取管理 SQL。

### 9.4 非破坏验证命令与环境

以下是实施后验证意图，不表示当前单模块已经支持：

| 顺序 | 命令/检查 | 必须说明 |
|---|---|---|
| 1 | `backend\\mvnw.cmd -f backend/pom.xml test`（仓库根） | 单元/架构，不等于数据库 IT；不使用 skip 报完整通过 |
| 2 | 更新后的 `powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/Test-DatabaseIntegration.ps1` | 注入既有受控测试/Reader 凭据并串行 verify；不创建新账号，不打印秘密 |

| 5 | `npm --prefix frontend run verify`、文档检查、公开 API 契约 | 实际契约连接候选端口；微信工具/真机验收单列 |

A0 必须确认旧服务从哪个 classes/jar 路径加载；不得在其共用输出执行 clean，也不依赖“文件已加载不会再读”的假设。候选源目录仅含受控源码/配置模板，凭据由原受控解析入口注入且不复制到候选；若脚本依赖目录语义，先支持显式候选路径再运行。环境不允许候选验证时标 BLOCKED，不擅自停服务。
