# 阶段开放与能力矩阵

> 文档编号：D-102
> 文档状态：评审中（已按仅小程序展示边界修订）
> 适用范围：阶段一、阶段二、阶段三
> 更新日期：2026-10-06
> 上游需求：A04-A16
> 上游架构：AT04、AT05、AT06、AT07、AT08、AT09
> 关联计划：P01

## 1. 使用说明

本文把 P01 的产品阶段范围映射为设计能力，避免目标架构一次性实现全部功能，也避免阶段计划遗漏必须共享的通用能力。矩阵中的“设计输入”不等于已经锁定的实现。

## 3. 阶段开放原则

- 业务事实的目标模型可以提前设计，但未开放能力不应通过半成品 UI 暴露为可用功能；
- 阶段一可以建设公开授权资格和下架基础，因为公开作品上线就必须满足授权边界；
- 阶段二可以保存未来支付所需的订单快照，但不把待支付金额显示成已支付事实；
- 阶段三开放支付、退款、履约、交付和完整授权闭环时，必须沿用阶段二的订单快照，不重新读取当前套餐；
- 所有阶段共用认证、权限、错误、日志、审计、任务、文件和通知的设计原则；
- 阶段验收只能验收本阶段开放能力，不能以未开放的后续能力作为当前阶段失败条件，但也不能违反目标架构的不变量。

## 4. 设计评审重点

- 阶段一公开数据由何种受控流程维护，并如何支撑授权资格核验和撤回后下架；
- 阶段二确认预约和创建订单是否在同一业务边界内；
- 阶段三是否能区分支付、履约、交付和授权状态；
- 阶段开放是否造成重复数据源或不同客户端各自保存一套事实；
- 阶段一和阶段二的历史数据如何平滑进入阶段三；
- 阶段三支付/交付失败是否有可观察的人工补偿入口。
