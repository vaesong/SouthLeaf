## 7. 公开案例授权、范围、证据和撤回

### 7.1 阶段边界与事实归属

本章与第 8 章为阶段一公开授权设计草案，待评审，不表示实现或验收完成；第 2–6、9–12 章仍为后续设计骨架。规则依据为 A15 §2.3、§10–11、§12.3–12.4，消费端与媒体边界分别引用 D-302 §3–4、D-205 §5–6。本文不重新定义案例编排、媒体存储或公开 HTTP 契约。

- A15 持有同意主体、范围、证据、变更、撤回和处理记录的唯一事实；A06 只计算公开资格，A05 只编排有效引用。
- 公开授权默认不存在。支付、拍摄、交付、客户未反对、历史公开或持有图片均不能替代明确同意。
- 公开授权与私密交付权限独立。公开撤回不删除私密文件、不取消客户自己的私密访问；私密授权不自动授予公开许可。
- 阶段一不开放匿名授权写接口、客户登录授权流程或完整后台。事实采集、核验和维护通过待确认的受控流程承载；没有真实证据不发布，不能为联调补造授权。

### 7.2 授权范围与证据

以下为内部业务语义清单，不锁定表结构、枚举、证据格式或供应商：

| 事实 | 最低语义与约束 |
|---|---|
| 授权主体 | 可追溯的同意主体、与影像人物关系及核验结果；不得假定预约联系人代表所有参与人 |
| 对象范围 | 明确案例、图片集合、人物范围及其与被发布版本/媒体的关系；单图同意不扩展为整次拍摄同意 |
| 用途与渠道 | 明确公开作品展示用途及微信小程序渠道；官网或其他用途不得自动继承 |
| 有效时间 | 明确有效时间与撤回条件；是否允许无固定截止及其证据口径由负责人确认，不以缺失值推断永久有效 |
| 同意证据 | 同意时间、受限证据引用、采集/核验责任、采用的范围及文本版本；证据正文不进入公开查询链路 |
| 变更与撤回 | 受影响范围、业务生效时间、记录时间、操作责任、当前事实版本及处理结果；保留历史而非覆盖同意记录 |

多人、儿童、监护关系、主体冲突和范围歧义必须按经确认的核验流程处理；未确认时暂停受影响内容，不自行选择一方代表所有人。证据格式、保管期限和审批方式仍待负责人确认，不在本稿中指定天数或法律结论。

### 7.3 判断结果及变化

对外提供给内部消费端的判断语义为 `VALID / INVALID / UNKNOWN`，不是授权原始记录的完整生命周期：

| 当前事实 | A15 判断语义 | 公开效果 |
|---|---|---|
| 明确同意、核验通过，当前对象/用途/渠道/时间均匹配，无撤回或暂停 | `VALID` | 仅允许 A06 继续其他资格检查，不直接发布 |
| 已确认撤回、失效、过期或范围不覆盖 | `INVALID` | 拒绝受影响内容的后续公开 |
| 缺失、主体/证据待核验、争议、版本不可确认 | `UNKNOWN` | fail-closed，不能借用旧 `VALID` |
| 授权服务整体不可用 | 依赖失败，不伪造业务事实 | 公开读取按第 8.4 节安全失败 |

撤回后重新同意或争议解除，必须形成可追溯的新事实版本。不得用迟到事件、历史备份或旧证据覆盖当前撤回；授权恢复本身也不自动恢复案例发布。

### 7.4 撤回联动顺序与失败处理

1. 受控流程核验请求主体和范围，保存撤回事实、当前版本、操作审计及可靠传播意图。事实写入、传播意图与审计的一致性方案待评审，不要求与存储或缓存建立分布式事务。
2. 撤回生效后，新的详情和媒体读取先按当前事实拒绝；不得等待首页清理、通知成功或定时任务才阻断。判断未知时同样不继续公开。
3. A06 重新计算受影响案例/图片资格；A05 移除首页及其他公开引用；清理列表、分享摘要和受控缓存。任务失败重试或转人工，不能回滚撤回或恢复旧许可。
4. 单图撤回先阻断对应媒体；封面失效、无剩余合格图或主题不完整时整案不可公开。只有经受控修复、确认剩余内容、形成有效版本并明确发布后才可继续，不能查询时自动换图。案例级、人物级或整案范围撤回按整案处理。
5. 恢复需重新核验当前授权、案例、媒体和发布条件；明确恢复/发布动作后才可公开，不能直接改 `authorized` 或 `published` 绕过校验。

传播可采用经评审的持久任务/outbox 或等效可靠机制，不强制新增消息队列。逻辑处理至少能关联变更标识、受影响引用、当前事实版本、执行结果及重试；重复处理不重复恢复，乱序处理不得回退事实版本。无法比较版本时重新读取权威当前事实，不按到达顺序猜测许可。

D-205 要求媒体读取经可撤回网关，不外发桶地址/签名直链，不依赖 URL TTL 充当授权。已发送字节、已下载副本和第三方不可控缓存无法承诺远程删除；在途流中止能力、客户端缓存行为、外部分享/搜索跟进责任和时限必须实测或确认。不得把系统内新请求拒绝与外部副本清除混为一个“立即完成”结论。

### 7.5 审计与访问控制

按 AT07，负责人或明确授权的人员维护记录；管理员涉及发布、撤回和授权变更默认需负责人确认，不能因有文件访问权就获得授权维护权。阶段一通过受控运维实现的角色映射仍需确认，不新增匿名维护入口。

受限审计至少关联事实/变更版本、范围、操作人、时间、前后结果、请求/任务标识及处理状态。客户姓名、联系方式、证据、监护关系、争议与撤回原因不进入公开 DTO、URL 或匿名错误。日志仅记录必要脱敏引用和错误类别，证据访问及保管规则单独确认。

## 8. A15 授权事实与 A06 公开资格消费

### 8.1 只读契约语义（待评审）

A06 通过只读边界请求“当前候选案例/图片/人物范围在指定用途、渠道、时点是否获准公开”，不能请求一个脱离对象范围的通用 `authorized=true`。

| 方向 | 所需语义 | 限制 |
|---|---|---|
| 消费上下文 | 案例及候选版本、媒体/人物范围、公开展示用途、微信小程序渠道、判断时点 | 来源必须是服务端受控绑定，客户端参数不能成为范围凭证 |
| 判断结果 | `VALID / INVALID / UNKNOWN`，以及服务端可核验的覆盖关系 | 仅整案 ID 不足以证明任意新增图片/人物已被覆盖 |
| 有效时间 | 可判定尚未生效、有效和已失效的时间语义 | 缺失/格式错误/边界无法解释时不公开；不借用私密交付默认一周期限 |
| 事实关联 | 不泄露证据的可比较事实版本/摘要及当前性校验语义 | 不把任意字符串摘要当作可排序版本，不将结构 schema 号当内容/授权版本 |
| 失败类别 | 单资源缺失/未知与授权依赖整体故障可区分 | 供上层安全响应，不公开主体和撤回原因 |

以上为设计语义，不规定 Java 方法签名或新增公开 API；证据由 A15 内部核验，A06 只接收必要结果与引用。是否由 A15 接收完整上下文，或通过服务端受控映射核验等效范围，须在适配器评审中明确，不能省略覆盖检查。

### 8.2 当前代码映射与实现缺口

| 当前实现 | 已表达 | 未表达/未验证 |
|---|---|---|
| `PublicAuthorizationReader.readPublicWorkFact(workId)` | 按作品读取可选结果 | 无显式候选版本、媒体/人物范围及用途上下文；正式来源未接入 |
| `AuthorizationFact(result, channel, validUntil, factDigest)` | 结果、单一渠道、截止时间、摘要 | 未表达有效起点、范围覆盖和可比较版本；摘要未证明当前性 |
| `JdbcPublicAuthorizationEvaluator` | 新库当前范围事实批量读取 | 精确绑定 release/candidate/binding/media/subject/purpose/channel/期限；外部真实证据仍需核验 |
| `PublicWorkEligibility` | 已发布、有封面引用、`VALID`、微信渠道且未到截止时间 | 尚不能证明真实媒体可读、完整范围、内容完整性及并发当前性 |

当前临时实现要求 `validUntil` 非空且 `now < validUntil`，等于截止时刻即拒绝。此为 ADR-001 的最小开发策略，不代表上游已确认所有授权必须有固定截止；正式期限规则待确认后再受控调整。`factDigest` 当前未用于有效性或版本比较，不得宣传为已完成防陈旧许可。

正式上线前必须补齐契约与适配、范围核验、版本当前性、整体故障分类和媒体复检，并保留 fail-closed；不能仅给 JSON 填 `VALID` 就宣称完成 A15 接入。

### 8.3 A06 资格消费与读取时机

- 仅当前授权 `VALID` 且范围/用途/渠道/时间完整匹配时继续；A06 仍需检查当前发布版本、内容、分类、封面、有序媒体及可读绑定，规则主归属见 D-302 §3。
- 单资源 `INVALID / UNKNOWN`：列表过滤，详情/旧链接统一不可用。不能把“作品已发布”或“媒体存在”当授权兜底。
- 首页引用、列表、详情及每次媒体请求独立按当前资格判断；HTTP `HEAD`、旧 URL、304/Range 不能绕过 D-205 的网关限制。
- 缓存资格必须核验其授权、案例和媒体输入版本仍当前；恢复页面或网络失败时不得用旧图回填，具体客户端策略需与 D-602 对齐。
- 撤回与读取竞争必须按 D-205 使用权威当前事实，不用延迟副本或旧事务快照。同步拒绝屏障、读取检查点与在途流边界仍需设计及并发测试，不能仅靠异步通知保证安全。

### 8.4 失败与外部响应

| 情况 | 公开结果 | 内部处理 |
|---|---|---|
| 单资源缺失、撤回、过期、范围不匹配或资源级未知 | 列表过滤；详情/媒体安全 404、`PUBLIC_RESOURCE_UNAVAILABLE` | 保留脱敏分类，不披露具体授权原因 |
| 授权依赖整体故障，无法可信计算列表 | 503、`PUBLIC_SERVICE_UNAVAILABLE` | 不伪装成成功空列表，不继续旧许可 |
| 合格媒体的存储读取失败 | 按 D-205/D-401 返回 `PUBLIC_MEDIA_UNAVAILABLE`/503 | 不回退原图、私密文件或永久地址 |
| 发布/投影/失效任务失败 | 已确认撤回仍有效，新读取继续拒绝 | 可靠重试与人工复核，不回滚撤回 |

上述为目标设计；当前演示端口及媒体适配器尚未实现全部生产分支，错误契约以 D-401 为主，不另建一套外部错误码。

### 8.7 拟议端口与类型边界（技术方案，待评审）

建议保留 `authorization/port` 为事实结果边界、`works/domain` 为资格规则边界；本节为技术方案；部分候选类型已按第 8.11 节落地，尚未作为正式授权链路或生产兼容承诺。

```text
PublicAuthorizationReader.evaluate(PublicUseContext) -> AuthorizationReadResult

PublicUseContext
  workPublicId, candidateVersion
  bindingSetVersion, requestedMediaRefs
  subjectScopeRef
  purpose = PUBLIC_WORK_DISPLAY
  channel = WECHAT_MINI_PROGRAM
  evaluatedAt (服务端 Clock)

AuthorizationReadResult
  Resolved(AuthorizationDecision)
  DependencyUnavailable(failureCategory)

AuthorizationDecision
  outcome = VALID | INVALID | UNKNOWN
  evaluatedContextDigest
  validFrom, validUntil
  authorityRevision, factDigest
```

- 拟以显式结果类型替代 `Optional<AuthorizationFact>` 的业务/依赖混用：单资源无记录为 `Resolved(UNKNOWN)`；已确认撤回/范围不匹配为 `Resolved(INVALID)`；超时、连接失败或无法保证权威读取为 `DependencyUnavailable`。失败类别为内部诊断，不进公开响应。
- `candidateVersion` 与 `bindingSetVersion` 标识服务端实际候选内容及媒体集合；新增或替换图片必须更新上下文。`requestedMediaRefs` 是受控绑定引用，不能由客户端任意注入。
- `subjectScopeRef` 是 A15 可解析的受限主体范围引用，不是公开人物姓名或证件信息。来源或多人/监护关系不可确认时不得构造有效覆盖关系。
- `PUBLIC_WORK_DISPLAY` 是拟议内部用途枚举，尚未加入现有代码；不能把相同渠道的其他用途当同意。需要其他用途时显式扩展评审，不提供“任意用途”默认值。
- A15 对完整上下文核验后才可返回 `VALID`；`evaluatedContextDigest` 仅关联所评估的上下文，不是证据，也不单独证明范围已被客户同意。摘要必须从服务端规范化上下文计算，不能接收客户端自报值。
- 阶段一技术草案采用明确时间区间 `[validFrom, validUntil)`：到起点有效，到截止即失效；时钟由服务端注入。缺失边界、逆序区间或解析失败不可放行。此为保守实现候选，不将其提升为已批准经营规则；无固定截止等情形待确认后用显式类型表达，不能以 `null` 代表永久有效。
- `authorityRevision` 建议为每次相关事实/范围变更均递增的权威修订号或等价版本令牌；事实内容摘要 `factDigest` 只用于关联/完整性，不进行字典序大小比较。修订号可否单调、是否需要源 epoch 及多事实聚合方式须由真实来源确认，未具备前不能假设实现已安全。
- 时间、上下文、结果字段、版本缺失或不匹配均不产生 `ELIGIBLE`；结构错误保留内部分类。全源损坏/读取能力失败按依赖故障处理，不能批量变成“正常无记录”。

### 8.8 当前性与撤回并发的读取协议

`authorityRevision`、`factDigest`、`evaluatedAt` 都只是输入或关联信息，不是可复用的许可票据，也不是“最近 N 秒必然有效”的租约。本方案不新增未经确认的授权缓存 TTL。

1. A06 从受控当前版本及绑定构造上下文，调用 A15 权威读取，再计算其他资格；缓存命中也必须确认输入版本当前。
2. 服务端输出详情前及媒体开始发送前，重新检查当前发布/绑定和 A15 当前事实；旧上下文或旧版本不得命中历史 `VALID`。媒体绑定解析必须能回溯所属资源，不能仅依赖现有 `readReference(null, ...)` 传参就跳过所有者核验。
3. **实现准入门槛**：必须证明撤回提交与最终放行检查之间的序列化/同步拒绝屏障。仅“查询一次授权后再发送”仍有 TOCTOU 窗口，不能作为满足撤回安全的证据。
4. 若未来权威事实与读取门槛可由同一受控存储协调，可评审锁定当前版本、拒绝标记与开始读取的线性化点；若权威来源在外部，必须评审其同步拒绝确认/权威重查协议，不能用异步本地投影冒充实时事实。具体技术选型未定，本稿不承诺一个远程接口能提供原子屏障。
5. 按最终放行检查线性化点区分新读取与已开始的流；撤回提交后进入放行检查的新请求必须拒绝。撤回前已开始的流、已发送字节及外部副本另行记录限制和中止能力，不虚构全量追回。
6. 重复或乱序通知只触发重读权威当前结果及安全失效，不按事件到达顺序覆盖授权。权威来源恢复/备份恢复后先核验源版本连续性；无法证明时关闭公开，不重放旧许可。

该门槛依赖真实授权源和媒体能力，开发替身只验证状态与调用顺序，不证明供应商或生产并发语义；方案未批准前禁止宣称撤回全链路完成。
