## 1. 设计目标

小程序在进入时得到一个稳定的微信用户，后台可以查看和修改他的称呼与备注，并查看他的打开和分享记录。预约客户仍然只在提交预约申请时出现。

本篇不覆盖点赞、留言、手机号、官网账号、注销、支付和公开预约开放。

## 2. 责任边界与规则归属

### 2.1 本模块拥有的事实

- 小程序用户是否存在，以及他的称呼、头像、备注、注册时间、最近登录。
- 用户会话是否有效。
- 一次页面打开、一次分享发卡、一张卡片被打开。
- 卡片之间的上一跳关系。

### 2.2 本模块只读取的事实

- 微信 `code2session` 返回的 openid。只在内存里用来计算指纹，不落库。
- `booking_external_identity` 上已有的指纹，用来找出这个人已经提交的预约。
- 预约申请的现有读模型，用来在「我的」和用户详情里展示，不在这里改变预约状态。
- 微信场景号。只存数字，不解析群名。

### 2.3 本模块明确不负责

- 创建、确认、拒绝预约，开放档期，改写预约客户的 `display_name`。
- 把用户写入公开内容投影。
- 采集手机号，合并同名用户，手工建档。
- 判断分享卡片是否已经被对方收到。

### 2.4 与其他模块的关系

| 依赖 | 读取或调用 | 不能做的事 |
|---|---|---|
| 现有微信 code 交换 | 用临时 code 取 openid | 复用预约会话的开关。预约入口关闭时，用户登录仍要成功 |
| D-304 预约客户 | 按同一指纹查找已有 `booking_customer` | 登录时插入 `booking_customer` 或 `booking_external_identity` |
| 后台审计 | 工作人员修改称呼或备注时写审计 | 把审计流展示成用户页上的修改历史 |
| 公开内容 | 页面打开时记录已发布作品或套餐的标识 | 用足迹接口读取未发布内容 |

A17 与 D-304 第 3 节冲突时，以 A17 为准。

## 3. 领域对象和数据归属

数据放在 `southleaf_admin`。不进入 `southleaf_public`。

| 对象 | 含义 | 权威 |
|---|---|---|
| `AppUser` | 一个小程序微信身份。内部 UUID。对外不接受客户端传入的用户 id 作为本人身份 | 本模块 |
| `UserAvatar` | 当前头像的一份字节。换新图时替换旧图 | 本模块 |
| `UserSession` | 发给小程序的持有者凭证。服务端可校验，不把 openid 放进凭证 | 本模块 |
| `ShareCard` | 一次分享签发的卡片。有自己的 id，可以指向上一张卡片 | 本模块 |
| `VisitEvent` | 一次打开，或一次「从卡片进入」。从卡片进入也是一次打开 | 本模块 |

草案字段：

- `app_user`：`id`，`provider`，`app_scope`，`subject_fingerprint`（64 位十六进制），`display_name` 可空，`note` 可空，`created_at`，`updated_at`，`last_seen_at`，`version`。唯一约束是 `(provider, app_scope, subject_fingerprint)`。
- `app_user_avatar`：`user_id` 主键，`content_type`，`byte_size`，`content`，`updated_at`。只保留当前一张。
- `share_card`：`id`，`user_id`，`parent_card_id` 可空，`page`，`content_id` 可空，`scene` 可空，`created_at`。
- `visit_event`：`id`，`user_id`，`client_event_id`，`kind`（`PAGE_OPEN`），`page`，`content_id` 可空，`share_card_id` 可空，`scene` 可空，`occurred_at`。唯一约束是 `(user_id, client_event_id)`。

不建用户和预约客户的绑定表。读取预约时，用本用户的指纹去 `booking_external_identity` 查找。找不到就是没有已接上的预约。

称呼最长 32 个 Unicode 标量，拒绝控制字符。空串存成空称呼。备注最长 500 个 Unicode 标量，允许换行。头像只接受 JPEG、PNG、WEBP，解码后不超过 512 KiB，长边超过 512 像素时缩到 512。默认头像不入库，由客户端和后台各自画占位。

短编号是指纹前六位的大写形式，不另存一列。

## 4. 状态及状态转换

用户没有停用和关闭状态。本期一旦创建就保持可用。

会话只有有效和无效。无效时小程序先静默再登录；再登录失败才进入重试页。重试页不写足迹。

分享卡片创建后不再修改。打不开上一跳时，新卡片的 `parent_card_id` 为空，卡片本身仍创建。

打开事件只有写入成功一种终态。写入失败不产生补偿任务，也不回滚页面。

## 5. 用例清单

| 编号 | 用例 | 角色 |
|---|---|---|
| U1 | 进入或回到前台，完成登录 | 客人 |
| U2 | 登录失败，停在重试页 | 客人 |
| U3 | 修改自己的称呼或头像 | 客人 |
| U4 | 查看自己已接上的预约申请 | 客人 |
| U5 | 打开一个页面 | 客人 |
| U6 | 发出一张分享卡 | 客人 |
| U7 | 从一张分享卡进入 | 客人 |
| U8 | 搜索并打开用户 | 管理员 |
| U9 | 修改称呼或备注 | 管理员 |
| U10 | 沿一张卡片看传递 | 管理员 |

## 6. 输入、前置条件、权限和幂等

- U1 的输入是微信临时 code。code 用过即失效。同一指纹并发第一次登录时，唯一约束保证只产生一个用户；失败的一方重新读取已存在的那一行。
- 每次回到前台都更新 `last_seen_at`。已有未过期会话时，先续期，不必每次都向微信换 code。会话失效或本地没有凭证时才换 code。
- 小程序持有者凭证放在独立的本地键里，不复用 `southleaf.booking.session`。
- U3、U4 必须带有效用户会话。服务端从会话解析用户，忽略客户端传来的用户 id。
- U5 的 `client_event_id` 由客户端生成。同一用户重复提交同一 id，返回已存在的结果。30 秒去重是另一条规则：同一用户、同一页面、同一内容、30 秒内的新 id 也不再插入，返回最近那一条。
- U6 在分享面板出现前向服务器要卡片 id。服务器失败时，客户端仍返回原来的分享路径，路径上不带编号。
- U8、U9、U10 使用现有后台会话。新增能力名 `USER_READ` 与 `USER_PROFILE_WRITE`，授予现有管理员。不新开角色。U9 使用用户 `version` 做条件更新。
- 工作人员修改称呼或备注时写后台审计，记录操作者、用户 id、字段名和发生时间。审计不记录头像字节，也不在用户页列出。

## 7. 输出、状态变化、错误、通知和审计

- U1 成功：返回会话凭证、过期时间、称呼、短编号、是否已有头像。首次登录插入用户。回到前台更新 `last_seen_at`。
- U1 失败：不插入用户，不写足迹。客户端留在重试页。
- U3 成功：更新称呼或替换头像，`version` 加一。
- U4：返回这个指纹已经拥有的预约申请摘要。没有则是空列表。不泄露别人的申请。
- U5、U6 失败：客户端当没记下，页面和分享继续。
- U9 版本冲突：不覆盖，后台重新读取后再提交。
- 不发送通知，不写预约 outbox。

## 8. 对外接口与内部端口

接口形状是草案，实现时再写入 OpenAPI。小程序走对外服务，后台走管理服务。两套会话不能互换。

小程序：

- `POST /api/v1/public/users/session`，正文 `{ loginCode }`。
- `GET /api/v1/public/users/me`。
- `PUT /api/v1/public/users/me`，正文 `{ displayName }`。
- `PUT /api/v1/public/users/me/avatar`，图片正文。
- `GET /api/v1/public/users/me/avatar`。
- `GET /api/v1/public/users/me/reservations`。
- `POST /api/v1/public/users/visits`，正文含 `clientEventId`、页面、内容 id、卡片 id、场景号。
- `POST /api/v1/public/users/shares`，正文含页面、内容 id、上一张卡片 id、场景号。返回卡片 id。

后台：

- `GET /api/admin/v1/users?q=&cursor=`。`q` 匹配称呼和短编号。排序是 `last_seen_at` 降序，其次 `id`。
- `GET /api/admin/v1/users/{id}`。含资料、只读预约摘要、最近足迹页。
- `PATCH /api/admin/v1/users/{id}`，条件写称呼和备注。
- `GET /api/admin/v1/users/{id}/avatar`。
- `GET /api/admin/v1/users/{id}/visits?cursor=`。
- `GET /api/admin/v1/shares/{id}`。含发出者、打开者，以及这些打开者再发出的下一张卡片。

分享路径在现有 query 上增加 `sls`，值为卡片 id。作品详情继续保留 `workId`。未知的 `sls` 不阻断页面。

内部端口：`WeChatCodeExchange` 可以和预约模块使用同一个官方端点，但配置和失败不能受 `SOUTHLEAF_PUBLIC_BOOKING_MODE` 控制。用户表的数据库账号单独授权，不复用 `southleaf_public_booking_writer` 那组「登录即插入预约客户」的权限。

## 9. 内部分层和依赖方向

- 小程序页面只调用户 API，不直接调用 `/api/v1/public/booking/session`。
- `app.js` 在进入业务页之前完成 U1。失败时只允许停留在重试页。
- 现有六个分享页，加上预约页和「我的」，在 `onShow` 上报打开。六个分享页的 `onShareAppMessage` 先尝试 U6，再拼路径。
- 预约页如果仍能被打开，只记足迹，不因此打开公开预约。
- 后台在现有路由旁增加 `/users`。用户详情里的预约跳到现有预约处理。

## 10. 事务、并发、唯一约束、重试和补偿

- 创建用户和第一次 `last_seen_at` 在同一个事务。冲突后读取已有行并更新 `last_seen_at`。
- 替换头像和更新用户 `version` 在同一个事务。旧字节被新字节替换，不保留旧图。
- 签发卡片是单独的插入。上一张卡片不存在时，插入的父 id 为空，不失败。
- 打开事件的幂等插入失败时，返回已有事件。
- 足迹没有补偿队列。丢失的打开不补写。
- 预约读取不在用户事务里更新预约。

## 11. 数据安全与隐私

- openid、session_key、临时 code 不写入用户表、足迹、日志和审计。
- 指纹算法与预约身份相同：对 provider、app scope、openid 做 SHA-256。这样旧预约才能按指纹对上。
- 用户凭证使用独立密钥，有效期 12 小时。回到前台时在未过期的情况下续期。
- 头像字节只通过本人会话或 `USER_READ` 读取。
- 备注不出现在小程序响应里。
- 日志可以有用户内部 id 和请求 id，不写完整指纹，不写头像正文。
- 足迹和卡片保留 180 天，到期删除。用户行不随足迹到期删除。按天次数若留下，不得含用户 id。

对外服务的数据库权限草案：

| 表 | 权限 |
|---|---|
| `app_user` | SELECT、INSERT、UPDATE |
| `app_user_avatar` | SELECT、INSERT、UPDATE、DELETE |
| `share_card` | SELECT、INSERT |
| `visit_event` | SELECT、INSERT |
| `booking_external_identity` | SELECT |
| `booking_reservation` 及其现有申请读模型 | SELECT |

没有对预约表的 INSERT、UPDATE、DELETE。

## 12. 日志、指标和可观测性

- 登录成功、登录拒绝、头像拒绝各记一条计数，不记 code 和 openid。
- 足迹写入失败记计数。失败不影响页面。
- 不把足迹事件再送进第三方统计。
- 后台三个数来自查询，不另建一套会和明细分叉的成功事实。180 天删除明细之后，按天次数如果要留下，必须不含用户 id。该汇总表在保留期限确认后再加。

## 13. 测试和验收场景

- 同一 code 不能使用两次。同一指纹两次登录得到同一个用户 id，预约客户表的行数不增加。
- 预约开关关闭时，用户登录仍成功。
- 并发第一次登录只插入一行。
- 称呼中的控制字符被拒绝。超过 32 个字被拒绝。空称呼读出来走默认文案。
- 超过 512 KiB 或不是 JPEG、PNG、WEBP 的头像被拒绝，旧头像还在。
- 后台用旧 `version` 保存称呼，得到冲突，库内称呼不变。
- 客人会话不能调用后台用户接口。后台会话不能调用小程序的「我的」。
- 指纹对得上的预约能在「我的」和用户详情读到。对不上时列表为空，响应看不出别人是否存在。
- 30 秒内同一作品的两次打开只留一行。同一 `client_event_id` 重复提交不产生第二行。
- 分享接口失败时，分享路径仍然是原来的作品路径，没有 `sls`。
- 未知 `sls` 的打开会留下事件，父卡片为空。
- 卡片传递能读出「发出的人」和「点开后再发出的人」。
- 公开内容接口的响应里没有用户和足迹。

## 14. 阶段开放范围

本期实现 A17 第 3 节和第 5 节。公开预约保持关闭。不迁移历史足迹。旧预约客户不批量插入 `app_user`。

管理库迁移编号在实现时取当前最大版本加一。本文起草时最大版本是 V17。

## 15. 设计假设和待确认问题

- 30 秒去重用来去掉刷新。这是设计规则，不是经营指标。
- 「点开分享面板」记为发出。微信不提供可靠的送达回执。
- 注销、导出个人数据和更长的法定保留，本期不实现。
- 180 天保留已在 A17 第 5.4 节确认。到期任务只删除 `visit_event` 和 `share_card`。
