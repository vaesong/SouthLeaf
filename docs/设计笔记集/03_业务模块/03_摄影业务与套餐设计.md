# 摄影业务与套餐设计

> 文档编号：D-303
> 文档状态：评审中（阶段一可编码草案）
> 适用范围：阶段一为主；阶段二、阶段三保留扩展边界
> 更新日期：2026-10-09
> 上游需求：A03、A07、A12-A14
> 上游架构：AT01、AT04、AT05、AT06
> 关联计划：P01；对齐 D-103、D-301、D-302、D-401、D-501、D-601、D-602、D-702、D-203、D-205

## 1. 设计目标

本模块为阶段一微信小程序提供匿名、只读的摄影业务目录、套餐列表和套餐详情。它维护“工作室提供什么业务”和“当前有哪些已确认的公开套餐”两类事实，向首页、作品关联和公开查询提供同源摘要。

阶段一必须保留并可表达儿童、亲子全家福、婚纱、写真、孕照、证件照六类摄影业务。业务存在不等于存在标准套餐、确认价格、可用档期或预约资格；没有套餐的业务返回真实空状态和经确认的联系入口，不生成测试套餐。

阶段一只交付公开读取，以及支撑真实资料进入公开数据源所需的受控导入、校验、发布和下架前置流程；不交付管理后台、客户登录、预约、档期、订单、支付、退款、履约或私密成片交付。本文为未来阶段保留版本引用边界，但不实现相关流程、接口或状态。

历史原型中的价格、活动价、30%/50% 定金比例、拍摄数量、精修数量、时长和交付日期只证明原型曾出现这些表达，不能成为经营事实、默认值、初始化数据或测试期生产兜底。

本文中的对象、状态和端口名称均为设计语义，不锁定数据库表、类名、枚举名或最终 DTO 字段。

## 2. 六类摄影业务目录

### 2.1 职责边界

| 事实或规则 | 权威归属 | 本模块职责 | 明确不负责 |
|---|---|---|---|
| 六类业务身份、公开名称、说明和排序 | A07 / `catalog` | 维护业务身份和可发布版本 | 作品分类、预约状态和档期 |
| 套餐内容、服务项、适用范围、价格表达和版本 | A07 / `catalog` | 校验、发布、下架并提供公开摘要 | 订单价格、支付结果和实际履约 |
| 作品案例及其公开资格 | A06 / `works` | 保存关联，读取当前合格作品摘要 | 复制作品图片、授权结果或案例正文 |
| 公开授权事实 | A15 / `delivery` | 对含人物媒体消费 A06/媒体资格结果 | 创建授权事实或推断客户同意 |
| 首页编排和联系资料 | A05 / `content` | 提供业务/套餐摘要，读取同源联系入口 | 复制首页排序或联系方式 |
| 公开媒体 | D-205 / 媒体能力 | 绑定已确认用途的展示衍生图 | 返回原图、对象 key 或不受控直链 |
| 预约、订单、支付和交付 | A12-A15 | 未来提供稳定套餐版本输入 | 在阶段一创建或改变这些事实 |

摄影业务目录、作品分类、标准套餐和可选展示分组必须分开。`创始人档` 在负责人确认前不是第七类摄影业务，也不自动成为套餐档位。

### 2.2 六类业务基线

| 已确认业务 | 阶段一最低表达 | 无已发布套餐时 |
|---|---|---|
| 儿童 | 稳定业务身份、已确认公开名称和可选说明 | 保留业务入口，显示真实空状态/咨询方式 |
| 亲子全家福 | 同上 | 同上 |
| 婚纱 | 同上 | 同上 |
| 写真 | 同上 | 同上 |
| 孕照 | 同上 | 同上 |
| 证件照 | 同上 | 同上 |

六类业务身份不能因历史代码缺项、暂时无套餐或阶段拆分而被删除、合并或改作作品分类。公开说明、封面和预约前置提示仍需真实资料确认；未确认字段可以省略，不能用原型文案补齐。阶段一生产验收至少证明公开模型能稳定表达六类业务及各自的真实套餐空/非空状态。

### 2.3 业务对象与状态

| 对象草案 | 业务含义 | 生命周期/阶段一用途 |
|---|---|---|
| `PhotoBusiness` | 六类业务之一的稳定身份 | 保留稳定公开标识和类型语义 |
| `PhotoBusinessVersion` | 名称、摘要、说明、排序、提示和媒体的一次版本 | 候选、校验、发布、下架和追溯 |
| `BusinessPublication` | 当前公开版本及其发布结果 | 仅当前已发布版本进入公开查询 |
| `BusinessPackageAssociation` | 套餐归属某一业务 | 套餐必须且只归属一个当前可识别业务 |

业务版本状态语义草案为 `draft / review / published / withdrawn / archived`。业务身份与公开版本分离：下架一个公开版本不物理删除六类业务身份，也不把其历史套餐改到其他业务。

### 2.4 业务不变量

1. 六类业务全部保留；“全部”只是聚合查询，不是第七类业务。
2. 套餐必须归属一个摄影业务；作品分类名称相同不能替代该关系。
3. 业务没有套餐是正常公开状态，不能用其他业务套餐、历史套餐或测试数据填充。
4. 业务公开不表示有档期、已接受预约或可以直接购买。
5. 业务下架后不进入新的公开查询，但稳定身份和历史版本保留；关联套餐按自己的规则进入不可公开/待修复路径，不能静默迁移归属。
6. 六类业务的显示名称可在经确认后调整，但语义身份和引用必须稳定，避免名称修改破坏旧关联。

## 3. 套餐版本、服务项和适用范围

### 3.1 逻辑对象

| 对象草案 | 业务含义 | 阶段一用途 |
|---|---|---|
| `Package` | 套餐稳定身份 | 公开链接、版本归属和历史追溯 |
| `PackageVersion` | 某次完整公开服务定义快照 | 当前公开详情；发布后不可原地改写 |
| `ServiceItem` | 套餐包含、不包含、可选或需咨询的服务说明 | 有序、可理解地展示服务范围 |
| `PricePresentation` | 经确认的当前公开价格语义 | 用 `priceType` 驱动展示，不靠文案猜测 |
| `PackageMediaBinding` | 套餐版本与封面/展示媒体的用途、顺序关系 | 经受控网关提供可选媒体 |
| `PackageWorkAssociation` | 套餐与当前公开案例的可选关联 | 只导流，不复制 A06 事实 |
| `PackagePublication` | 当前生效版本及下架结果 | 决定是否进入列表和详情 |

### 3.2 套餐版本内容

一个候选公开版本可以表达：所属业务、公开名称、摘要/说明、有序服务项、适用人群、时长说明、地点/服务区域、公开注意事项、`priceType` 与相应价格表达、媒体绑定、作品关联和公开排序。

阶段一只返回负责人已确认且 D-401 纳入的字段。固定定金、尾款安排、预约必填资料、内部成本、版本操作说明和未发布活动规则不因未来可能需要就进入阶段一 DTO。

### 3.3 服务项规则

- 服务项至少区分“包含”“不包含”“可选附加”“需咨询”等业务语义；具体编码形式评审后确定。
- 数量和单位只有在经营资料确认后才可公开；未知时不填 0、不用原型数值，也不把预计值写成保证值。
- 服务项有稳定顺序，不依赖逗号分隔文本、数据库返回顺序或客户端解析自由文本。
- 附加费用未确认时只能表达为需咨询，不能生成金额。
- 套餐公开说明是当前服务定义，不是某个客户订单的履约承诺；实际交易以后续订单快照为准。
- 私密交付文件、实际交付批次和访问期限不属于套餐服务项实现；阶段一最多展示经确认的公开说明。

### 3.4 版本边界

已发布套餐版本不可原地覆盖。以下变化至少需要形成新候选版本并重新发布：

- `priceType`、金额或价格公开策略变化；
- 活动规则、适用时间或活动结束后的价格语义变化；
- 固定定金金额或未来支付说明变化；
- 服务项、数量、单位、交付说明或适用范围变化；
- 时长、地点、人数、服务区域或重要注意事项变化；
- 所属业务变化；
- 会影响客户理解的标题、摘要、封面或作品关联变化。

为简化阶段一并发和追溯，任何已发布内容的修改均可采用新候选版本；不要求在本稿锁定“重大/轻微变更”的最终分类算法。

### 3.5 套餐不变量

1. 公开套餐必须有稳定身份、当前已发布版本和一个有效业务归属。
2. 列表、详情和首页摘要读取同一当前版本；不得各自硬编码价格或服务项。
3. `PackageVersion` 与未来 `OrderSnapshot` 是不同对象；当前套餐变化不得覆盖历史交易事实。
4. 套餐媒体只通过受控网关读取；权利/资格未知、绑定失效或对象状态未知时 fail-closed，不返回旧图、原图或私密作品。
5. 套餐关联作品必须由 A06 当前公开资格决定；失效作品不返回，也不复制旧图片维持展示。
6. 公开套餐浏览不创建预约、订单、支付、交付或客户身份事实。

## 4. 价格、固定定金和尾款快照输入

### 4.1 `priceType` 公开语义

`priceType` 是机器可读的公开价格语义，客户端必须按该字段展示，不能根据 `displayPrice` 文本、是否存在数字或旧页面样式自行推断。

| `priceType` | 严格语义 | `displayPrice` 约束 | 禁止解释 |
|---|---|---|---|
| `FIXED` | 当前公开版本存在一个已确认的精确标准价格 | 必须有与同一经营事实一致的金额/格式化表达 | 不是成交价、支付成功或当前有档期 |
| `FROM` | 当前公开版本存在一个已确认的起始价/最低基础价，最终价格可能因条件变化 | 必须明确“起”语义并有已确认起始金额 | 不得展示为固定总价或最高价 |
| `INQUIRY` | 该业务/套餐经确认需要沟通条件后报价 | 不返回虚构金额；可返回契约允许的咨询文案或由客户端按类型呈现 | 不等于免费、0 元或价格丢失 |
| `UNDISCLOSED` | 已确认存在“不公开披露价格”的经营策略 | 不返回金额；客户端隐藏价格值并按契约呈现 | 不等于 `INQUIRY`，也不能由数据缺失自动推导 |

未确认价格不是一种可自动发布的价格类型：

- 只有负责人确认“需要咨询报价”时才能使用 `INQUIRY`；
- 只有负责人确认“价格不公开披露”时才能使用 `UNDISCLOSED`；
- 没有任何价格策略确认时，套餐候选不能靠默认类型通过发布；可仅公开所属业务及真实无套餐/待确认状态；
- `FIXED`/`FROM` 的金额应使用结构化金额事实并生成展示文本，不能只保存自由文本；具体金额字段和币种模型由数据/API 评审锁定；
- `displayPrice` 只用于公开展示，不作为未来订单计算输入。

### 4.2 活动价格

阶段一不把历史“原价 + 活动价 + 日期”直接迁移成现行事实，也不要求为了兼容原型而公开划线价。若后续确有经确认的活动价格：

- 活动条件、开始/结束时刻、适用范围和结束后的价格语义必须完整；
- 它形成新的套餐版本或明确的版本生效区间；
- 公开查询只返回当前时点唯一有效的 `priceType` 和价格表达，不同时返回含义不清的多个“当前价”；
- 生效判断由服务端完成，客户端时钟和缓存不决定活动是否有效；
- 过期后没有确认的恢复价格时，套餐停止公开或进入已确认的询价/不披露新版本，不能继续显示旧活动价。

在活动规则完成经营确认和契约评审前，阶段一首批数据不得包含原型活动价。

### 4.3 固定定金边界

A07 已确认的未来规则是：可直接选择并成单的套餐使用套餐版本中确认的固定定金金额，不从套餐总价按比例计算。历史 30%/50% 文案无效，不得迁移、展示或参与任何计算。

阶段一没有预约、订单或支付能力，因此：

- 公开查询不计算定金、尾款或支付计划；
- D-401 阶段一 DTO 不因未来成单需要而强制暴露定金字段；
- 缺少固定定金不阻止一个套餐作为“仅公开了解/联系咨询”的内容展示，但不能据此声明它可直接预约或成单；
- 受控资料可以为后续阶段保留已确认的固定定金输入，但其是否进入阶段一存储模型由后续数据评审决定；
- 若未来开放直接选择，固定定金必须非负、不高于对应固定总价，并与套餐版本一起被冻结；`FROM`、`INQUIRY`、`UNDISCLOSED` 默认不能仅凭公开价格语义直接计算订单定金。

### 4.4 尾款与未来快照边界

尾款应付、支付状态、退款和交付门槛分别属于 A13-A15。未来阶段可通过稳定的套餐版本读取端口向预约/订单域提供经确认的价格、固定定金、服务项、时长和适用条件；订单域在客户确认时形成自己的不可变快照。

阶段一不实现该端口的交易调用方，不创建订单快照，不展示“已付定金/尾款”，也不因预留字段而调用预约、订单或支付模块。

## 5. 发布、下架和历史版本

### 5.1 状态分离

| 概念 | 状态语义草案 | 公开规则 |
|---|---|---|
| 业务版本 | `draft / review / published / withdrawn / archived` | 仅当前 `published` 版本 |
| 套餐版本 | `draft / review / published / withdrawn / expired / archived` | 仅当前有效 `published` 版本 |
| 媒体绑定 | `registered / validated / readable / unavailable / withdrawn` | 仅当前受控可读媒体；未知 fail-closed |
| 公开投影 | `building / current / superseded / invalid` | 仅 `current`，读取时仍校验源版本 |
| 未来选择资格 | 非阶段一状态 | 不进入阶段一 DTO 或页面判断 |

`published` 只表示公开内容通过校验，不代表有档期、可提交预约、已成单或可支付。`expired` 仅用于确有明确有效期的版本，不能用来掩盖内容未确认。

### 5.2 转换和校验

| 当前状态 | 受控动作 | 前置条件 | 结果 | 失败/未知 |
|---|---|---|---|---|
| 无 / `draft` | 准备候选 | 来源、责任人和基础内容明确 | 候选版本 | 保留未发布候选和问题 |
| `draft` | 提交校验 | 必需字段齐全 | `review` | 仍为 `draft` |
| `review` | 发布业务 | 类型属于六类、名称/说明/媒体真实且版本未冲突 | 当前业务版本切换为 `published` | 旧安全版本不变 |
| `review` | 发布套餐 | 业务归属、内容、价格语义、服务项和媒体校验通过 | 当前套餐版本切换为 `published` | 旧安全版本不变 |
| `published` | 下架 | 范围、原因、操作者和预期版本明确 | `withdrawn`，新读取不可用 | 失效任务失败不恢复公开 |
| `published` | 到期 | 已确认的有效期届满 | `expired` 或切换至已准备的新版本 | 无安全后继版本时停止公开 |
| `withdrawn / expired` | 恢复 | 新候选重新完成全部校验 | 新版本 `published` | 保持不可公开 |
| 非公开版本 | 归档 | 不再作为当前候选 | `archived` | 保留历史和审计 |

业务发布至少校验六类语义身份、公开名称、顺序和可选媒体；套餐发布至少校验所属业务、标题/摘要、服务项、`priceType` 一致性、所需金额、媒体用途、作品关联及禁止信息。未确认的历史经营数值导致校验失败，不能自动改成 0、`FIXED`、`INQUIRY` 或 `UNDISCLOSED`。

### 5.3 下架与历史版本

- 业务下架后从公开业务列表移除；其套餐不能继续作为正常公开套餐返回，但稳定身份和历史归属保留。
- 套餐下架后从首页、列表和业务详情移除，旧链接统一不可用；不返回旧价格、内部原因或历史版本选择器。
- 套餐下架不自动下架仍然合格的作品案例；作品侧只移除失效套餐入口。
- 已发布历史版本只读保存，供审计及未来下游引用；阶段一匿名接口只返回当前公开版本。
- 物理删除不是发布/下架动作。存在历史引用时不得靠删除当前记录破坏版本追溯。

### 5.4 本地事务、并发和幂等

本模块本地事务覆盖候选/发布版本、当前版本指针、业务归属和关联、审计摘要及任务/outbox 意图。首页投影、作品摘要、媒体存储和缓存不加入分布式事务。

- 受控编辑/发布携带预期资源版本和预期当前公开版本；冲突时拒绝覆盖并重新读取。
- 业务下架与套餐发布并发时，以提交时重新读取的当前业务状态为准；无法确认业务仍公开时套餐不得发布。
- 调价与下架并发时，不允许较早的发布任务恢复已下架套餐。
- 发布、下架、投影重建和缓存失效以“资源 + 动作 + 目标版本”作为幂等语义；重复任务不创建重复版本或审计动作。
- 异步任务携带目标版本，旧任务不得覆盖较新投影或把当前版本降回历史价格。
- 发布失败不产生价格已更新但服务项仍旧的混合版本。

## 6. 输入输出和用例

### 6.1 输入边界

匿名查询只接受不透明公开 ID、公开 `businessId` 筛选、受限分页和可选来源上下文。入口层校验长度、字符集、白名单和数量上限；不接受任意排序表达式、金额、`priceType`、发布状态、媒体 URL 或套餐完整对象作为事实。

受控维护输入至少包括资料来源、业务/套餐稳定标识、候选内容、价格语义及其确认来源、服务项、媒体/作品关联、预期版本、操作者/责任来源和动作幂等标识。受控输入不通过阶段一匿名接口开放。

历史原型只能作为待核实资料线索；导入时必须逐项显式确认，不能批量将价格、活动价、定金比例、时长或服务数量标记为现行事实。

### 6.2 公开输出

公开输出沿用 D-401 的统一外层和 `PublicBusinessSummaryDTO`、`PublicPackageSummaryDTO`、`PublicPackageDetailDTO`、`PublicMediaDTO` 语义。套餐列表和详情必须同时返回 `priceType`；客户端不得只消费 `displayPrice` 后自行猜测语义。

允许公开：业务/套餐公开标识、当前名称、摘要/说明、服务项、适用范围、时长、经确认的价格表达、注意事项、当前合格作品入口和受控媒体引用。禁止返回内部成本、未发布金额、历史活动价、定金比例、客户资料、订单/支付状态、对象 key、授权证据、后台备注和历史版本操作信息。

### 6.3 用例

| 用例 | 发起方 | 输入与前置 | 成功结果 | 失败/安全结果 |
|---|---|---|---|---|
| 浏览六类业务 | 匿名访客 | 当前公开业务版本 | 六类业务可表达，各自显示真实套餐状态 | 未确认字段省略，不用原型补齐 |
| 查看业务详情 | 匿名访客/旧链接 | `businessId`，服务端重查 | 当前业务说明、套餐摘要和可选作品 | 不存在/下架统一 404 |
| 浏览套餐列表 | 匿名访客 | 可选业务筛选和分页 | 当前已发布套餐摘要及明确 `priceType` | 非法参数 400；真实空列表为 200 |
| 查看套餐详情 | 匿名访客/旧链接 | `packageId`，服务端重查 | 同一版本的价格、服务项、说明和媒体 | 不存在/下架/过期统一 404 |
| 为首页/作品提供摘要 | A05/A06 | 当前公开 ID | 当前业务/套餐安全摘要 | 失效关联不返回，触发修复任务 |
| 受控准备并发布 | 维护适配器 | 候选、来源、确认记录和预期版本 | 原子切换当前版本，记录审计/任务 | 冲突重读；校验失败保持候选 |
| 受控下架 | 维护人 | 对象范围、原因和预期版本 | 新查询立即不可用，派发失效任务 | 重复动作幂等，任务失败转人工 |
| 媒体状态变化 | 媒体任务 | 绑定和来源版本 | 省略可选媒体或使依赖媒体的资源安全不可用 | 未知 fail-closed，不返回旧图 |

错误码沿用 D-203/D-401：非法参数为 `PUBLIC_QUERY_INVALID`，资源不可公开为 `PUBLIC_RESOURCE_UNAVAILABLE`，必需依赖整体故障为 `PUBLIC_SERVICE_UNAVAILABLE`，媒体和响应失败使用统一既有码。不得新增套餐私有公开码泄露内部发布原因。

## 7. 权限、审计和变更影响

### 7.1 权限和阶段一维护边界

匿名访客只能读取当前安全公开投影和受控媒体。阶段一不交付业务/套餐 CRUD、调价、发布、下架或媒体上传后台接口；维护人、审核人和发布人由经批准的受控流程落实，并明确最小权限和责任。

未来谁可以调价、修改固定定金或发布重大服务变更，由 A10/负责人评审。公开署名、摄影师身份或作品贡献关系不自动授予目录维护权限。

### 7.2 变更影响

受控流程在发布前至少列出对首页引用、业务详情、套餐列表/详情、作品关联和未来下游版本引用的影响。阶段一只有公开投影与缓存影响，不得为“预估影响”创建预约、订单或支付记录。

业务名称调整保留稳定身份；套餐归属变化形成新版本并重新校验。价格、服务项或媒体变化只影响新公开版本，不静默回写历史版本。作品撤回只移除关联，不改变套餐服务事实；套餐下架只移除作品入口，不改变案例历史。

### 7.3 审计与可观测性

至少记录：六类业务和套餐的来源、候选创建/编辑、提交校验、发布、下架、恢复、归档；业务归属、排序、`priceType`、金额、服务项、适用范围、媒体和作品关联变化；版本冲突、投影/缓存任务和人工补偿结果。

审计包含操作者或系统身份、动作、对象、前后版本、时间、原因摘要、结果和 `requestId/taskId`。普通日志和公开响应不得记录内部成本、未发布价格、客户资料、授权证据、对象 key 或供应商签名。

指标至少观察六类业务完整性、业务无套餐数、套餐公开查询成功/不可用率、各 `priceType` 分布、价格校验失败、失效作品关联、媒体失败、版本冲突、缓存失效积压和补偿失败。指标不构成经营事实，阈值待真实环境确认。

## 8. 数据结构草案

以下仅说明逻辑信息和约束，不是最终表、字段或类设计：

| 逻辑集合 | 候选信息 | 关键约束 |
|---|---|---|
| 业务身份 | 内部/公开标识、六类语义类型、创建来源 | 六类均可表达；公开 ID 稳定不透明 |
| 业务版本 | 名称、摘要、说明、排序、提示、状态和版本 | 已发布版本只读；未确认字段可省略 |
| 套餐身份 | 内部/公开标识、稳定业务归属和来源 | 不以标题作为身份；不物理覆盖历史 |
| 套餐版本 | 标题、摘要、服务说明、适用范围、时长、注意事项、状态和版本 | 一个版本内语义一致；发布后只读 |
| 服务项 | 类型、名称、数量/单位、说明、顺序 | 数值需确认；不依赖逗号字符串 |
| 价格表达 | `priceType`、结构化金额候选、币种/格式化表达、确认来源 | 四类语义严格；缺失不自动映射 |
| 媒体绑定 | 所属版本、媒体引用、用途、顺序、封面标志、媒体版本 | 受控衍生图；权利/资格未知不公开 |
| 作品关联 | 作品公开标识、用途、顺序 | 不复制 A06 内容，读取时重查资格 |
| 发布/任务/审计 | 动作标识、目标版本、影响范围、状态和重试 | 与本地事实同事务记录意图，可补偿 |

持久化模型、公开投影、API DTO 和小程序展示模型分层；不得直接序列化领域或持久化对象。具体关系、唯一约束、金额类型和迁移由数据设计评审锁定。

## 9. 接口与内部架构草案

### 9.1 对外读取

阶段一沿用 D-401 路径草案：

- `GET /api/v1/public/businesses`：六类业务公开摘要及套餐概况；
- `GET /api/v1/public/businesses/{businessId}`：当前业务公开详情和有效关联；
- `GET /api/v1/public/packages`：按业务受限筛选和分页；
- `GET /api/v1/public/packages/{packageId}`：当前套餐版本详情；
- `GET/HEAD /api/v1/public/media/{mediaId}/{variant}`：D-205 受控媒体读取，阶段一仅允许已评审缩略/预览变体。

阶段一没有公开写接口、客户接口或后台接口。对外路径、字段和 API 版本以 D-401 最终评审为准。

### 9.2 内部语义端口

| 端口语义草案 | 提供方 → 消费方 | 输入输出边界 |
|---|---|---|
| `PublicCatalogReader` | A07 → A05/A06/公开查询 | 当前已发布业务/套餐摘要和详情；只含白名单字段 |
| `PublicWorkReader` | A06 → A07/查询编排 | 当前合格作品摘要；资格无效/未知不返回 |
| `PublicMediaReader` | 媒体能力 → A07/查询层 | 校验用途、绑定和资格后的受控媒体引用/流 |
| `PublishedContentReader` | A05 → 查询编排 | 当前联系摘要；A07 不保存联系方式副本 |
| `ControlledCatalogMaintenance` | 受控适配器 → A07 | 候选准备、校验、发布/下架意图；不对匿名端开放 |
| `PublicProjectionPublisher` | A07 → 查询投影 | 按业务/套餐目标版本构建或失效安全投影 |
| `PublicCacheInvalidator` | A07 → 缓存/任务能力 | 资源范围、目标版本和幂等失效意图 |
| `AuditAndTaskRecorder` | A07 → 通用后端能力 | 脱敏审计、任务状态和人工补偿结果 |
| `PackageVersionReader`（后续） | A07 → A12/A13 | 未来读取明确版本和成单输入；阶段一无调用方、不开放接口 |

端口名称可以按工程规范调整；事实归属、只读边界和依赖方向不可反转。模块不得直接读 A06/A05 表，不直接调用对象存储 SDK，也不在阶段一调用预约、订单或支付模块。

### 9.3 内部架构与失败处理

```text
D-401 adapter
  → 目录公开查询应用服务
  → A07 当前业务/套餐版本与价格规则
  → A06/content/media 只读端口
  → 安全投影/DTO

受控维护适配器
  → 目录维护应用服务
  → 本模块版本、发布和校验规则
  → 本地存储 + 审计/任务意图
```

跨模块和存储调用不放入长数据库事务。结果未知时保持候选未发布或公开端安全省略/不可用；有限重试后进入人工复核，不能通过直接改状态、使用原型值或回退旧媒体伪造成功。

## 10. 与作品、预约和订单的协作

### 10.1 与作品和首页

- A06 案例与 A07 业务/套餐通过稳定公开标识关联，双方不复制对方正文、价格、图片或状态。
- A07 只返回当前合格作品摘要；作品授权撤回或资格未知时，关联入口和媒体 fail-closed，套餐服务事实可在不误导的前提下继续展示。
- A05 只保存首页引用和顺序，读取 A07 当前摘要；首页不能让未发布套餐获得公开资格。
- 套餐媒体若直接引用作品/人物图片，必须经 A06/A15 当前资格链和 D-205 网关，不因用于套餐营销而豁免授权。

### 10.2 与预约、订单、支付和交付

阶段一只保留以下契约边界，不实现流程：

- A12 未来读取业务/套餐版本及是否允许作为预约候选；档期和预约状态不属于 A07。
- A13 未来在客户确认时生成订单快照；套餐当前版本不能替代订单历史快照。
- A14 未来管理定金/尾款支付和退款；A07 只提供经确认的固定定金输入，不持有支付状态。
- A15 未来管理私密成片交付；公开服务项不授予文件访问权，也不创建交付批次。

阶段一页面只有电话/微信等已确认联系动作。任何“立即预约”“下单”“支付定金”“查看成片”入口及其 API 调用均不在本阶段。

## 11. 缓存、旧链接、测试和验收

### 11.1 缓存和旧链接

- 首页、业务列表和套餐列表可缓存安全公开 DTO，并携带 `contentVersion` 或等价版本；具体 TTL/ETag 待统一评审。
- 命中缓存、条件请求或 304 前仍要确认资源当前发布版本；下架、到期或版本替换后不能把旧价格/服务项作为当前详情展示。
- 套餐详情和旧分享按稳定 `packageId` 重新查询当前版本。资源不存在、下架或过期统一返回公开不可用，不暴露内部原因或历史价格。
- 旧分享不携带可信价格、`priceType`、服务项或媒体地址；分享卡片中的旧文案不能替代详情重查。
- 业务/套餐发布、下架、调价、活动到期、媒体/作品关联变化触发首页、列表、详情和关联缓存失效；任务失败不得恢复已知下架资源。
- 公开媒体全部通过 D-205 网关。资格/权利未知时 fail-closed；不以缓存、CDN、302、旧 URL、原图或私密文件兜底。
- 服务端确认资源不可用后客户端清理对应缓存；网络失败不得把旧固定价、旧活动价或旧套餐详情呈现为当前事实。

D-602 现有“首页和列表可先显示最近缓存”规则没有区分普通业务文案与价格事实。阶段一采用更严格默认：未经当前版本确认的缓存价格不作为当前报价展示；是否允许标明缓存来源后只展示不含价格的业务/套餐摘要，需由主代理统一 D-401/D-602 的展示模型和验收口径。

### 11.2 测试和验收

| 验证重点 | 必须证明的结果 | D-702 对应 |
|---|---|---|
| 六类业务 | 儿童、亲子全家福、婚纱、写真、孕照、证件照均可表达且不被作品分类替代 | `S1-BIZ-01/02/03/04` |
| 无套餐业务 | 保留业务与真实空状态，不产生测试套餐或虚构价格 | `S1-BIZ-02`、`S1-STATE-02` |
| 四类价格 | `FIXED/FROM/INQUIRY/UNDISCLOSED` 展示语义稳定，客户端不靠文本猜测 | `S1-PKG-01/02/03` |
| 历史数据隔离 | 原型价格、活动价、30%/50% 定金比例和服务数量不进入公开结果 | `S1-PKG-03`、`S1-API-06` |
| 同源版本 | 首页、列表、详情读取同一当前套餐版本和 `priceType` | `S1-PKG-01/05`、`S1-API-01` |
| 发布/下架/旧链接 | 下架及过期资源从聚合移除，旧链接安全不可用 | `S1-PKG-04`、`S1-API-03/05` |
| 作品/媒体资格 | 失效作品入口移除；媒体资格未知、旧 URL 和对象故障不泄露或回退 | `S1-WORK-03/05`、`S1-CACHE-03/05` |
| 并发与任务 | 并发调价/发布不丢更新；下架优先；重复和乱序任务不降版 | `S1-CACHE-01/04/05` |
| 缓存 | 版本变化后获取新内容，旧价格和活动信息不作为当前事实 | `S1-CACHE-01/02/03` |
| 阶段边界 | 浏览/联系不触发登录、预约、订单、支付或私密交付 | `S1-NAV-05` |

额外测试数据至少包括：每类业务有/无套餐；四种 `priceType`；完全未确认价格；过期活动原型；历史定金比例；套餐下架旧链接；业务下架与套餐发布并发；调价并发；关联作品撤回；媒体资格未知；网络失败命中旧套餐缓存。

测试必须断言数值来源和语义，而不只断言页面出现价格文本。`INQUIRY` 与 `UNDISCLOSED` 必须分别覆盖，不能都降级为同一缺失值处理。

## 12. 阶段开放与待确认问题

### 12.1 阶段范围

| 能力 | 阶段一 | 后续阶段 |
|---|---|---|
| 微信小程序匿名业务/套餐读取 | 开放，只读 | 继承同一公开版本边界 |
| 六类业务目录 | 全部保留并可表达 | 可完善业务特有规则，不随意删除语义身份 |
| 四类公开价格语义 | 开放已确认版本 | 可扩展经评审的活动/区间规则 |
| 受控导入、校验、发布和下架 | 作为非公开前置流程落实，不交付管理 UI | 阶段二纳入运营后台 |
| 公开媒体 | 经 D-205 受控网关开放 | 仍与私密交付隔离 |
| 客户登录、预约和档期 | 不开放 | 阶段二设计/开放 |
| 订单、套餐快照和履约 | 不开放 | 阶段二设计/开放 |
| 支付、退款和私密交付 | 不开放 | 阶段三设计/开放 |
| 品牌官网 | 不属于阶段一交付 | 共享公开事实前单独评审缓存和渠道 |

### 12.2 设计假设

- 六类业务语义已确认；首批说明和套餐资料可以分批确认，缺失时使用真实空状态。
- 初期公开投影可以实时组装或按版本构建；无论采用哪种方式，详情按当前发布版本读取。
- 同库任务/outbox 可以满足首版投影和缓存失效，不因此要求 Redis 或消息队列。
- 首版不要求活动价双价格展示；只有经经营确认和契约评审后才纳入。

### 12.3 待确认问题

| 待确认项 | 责任方向 | 未确认时处理 |
|---|---|---|
