> 文档状态：评审中（阶段一可编码草案）
> 适用范围：阶段一为主；阶段二、阶段三保留扩展边界
> 更新日期：2026-10-09

> 上游架构：AT01、AT04、AT07、AT09
> 关联计划：P01；对齐 D-103、D-301、D-401、D-501、D-601、D-602、D-702、D-203、D-205

## 1. 设计目标

本模块为阶段一微信小程序提供匿名、只读的作品列表、案例详情、分类/标签浏览和公开媒体展示。公开结果来自同一份当前有效事实，不再由首页、列表和详情分别维护作品副本。

阶段一只交付公开读取，以及支撑真实资料进入公开数据源所需的受控导入、校验、发布、下架和资格刷新前置流程；不交付管理后台、客户登录、客户端上传、预约、订单、支付或私密成片交付。受控流程可以由经确认的脚本、运维工具或其他非公开适配器承载，但不得因此新增匿名写接口或假定已有后台。

本设计遵守以下责任链：

```text
A15 持有公开授权事实
  → A06 消费授权结果并计算作品公开资格
  → A05 只编排当前有效作品引用
  → D-401 输出安全公开 DTO
  → D-601/D-602 展示和反馈
```

本文中的对象、状态和端口名称均为设计语义，不锁定数据库表、类名、枚举名或最终 DTO 字段。

## 2. 案例、图片、分类和标签

### 2.1 职责边界

| 事实或规则 | 权威归属 | 本模块职责 | 明确不负责 |
|---|---|---|---|
| 案例正文、图片顺序、封面、分类、标签、署名快照 | A06 / `works` | 形成候选版本、公开版本和当前公开投影 | 客户身份、授权证据和私密交付 |
| 公开授权主体、范围、用途、渠道、期限、证据和撤回 | A15 / `delivery` | 通过只读端口消费当前判断结果 | 创建、补写或修改授权事实 |
| 图片登记、衍生图、对象状态和受控读取 | D-205 / 媒体能力 | 保存作品用途和顺序绑定，消费可读结果 | 暴露对象 key、原图或供应商地址 |
| 摄影业务、套餐、价格和公开版本 | A07 / `catalog` | 保存稳定关联并读取当前公开摘要 | 复制价格、定金、服务项或预约资格 |
| 首页精选及排序 | A05 / `content` | 提供当前有效作品摘要 | 因被首页引用而获得公开资格 |
| 公开接口、错误和客户端状态 | D-401、D-203、D-601、D-602 | 提供安全投影所需语义 | 自建另一套外部错误码或展示字段 |

### 2.2 逻辑对象

| 对象草案 | 业务含义 | 阶段一用途 |
|---|---|---|
| `WorkCase` | 一个单图或多图的公开案例身份 | 稳定公开标识和版本归属 |
| `WorkCaseVersion` | 标题、摘要、说明、署名、关联等一次不可变候选/发布快照 | 发布切换、历史追溯、并发控制 |
| `WorkMediaBinding` | 案例版本与公开媒体的用途、顺序、封面关系 | 列表封面和详情有序图片 |
| `WorkCategory` | 作品浏览主维度 | 分类筛选；至少一个有效分类才能发布 |
| `WorkTag` | 风格、场景、人物或主题等辅助维度 | 可选展示或筛选，是否首版开放由接口评审决定 |
| `ContributorCredit` | 工作室或贡献者的已确认公开署名快照 | 保持历史公开表达，不等同后台账号 |
| `WorkCatalogAssociation` | 案例与摄影业务/套餐的可选稳定关联 | 导流到当前有效公开对象，不复制其事实 |
| `Publication` | 哪个案例版本当前处于发布或下架结果 | 公开版本选择和追溯 |
| `PublicEligibility` | A06 基于当前授权、媒体和案例规则形成的派生结果 | 公开查询和媒体网关的必要输入 |

`PublicAuthorizationFact` 不属于本模块。`PublicEligibility` 可以记录计算所依据的授权事实版本、案例版本、媒体版本和计算时间摘要，但该摘要不是授权证据，也不能覆盖 A15 当前事实。

### 2.3 案例、图片和浏览维度规则

- 客户主要浏览单元是 `WorkCase`；单张作品可形成只有一张图片的案例，多张相关图片按明确顺序组成同一案例。
- 一个可发布案例至少关联一个作品分类、一个已确认封面和一张可公开读取的图片；“全部”仅是查询聚合条件，不保存为真实分类。
- 封面必须来自当前案例版本的公开图片集合，不允许从客户私密交付文件、历史前端静态资源或其他案例临时兜底。
- 图片顺序由业务绑定明确，不依赖文件名、对象存储列举顺序或客户端数组顺序。
- 作品分类、摄影业务和套餐所属业务是不同概念；名称相同也不能共享一个未经区分的事实对象。
- `创始人档` 在负责人确认前只可作为待核实的作品/品牌栏目线索，不得成为可预约业务或套餐档位。
- 标签为可选辅助信息；停用分类/标签保留历史关联，但公开查询只返回当前允许公开的维度。
- 公开署名使用已确认的显示快照，不返回后台账号、真实身份资料或权限；未确认署名省略，不从原型自由文本补齐。
- 拍摄时间、客户姓名、订单号、联系方式、内部备注、授权证据和私密文件信息均不因存在于源资料而自动公开。

### 2.4 核心不变量

1. A15 是公开授权事实唯一来源；A06 不创建第二套同意、撤回、主体或证据记录。
2. 只有当前发布版本且 `PublicEligibility = ELIGIBLE` 的案例进入公开列表、详情、首页引用和相关作品候选。
3. 资格为 `UNKNOWN`、读取超时、范围不明、渠道/用途不匹配或依赖版本过期时一律 fail-closed。
4. 案例资格不能由客户端的 `published`、`authorized`、`visible`、缓存标记或媒体 URL 决定。
5. 公开媒体只经 D-205 受控网关读取；对象 key、原图、私密交付文件和永久签名地址不进入 DTO。
6. 首页、列表、详情和分享只引用案例公开标识与当前投影，不复制作品事实。
7. 可选业务/套餐关联失效时移除入口；不得复制旧价格或服务内容维持卡片。关联失效本身不自动下架仍然完整合规的案例。
8. 发布失败保留仍然安全的旧公开版本；授权撤回、主动下架或资格未知不适用旧版本继续公开。
9. 公开查询和受控维护均不得创建预约、订单、支付或私密交付事实。

## 3. 公开资格和授权结果消费

### 3.1 资格计算

案例公开资格按当前事实计算，语义上至少满足：

```text
案例当前版本已发布
+ 案例未主动下架、归档或因完整性问题停止公开
+ A15 对当前案例、图片、人物、用途和微信小程序渠道返回 VALID
+ 当前版本具有已确认封面和至少一张合格公开媒体
+ 媒体绑定、衍生图和用途校验有效
+ 标题、摘要/说明、分类和公开署名不含禁止信息
= ELIGIBLE
```

可选标签、贡献者或业务/套餐入口失效时，查询层优先安全省略对应可选信息并记录待修复；如果缺失会改变案例主题、造成错误署名或使内容误导，则整案转为不可公开。该判断规则应由发布校验明确，不由客户端临时决定。

### 3.2 A15 授权结果输入

A15 的只读结果至少需要表达：判断结果 `VALID / INVALID / UNKNOWN`、适用对象范围、用途、渠道、有效时间和可比较的事实版本摘要。阶段一渠道必须明确覆盖微信小程序公开展示；官网或其他渠道的授权不能自动扩展到小程序。

A06 只保存资格计算引用和结果摘要，不保存授权证据正文、客户身份材料或撤回原因。每次资格计算使用当前事实：

- `VALID` 且范围完整匹配，才可继续其他资格检查；
- `INVALID`、过期、撤回或范围不匹配，结果为 `INELIGIBLE`；
- 缺失、争议、超时、版本无法确认或主体关系不明，结果为 `UNKNOWN`，对公开效果等同不可公开；
- 单资源确定不可公开或资源级未知时，列表过滤、详情统一不可用；
- 授权依赖整体故障导致列表无法可信计算时，返回 `PUBLIC_SERVICE_UNAVAILABLE`，不能伪装成真实空列表。

### 3.3 图片级与整案变化

- 单张图片授权撤回或失效：立即阻断该媒体读取，移出资格候选并重新计算案例。
- 被撤回图片是当前封面、案例没有剩余合格图片或剩余内容不能准确表达主题：整案不可公开，等待受控修复和重新发布。
- 仍有合格图片且内容语义完整：只有在受控流程确认新的图片集合、封面和版本后才能继续公开；不得在查询时自动挑选另一张私密或未确认图片。
- 案例级、人物级或覆盖整案的授权撤回：整案不可公开，不适用“保留剩余图片”。
- A15 授权恢复或争议解除不自动恢复案例；A06 重新计算、校验并通过明确发布/恢复动作后才可公开。

### 3.4 资格读取时机

列表查询在服务端过滤不合格案例；详情、首页摘要解析和每次媒体读取仍分别检查当前发布版本与资格。资格缓存只能作为计算加速，命中后也须确认其输入版本仍是当前版本；不能把缓存中的 `authorized=true` 当作许可。

## 4. 案例发布、下架和撤回

### 4.1 状态分离

内容生命周期、授权事实、公开资格和媒体状态分别表达，不合并为单一布尔字段：

| 概念 | 状态语义草案 | 公开规则 |
|---|---|---|
| 案例版本 | `draft / review / published / withdrawn / repairing / archived` | 仅当前 `published` 版本有资格进入公开读取 |
| A15 授权结果 | `valid / invalid / unknown` 及范围/期限 | 仅当前完整匹配的 `valid` |
| A06 公开资格 | `eligible / ineligible / unknown` | 仅 `eligible` |
| 媒体绑定 | `registered / validated / readable / unavailable / withdrawn` | 仅当前受控可读绑定 |
| 公开投影 | `building / current / superseded / invalid` | 仅 `current`，且读取时仍校验当前资格 |

`published` 表示一个案例版本通过发布校验，不表示授权永久有效。授权、媒体或完整性变化可以使已发布版本立即失去公开资格，而不抹去其历史发布事实。

### 4.2 转换与失败结果

| 当前状态 | 受控动作/事实变化 | 前置条件 | 结果 | 失败或未知 |
|---|---|---|---|---|
| 无 / `draft` | 准备候选 | 来源、责任人、内容和媒体登记明确 | 新候选版本 | 保留未发布候选与校验问题 |
| `draft` | 提交校验 | 必需内容齐全 | `review` | 仍为 `draft` |
| `review` | 发布 | 版本未冲突；授权、媒体、分类和内容校验通过 | 原子切换为当前 `published` 版本 | 旧安全版本不变；候选记录失败 |
| `published` | 主动下架 | 操作者、范围、原因和预期版本明确 | `withdrawn`，立即停止公开读取 | 失效任务失败不恢复公开 |
| `published` | 授权/媒体失效 | 当前输入变为无效或未知 | 资格转为不可公开，可标记 `repairing` | fail-closed 并进入任务/人工复核 |
| `withdrawn / repairing` | 恢复 | 形成候选版本并重新执行全部校验 | 新版本 `published` | 保持不可公开 |
| 任意非公开状态 | 归档 | 无当前公开引用或已完成下架 | `archived` | 保留历史和审计，不物理删除授权/私密文件 |

### 4.3 发布校验和原子性

发布前至少校验标题及公开说明、作品分类、封面、有序图片、A15 当前授权范围、媒体可读性、署名、可选关联安全性和禁止信息。历史原型图片、标题或页面曾经公开不能替代以上校验。

本模块本地事务只覆盖候选/发布版本、当前版本指针、作品关联、资格摘要、审计摘要和任务/outbox 意图。对象存储、A15、A07、首页投影和缓存不加入分布式事务。发布切换失败时不得产生“新标题配旧图片”等部分公开状态。

### 4.4 下架、资格撤回和恢复

主动下架、A15 授权撤回和媒体撤回均优先阻断新的详情与媒体读取，再异步清理首页、列表投影、分享摘要和缓存。通知、投影或缓存失效任务失败不回滚已确认的下架/撤回事实。

恢复必须建立新的候选或明确复核当前候选，并重新读取 A15 当前授权和媒体绑定；不能通过撤销一个错误标记、恢复备份或直接修改 `published` 字段恢复公开。

## 5. 作品与摄影业务/套餐关联

- 案例可以选择关联零个或多个当前可识别的摄影业务/套餐；具体关联基数由经营确认，不作为阶段一硬编码约束。
- 关联只保存目标稳定标识、关联用途和必要顺序，不复制业务名称、套餐标题、价格、定金、服务项或预约资格。
- 公开输出通过 A07 只读端口获取当前有效摘要；目标未发布、已下架或不可识别时省略入口并记录失效关联。
- 套餐下架不自动下架案例，案例授权撤回也不改写套餐历史版本；双方分别按自己的资格公开。
- 案例图片可以被套餐或首页引用，但引用方不能建立绕过当前作品资格的媒体直链。
- 页面需避免表达“案例中的内容全部包含在当前套餐”“该业务当前有档期”或“查看案例即已选择服务”。
- 六类摄影业务是 A07 的目录；作品分类可与其关联或用于筛选，但不得按名称自动合并。

## 6. 输入输出和用例

### 6.1 输入边界

匿名公开输入仅包括不透明公开 ID、已允许的作品/业务/标签筛选、受限分页参数和可选来源上下文。入口层校验长度、字符集、枚举白名单和数量上限；路由参数只是定位条件，不是权限凭证。

受控维护输入至少包括资料来源、目标案例、候选内容、媒体绑定、分类/标签、署名、业务/套餐关联、预期版本、操作者/责任来源和动作幂等标识。它不通过阶段一匿名接口开放，也不接受客户端提交授权结论、对象 key 或任意 URL。

资格刷新输入来自 A15 授权版本变化、媒体状态变化、案例发布/下架或一致性检查结果，至少携带对象范围、来源版本和事件/任务标识。乱序或重复输入不得覆盖更新结果。

### 6.2 输出边界

公开成功输出沿用 D-401 的统一外层和 `PublicWorkSummaryDTO`、`PublicWorkDetailDTO`、`PublicMediaDTO` 语义，并携带可比较的 `meta.contentVersion`。具体字段在 D-401 评审后锁定。

允许公开的内容包括案例公开标识、标题、摘要/说明、当前公开分类/标签、已确认署名、业务/套餐入口摘要、发布时间和受控媒体引用。禁止返回客户资料、授权证据/原因/内部标识、拍摄记录、订单、私密文件、对象 key、后台状态细节和未发布版本。

### 6.3 用例

| 用例 | 发起方 | 输入与前置 | 成功结果 | 失败/安全结果 |
|---|---|---|---|---|
| 浏览作品列表 | 匿名访客 | 允许的筛选和分页 | 当前合格摘要、稳定排序和分页 | 非法参数 400；整体资格依赖故障 503 |
| 查看案例详情 | 匿名访客/旧分享 | `workId`，服务端二次校验 | 当前合格详情和有序媒体 | 不存在/下架/无资格统一 404 |
| 读取公开媒体 | 小程序页面 | 案例、媒体、用途和可选版本定位 | 网关返回当前合格缩略/预览流 | 资格无效/未知 404；合格媒体存储故障 503 |
| 为首页提供摘要 | A05 / 查询编排 | 当前公开 ID 和版本 | 当前有效作品摘要 | 失效项不返回，触发引用修复 |
| 受控准备并发布 | 维护适配器 | 候选、来源、预期版本和校验结果 | 当前版本原子切换，记录任务/审计 | 冲突重读；失败保持安全旧版本 |
| 主动下架 | 受控维护人 | 对象范围、原因、预期版本 | 新读取立即不可用，派发失效任务 | 重复动作幂等；任务失败转人工 |
| 处理授权/媒体变化 | A15 / 媒体任务 | 对象范围和来源版本 | 重算资格，隐藏受影响内容 | 未知时 fail-closed，不回退旧结果 |

## 7. 权限、版本和审计

### 7.1 权限和阶段一维护边界

匿名访客只能读取安全公开投影和受控媒体。阶段一不提供案例 CRUD、发布、下架、授权或上传后台接口；维护人、审核人和发布人通过经批准的受控流程落实，并明确责任与最小权限。

未来后台角色、复核层级和敏感案例审批由 A10/A15 后续设计确定。公开署名为摄影师不自动获得维护权限；能够导入图片也不自动获得发布或授权修改权限。

### 7.2 版本、并发和幂等

- `WorkCase` 使用稳定身份；候选内容、公开内容和媒体集合以不可变版本或等价快照区分。
- 编辑和发布携带预期案例版本/当前发布版本；版本不符返回受控冲突并重新读取，不做最后写入覆盖。
- 发布仅在本地事务中切换当前版本；跨模块校验记录所依据的来源版本，公开读取仍以 A15 和媒体当前事实兜底。
- A15 撤回与作品发布并发时，当前授权判断优先；任何无法证明授权仍有效的结果不得公开。
- 资格重算、投影重建和缓存失效使用“资源 + 动作 + 目标版本/来源版本”作为幂等语义；旧任务不得覆盖较新资格或恢复旧媒体绑定。
- 同一匿名读取可安全重复；`requestId` 只用于追踪，不作为幂等键。

### 7.3 审计与可观测性

至少记录：候选来源、创建/编辑、提交校验、发布、下架、恢复、归档；分类/标签、图片、封面、顺序、署名和业务/套餐关联变更；资格计算输入版本与结果；授权/媒体变化触发的影响范围；投影、缓存和人工补偿结果。

审计包含操作者或系统身份、动作、对象、前后版本、时间、原因摘要、结果和 `requestId/taskId`。授权证据正文、客户资料、撤回原因、对象 key、签名参数和私密地址不得进入普通日志或公开响应。

指标至少观察公开作品查询成功/不可用率、资格未知率、授权读取失败、媒体失败、失效关联、版本冲突、资格重算积压、缓存失效与补偿失败。阈值在真实环境验证后确定。

## 8. 数据结构草案

以下仅说明逻辑信息和约束，不是最终表、字段或类设计：

| 逻辑集合 | 候选信息 | 关键约束 |
|---|---|---|
| 案例身份 | 内部标识、公开标识、创建来源、当前状态摘要 | 公开 ID 不透明稳定，不可反查客户 |
| 案例版本 | 标题、摘要、说明、公开时间表达、版本、状态 | 发布后只读；修改产生候选/新版本 |
| 图片绑定 | 案例版本、媒体引用、用途、顺序、封面标志、媒体版本 | 封面唯一候选；顺序稳定；只绑定公开衍生图 |
| 分类/标签 | 类型、公开名称、排序、状态、版本 | 与摄影业务分域；“全部”不持久化 |
| 署名快照 | 公开称呼、角色表达、顺序、来源确认 | 不含账号权限或不必要身份资料 |
| 目录关联 | 目标类型、目标公开标识、用途、顺序 | 不复制 A07 事实；公开时重查目标 |
| 资格摘要 | 结果、案例/授权/媒体版本摘要、计算时间、原因分类 | 可重算；不是授权事实；未知不公开 |
| 发布/任务/审计 | 动作标识、目标版本、状态、重试和影响范围 | 与本地事实同事务记录意图，可补偿 |

持久化模型、公开投影、API DTO 和小程序展示模型保持分层；不得直接序列化领域或持久化对象。具体关系、索引和迁移由数据设计后续锁定。

## 9. 接口与内部架构草案

### 9.1 对外读取

阶段一沿用 D-401 路径草案：

- `GET /api/v1/public/works`：作品列表、受限筛选和分页；
- `GET /api/v1/public/works/{workId}`：详情二次校验；
- `GET/HEAD /api/v1/public/media/{mediaId}/{variant}`：D-205 受控媒体网关，变体仅限阶段一允许的缩略/预览。

不存在、未发布、下架、授权撤回、资格无效或资源级资格未知统一映射 `PUBLIC_RESOURCE_UNAVAILABLE`。参数、整体依赖、媒体存储和响应转换错误沿用 D-203，不新增作品私有码。阶段一没有公开写接口、客户接口或后台接口。

### 9.2 内部语义端口

| 端口语义草案 | 提供方 → 消费方 | 输入输出边界 |
|---|---|---|
| `PublicAuthorizationReader` | A15 → A06 | 按案例/图片、渠道、用途和时点返回当前判断及事实版本，不返回证据正文 |
| `PublicEligibilityReader` | A06 → 查询层/媒体网关 | 返回当前资格及输入版本摘要；未知按不可公开 |
| `PublicMediaReader` | 媒体能力 → A06/查询层 | 校验绑定、用途和当前资格后提供受控引用/媒体流 |
| `PublicCatalogReader` | A07 → A06 | 返回当前有效业务/套餐摘要；失效关联不返回 |
| `PublicWorkReader` | A06 → A05/公开查询 | 返回当前合格作品摘要或详情，不返回全量领域对象 |
| `ControlledWorkMaintenance` | 受控适配器 → A06 | 候选准备、校验、发布/下架意图；不对匿名端开放 |
| `PublicProjectionPublisher` | A06 → 查询投影 | 按目标版本重建/失效安全投影 |
| `PublicCacheInvalidator` | A06 → 缓存/任务能力 | 资源范围、目标版本和幂等失效意图 |
| `AuditAndTaskRecorder` | A06 → 通用后端能力 | 脱敏审计、任务状态和人工补偿结果 |

以上名称可以在编码时按工程命名规范调整；依赖方向和事实边界不可反转。模块不得直接读 A15/A07 表，也不得直接调用对象存储供应商 SDK。

### 9.3 内部调用和事务方向

```text
D-401 adapter
  → 作品公开查询应用服务
  → A06 当前版本与资格规则
  → A15/A07/media 只读端口
  → 安全投影/DTO

受控维护适配器
  → 作品维护应用服务
  → 本模块版本、发布和资格规则
  → 本地存储 + 审计/任务意图
```

外部或跨模块读取不放入长数据库事务。结果未知时保持候选未发布或公开端隐藏，并由有限重试/人工复核处理，不直接更改授权或媒体状态。

## 10. 缓存、分享和旧链接

- 服务端缓存键至少区分案例公开 ID、查询条件、案例版本、资格输入版本和媒体绑定版本；具体 TTL/ETag 待统一评审。
- 任何缓存命中、条件请求或 304 判定前，必须确认当前发布和资格；资格未知时不返回旧 DTO。
- 作品封面、详情图片和分享缩略图均通过 D-205 受控网关读取。阶段一作品媒体使用 `no-store` 安全默认，不通过 CDN、永久 URL、302 到对象存储或旧签名绕过复核。
- 小程序不得在弱网、刷新失败或从后台恢复时直接显示未重新确认的旧作品媒体；待确认期间显示骨架或安全不可用状态。
- 客户端可保存筛选、滚动位置和公开 ID，但旧作品卡片/详情不能作为资格事实。服务端返回不可用后清理对应 DTO 与媒体缓存。
- 旧分享只携带稳定 `workId`；打开时重新查询。案例下架、授权撤回或资格未知时统一显示内容不可用，不透露内部原因。
- A15 授权变化、案例下架、封面/媒体替换和资格变化触发案例、首页精选、相关作品及媒体绑定失效任务；任务失败不改变网关当前拒绝结果。
- 已发送字节、访客已下载副本、平台历史卡片或外部搜索缓存可能无法即时远程删除；记录可控入口处理与外部跟进，不虚构“全部立即清除”的承诺。

D-602 现有“首页和列表可先显示最近缓存”表述与 D-203/D-205 的作品媒体二次确认规则冲突。阶段一对作品内容采用本节更严格的 fail-closed 安全默认，待主代理统一 D-401/D-602 的跨文档措辞。

## 11. 测试和验收

| 验证重点 | 必须证明的结果 | D-702 对应 |
|---|---|---|
| 合格案例 | 当前发布、A15 授权有效、封面和媒体可读时，首页/列表/详情顺序一致 | `S1-WORK-01`、`S1-API-01` |
| 无授权与未知 | 未核验、范围不符、超时或未知均不公开；整体依赖故障不伪装空结果 | `S1-WORK-02`、`S1-API-05` |
| 下架与撤回 | 列表/首页移除，详情旧链接不可用，媒体网关拒绝旧 URL | `S1-WORK-03/04`、`S1-CACHE-03` |
| 单图变化 | 非封面单图失败可隔离；封面/最后一图/整案授权变化导致安全隐藏 | `S1-WORK-05` |
| 注入与深链 | 固定 ID、客户端对象、伪造状态/URL 不能绕过服务端复核 | `S1-WORK-06`、`S1-API-03/04/06` |

## 12. 阶段开放与待确认问题

### 12.1 阶段范围

| 能力 | 阶段一 | 后续阶段 |
|---|---|---|
| 微信小程序匿名作品列表/详情 | 开放，只读 | 继承同一资格边界 |
| 公开分类/受控筛选 | 开放已评审范围 | 可扩展搜索、标签和推荐 |
| 公开媒体读取 | 经 D-205 受控网关开放 | 仍不得与私密交付混用 |
| 受控导入、校验、发布、下架 | 作为非公开前置流程落实，不交付管理 UI | 阶段二纳入运营后台 |
| A15 授权事实维护 | 只消费已核验前置事实/变化结果 | 后续提供正式授权运营能力 |
| 客户上传、登录和客户资料 | 不开放 | 按后续阶段设计 |
| 预约、订单和支付 | 不开放 | 按阶段二/三设计 |
| 私密相册、原片/精修交付 | 不开放 | 阶段三按 A15 设计 |
| 品牌官网和外部搜索 | 不属于阶段一交付 | 共享事实前另行评审渠道授权与缓存 |

### 12.2 设计假设

- 阶段一存在可审计的受控数据来源，能够提供已核实案例内容、媒体和 A15 授权结果；没有真实资料时允许作品集为空。
- 初期可以实时组装或按版本构建公开投影；无论采用哪种方式，详情和媒体读取均检查当前资格。
- 同库任务/outbox 可以满足首版资格重算与缓存失效，不因此要求 Redis 或消息队列。

### 12.3 待确认问题

| 待确认项 | 责任方向 | 未确认时处理 |
|---|---|---|
| 首批真实案例清单、图片来源及小程序渠道授权证据 | 工作室负责人、授权责任人 | 不公开历史原型作品 |
| 案例粒度、正式作品分类、标签首版是否展示/筛选 | 产品与内容负责人 | 支持单/多图基本模型；未确认标签能力不开放 |
| `创始人档` 的真实含义 | 工作室负责人 | 仅保留为待核实作品/品牌栏目线索 |
| 儿童、孕照、全家福、婚纱多人授权与监护核验 | A15/A11/负责人 | 无法确认时整案不公开 |
| 单图撤回后可否保留案例、哪些敏感业务一律整案隐藏 | A06/A15/负责人 | 封面或语义受影响时整案隐藏；其他情况也需受控复核后新版本发布 |
| 署名角色、历史成员停用后的公开表达 | 内容负责人 | 未确认署名省略或使用已确认工作室署名 |
| 相关作品是否纳入阶段一及匹配方式 | 产品负责人 | 不自动推荐；可隐藏区块 |
| A15 结果端口、事实版本、撤回通知和可接受传播目标 | 架构、授权与运维 | 查询/媒体未知即拒绝；不假定时限 |
| D-401 的 `businessLabels/packageLabel`、A06 的作品分类/标签/关联和 D-601 的 `businessId/tag` 如何形成单一 DTO 与筛选语义 | API、作品与客户端评审 | 不新增平行正式字段；只开放共同评审后的筛选和展示字段 |
| 必需封面失效、列表局部失败和错误映射最终契约 | D-203/D-401/D-602 共同评审 | 采用严格隐藏，不返回假图或旧图 |
| 公开媒体尺寸、变体、水印、生产域名和网关能力 | 媒体、客户端与运维 | 仅开放实测通过的缩略/预览能力 |
| 公开数据导入、审核、发布、下架和补偿责任 | 工作室、产品与运维 | 编码前形成批准的受控流程，不假定后台 |

以上事项不阻止按本稿实现安全边界和接口骨架，但首批真实作品、授权输入、受控发布责任和媒体网关能力是生产公开前置条件。
