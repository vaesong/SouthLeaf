# 内容与品牌设计

> 文档编号：D-301
> 文档状态：评审中（阶段一内容与品牌草案）
> 适用范围：阶段一为主；阶段二、阶段三保留扩展边界
> 更新日期：2026-10-08
> 上游需求：A05、A08、A09、A15、A16
> 上游架构：AT01、AT04、AT07、AT09
> 关联计划：P01

## 1. 设计目标

为阶段一“小程序公开展示”提供单一权威的品牌、工作室、联系资料和首页编排。首页、关于页、作品详情和套餐详情消费同一份已发布事实，避免页面、底部组件和接口分别保存电话、地址或品牌文案。

本设计与 D-103、D-401、D-501、D-601、D-602、D-702 对齐。文中对象、端口和版本表达均为评审草案，不锁定数据库表、类名或最终 DTO 字段。

阶段一交付匿名公开读取，以及支撑发布、下架和撤回的受控前置流程；不交付管理后台、内容编辑工作台、客户端上传、客户登录、预约、订单、支付或私密交付。A05 中面向后台的目标需求保留到后续阶段，本阶段由经确认的受控维护方式提供事实。

## 2. 内容类型与权威归属

### 2.1 职责边界

| 内容或规则 | 权威归属 | `content` 的职责 | 协作边界 |
|---|---|---|---|
| 品牌、工作室公开资料 | A05 / `content` | 维护权威正文、公开摘要和版本 | 不从历史原型推断真实性 |
| 联系渠道、地址、联系时间 | A05 / `content` | 统一确认、发布和停用 | 各页面只消费，不另建副本 |
| 首页区块与推荐引用 | A05 / `content` | 保存区块类型、顺序和目标引用 | 引用 A06/A07 当前有效公开对象 |
| 作品案例与公开资格 | A06 / `works` | 通过 `PublicWorkReader` 读取摘要 | 不改作品、图片集合或授权判断 |
| 六类业务、套餐与价格 | A07 / `catalog` | 通过 `PublicCatalogReader` 读取摘要 | 不复制或计算价格、定金和服务承诺 |
| 公开授权事实 | A15 | 消费 A06 返回的资格过滤结果 | 不保存第二套同意、范围或撤回主记录 |
| 媒体登记与读取 | 文件/媒体能力 | 保存用途和业务引用，读取受控媒体 | 不持有对象存储凭证或原始 key |
| 页面路由与状态 | D-601、D-602 | 提供公开内容和稳定标识 | 不决定客户端身份或系统能力结果 |

A15 持有公开授权事实，A06 消费授权结果并计算公开资格，A05 负责公开编排。首页选择某个作品不能使其获得公开资格。

### 2.2 内容对象与发布单位

| 对象草案 | 表达内容 | 阶段一用途 |
|---|---|---|
| `BrandProfile` | 品牌名称、Logo 引用、简介、工作室介绍和服务区域 | 首页品牌摘要、关于页 |
| `ContactProfile` | 已确认的电话、微信渠道、文字地址和联系时间 | 首页、关于页和详情联系摘要 |
| `PublicContentVersion` | 一次可识别的品牌/首页公开内容版本 | 稳定公开读取、替换与追溯 |
| 首页区块与引用项 | 区块类型、文案、顺序、启用状态、目标公开 ID | 精选作品、业务、套餐和联系入口 |
| 可选公共内容 | 团队公开资料、服务流程、FAQ 等 | 有真实资料且 DTO 评审纳入时展示 |
| `Publication` | 当前生效版本及发布、下架记录 | 决定是否进入公开查询 |

品牌与联系资料可以独立维护，但一次公开读取必须明确所用版本组合。首页和详情中的联系信息通过同一读取端口获得；公开摘要是可重建投影，不是新的权威资料源。

团队履历、奖项、数量、评价、FAQ 和流程文案没有确认时不发布。可选内容不能因模板存在而被视为阶段一必做对象；需要新增公开字段时，先评审 D-401 与 D-602。

## 3. 草稿、预览、发布和下架

### 3.1 状态及转换

| 状态草案 | 含义 | 公开条件 |
|---|---|---|
| `draft` | 受控来源正在整理内容 | 不公开 |
| `review` | 等待真实性、媒体和引用校验 | 不公开 |
| `published` | 已通过校验并成为当前公开版本 | 读取时仍校验引用和媒体 |
| `withdrawn` | 主动停止公开展示 | 不公开，保留历史 |
| `expired` | 已确认有效期届满；无期限内容无需使用 | 不公开 |

```text
draft → review → published → withdrawn / expired
              ↘ 校验失败：保留候选和失败记录
withdrawn / expired → 新候选版本 → 重新校验 → published
```

预览是查看草稿或待发布版本的能力，不是 `PublicContentVersion` 的公开状态。阶段一可通过受控检查报告或非公开预览验证内容，不要求建设预览后台；匿名公开查询不能提供草稿预览入口。

编辑形成候选版本，不直接覆盖当前公开版本。已发布内容保留版本标识和历史；新版本发布校验失败时，原版本只有在仍满足公开条件时才能继续提供。下架、联系方式已知错误或授权失效属于停止公开信号，不能用“保留旧版本”恢复已知不安全内容。

### 3.2 发布和恢复前置条件

- 品牌必需资料真实、来源和确认人可追溯；首版所需字段由内容负责人确认。
- 联系信息仅使用已确认字段；正式发布入口至少有一个可用且经过确认的公开联系渠道。
- 必需媒体通过校验，公开引用可读；可选图片缺失时允许省略对应区块。
- 首页目标通过 A06/A07 的公开摘要端口检查，作品授权和资格不由 `content` 自行推断。
- 文案、地址、渠道说明、图片用途一致，不包含测试评价、内部备注或客户资料。
- 发布人、来源批次、目标版本和审计摘要明确；恢复同样执行全部校验。

## 4. 首页编排与公开查询

### 4.1 编排流程

```text
读取当前已发布 PublicContentVersion
  → 读取 BrandProfile / ContactProfile 公开摘要
  → 按区块顺序读取目标公开 ID
  → PublicWorkReader / PublicCatalogReader 校验并返回摘要
  → PublicMediaReader 提供受控媒体引用
  → 过滤失效项并组装安全投影
  → D-401 PublicHomeDTO
```

首页保存引用、顺序和区块文案，不保存另一份作品图片、套餐价格或授权事实。所有区块和引用项设置数量上限，不能用全量无限查询拼接首页；上限、排序并列时的规则在接口评审时确定。

### 4.2 空态、失效和部分失败

| 情形 | 公开结果 | 内部处理 |
|---|---|---|
| 未配置可选区块或没有精选项 | 省略/隐藏区块或返回真实空集合 | 不随机补入历史作品或套餐 |
| 引用对象下架、撤回或资格失效 | 过滤该项，保留其他有效区块 | 标记引用异常并触发投影/缓存失效 |
| 品牌必需资料未发布或版本不可用 | 统一公开不可用结果 | 阻止正式品牌入口发布 |
| 部分联系字段缺失 | 只返回已确认字段 | 不用历史默认电话或地址补齐 |
| 可选摘要依赖暂不可用 | 允许经契约确认的局部降级 | 记录依赖失败；不能伪装为业务上无内容 |
| 必需依赖不可用或无法判断安全性 | `PUBLIC_SERVICE_UNAVAILABLE` 或安全不可用 | 不返回未经校验的缓存副本 |

部分区块成功的响应表达、缺失字段与依赖失败的区分，须与 D-401、D-602 共同评审；不在本文另加一套成功码或私有字段。D-702 的 `S1-STATE-08` 要验证其他区块可继续使用及失败区块反馈。

## 5. 工作室、团队、服务流程、联系方式和地址

### 5.1 单一来源与真实性

品牌名称、介绍、电话、微信、文字地址和联系时间由统一内容源发布；首页、关于、页脚及作品/套餐详情不能硬编码另一份。服务区域与工作室地址分别表达。未确认地点资料时不展示地点入口，也不从旧原型坐标推导真实位置。

每个联系渠道独立保存类型、用途标签、已确认值、公开状态和必要说明。二维码作为媒体引用管理，不能把同一个二维码标成多个社交平台。无有效配置的渠道不进入公开投影。

电话、微信等动作只表达联系。系统调用成功、取消或失败由客户端按 D-601、D-602 提供反馈；不生成客户账号、预约编号、订单或支付事实。

### 5.2 可选内容边界

- 团队公开称呼、职位、简介和头像需确认，且与后台账号、权限和排班资源分离。
- 成员停用后移出当前团队展示；案例历史署名由 A06 处理，不能级联擦除。
- 服务流程只说明通用服务顺序，不改变 A12-A15 的业务状态、金额或交付权限。
- FAQ、奖项和评价没有可信来源或适当公开许可时不展示，不用占位图制造背书。
- 文字内容按允许的格式输出；富文本如被纳入须进行安全清洗，不能允许脚本或任意跳转。

阶段一不要求新增团队详情、FAQ、地图或社交平台专用 API；公开字段和端能力以已评审的 D-401/D-601 为准。

## 6. 输入输出和用例

| 用例 | 输入与前置 | 输出或状态变化 | 失败路径 |
|---|---|---|---|
| 读取品牌 | 匿名请求；当前版本已发布 | 品牌、工作室和已确认联系摘要 | 未发布统一不可用；依赖故障返回服务不可用 |
| 读取首页 | 匿名请求；已发布编排 | `PublicHomeDTO` 与版本标识 | 过滤失效项，按区块规则降级 |
| 为详情提供联系摘要 | A06/A07 查询编排调用 | 同源 `PublicContactDTO` 语义 | 不返回未确认字段或旧默认值 |
| 受控准备候选 | 有权限维护人、资料来源、候选内容和预期版本 | 草稿/待校验候选及校验报告 | 格式/真实性/引用问题保持候选未发布 |
| 受控发布或恢复 | 审核结果、目标版本、动作幂等标识 | 原子切换当前版本，记录审计和任务 | 冲突重新读取；失败保持仍安全的旧版本 |
| 受控下架或联系停用 | 有权限人员、对象范围、原因与当前版本 | 停止相关公开返回，产生失效任务 | 已知停止信号不能因任务失败被忽略 |
| 接收作品/套餐资格变化 | 对象 ID、来源版本和变化结果 | 重建投影、隐藏失效引用 | 乱序任务不覆盖新结果 |

受控维护输入不通过匿名接口暴露。校验内容长度、媒体用途、引用类型、联系格式和版本来源；客户端不能提交 `published`、`authorized`、电话、价格或媒体地址来改变正式结果。

## 7. 权限、审计和版本

### 7.1 维护权限

公开访客只能读取已发布投影。阶段一维护人、审核人和发布人由受控操作流程落实，至少要有明确承担发布、下架和异常处理责任的人；不因此交付后台登录或角色管理系统。管理员未来能否直接发布、联系方式变更是否需要负责人复核，仍由 A05/A10 决定。

### 7.2 事务、并发和幂等

- 本模块本地事务覆盖候选/发布版本、当前指针、引用关系、审计摘要和任务/outbox。
- 跨模块摘要和媒体校验在明确的应用服务边界执行，不在长数据库事务中等待存储或其他外部服务。
- 发布切换需检查预期版本，竞争修改返回受控冲突结果，不静默覆盖另一维护人的内容。
- 同一发布/下架动作按动作标识和资源版本幂等；重试不重复创建公开版本或业务审计事件。
- 投影重建和缓存失效按目标版本执行，旧任务不得把当前指针或投影降回旧版本。
- 公开读取不写入发布、授权、客户或交易事实；运行日志不视为业务写操作。

### 7.3 审计与可观测性

记录内容来源、维护/确认/发布责任、动作、对象、前后版本、时间、影响范围和 requestId/taskId。电话、微信和地址变更记录必要摘要，限制原值访问，日志避免重复打印完整联系资料和二维码内容。

指标观察首页/品牌成功率、依赖失败、空区块、失效引用、版本传播、缓存失效积压和补偿失败。普通日志不记录授权证据、客户资料、对象 key、签名参数或供应商凭证。

## 8. 跨端缓存和旧链接

公开缓存键至少区分端侧编排、资源、查询条件和公开版本；具体键名、TTL、ETag 和持久化方式待评审。可缓存安全投影，不能以缓存副本替代权威内容、授权或媒体判断。

品牌/联系更新、区块发布或下架、A06 资格失效、A07 下架及媒体撤回应定位受影响首页和详情联系摘要，触发版本更新与缓存失效。即使失效任务未完成，服务端也必须过滤当前已知失效引用。

首页和列表客户端可按 D-602 短时展示标明来源的最近成功缓存并刷新；进入详情必须重新查询或确认版本。服务端返回不可用后清理对应缓存，不能在刷新失败后恢复已经确认撤回的内容。

失败任务有限重试并记录最后错误、次数、目标版本和人工处理结果。人工补偿重新读取当前事实、重建投影并复核，不直接修改授权标志。通知或缓存任务失败不回滚已确认的下架或撤回事实。

旧分享只携带稳定公开 ID；新的分享内容来自当前公开模型。历史卡片、外部缓存和已下载文件可能无法即时清除，须记录可控入口处理和外部跟进结果；不承诺远程删除已到访客设备的副本。

## 9. 数据结构草案

以下是逻辑语义，不是字段、表名或 DTO 的最终清单：

| 逻辑集合 | 候选信息 | 关键约束 |
|---|---|---|
| 品牌资料 | 内部标识、公开标识、正文、媒体引用、资料确认记录 | 单一权威源；必需资料未确认不发布 |
| 联系资料 | 渠道类型、用途、确认值、公开状态、文字地址、联系时间 | 同源读取；无效/未确认渠道不可公开 |
| 内容版本 | 资源引用、内容快照/版本关联、状态、版本、发布时间 | 已发布版本可追溯；候选不覆盖公开事实 |
| 首页区块 | 所属版本、类型、标题、启用、顺序、展示上限 | 有界编排，顺序稳定 |
| 区块引用项 | 目标类型、目标公开 ID、顺序 | 不复制目标事实；发布和读取均校验 |
| 发布与任务记录 | 动作标识、前后版本、影响对象、任务状态、审计摘要 | 本地事务保存意图，外部动作可补偿 |

具体关系、唯一约束候选和迁移要求见 D-502；媒体关联、用途和撤回见 D-503。公开投影只含 D-401 允许字段，不直接序列化以上持久化对象。

## 10. 接口与内部架构草案

### 10.1 对外读取

- `GET /api/v1/public/home`：`PublicHomeDTO`。
- `GET /api/v1/public/brand`：D-401 品牌/联系公开资料语义。
- 统一外层使用 `requestId`、稳定 `code`、`data`、`meta.contentVersion`，具体 API 前缀及字段在 D-401 评审后锁定。

不存在、未发布或下架统一使用 `PUBLIC_RESOURCE_UNAVAILABLE`；参数错误、依赖不可用和响应转换失败分别沿用 D-401 的稳定码，不暴露内部原因。

### 10.2 内部端口和依赖方向

| 语义端口 | 提供方/消费方 | 允许输入输出 |
|---|---|---|
| `PublishedContentReader` | `content` → 查询层、A06/A07 查询编排 | 当前品牌、联系摘要、首页编排和版本 |
| `PublicWorkReader` | A06 → `content` | 按公开 ID 返回当前有效作品摘要，失效项不返回 |
| `PublicCatalogReader` | A07 → `content` | 已发布业务/套餐摘要及版本 |
| `PublicMediaReader` | 媒体能力 → `content` | 已校验、用途匹配的受控公开引用 |
| `PublicProjectionReader` | 查询层 → D-401 adapter | 安全投影，执行当前有效性过滤 |
| `PublicCacheInvalidator` | 查询/任务层 ← 发布与资格变化 | 资源范围、目标版本和幂等失效意图 |

```text
D-401 adapter → 公开查询应用服务 → content 公开读取/编排
                                   → A06/A07/media 只读端口
受控维护适配器 → content 应用服务 → 本模块领域规则与存储
```

同库不等于允许跨模块直接读表；对象存储、缓存和任务设施通过适配层隔离。A06/A07 调用联系读取时不反向触发首页聚合，避免形成查询循环。以上端口是语义约束，不指定最终函数签名。

## 11. 测试和验收

| 验证重点 | 必须证明的结果 | D-702 对应 |
|---|---|---|
| 同一内容源 | 首页、关于和详情联系摘要来源/版本一致 | `S1-CONT-01`、`S1-API-01` |
| 真实性与缺失 | 未确认字段、评价和历史原型值不进入公开结果 | `S1-CONT-02`、`S1-CONT-05` |
| 联系动作 | 电话/微信成功、取消、失败可反馈，业务事实未产生 | `S1-CONT-03`、`S1-CONT-04` |
| 首页引用 | 下架/撤回作品与套餐从首页移除，详情仍重查 | `S1-WORK-03`、`S1-PKG-04`、`S1-API-03` |

| 失败与补偿 | 安全旧版本可保留；撤回信号优先；任务失败可跟进 | `S1-CACHE-03`、`S1-CACHE-05` |

## 12. 阶段开放与待确认问题

### 12.1 阶段范围

| 能力 | 阶段一 | 后续阶段 |
|---|---|---|
| 品牌/首页/联系公开读取 | 开放，匿名只读 | 继承同一事实源 |
| 受控维护、确认、发布和下架 | 作为前置流程落实，不交付管理 UI | 阶段二纳入运营后台 |
| 非公开候选检查 | 受控校验/等价检查 | 后台编辑与预览体验 |
| 公开媒体读取与受控导入 | 按 D-503 | 后续后台素材管理 |
| 官网、复杂推荐、评价体系 | 不作为本阶段交付 | 单独评审 |
| 客户登录、预约、订单、支付、私密交付 | 不开放 | 按各阶段规则设计 |

### 12.2 设计假设与未决事项

设计假设：首版首页采用明确配置的有序引用，安全投影可实时组装或按版本重建；不依赖浏览/成交数据自动推荐。最终持久化形式不影响事实唯一归属和当前资格过滤。

| 待确认项 | 责任方向 | 未确认时处理 |
|---|---|---|
| 权威维护来源、导入/审核/发布/撤回责任 | 工作室负责人、产品与运维 | 作为 D-702 编码前决策；不假定已有后台 |
| 正式品牌、联系渠道、地址、联系时间及首版必需字段 | 内容负责人 | 缺失字段不公开，缺必需资料阻止正式发布 |
| 团队、流程、FAQ 和评价是否纳入首版字段 | 产品与内容负责人 | 可选内容隐藏，不扩展正式 DTO |
| 首页区块上限、引用失效提示和局部失败契约 | 产品、后端与客户端 | 安全过滤；契约评审后实现 |
| 内容版本组合、ETag/TTL 和更新/撤回传播目标 | 架构与运维 | 不填写假定时限，关键参数实现前评审 |
| 联系/品牌高影响变更的复核权限 | 负责人、运营 | 由受控流程明确责任，不以客户端授权代替 |

以上问题保留为评审输入；具体阻塞条件以 D-702 为准，补齐设计文档不能替代经营资料与发布责任确认。
