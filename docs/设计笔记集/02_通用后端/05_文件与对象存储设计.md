# 文件与对象存储设计

> 文档编号：D-205
> 文档状态：评审中（阶段一公开媒体读取草案；已补 S2-A 受控上传/发布设计）
> 适用范围：阶段一公开媒体只读、阶段二 S2 单作品受控上传/衍生/发布/撤回；阶段三私密交付仅保留边界
> 更新日期：2026-10-25
> 上游需求：A05、A06、A15、A16
> 上游架构：AT04、AT08、AT09
> 关联计划：P02/P03（S2）；对齐 P01 阶段一媒体读取及 D-401、D-501、D-601、D-602、D-702

## 1. 设计目标

沿用 Java 21 / Spring Boot / MySQL，媒体元数据在 MySQL、文件在对象存储；不要求 Redis 或消息队列。
阶段一只有匿名公开媒体读取，不交付管理后台、上传工作台、登录、预约、订单、支付、私密交付或正式原图下载。
A15 `delivery` 持有授权事实，A06 `works` 计算作品公开资格，A05 `content` 编排；文件校验完成不等于获得公开资格。

## 2. 文件类别和业务归属

| 类别 | 权威关系与存储 | 阶段一返回范围 |
|---|---|---|
| 原始图片/工作文件 | 媒体登记与业务关联；非公开原图区域 | 不返回字节、key 或下载地址 |
| 作品展示衍生图 | 缩略/预览版本；非公开对象，由 A06 绑定作品 | 网关读取，须当前发布和资格有效 |
| 品牌/套餐媒体 | A05/A07 持有已确认的发布用途和权利依据 | 仅核验后的展示衍生图，不豁免人物授权 |
| 私密交付/授权证据 | A15 持有后续访问边界，独立非公开区域 | 不纳入公开查询或阶段一交付 |

D-501 的 `MediaAsset` 保存内部存储引用；公开 `mediaId` 指向有明确所属资源/用途/版本的读取绑定。
同一文件用于多资源时分配独立公开绑定，不能通过“另一个作品已授权”放行当前作品；引用关系不复制授权事实。

## 3. 上传会话与文件登记

不开放上传会话、预签名上传、浏览器/小程序直传或上传回调接口；首批导入由待确认受控工具/运维流程承载。
维护流程登记候选输入：`ownerModule/ownerRef/purpose/objectRef/objectVersion/checksum/validatedMetadata`；证据与操作责任受限记录。
登记输出 `internalAssetRef/validationState/mediaVersion`；未校验状态不建立公开读取绑定，不以客户端提供的文件名/地址做凭证。
上传、登记、审核/发布和授权核验分别记录；缺少真实素材或权利依据就不发布，不补造样图或授权记录。

## 4. 类型、大小、完整性和安全校验

校验真实文件签名、允许 MIME、大小、尺寸/解码上限和完整性；checksum 以真实字节计算，不把供应商 ETag 一概当摘要。
生成展示衍生图时清除 EXIF/GPS/拍摄者等非公开信息；原图保持非公开，预览不意外返回高分辨率原始文件。
允许类型、压缩、最大尺寸/字节、必要水印和扫描策略上线前确认；不接收任意远程 URL 做抓取源或任意转换参数。
状态候选：`REGISTERED → VALIDATED → BOUND → READABLE`，可转为 `UNAVAILABLE/WITHDRAWN`；`READABLE` 为当前校验结果。
数据缺项、衍生图不存在或摘要/类型不匹配时拒绝对应媒体；不能伪造尺寸、继续旧对象或回退原图。

## 5. 公开媒体与私密成片隔离

原图与展示衍生图都关闭匿名存储读取；凭证、区域/key 和供应商地址仅适配层可见，不写入 D-401 DTO。
作品每次读都经 A06 `PublicEligibilityReader` 消费 A15 `PublicAuthorizationReader` 的当前范围、渠道、用途和有效期结果。
授权、发布和绑定核验使用主库当前事实，不用延迟副本或请求开始前旧事务快照；显式旧绑定版本不匹配返回安全 404。
授权读取超时、未知、未核验、过期或撤回 fail-closed；网关不得从媒体状态、旧投影或缓存中的 `authorized=true` 推断许可。
品牌/套餐若引用作品或人物图片同样执行所属资源的资格/权利检查；无可验证绑定时拒绝，不能只查桶权限。

## 6. 短期访问和下载

候选读取路由为 `GET/HEAD /api/v1/public/media/{mediaId}/{variant}`，`variant` 仅允许 `thumbnail/preview`；不开放 `original`。
`PublicMediaReader.resolve(ownerPublicId, mediaId, purpose) → PublicMediaDTO / 安全失败`，先读绑定、发布、资格和衍生图元数据。
公开字段沿用 D-401：`id/thumbnailUrl/previewUrl/width/height/altText/sortOrder`；URL 由服务端生成，只指向可撤回读取网关。
`ReadPublicMedia(mediaId, variant, publicVersion?) → 有界媒体流/404/503`；ID/版本只是定位条件，不是授权凭证。
流开始前重查所属资源当前公开资格与绑定版本；`HEAD` 同样校验，客户端版本/旧 URL 不能选择历史许可。
网关后端读取私有对象并流式输出，禁止 302 到桶或外发短期签名；签名到期本身不能证明撤回立即生效。
阶段一作品媒体响应 `Cache-Control: no-store`，不支持绕过校验的 304/Range，边缘不缓存；版本协商仍受资格检查约束。
客户端首页/列表/详情/预览/新分享均须二次确认后显示媒体；刷新失败或后台恢复待确认时隐藏旧图，不回退缓存。
撤回提交后新的读取一律拒绝；已发送字节、已下载副本不能远程删除，在途流中止能力与时限需真实验证。

## 7. 孤立对象、重传和一致性检查

`CheckMediaBinding(mediaRef, expectedVersion) → VERIFIED/MISSING/MISMATCH/UNKNOWN`；比对登记、对象版本和衍生图，未知不得公开。
一致性检查由 D-206 有界任务驱动，失败记录原因分类和重试；失效清理未完成也不改变网关当前拒绝结果。
对象已上传但未登记/绑定视为不可公开的孤立对象，进入受限核查；不自动补登记、不推断属于某客户或作品。
重传/替换由受控流程新建媒体版本并重新校验，旧公开绑定失效；不覆盖旧 key 后继续复用已缓存资格。

## 8. 删除、备份、恢复和保留

公开撤回只阻断绑定和展示，不能自动删除原图、私密交付文件或证据；孤立对象删除须独立确认的保留/清理规则。
备份恢复只恢复登记和文件，不自动恢复公开许可；重新核验当前 A15 事实、发布版本和绑定后才能恢复读取。
保留期限、原图/衍生图备份、恢复目标和物理删除责任待确认；不填写假定容量、天数或供应商能力。

## 9. 外部存储适配层

`MediaMetadataReader.find(publicMediaId) → 内部绑定/不存在`；仅按已登记引用寻址，不接受客户端 object key。
`PrivateObjectReader.head(objectRef) → ObjectMetadata`；`open(objectRef, objectVersion) → BoundedStream / StorageFailure`。
供应商类型、权限、重试与一致性语义见 D-405；读取账号最小权限，不提供 list/upload/delete 给匿名查询链路。
不存在/失效绑定映射 `PUBLIC_RESOURCE_UNAVAILABLE`/404；已合格媒体存储失败映射 `PUBLIC_MEDIA_UNAVAILABLE`/503；整体依赖故障为 503 通用码。
参数错误为 `PUBLIC_QUERY_INVALID`/400，转换失败为 `PUBLIC_RESPONSE_INVALID`/500；错误与日志不泄露内部 key、签名或授权证据。

## 10. 权限、审计和测试

- `S1-API-06`：响应仅含白名单字段；直接访问桶、原图/私密路径、伪造 key/URL/变体和跨绑定读取均不可用。
- `S1-WORK-02/03`、`S1-CACHE-02/03/05`：授权超时、到期、撤回、304/旧 URL/缓存命中及失效任务失败均不显示旧作品媒体。
- `S1-WORK-05`：单图存储失败不泄密、不回退原图；验证其余已确认媒体、流中断和有界资源占用。
- `S1-CACHE-04`：替换/检查/恢复任务可重放，旧版本不能恢复公开；记录脱敏 requestId、媒体引用、资格摘要和任务结果。

## 11. 待确认问题

设计假设：首版使用每次校验的媒体网关和非公开衍生图，不用直链 TTL 或 CDN 清理充当安全门槛；本稿尚未实施验证。
一致性复核：D-401 §1、§6–7 与 D-602 §2.3、§7–9 已明确作品媒体 `no-store`、展示前资格二次确认、待确认隐藏旧图及失败不回退旧图；原“先显示缓存/自然过期待同步”的冲突备注已过时，撤销该待办。这是设计正文对齐结论，不表示媒体网关或客户端行为已实现验收。资源级未知安全拒绝；授权依赖整体故障导致无法可信计算时按 D-401 返回 `PUBLIC_SERVICE_UNAVAILABLE`/503，不伪装成功空列表。
真实作品、人物授权/监护关系、导入工具、发布与撤回责任、品牌/套餐媒体权利依据上线前确认，缺失一律不公开。
供应商私有读/对象版本/摘要能力、生产域名、小程序图片与预览缓存行为、流中止和撤回目标需实测确认，不能虚构承诺。

## 12. 演示实现检查点

当前由 PublicMediaService 协调发布/资格与 MediaObjectStore，FileMediaObjectStore 读取私有预制对象；无 JSON 媒体适配器、远程来源或运行时绘图。请求在缓冲前后复核当前资格及发布，核对 canonical root/长度/SHA-256；只提供 thumbnail/preview，GET/HEAD 同资格，no-store/nosniff，Range 拒绝。显式演示准备与真实素材责任、媒体数据模型和恢复演练见 D-503/D-504。代码实现不证明真实权属、EXIF 清理或生产撤回协议已经验收。

所有公开 JSON 当前也采用 no-store，以简化演示更新；普通文字的缓存是未来可选优化，不是当前已实施能力。素材导入、EXIF/GPS 清理、真实主体授权、供应商及真机/在途流行为仍按前文评审验证；不能直接把原图放进媒体根目录。参见 `docs/开发与演示/阶段一演示运行指南.md`。

## 13. 阶段二 S2-A：单作品上传、校验与衍生图（设计补充，待编码验证）

本节把阶段一“没有管理上传接口”的边界扩展为 S2 的显式、本地隔离工作流；不追溯扩大阶段一接口，不意味着真实上传/授权/存储已接入。

### 13.1 入口与文件接受规则

- 仅允许已登录后台经同源 HTTPS、Origin/CSRF 和 `CONTENT_EDIT` capability 调用服务端上传；一个请求只收一个文件，使用受限 `multipart/form-data`。不提供浏览器/小程序直传、预签名 URL、任意远程 URL 抓取、回调或客户端指定对象 key。
- MIME 和文件名均是提示，不是证据。先限制请求字节，再核对 JPEG/PNG 签名、真实解码器格式、长宽/像素和完整性；损坏、伪装、超限、超像素、解码失败的输入拒绝且不建立可发布绑定。
- S2 本地合成测试 profile 采用有界上限（单文件 4 MiB、边长不超过 8192、像素总数不超过 24 MP）；这些仅是隔离测试资源上限，不是经营/生产接收策略。2B 必须依据存储、容量与处理器实测另行配置，缺省不得悄悄放大上限。
- 仅生成固定的 `thumbnail`/`preview` 两种展示衍生图；重解码/编码清除 EXIF、GPS 与不在公开输出范围内的元数据。不接受客户端传入转换参数，不生成/提供 `original` 公开变体。水印和恶意软件扫描供应商能力仍待 2B 评审；S2 synthetic profile 不可冒充扫描通过。

### 13.2 对象与状态

媒体状态为 `RECEIVING → PROCESSING → READY`，或 `REJECTED / FAILED_RETRYABLE / WITHDRAWN`。只有 `READY` 且两种受支持衍生物、字节数、尺寸与 SHA-256 均已验证的 asset 才能绑定作品。原件与衍生图均放在非公开存储；key 为服务器生成的随机内部引用，API、DTO、审计与普通日志不暴露 key、桶地址或签名。

文件对象写入先于作品发布的 MySQL 事务，两者不假装原子：处理失败/数据库失败时最多留下不可读取的私有孤儿对象；清理须确认没有 canonical、当前发布或保留版本引用。绝不通过数据库失败后的“补发 URL”、原图兜底或旧版本缓存恢复公开。

### 13.3 S2 隔离测试边界

2A 仅使用合成生成图及专用可销毁本地对象根；测试模拟明确标记为 `TEST_SYNTHETIC` 的 A15 判定输入，不写入真实授权证据或真实主体资料。后台 UI/API 不提供授权事实新建、编辑、补证或法律撤回入口。正式媒体后端、扫描、备份/保留责任、真实作品与人物授权和平台缓存行为属于 2B 门禁；任何未配置/未知依赖都 fail-closed。
