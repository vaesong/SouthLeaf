# 通知与任务补偿设计

> 文档编号：D-206
> 文档状态：评审中（阶段一可编码草案）
> 适用范围：阶段一公开投影/缓存/媒体补偿；客户通知后置
> 更新日期：2026-10-08
> 上游需求：A04、A10、A13-A16
> 上游架构：AT06、AT08、AT09
> 关联计划：P01；对齐 D-401、D-501、D-601、D-602、D-702

## 1. 设计目标

沿用 Java 21 / Spring Boot / MySQL，以 MySQL 持久任务和进程内定时调度支撑恢复，不要求 Redis 或消息队列。
阶段一对外匿名只读；内部任务记账不交付管理后台、上传工作台、登录、预约、订单、支付、私密交付或客户通知。
A15 `delivery` 持有授权事实，A06 `works` 计算资格，A05 `content` 编排；补偿任务不能替任一模块修改事实或授予公开许可。

## 2. 通知任务模型

阶段一任务类型候选：`PUBLIC_PROJECTION_RECHECK`、`PUBLIC_CACHE_INVALIDATE`、`PUBLIC_MEDIA_BINDING_CHECK`，不发送预约/支付/交付消息。
内部任务字段：`taskId/eventId/type/resourceRef/targetVersion/causeRequestId/idempotencyKey/state/attempt/nextRunAt/leaseUntil/leaseOwner/leaseEpoch/lastErrorKind`。
`TaskIntentWriter.append(ChangeIntent) → taskId / PersistenceFailure`；输入为变化类型、范围及源版本，不接受客户端任务请求。
`TaskRepository.claimDue(now, leaseOwner, limit) → 有界任务批次`；使用 MySQL 条件更新/行锁领取，事务完成后执行外部读。
`TaskExecutor.execute(TaskContext) → APPLIED/NOOP/RETRY/MANUAL`；结果附脱敏原因和核验版本，不把不确定结果写为完成。
任务模型在 MySQL 中持久化，状态变更必须校验租约 epoch；批量大小、租约和调度间隔为上线待确认参数。

## 3. 业务事实与通知生成

受控维护流程由所属模块在本地事务内保存发布/下架/撤回事实、审计和任务意图；数据维护工具尚待确认。
事实提交即影响下一次公开读取；不得等通知、投影重建、缓存清理或任务成功才停止已撤回作品及媒体。
任务领取/失败不回滚业务事实；若任务意图无法落库，不报告维护成功，并走受控阻断/故障处理流程。
A15 变化触发 A06 重算，A06 输出当前资格后 A05 重新编排引用；通过端口读取，不直接跨模块改表。
公开请求永远重查当前发布/资格；持久投影、缓存布尔值和任务 `SUCCEEDED` 都不是授权凭证。

## 4. 渠道、模板和接收人

阶段一“通知”仅指内部变化处理及脱敏故障待办，默认用运行日志/审计记录，不承诺已有短信、邮件或订阅消息供应商。
接收人是待确认的工作室/运维责任角色，不从匿名浏览推导客户手机号、微信身份或设备关联。
若后续接入运维告警，输出仅任务引用、失败类型、等待时长和内部排查入口；不携带作品原图/授权证据/签名 URL。
客户通知模板、订阅授权、预约/订单接收人和发送结果均留到后续阶段，不加入阶段一公开字段。

## 5. 幂等、重试和失败

唯一键候选为 `type + resourceRef + targetVersion + effectScope`；重复意图返回既有 taskId，不重复生成版本或审计事件。
任务至少一次执行：完成更新前崩溃允许重放；失效操作幂等，重建只发布与当前事实/版本一致的安全投影。
执行前经所属模块端口读取主库当前授权/发布/绑定事实，不用延迟副本或旧事务快照；目标已过时进入 `NOOP/SUPERSEDED` 或重核最新版本，不用旧载荷还原许可。
投影替换通过 `PublicProjectionWriter.replaceIfCurrent(expectedVersions, safeProjection) → APPLIED/STALE`，原子比对当前版本后生效。
完成/失败落库及投影写入都防止旧租约执行者越权覆盖；版本变更或租约丢失终止该次写入，过期投影不能复活作品。
可恢复读取超时/连接失败有限退避加抖动；次数、总预算和间隔配置化，达到上限转人工，不无限循环。
资格未知 fail-closed：不生成媒体引用或带旧图投影；依赖暂不可用可重试，明确撤回按当前事实安全失效。

## 6. 支付/退款/文件/授权任务

| 阶段一用例 | 输入 | 输出与失败路径 |
|---|---|---|
| 重核公开投影 | 资源/影响范围、目标版本 | 当前合格引用；UNKNOWN 阻断该资源，依赖故障重试 |
| 失效公开缓存 | 资源范围、目标版本 | 清理结果/NOOP；失败仍由读时校验阻止旧媒体 |
| 检查媒体绑定 | 媒体引用、预期版本 | VERIFIED/MISSING/MISMATCH/UNKNOWN；缺失或未知不公开 |
| 人工重放 | taskId、处理人受限引用、原因 | 新尝试/无需处理；重读事实，不编辑授权布尔值 |

支付查单、退款、订单过期、私密交付到期、网盘补交和客户发送任务不在阶段一实施；不生成相应业务事实。
D-205/D-405 约束媒体可撤回网关及非公开原图；任务不能改为公共桶、直链或原图兜底。

## 7. 人工补偿和升级

`ReplayFailedTask(taskId, expectedState, operatorRef, reason) → ACCEPTED/NOOP/CONFLICT` 为内部受控用例，不提供匿名或后台产品接口。
阶段一可由待确认运维流程执行；查看日志/重放权限与授权事实维护权限分开，操作保留审计摘要。
先核验当前发布、授权和媒体绑定，再清理/重建；无法确认时继续阻断，不以“处理完成”人工放开未知资格。
持续未知或达到次数/龄阈值升级责任人；责任方和处理时限尚未确认，不能声称通知已送达或故障已闭环。

## 8. 任务状态、超时和告警

状态候选：`PENDING → RUNNING → SUCCEEDED`；失败转 `RETRY_WAIT → RUNNING` 或 `MANUAL_REQUIRED`，过时转 `SUPERSEDED`。
`RUNNING` 必须有有界租约；进程重启/租约到期可条件领取，记录新 epoch，防止同任务无界并发执行。
成功仅表示当前任务效果已核验；公开权限始终由读时事实确定，后续撤回不受此前成功状态限制。
告警观察待执行龄、重试/人工数量、资格未知和流故障；日志/告警失败不恢复已下架内容，不泄露敏感载荷。

## 9. 权限、隐私和审计

公开响应仅 D-401 白名单及 requestId，不返回 taskId、接收人、内部原因、授权证据、存储 key 或供应商签名。
任务状态仅内部使用；公开读取沿用 `OK/200`、`PUBLIC_QUERY_INVALID/400`、`PUBLIC_RESOURCE_UNAVAILABLE/404`、`PUBLIC_SERVICE_UNAVAILABLE/503`、`PUBLIC_MEDIA_UNAVAILABLE/503`、`PUBLIC_RESPONSE_INVALID/500`，不新增任务错误码或暴露重试状态。
后台/运维查询与存储凭证受限隔离；任务载荷只存引用/版本，不复制客户资料、原图地址或授权原文。
脱敏审计用 eventId 与尝试引用防重复，记录处理人、目标版本、结果；保留/查询规则见 D-204。
服务端及客户端旧作品媒体须二次确认后显示；304/CDN/失效任务失败均不得绕过网关和当前资格读取。

## 10. 测试和验收

- `S1-CACHE-04`：重复/乱序意图、重复执行和投影 CAS 冲突不生成重复事实，不恢复旧版本。
- `S1-CACHE-05`：任务失败、进程崩溃、租约到期、旧执行者回写和人工重放均可追踪且有界恢复。
- `S1-WORK-02/03`、`S1-CACHE-02/03`：授权读取未知、撤回与重建并发、清理失败仍拒绝所有新旧媒体入口。
- `S1-STATE-08`、`S1-API-06/07`：安全局部降级不伪装空态，公开字段和脱敏 requestId 正确，无阶段外通知/写接口。

## 11. 待确认问题

设计假设：MySQL 本地任务意图、租约和版本比对足以支撑首版，不要求独立调度平台；本稿未声称现有实现具备这些能力。
D-602 先展示旧缓存须收紧作品媒体规则；D-401 局部失败表达、任务意图的真实维护入口需由主代理统一确认。
真实数据发布/授权核验/撤回责任、操作身份、任务龄/次数/退避/租约与人工处理时限在上线前确认，未确认不补造。
媒体存储供应商、真实超时与恢复行为、告警渠道及网关撤回时限须实测；任务补偿不承诺删除已下载副本。
