## 1. 权限判定分层

```text
认证当前会话及账号
  → 显式能力判定 AdminAccessPolicy（默认拒绝）
  → 业务模块的资源范围及当前状态校验
  → 事务内复核安全版本/权限和业务约束
  → 执行业务动作，写审计及可靠任务
```

前端隐藏按钮不构成授权；认证成功不等于可以访问所有对象；能力词表不拥有预约确认、订单快照或公开授权资格的业务规则。

## 2. 首批技术能力词表

| 能力 | 作用边界 | 不隐含的能力 |
|---|---|---|
| CONTENT_READ | 查看管理内容 | 私密客户资料、公开发布 |
| CONTENT_EDIT | 编辑内容草稿 | 发布、授权核验 |
| CONTENT_PUBLISH | 请求发布/下架 | 绕过媒体和当前授权资格 |
| PUBLIC_AUTHORIZATION_REVIEW | 记录核验结果 | 自动成为权利人或给客户私密交付资格 |
| PUBLIC_AUTHORIZATION_REVOKE | 执行公开授权撤回流程 | 删除私密交付文件 |
| RESERVATION_READ | 读取允许范围的预约 | 确认占档、读取所有客户资料 |
| RESERVATION_CONFIRM | 调用统一确认成单动作 | 绕过冲突、幂等或快照校验 |
| RESERVATION_CANCEL | 调用取消流程 | 退款执行或改写取消责任 |
| RESERVATION_RESCHEDULE | 调用修订改期流程 | 覆盖历史快照或先释放旧档 |
| ORDER_READ | 读取允许范围的订单 | 改价、改快照、标记已付款 |
| AUDIT_READ | 脱敏审计查询 | 修改/删除审计或导出全部个人信息 |
| STAFF_ACCESS_MANAGE | 受控人员权限管理 | 无审计自我提权或默认绕过复核 |

枚举只定义技术能力，不代表对应管理接口已实现；实际角色映射未批准，不在代码中给任意账号默认全权。

## 3. 当前内核

AdminPrincipal 仅携带当前账号 ID 和不可变能力集合，不携带 token/密码/客户资料。AdminAccessPolicy 对缺失身份、缺失能力及空集合返回 false；编辑不自动包含发布，账号名称不产生特权。

SessionService 每次通过当前存储事实重新获取权限。不复用先前请求的 principal 作为长期权限缓存。正常权限变更须递增 securityVersion，使旧会话失效；即使漏增，当前权限减少仍不能通过下一次能力核验。

## 4. 资源与状态策略（未来各业务切片落实）

- 客户只能查询自己的预约和订单，参与人不自动取得联系人权限；手机号、对象 ID 或前端缓存都不是归属证据。
- 内容发布需当前资格、媒体状态和版本一致；历史发布回退不恢复已撤回授权。
- 预约确认需当前状态合法和排他占档；线下录入不绕过同一事务。
- 改期先成功占新档再释放旧档，保留原约定和修订；取消不等于付款/退款成功。
- 摄影师只看分配范围的必要资料，不默认具有确认、改价、激活尾款或发布权限；是否启用该角色后续确认。
- 系统任务与回调使用受限系统身份，不模拟工作人员；任务具备幂等、来源及审计。
- 对象存储凭据不是业务访问授权，直连存储不得绕过服务端资格。

## 5. 敏感操作与错误

后续人员权限修改、授权核验/撤回、发布、确认/取消/改期应保存操作者、目标、动作、关键前后状态、时间、结果及 requestId；不记录 bearer token、密码或不必要的联系方式。

会话无效统一认证失败；身份有效但能力不足为禁止操作。对象不属于可见范围时按资源契约隐藏存在性。HTTP 状态及稳定错误 DTO 在管理接口切片实现，当前纯内核不映射 Web。

审计失败不得留下敏感业务已成功但无审计的结果。当前只实现端口要求，不宣称已完成审计存储或不可篡改能力。
