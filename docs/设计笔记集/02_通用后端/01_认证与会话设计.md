# 认证与会话设计

> 编号：D-201；日期：2026-10-24；状态：会话内核/JDBC 与 S1-C1 纯凭据核心/KDF 已验证；C2 的 JDBC 凭据/认证事件/非 Web 接线已在独立管理范围验证，但完整公开回归仍阻断；C3 纯生命周期/V4 迁移文本/CLI grant 策略实现进行中，独立 CLI JDBC 与 HTTP 未实现。
> 范围：阶段二；上游：A08/A10/A11/A16、AT04/AT07/AT09；关联：[P02](../../计划/P02_阶段二目标与实施计划.md)、[ADR-003](../08_决策记录/ADR-003_阶段二管理安全与公开读取隔离.md)。

## 1. 职责与身份隔离

公开浏览不登录。客户身份由独立客户模块持有，正式微信身份在 2B 验证；后台账号不会通过微信客户身份或手机号同名获得权限。当前已实现后台会话内核及未接线的凭据核验核心，不声称运行中的后台已支持密码登录或客户登录。

后台 Account 是最小安全投影：稳定内部 accountId、enabled、securityVersion、显式 permissions。不含姓名、手机号、密码或业务客户资料。权限集合防御复制且不可变。

## 2. 会话模型与生命周期

Session 持有 tokenDigest、accountId、securityVersion、issuedAt、expiresAt；原 token 不进入存储端口。SHA-256 摘要为 64 位小写十六进制；token 使用 JDK SecureRandom 的 32 随机字节及无填充 Base64URL，43 字符。

- 尚未签发 → 凭据核验成功并捕获安全版本 → 原子检查版本/启用状态、存储会话及审计 → 返回签发结果。
- 活跃 → 到绝对截止时间失效，截止点本身无效；不因请求滑动延长。
- 活跃 → 显式撤销当前会话；重复撤销不泄露是否存在。
- 账号禁用、删除、版本变化 → 后续请求认证失败；重启不会自动生成或续签会话。
- 令牌畸形、未知、过期、版本不匹配、账号不匹配对调用者统一为 AdminAuthenticationException，不暴露具体原因。

应用内核允许 1 分钟到 8 小时配置，当前核心测试使用 2 小时；不是生产配置已完成。时间来自注入 Clock，签发和截止截到微秒，持久化按 UTC 保存，与 DATETIME(6) 精度一致。

## 3. 应用与端口

`AdminSessionService` 依赖 `AdminSessionStore`、`SessionTokenCodec`、Clock；不依赖 Web、Spring、JDBC、文件系统或公开读模型。

| 用例 | 前提/输入 | 输出及失败 |
|---|---|---|
| openForVerifiedCredentials | 只限可信凭据核验流程调用；accountId 和当次验证捕获的版本 | 仅一次向安全响应提供原 token 和截止时间；账号改变/停用拒绝；存储失败不返回 token |
| authenticate | 请求提取的 token；先做定长字符校验 | 同一数据库视图内加载当前会话及账号，检查摘要绑定、启用、版本和时间，返回当前 principal |
| revoke | token | 定向撤销及审计；重复/未知不泄露信息；存储异常不能当作成功登出 |

签发结果 toString 隐去 token；这不是允许将完整响应、Cookie 或领域对象随意记录日志。原 token 仅通过未来安全 Cookie 写入浏览器，内部参数不得接受不可信客户端的“已验证账号”。

## 4. 持久化契约（本批已实现适配器）

`createIfAccountCurrent`：账号启用且版本匹配才创建；与审计同事务；摘要唯一冲突必须报错，禁止覆盖旧会话。凭据验证到签发之间发生重置应拒绝。

`findCurrent`：读取未撤销会话、当前账号及权限，一致性视图，不用旧缓存/副本。账号/会话缺失为空；依赖异常向上抛出。JdbcAdminSessionStore 已按端口实现，真实 MySQL 测试覆盖事务、约束、审计回滚和版本竞争，不拿内存 double 当作持久化验收。

`revoke`：未知/已撤销幂等，无意义重复不刷审计；有效撤销与审计原子提交。清理过期会话应按保留策略执行，不在认证时偷偷重置表。

## 5. 凭据与 HTTP（C1 核心及 C2 非 Web 接线已实现；HTTP 未实现，不允许提前开放）

- 采用受维护自适应密码 KDF；禁止以普通 SHA-256 处理密码。
- 账号初始化为显式受控工具，不提供默认密码、不自动建管理员。
- 登录失败统一提示、限制尝试速率并记录脱敏安全事件；密码验证失败无论账号是否存在都走一致策略。
- 同站后台安全 Cookie，HttpOnly、Secure、SameSite=Strict、host-only；结合 Origin/CSRF 校验，登出使用受保护 POST。不存 localStorage，不经 URL 传递，不使用通配凭据 CORS。
- 最终路由、状态码、响应 DTO、Cookie Path、安全头、限流和密码策略在 HTTP 切片冻结并测试；当前没有管理 Controller 或安全 Bean。

## 8. S1-C 凭据与账号生命周期设计（C1/C2 已实现；C3 未实现）

本节的核心/维护库由 C1 实现，JDBC 凭据、认证事件与非 Web 组合由 C2 实现；账号 CLI 和 HTTP 仍是待实施契约，具体界线见第 13–14 节。C2 仍受公开回归阻断，不能以源码/管理范围结果提前关闭。技术选型见 [ADR-004](../08_决策记录/ADR-004_阶段二分批交付与后台安全闭环.md)，执行顺序见 [P03](../../计划/P03_阶段二分批交付与编码执行计划.md)。

### 8.1 内部端口与依赖

| 端口/用例 | 输入/输出 | 责任 |
|---|---|---|
| CredentialLookup | accountId → 可选凭据快照（hash、enabled、securityVersion） | JDBC 查询，不返回密码；不向 HTTP/UI 暴露 hash |
| PasswordVerifier | 原密码、版本化 hash → match/upgradeRequired | 维护库 KDF adapter；不在 domain 里引用库类型 |
| AdminLoginService | 有界原始凭据 + 脱敏请求上下文 → IssuedSession 或统一失败 | 查凭据、KDF 核验、调用现有版本重检签发用例；不接收客户端 verifiedVersion |
| AuthenticationEventSink | C1：白名单类型、可空已知内部 accountId、可信 UUID requestId、时间 | LOGIN_DENIED / CREDENTIAL_UPGRADE_REQUIRED；append 必须成功或抛错；eventId 由未来持久化 adapter 生成；限流类型待 S1-D |
| AccountLifecycleCommands | 已授权运维上下文、命令 ID、目标与预期版本 → 确定结果 | 首次初始化、改密、禁用、显式权限变更；仅受控 CLI |

凭据快照只在可信应用路径短暂存在，toString/日志不包含 hash。所有 adapter 显式接线。账号 CLI 不依赖 admin-runtime；它与 runtime 共享 KDF 实现时新增专门 crypto 模块，不让 core 依赖技术库。公开应用不得包含这些依赖。

### 8.2 账号标识与密码

S1 使用既有 `admin_account.account_id` 作为显式分配的后台登录标识（新账号限定 3–64 位 ASCII 字母/数字/点/下划线/连字符，大小写敏感）；登录沿用既有内部标识最短 1 位的兼容性，核心同一校验器补入点号；新建最短 3 位由 C3 策略执行。不拿手机号、客户 ID 或显示名推断账号。UI 不 trim/转小写后默默换账号；错误格式统一凭据失败。未来别名登录另加唯一映射和迁移。

密码按原值验证，不裁剪、不 Unicode 归一化。初始化/重置要求 15–128 个 Unicode code point，UTF-8 最多 512 字节，允许空格和粘贴；不用强制大小写/符号组合或周期性改密代替长度和泄露密码阻断。使用有来源、版本化的本地常见/泄露密码拒绝表，不把密码发送外部 API。登录只做长度/字节上界约束，不把后来新增的创建策略套到历史密码验证。

KDF 为维护库 Argon2id，最低参数见 ADR-004。`credential_hash` 保存带算法/参数版本的编码；解析仅允许受支持算法及有界参数，未知、畸形或超出安全资源上限的 hash 拒绝并报警，不降级到明文或普通 SHA-256。16 字节随机盐由库生成，不以 accountId 作盐。

S1 不在登录时偷偷重写 hash：runtime 账号无 UPDATE 权限。upgradeRequired 记录为受控运维待处理，升级经账号命令完成并递增 securityVersion、撤销旧会话资格。后续无感 rehash 必须单独设计权限与竞争语义。

### 8.3 登录竞态与失败语义

1. S1-D HTTP adapter 先检查大小、Origin/CSRF、外部限流，生成可信请求上下文；C1 的 KDF adapter 自身也必须实施跨实例共享的并发预算，不能只依赖 HTTP 层。
2. 读取账号凭据快照。格式不符的账号、未知或禁用账号执行固定当前 profile 的 dummy 验证；旧 profile 的耗时可能不同，不能宣称消除了时间侧信道；有效/无效密码、未知/禁用账号对外统一 401/INVALID_CREDENTIALS。仅做近似时间等价，不承诺网络恒定时间。
3. 在数据库锁外进行 KDF，避免高成本计算持有账号行锁。验证成功捕获的 securityVersion 必须由现有 `createIfAccountCurrent` 在事务内重检。
4. 版本改变/账号禁用时统一失败，不自动绕过重检重试。签发与 ADMIN_SESSION_OPENED 审计仍使用同一事务。
5. 事务成功后才写 Cookie；依赖/审计失败返回 503，不发 token。不要把未知提交结果盲目重放成成功；本批无登录幂等键，响应丢失可能留下到期前有效但客户端未取得的会话，后续登录不复用其 token，须以限流和会话保留策略约束。

失败事件通过独立短事务写入新增认证事件表；不写不存在账号作为假 actor，不存原密码/token/全 Cookie。认证依赖或事件存储故障统一 503，不伪装“账号不存在”。成功签发事件不异步外发；最小审计失败仍回滚。观测日志只记录 requestId、分类和指标。

### 8.4 受控账号管理与权限

不提供默认 admin、自动 seed、公开注册或 HTTP 账号重置接口。首次账号初始化采用独立 CLI + 独立最小权限数据库身份，要求显式动作、目标环境、账号标识和显式 capability 集；不得把某个角色名解释为所有权限。

- 密码仅经受控交互终端/秘密输入通道提供，不作 argv、脚本常量、普通配置或 stdout 内容；CLI 无可用安全输入时失败，不回退默认密码。
- 首次初始化通过 singleton bootstrap guard 行锁和持久化完成标识保证一个 schema 仅成功一次，账号、权限、完成标识及审计同事务提交；重复调用返回明确冲突，不能重置已有账号。
- C3 拟定锁序：所有账号变更先锁 singleton guard，再锁目标账号，检查 expectedSecurityVersion；guard 串行化首次初始化及最后可用维护账号保护；修改事实并使 securityVersion 加一，审计同事务。对同一版本的并发操作只有一个成功；再次启用不恢复旧版本会话。
- CLI 凭据与 runtime、migrator 分开。CLI 不是用户自称 actor 即可执行的后门：授权由受控主机访问和专属数据库身份保证，审计记录可信运行身份的非秘密标识、命令 ID、原因码及目标。
- 保留账户停用与历史审计，不提供硬删；最后可用维护账号被禁用/移除维护权限的保护规则及恢复 SOP 必须在 S1-C 实施前写入运维用例。Q06 未确认不开放真实角色映射，测试能力集显式声明。

命令 ID 与请求摘要持久化，重复同 payload 返回原结果，同 ID 不同 payload 拒绝；摘要不能直接哈希低熵密码并保存，秘密部分采用受控密钥 HMAC 或把重试明确限制为不携带秘密的结果查询。详细 CLI 参数、唯一约束、锁序和恢复验收属于 S1-C 编码前 G1，不在 S1-A 预先实现。

## 9. 增量表与授权演进（C2 已迁移；C3 为设计候选）

V2 的账号/权限/会话/会话审计表保持不变。凭据使用已有 `credential_hash`；既有会话审计表仅允许 OPENED/REVOKED 且 session_id 非空，不能硬塞登录失败或账号管理事件。

C2 已增加 V3 `admin_auth_event`：`event_id`、`occurred_at`、白名单 `event_type`、可空已知内部 `actor_account_id` 与可信 `request_id`。它只承载 `LOGIN_DENIED` 和 `CREDENTIAL_UPGRADE_REQUIRED` 等认证事实，不存输入账号、IP、UA、密码、hash、token 或 C3 命令结果；当前 runtime 只获得该表的精确 `INSERT`。已分配 V1–V3 绝不修改或重用。

C3 在 G1 锁定后才新增后续迁移（不预占号、不覆盖 V1–V3）：

- `admin_account_command`：命令 ID、操作类型、目标、预期/结果安全版本、非秘密结果与脱敏审计事实；与账号变更同事务。包含秘密的创建/改密不得把低熵密码、普通密码哈希或可离线猜测的请求摘要写入本表。
- `admin_bootstrap_guard`：固定单例主键、完成状态/时间、首次命令 ID，以及可供“最后可用维护账号”规则在同一锁域判断的最小非秘密事实；由显式迁移准备初始行，CLI/runtime 都不得自动补建。

字段长度、FK/UNIQUE/CHECK、保留期、命令结果 schema、命令 ID 的唯一性和迁移版本在 C3 G1 锁定；无生产默认保留期；2A 可用显式测试配置验证清理工具，生产保留政策在 2B 确认。

授权版本分开：S1-B/C2 runtime 保持会话四表与 `admin_auth_event INSERT` 的实际精确矩阵，仍不写账号/权限/命令/guard 表。账号 CLI 才拥有 C3 实际 SQL 所需的精确账号更新和命令/guard 写入能力；每条 SQL 与 grants 单独建表对照并做正反测试。CLI、runtime 与 migrator 不能共享 DataSource 或数据库身份。

## 10. HTTP 安全与资源预算（S1-D）

具体接口/状态码以 [D-403](../04_接口与外部契约/03_后台管理接口.md) 为准。维护框架处理 Cookie CSRF；核心仅处理 actor/session，不自己实现 Web 过滤器或加密 CSRF 协议。

2A 单实例登录限流基线（技术配置，可收紧）：账号标识键每 5 分钟 5 次、可信来源地址每 5 分钟 30 次、全进程每分钟 120 次；每次登录尝试都计数，不因账号是否存在改变规则。键有界且 5 分钟过期，最大 10,000 键，容量满对新键 fail-closed，不驱逐仍有效键来绕过限流。先做边缘/全局/来源限制，再做账号限制和 KDF；KDF 同时最多 2 个，忙时 429 + Retry-After，不无限排队。

限流状态只驻留内存且键不落日志；可信代理列表之外忽略 Forwarded/X-Forwarded-For，不能信任客户端自报 IP。实现需定义 IPv6/代理归一化、时钟回退与并发原子计数测试。拒绝后的恢复有界，不永久锁账号，不泄露账号存在。重启会重置限流、多实例不共享额度是明确限制，生产拓扑必须重新评审。

请求体上限 4 KiB、仅 JSON、重复 JSON 字段拒绝。限制在 KDF 前执行；格式错误不回显输入。Cookie/session 绝对有效期 S1-D 技术默认 2 小时，允许 1 分钟到 8 小时显式配置；不滑动续期。HTTP error body 无 stack trace、schema、grants、hash 或原 token。

## 11. S1 认证验收与未关闭项

必须覆盖：密码边界与 Unicode 原值、dummy 路径、KDF 有界参数/资源耗尽、同账号限流、跨账号全局限流、改密/禁用与签发两种提交顺序、初始化并发、同命令重放、审计故障、CSRF/Origin、Cookie 标志、退出旧 token 失效、401/403/429/503 的 UI 区分。

## 12. 未来扩展边界

后续账号别名、MFA、自助改密/找回、会话设备管理和多实例限流都走独立端口/切片，不预建空接口。客户身份始终单独设计；内容/预约业务写命令仍须在执行时检查资源/状态权限，不把 HTTP 层认证当成永久授权。

## 13. C1/C2 实施契约与证据（2026-10-24）

C1 实现 `CredentialLookup`、`PasswordVerifier`、`PasswordHasher`、`AuthenticationEventSink` 和 `AdminLoginService`，未接线 runtime/JDBC。登录输入为账号、char[]、可信 UUID；快照 ID 必须匹配查询键。KDF 锁外运行，匹配后只用快照版本进入原 Store 重检；失败事件/升级提示不能吞写入异常，升级提示不意味着签发成功。登录复制数组并 finally 清理，调用方负责原数组。坏密码统一拒绝；损坏 hash、容量不足、错误快照和存储故障仍是依赖失败。

独立 `admin-credential-crypto` 使用 Spring Security crypto 7.1.1、显式 Spring Core 7.0.9、bcprov-jdk18on 1.86。新 hash 固定 Argon2id v19/m65536/t3/p1/salt16/hash32，仅兼容校验 m19456/t2/p1；PHC 严格规范 Base64、固定参数白名单，禁止在线 rehash。共享静态预算最多 2、无队列；同一应用 classloader 内生效，不跨 JVM。库内部 String/char[] 副本不能承诺即时擦除。`hash` 不替代未来创建密码策略。

234 单元/架构 + 42 真实 MySQL IT、29 独立权限回归、24 打包启动负向通过；crypto 5 包/公开 52 包独立 OSV 均零命中；负载和全部限制见 [C1 指南](../../开发与演示/阶段二S1-C1凭据核心与KDF验证指南.md)。

C2 的运行候选 SHA 为 `b97bb404affd3333e7de681e62b100ce5eb0aa3bc31ce2426a1835b46da62ac4`。独立管理范围 199 单元/架构 + 35 真实 MySQL IT、39 私有运行时/权限/认证场景均通过，测试实例正常关闭；V1/V2 与旧运行基线未漂移。因既定公开测试入口不可达，完整状态仍是 `BLOCKED_PUBLIC_REGRESSION`；C3、HTTP 与生产未完成。详见 [C2 指南](../../开发与演示/阶段二S1-C2凭据持久化与接线验证指南.md)。

## 14. C3 编码前 G1（设计已细化；源码实现已单独启动）

C3 的对象是**独立受控 CLI**，不是管理 HTTP 后门，也不是对 runtime Writer 增加账号 UPDATE。用户已明确要求继续推进阶段二，故已创建独立 C3 任务开展源码、迁移文本与静态/单元验证；这不授权真实数据库/身份/grant 操作，不解除 C2 的公开回归阻断，也不开放 HTTP。下列输入是 C3 实现及后续真实验证前必须维持的可审阅契约：

1. **命令与结果。** 冻结 `bootstrap`、`change-password`、`disable-account`、`replace-permissions`（以及仅在需要时显式 `enable-account`）的非秘密参数、命令 ID、预期安全版本、稳定结果码和只读结果查询。命令 ID 重复且同一非秘密摘要时返回原结果；同 ID 不同操作/目标/版本拒绝。秘密命令不能通过保存普通 hash 来“比较重试”。
2. **秘密输入与拒绝表。** CLI 仅接受受控交互终端或等价的非回显秘密通道；argv、环境变量、普通配置、脚本常量、stdout、错误回显和诊断报告均不得承载密码。无安全输入能力立即失败。创建/重置执行 15–128 Unicode code point、UTF-8 ≤512 bytes、原值验证及版本化本地泄露/常见密码拒绝表；拒绝表来源、版本、离线更新/审计和无法加载时的 fail-closed 语义必须冻结。
3. **事务和锁。** 每次账号事实变更按 `bootstrap_guard → target account` 的固定锁序，验证 expectedSecurityVersion；账号、权限、命令结果、guard 事实和最小审计在一个事务提交。并发同版本只有一个成功；改密/禁用/权限缩减均递增版本，不恢复旧会话资格。
4. **最后维护账号与恢复。** 维护账号定义为“enabled 且持有 `STAFF_ACCESS_MANAGE`”；任何命令不得把数量降为零。恢复仅走同一专属身份和受控 CLI，预先写明失去所有维护账号、命令未知提交、拒绝表/秘密通道故障的离线 SOP、责任和双人复核要求；不制造默认超级管理员。Q06 未确认前只允许显式测试 capability 集，不推断真实角色。
5. **迁移与最小授权。** 先按第 9 节冻结 C3 表/约束/索引和每条 SQL，再编写 CLI 专用 grants。运行身份、CLI 身份和迁移身份互斥；不得使用 root、schema/global 通配、role、GRANT OPTION 或共享池。
6. **真实测试与退出。** 映射 D-703 `S1C-03` 到 `S1C-07`：两连接 bootstrap 竞争、同命令重放、同版本冲突、改密/禁用后旧会话拒绝、审计回滚、CLI/runtime/migrator 授权反例、argv/日志秘密扫描。仅在用户另行授权的隔离实例运行，失败和 skip 不得计为通过。

2026-10-24 的 C3 源码增量已将独立 `admin-account-cli` 加入 reactor：它实现严格 allowlist argv、console-only 双次秘密输入、独立配置/TLS URL/`CURRENT_USER()`/精确 grant verifier、verified pool、显式 main 和 guard→account JDBC 生命周期事务。其命令事实不保存秘密 fingerprint；bootstrap/change-password 重复需改用结果查询；非秘密命令只允许相同 canonical SHA-256 fingerprint 重放。模块单元、子进程负向和依赖/产物边界检查已通过，但 verifier/store **从未在有效数据库配置上运行**；真实 TLS/identity/grant/并发/迁移验证仍为待授权的 D-703 S1C-03..07，不能据此宣布 C3/S1/C2/生产完成。
