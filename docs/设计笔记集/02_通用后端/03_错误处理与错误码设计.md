# 错误处理与错误码设计

> 文档编号：D-203
> 文档状态：评审中（阶段一可编码草案）
> 适用范围：阶段一匿名只读公开展示；后续阶段仅保留边界
> 更新日期：2026-10-08
> 上游需求：A08、A10、A14、A15、A16
> 上游架构：AT09
> 关联计划：P01；对齐 D-401、D-501、D-601、D-602、D-702

## 1. 设计目标

Java 21 / Spring Boot / MySQL 沿用既有基线，不要求 Redis 或消息队列；对外只开放匿名公开读取。
不交付管理后台、上传工作台、登录、预约、订单、支付或私密交付；内部审计/补偿记录不构成公开写能力。
A15 `delivery` 持有授权事实，A06 `works` 计算公开资格，A05 `content` 编排；错误处理不能修改任何事实。

## 2. HTTP 状态与业务错误码

| 稳定码 | HTTP 草案 | 客户端语义与处理 |
|---|---:|---|
| `OK` | 200 | 成功；真实空列表仍为成功 |
| `PUBLIC_QUERY_INVALID` | 400 | 参数无效，修正请求或返回 |
| `PUBLIC_RESOURCE_UNAVAILABLE` | 404 | 不存在、未发布、撤回、到期或资格未知统一不可用 |
| `PUBLIC_SERVICE_UNAVAILABLE` | 503 | 必需依赖暂不可用，允许主动重试 |
| `PUBLIC_MEDIA_UNAVAILABLE` | 503 | 资格已确认但媒体读取失败，单项重试 |
| `PUBLIC_RESPONSE_INVALID` | 500 | 服务端转换失败，通用提示；客户端解析失败使用同名本地状态 |

部分媒体失败时，已通过校验的 JSON 仍为 `OK`/200，失败图片由独立媒体读取返回错误；不新增私有局部成功码。
必需封面不可用时不能填充假图片或违背 D-401 非空字段；过滤该条目或按必需依赖失败处理，具体区块策略待共同评审。

## 3. 统一错误响应结构

沿用 D-401 外层：`requestId`、`code`、安全 `message`、`data`、`meta.serverTime/contentVersion/nextCursor`。
错误时 `data=null` 或省略，不返回旧作品/媒体；没有安全公开版本时省略 `contentVersion`，不暴露授权版本。
响应头只允许必要协议字段和 `X-Request-Id`；堆栈、SQL、客户资料、授权原因、供应商及存储 key 均不输出。
成功媒体流输出受控类型和字节；开始发送前失败可用统一 JSON，发送后失败终止流并记录，不能混写错误 JSON。
错误与作品媒体响应使用 `Cache-Control: no-store`；错误不参与 ETag/304 协商。

## 4. 参数校验与字段错误

校验公开 ID、白名单筛选/排序、分页上限、媒体变体及请求大小；拒绝任意对象 key、URL、SQL 排序和授权结论输入。
公开错误只描述契约参数名，不回显非法值；字段错误数量有上限，不输出持久化字段或完整请求体。
`PublicErrorMapper.map(FailureKind, RequestContext) → (httpStatus, ErrorEnvelope)` 为统一异常转换端口。
Spring MVC 参数绑定、校验、应用失败和适配器异常进入该端口；非约定写方法由路由返回通用 405，不进入业务服务。

## 5. 业务状态冲突

只读公开查询不引入预约/订单冲突码或登录挑战；资格是服务端结果，不能通过重试写操作“恢复公开”。
`PublicEligibilityReader.check(workId, mediaId?, channel, purpose, now) → ELIGIBLE/INELIGIBLE/UNKNOWN + 内部版本摘要`。
A06 经 A15 `PublicAuthorizationReader.readCurrent(workId, mediaId?, channel, purpose, now) → VALID/INVALID/UNKNOWN + 内部事实版本` 读取授权事实。
授权与发布核验使用主库当前事实，不用延迟副本或旧事务快照；超时、缺失、过期快照、范围/主体未核验均不得形成 `ELIGIBLE`。
单资源否定或未知统一 404；授权或资格 UNKNOWN 按 fail-closed 处理。列表过滤单项不合格，依赖整体故障无法完成查询时返回通用 503，不能伪装成真实空结果。

## 6. 外部服务错误和未知结果

`ReadPublicDetail(workId) → 当前公开 DTO / 404 / 503`；返回前校验当前发布和资格，不信任缓存里的授权布尔值。
`ReadPublicMedia(mediaId, variant, publicVersion?) → 网关媒体流 / 安全错误`；每次读取重查绑定、资格和变体，禁止重定向原图。
对象存储超时/拒绝/未知在内部分类；客户端只得稳定公开码，不使用原图、网盘链接或上次成功地址兜底。
重试有超时预算和次数上限；只重试可安全重复的读，不把未知结果当成功，不在请求内无限等待补偿任务。

## 7. 客户端、后台和日志分层

客户端按 `code` 分支，不解析供应商文案；日志保存脱敏内部原因，后续后台诊断不加入阶段一公开 DTO。
旧作品媒体未经服务端二次确认不得显示，包括首页/列表封面、详情、预览和新分享；弱网刷新失败不能恢复旧图。
重新进入或从后台恢复先隐藏待校验媒体；收到不可用清理缓存，无网络保留骨架/文字安全提示，不能以缓存命中代替资格。
服务端响应缓存和条件请求也先核验当前资格；不得通过 304、CDN、旧 URL 或任务失败绕过撤回。

## 8. requestId、taskId 和追踪

请求入口生成长度有界的不透明 `requestId` 并贯穿异常和媒体读取；外部传入值不直接作为可信日志字段。
异步任务关联 `causeRequestId/taskId`；`taskId`、授权标识和原始原因只在内部，不作为公开查询参数或权限凭证。
日志/审计端口由 D-204 提供；记录失败不改变拒绝公开结论，关键事实操作的审计持久化规则见 D-206。

## 9. 错误码版本和兼容

沿用 D-401/D-602 的六个公开码；Java 枚举和映射表集中维护，不把异常类名作为契约。
本稿明确媒体单项 503、转换失败 500 的映射候选；D-401 现有 200/503、500/503 多义需同步评审后锁定。
内部原因可增补而公开语义不变；新增字段/码需联合客户端评审，不直接复用后续支付、授权管理或私密交付错误。

## 10. 测试场景

- 对应 `S1-API-04/05/06/07`：非法参数、枚举草稿/撤回/未知均得到安全响应，不包含敏感字段。
- 对应 `S1-WORK-02/03/05`：授权读取超时、撤回、单图故障及网关流中断分别拒绝、下架、单项失败。
- 对应 `S1-CACHE-02/03/05`：缓存命中/304/旧媒体请求、二次确认失败和失效任务失败均不能显示旧作品媒体。
- 对应 `S1-STATE-04/05/08`：有界重试、转换异常及部分区块失败不产生假空态、假图或请求风暴。

首批真实内容、授权核验与撤回责任、必需封面/区块策略未确认；缺失不以原型数据替代，正式上线前补齐。
