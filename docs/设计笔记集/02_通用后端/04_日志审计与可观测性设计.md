# 日志审计与可观测性设计

> 文档编号：D-204
> 文档状态：评审中（阶段一可编码草案）
> 适用范围：阶段一匿名只读公开展示；后续审计保留扩展边界
> 更新日期：2026-10-08
> 上游需求：A10、A14、A15、A16
> 上游架构：AT04、AT07、AT08、AT09
> 关联计划：P01；对齐 D-401、D-501、D-601、D-602、D-702

## 1. 设计目标

Java 21 / Spring Boot / MySQL 提供请求、资格校验、媒体网关和补偿任务的可追踪证据，不要求 Redis 或消息队列。
阶段一匿名 API 只读；日志和任务记账为内部设施，不交付管理后台、上传工作台、登录、预约、订单、支付或私密交付。
A15 `delivery` 的授权事实、A06 `works` 的资格结果和 A05 `content` 的编排版本分别记录，日志不能成为第二套事实源。

## 2. 运行日志

使用结构化日志：`time/level/event/requestId/routeTemplate/status/code/durationMs/module/resourceRef/outcome`。
`resourceRef` 使用不透明公开 ID 或受控内部引用；路由用模板，不写完整 URL、查询串、响应体、图片字节或供应商原始报文。
`RequestObservation.record(ReadObservation) → 接受/丢弃计数`；输入为有界脱敏字段，输出不影响公开查询资格或 DTO。
每次请求一条摘要；正常拒绝公开不打印堆栈，系统异常按受控规则记录异常类型和诊断编号，重复故障避免日志风暴。
媒体记录 `mediaRef/variant/bytesSent/streamOutcome`，存储读取前失败与发送中断区分；内部原图 key 不作为日志标签。

## 3. 业务审计

受控维护流程记录发布、下架、授权核验/撤回、媒体替换和人工重放；浏览请求只记运行摘要，不逐次制造业务审计事实。
`AuditWriter.append(AuditEvent) → auditId / PersistenceFailure`；输入含 `eventId/action/actorRef/resourceRef/fromVersion/toVersion/time/result`。
`actorRef` 指内部操作责任引用，授权证据仅记录受限证据引用；不写证据原文、客户姓名、家庭关系或联系方式。
关键事实与审计、任务意图在所属模块 MySQL 本地事务中持久化；维护方式仍待确认，不在公开 API 增加审计写入口。
审计使用唯一 `eventId` 防重复、追加式存储和受限账号；应用账号不得修改/删除历史，具体表结构仍为候选。
无法持久化关键记录不得报告维护成功；撤回处理失败先按受控流程关闭受影响公开读取，不能依靠日志代替阻断。

## 4. 安全事件

记录资格未知仍试图读取、媒体绑定/变体不匹配、跨对象引用、非法路径、异常请求量和原图暴露检测的脱敏摘要。
授权读取超时/不确定按 fail-closed：拒绝受影响作品及媒体；单项与整体故障按 D-203 映射 404/503。
公开码沿用 `OK`、`PUBLIC_QUERY_INVALID`、`PUBLIC_RESOURCE_UNAVAILABLE`、`PUBLIC_SERVICE_UNAVAILABLE`、`PUBLIC_MEDIA_UNAVAILABLE`、`PUBLIC_RESPONSE_INVALID`，观测故障不新增公开码。
事件观察不把拒绝变为放行；告警、日志或缓存清理失败都不恢复授权、不回滚已确认撤回。
客户端/代理日志一并执行脱敏；不创建匿名访客账号、设备指纹或跨设备画像，网络标识只在必要防护边界有界处理。

## 5. requestId、traceId 和 taskId

入口生成不透明 `requestId` 并关联成功/错误；不直接信任外来标识，去除控制字符并限制所有结构化字符串长度。
Spring 请求上下文向网关和只读端口传递；任务携带 `causeRequestId/taskId/eventId/targetVersion`，执行另建追踪上下文。
`traceId` 为可选内部诊断标识，单体不要求独立链路系统；客户端只接收 D-401 的 `requestId`。
异步执行完成清理线程上下文，防止串请求；任务 ID 不进入公开 DTO，不作为媒体资格或权限凭证。

## 6. 脱敏和敏感信息边界

| 信息 | 处理规则 |
|---|---|
| 公开响应 | 仅 D-401 白名单；媒体含 `id/thumbnailUrl/previewUrl/width/height/altText/sortOrder`，URL 指向网关 |
| 授权/客户 | 不记证据原文、内部撤回原因或客户数据；受限审计引用与普通运行日志分离 |
| 凭证/存储 | 不记 Authorization、Cookie、密钥、签名串、原图 key、完整供应商地址和网盘链接 |
| 外部异常/输入 | 归一错误类型，参数不回显；控制字符过滤，长度/字段数量有上限 |

媒体原图和展示衍生图均在非公开存储；日志排障不允许临时开放桶、打印可下载原图地址或给访客供应商凭证。

## 7. 指标、健康检查和告警

指标候选：请求数/错误率/延迟、资格 `UNKNOWN` 数、媒体读取失败/中断、待执行任务龄、重试和人工待办数。
标签只用路由模板、公开码、模块和失败分类；`requestId/taskId/resourceRef` 不作高基数指标标签。
存活检查验证进程；就绪检查验证必需配置/数据读取能力，存储探测有超时预算，不输出连接串、桶或凭证。
若授权读取不可用，受影响入口拒绝读取并告警；部分资源失效不等同整站故障，就绪状态不能代替逐次资格校验。
管理健康详情/指标仅内部受限网络可读，公共端不暴露 Actuator 明细；告警接收人/渠道和阈值上线前确认。

## 8. 日志/审计保留与查询

运行日志滚动输出并限制磁盘使用，审计在 MySQL 持久化；阶段一不要求日志平台、管理检索页面或用户通知供应商。
日志按 `requestId`，审计按受限资源引用/事件 ID，任务按 `taskId` 关联；查询和导出仅由运维授权流程执行。
保留期、容量、备份、恢复和清理责任未确认，不填写假定天数；审计清理由独立保留流程执行并记录处理证据。

## 9. 故障排查路径

`requestId → 请求摘要 → 资格结果/版本 → 媒体流结果 → taskId/审计事件`，只追踪元数据，不重放敏感请求体。
`DiagnosePublicRead(requestId) → 脱敏故障摘要/关联任务` 为内部用例；不存在面向匿名客户的诊断查询接口。
缓存复现必须检查二次确认：未确认不得显示旧作品媒体，304/网关缓存不能跳过资格；清理任务失败仍拒绝已撤回资源。
输出中区分真实空结果、资格拒绝、依赖故障、媒体故障；记录可控入口处理结果，不声称清除了设备既存副本。

## 10. 测试和验收

- `S1-API-06/07`：成功、拒绝和媒体中断均可关联 requestId，日志/响应不出现敏感字段或原图地址。
- `S1-WORK-02/03`、`S1-CACHE-03/05`：授权读取未知、撤回、缓存命中和任务失败均保留拒绝证据且不显示旧图。
- `S1-CACHE-04`：重放审计/任务不重复生成事实；并发请求和线程复用不串 requestId/actorRef。
- 验证异常注入、日志盘满/输出失败、审计持久化失败与指标标签基数；就绪检查不泄密、不触发无限探测。

## 11. 待确认问题

设计假设：结构化日志、MySQL 追加审计和内部指标足以支撑首版；当前仅设计，没有声称真机或故障演练已通过。
D-602 的旧缓存展示表述须收紧至作品媒体二次确认；本稿只记录矛盾，不修改客户端/索引/决策记录。
真实维护/撤回责任、首批授权证据、告警接收方、保留期限和恢复目标须由负责人确认，未确认数据不伪造。
存储供应商诊断字段、日志设施和小程序生产环境需实测确认；公开读取持续性目标与撤回传播目标不可凭空填写。
