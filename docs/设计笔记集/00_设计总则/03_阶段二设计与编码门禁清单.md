## 1. 范围与完成口径

阶段二按 P02 分 2A 基本功能 S0–S6、2B 真实接入/上线 S7。阶段三单独管理支付/退款、完整履约/售后、私密交付等，不作为阶段二的隐含验收。

“文档设计完成”表示 P02 相关模块边界、主数据与状态、命令/查询契约、事务与并发、UI 状态、异常补偿、测试和运维接口有可追溯的方案；所有未决经营规则均显式标门禁。它不表示实现已完成、表结构已迁移、生产账号已开通、真实业务策略已批准或可部署。

## 5. 从文档到编码的门禁

### 5.1 开始某一工作包编码前

- 对应业务/接口/客户端/测试文档已完成并互相链接；相应 open questions 已经确认，或者实现被明确限制在不触碰该决策的边界。
- D-104/D-105 模块依赖、组合根、artifact 打包、脚本和测试迁移方案一致；建立旧 public-api 基线/可回退方案。
- DB 表与索引有数据分级、owner、读写用例、唯一约束、保留期、迁移和最小权限矩阵；V1 保持不可修改。
- 每个写命令有 actor/授权、幂等、并发版本、事务边界、审计、外部副作用与错误结果定义。
- 每个 API 有身份、输入校验、资源归属、DTO、幂等键/乐观锁、错误和兼容策略；管理与客户 cookie/CSRF/CORS 不混用。
- 负向安全和数据库集成测试覆盖有路径，目标 MySQL 8.4/InnoDB 与 JDK/Maven 配置明确；Mock/H2 不代替数据库锁/权限验证。

### 5.2 实现完成（不等于可上线）

- 单元/应用用例、MySQL 集成、架构隔离、API 契约、E2E/可访问性和数据权限测试有可重现结果。
- migration 仅在明确授权的隔离测试库跑；失败/重跑/回滚路径验证；不操作生产数据库。
- `get_problems` 无新增 errors/warnings；`get_changes` 审核本工作包变更；构建产物中公开应用不含 admin runtime/security/write adapter、管理应用不含 public controllers/root。
- 失败和部分成功（媒体孤儿、通知重试、外部 provider timeout、事务结果未知）有运营可观察状态和修复手册。

### 5.3 2B 部署/真实数据门禁

生产部署另需用户明确授权，并完成真实账号/域名/证书/API 回调、DB grants 与独立迁移身份、备份恢复演练、审计留存和负责人、故障告警、回滚与数据恢复、真实素材授权、隐私政策/客户沟通及支付/退款规则确认。本清单绝不授权创建账号、迁移、部署或发送通知。

## 6. 阶段三排除项

阶段二不默认为实现：支付/定金/退款/对账、完整订单履约状态机、售后与纠纷、私密交付/高权限下载/数字水印、客户聊天、营销自动化、实际收集真实儿童影像。它们需在阶段三拆独立工作包，增加新的数据分级、用户同意、支付对账、访问授权、审计和安全验收。
