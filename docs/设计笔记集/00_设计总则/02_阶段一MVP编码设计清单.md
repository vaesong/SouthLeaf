## 1. 目的与当前结论

本文把 P01 阶段一范围转成进入编码前必须完成的详细设计工作项，作为设计协作者的任务入口和评审检查表。它不替代各模块设计文档，也不锁定最终数据库结构、生产 API 或部署参数。

当前结论：阶段一小程序前端首批源码已经落地，但尚不能宣称阶段一端到端验收完成。当前交付包含四 Tab 页面、公开查询适配层、列表/详情路由、加载/空/不可用/错误状态、媒体失败占位和电话/微信外部联系入口。后端公开数据源、公开 DTO 最终字段、受控媒体网关、正式 HTTPS 域名和目标微信构建仍需联合验收。工作室管理后台、内容 CRUD、媒体上传工作台和客户业务流程不属于阶段一 MVP 交付。

阶段一产品范围以 P01 第 3 节为准。阶段一面向客户的主入口是小程序；品牌官网、客户业务身份、预约、订单、支付、私密成片交付和工作室管理后台属于后续阶段或另行确认的运维能力。

## 2. 阶段一 MVP 边界

### 2.1 必须设计并交付

- 小程序公开浏览：品牌首页、作品与案例、六类摄影业务、已发布套餐、工作室信息和电话/微信联系入口。
- 小程序页面任务：首页、作品列表与详情、业务/套餐列表与详情、关于/联系；不保留“我的”客户业务入口。
- 只读公开查询：品牌内容、作品、摄影业务、套餐和必要的公开媒体读取；查询结果只包含已发布且满足公开资格的内容。
- 公开授权安全：公开案例默认不公开；查询前检查 A15 提供的公开授权资格；授权未核验、撤回或资格失效时阻止返回或触发下架处理。
- 阶段一通用后端最小能力：匿名公开访问、查询参数校验、稳定错误响应、requestId、日志与必要审计、运行配置、缓存失效和公开媒体读取。
- 阶段一质量保障：小程序关键状态反馈、公开内容资格、媒体读取失败、下架/旧链接、授权撤回联动、网络恢复和重试验收。

六类摄影业务必须都能在内容模型和展示路径中表达：儿童、亲子全家福、婚纱、写真、孕照、证件照。未确认的价格、套餐细节和经营承诺不得由设计或示例数据伪造。

### 2.2 数据维护与发布前置

阶段一不交付工作室人员使用的管理后台，因此必须在编码设计中单独明确公开数据如何产生、审核、发布、更新和撤回。该维护方式可能由已有工具、受控数据导入、人工运维流程或后续阶段后台承载，但在设计评审前不能假定某一种方式已经确定。

必须满足以下约束：

- 小程序不得把品牌、作品、套餐和联系方式长期作为正式事实硬编码；本地 mock 只能用于开发和测试，并与生产数据隔离。
- 公开查询只读取已进入公开数据源的内容；草稿、内部备注、未发布价格、内部媒体地址和未满足授权资格的作品不得返回。
- A15 持有公开授权事实；A06 消费授权结果并计算案例公开资格；A05 负责公开内容编排。作品模块不另存一份可覆盖 A15 的授权同意/撤回事实。
- 数据更新、下架和授权撤回后的缓存失效、旧链接处理和小程序刷新结果必须可验证。
- 公开数据维护责任人、首批真实数据、审核证据和发布责任必须记录为阶段一实现前置或运维确认项。

### 2.3 阶段一明确不开放

- 工作室管理后台登录、后台内容 CRUD、媒体上传工作台、草稿预览和后台发布操作；
- 正式预约申请、固定档期、预约确认、订单、支付、退款和线下收款核验；
- 客户业务账号和客户订单；
- 私密成片交付、下载、家庭成员授权及完整交付工作台；
- 预约、订单、支付、售后等阶段二/三后台运营功能；
- 多工作室、多租户、会员、积分、优惠券和复杂营销。

阶段二、三可以保留目标架构设计入口，但不能把后续能力做成阶段一可用功能，也不能让阶段一为了暂未开放功能承担不必要的完整实现。

## 3. 设计工作包与现有文档

设计协作者按以下顺序完善现有 D 文档。文件当前多为章节骨架，完成状态必须按实际内容和评审记录更新，不得仅因文件存在就视为完成。

### A. 总体设计与规则

- `01_总体设计/01_总体模块与依赖设计.md`：明确阶段一小程序调用链、模块事实归属、公开授权资格来源和依赖方向。
- `01_总体设计/02_阶段开放与能力矩阵.md`：区分阶段一开放、只设计不开放、完全后置的能力，明确不把后台产品列入阶段一交付。
- `01_总体设计/03_跨模块用例与事务边界.md`：补充公开查询、作品公开资格计算、授权撤回后下架和缓存失效等跨模块用例；不引入预约、订单或支付事务。
- `00_设计总则/01_领域术语与规则归属.md`：补齐阶段一关键术语、授权与公开资格的唯一事实归属。

### B. 小程序前端

- `06_客户端/小程序/01_客户任务与路由.md`：明确首页、作品、业务、套餐、关于/联系等页面和任务入口、导航、深层入口及返回路径；移除“我的”作为 MVP 功能入口。
- `06_客户端/小程序/02_状态反馈与接口消费.md`：定义公开查询消费方式及加载、空数据、下架、内容不可用、网络失败、服务异常、重试和恢复反馈。
- `06_客户端/小程序/03_身份、支付与交付体验.md`：标明阶段一不触发客户登录、支付和交付流程；保留未来阶段边界，不提前实现。

阶段一小程序验收应能从首页抵达全部公开内容，清楚展示六类业务和已发布套餐；联系动作只打开电话/微信联系，不创建预约事实。

### C. 阶段一后端公开支撑

- `02_通用后端/03_错误处理与错误码设计.md`：定义公开查询统一响应、稳定错误码、requestId、可公开提示和内部诊断信息边界。
- `02_通用后端/04_日志审计与可观测性设计.md`：覆盖公开查询、授权资格检查、下架联动、缓存失效和失败处理；日志不得记录客户私密信息或内部媒体地址。
- `02_通用后端/05_文件与对象存储设计.md`：限定阶段一公开媒体读取、缩略图/预览引用、替换/下架和存储失败处理；不得把公开媒体能力误作私密交付。
- `02_通用后端/07_配置与密钥设计.md`：区分运行配置、公开数据源配置和敏感凭证，明确各环境隔离及客户端不可获得服务端凭证的规则。
- `02_通用后端/06_通知与任务补偿设计.md`：仅设计阶段一确有需要的授权撤回下架、缓存失效和公开数据异常任务；明确失败记录、重试和人工处理入口，不强行引入无业务价值的通知渠道。

阶段一不要求工作人员登录、后台角色权限或后台管理接口可用。认证、后台权限和完整管理审计仍属于目标架构及后续后台阶段输入；如果公开数据维护工具复用既有身份体系，只能作为运维前置，不得扩展为小程序 MVP 的客户功能。

### D. 阶段一业务模块

- `03_业务模块/01_内容与品牌设计.md`：内容类型、公开版本、下架和首页编排；将后台编辑操作标记为后续维护入口或运维流程，不列入小程序交付。
- `03_业务模块/02_作品与案例设计.md`：案例、图片集合、分类与标签、排序、公开资格消费和撤回后处置；作品模块不另存授权同意/撤回事实。
- `03_业务模块/03_摄影业务与套餐设计.md`：六类业务、套餐和服务项的展示信息、价格说明、公开版本及未确认信息的阻断。
- `03_业务模块/08_成片交付与授权设计.md`：本阶段只补足公开案例授权资格读取、查询阻断和撤回联动；私密交付完整设计仍归阶段三，不纳入阶段一 MVP。

### E. 接口、数据和测试

- `04_接口与外部契约/01_公开查询接口.md`：小程序所需的公开内容、作品、业务和套餐读取契约，以及发布状态、公开资格、下架和旧链接处理。
- `04_接口与外部契约/03_后台管理接口.md`：阶段一不实现；保留为阶段二工作室运营后台的设计入口，不得作为 MVP 编码前置。
- `04_接口与外部契约/05_对象存储与网盘契约.md`：只细化阶段一公开媒体读取所需契约；不假定供应商字段，不把网盘交付带入阶段一。
- `04_接口与外部契约/06_通知渠道契约.md`：仅在阶段一确有授权撤回或数据异常通知需求时细化；否则记录本阶段不启用及后续触发条件。
- `05_数据与存储/01_领域对象与数据归属.md`、`02_关系数据模型草案.md`、`03_文件与媒体数据模型.md`：形成阶段一公开展示必要的数据草案并标注待评审项，不提前锁定最终表结构。
- `07_测试与验证/01_设计级测试策略.md`、`02_模块验收场景.md`、`04_外部服务故障与补偿测试.md`：覆盖阶段一范围、公开资格、公开内容、媒体读取、下架、旧链接、故障恢复和验收证据。

客户业务接口、支付回调、并发预约、私密交付、退款接口和后台管理 CRUD 不是阶段一编码前置项；仅当阶段一实现依赖目标架构约束时，引用其上游规则，不要求提前锁定实现细节。

## 4. 设计输出要求

每个适用的设计文档至少给出：

1. 目标、范围和明确不做事项；
2. 事实归属、调用方、主要用例及正常/异常路径；
3. 领域对象与生命周期；
4. 输入、输出、权限、错误和审计要求；
5. 接口/内部端口草案及兼容边界；
6. 领域模型、持久化模型、API DTO、客户端展示模型的区分；
7. 阶段一涉及的查询一致性、缓存、文件和补偿边界；
8. 可验证的测试场景、验收条件和未决问题；
9. 设计假设、责任人/确认角色以及需要回看的条件。

数据库和 API 字段可以在设计中提出草案，但未评审前必须显式标记为草案。不得以客户端传入的公开状态、授权结论、角色、文件地址或发布状态作为服务端最终事实。

## 5. 推荐推进顺序

```text
阶段范围/术语/模块事实归属
  → 小程序客户任务、页面和路由
  → 小程序状态反馈与公开接口消费
  → 公开查询、发布状态和授权资格接口草案
  → 内容、作品、套餐与公开授权资格用例
  → 阶段一数据/媒体草案
  → 通用后端错误、日志、缓存和下架联动设计
  → 测试与故障补偿场景
  → 跨文档一致性检查和设计评审
  → 锁定阶段一实现所需公开查询契约
  → 开始阶段一编码
```

公开数据维护方式必须在设计评审中形成明确决策：由现有运维工具、受控导入流程或后续后台承载。无论采用哪种方式，小程序只消费公开查询结果，不直接承载维护权限。

## 6. 进入编码的评审门槛

开始阶段一业务代码实现前，必须全部满足：

- 阶段一功能范围与 P01 一致，客户侧只有小程序公开展示；官网、管理后台、预约、订单、支付和私密交付没有被隐式加入；
- 小程序页面/路由、内容路径、关键状态反馈和电话/微信联系路径可验收；
- 公开数据源、维护责任、发布方式、更新方式和授权撤回后的下架机制已明确，或已记录经确认的安全运维替代方案；
- 六类摄影业务可表达，未经确认的套餐与价格信息不会被当作事实；
- 公开案例授权资格的唯一来源、查询过滤、撤回联动和下架处理明确；
- 公开查询接口草案、必要数据模型草案、媒体读取流程和客户端展示模型已相互一致；
- 权限边界、错误提示、日志脱敏、媒体不可用、重复请求、缓存陈旧和发布/下架失败有明确处理路径；
- 阶段一模块验收和关键端到端测试均有可执行预期结果；
- 高影响未决项已由相应业务/隐私/技术责任角色确认，其他假设均有记录；
- 产品范围、后端/架构、客户端、隐私安全和测试验收评审意见已记录；阶段一实现所需设计状态达到“已确认”，需冻结的公开查询契约达到“已锁定”。

只有上述门槛完成后，才更新推进索引为“开始阶段一实现”。设计骨架本身、单篇文档完成或技术选型已有结论，都不能单独作为开工批准。

## 7. 当前实现记录

截至 2026-10-11，前端源码已按本清单的阶段一客户侧边界完成首批落地：

- `frontend/pages.json` 已收敛为“首页 / 作品 / 服务 / 关于”四个 Tab，不注册“我的”；
- `frontend/api/api.js` 负责公开响应解析、稳定错误码、`requestId`/`meta` 保留和网络/超时映射；
- `frontend/api/public.js` 负责 `HomeViewModel`、`WorkViewModel`、`BusinessViewModel`、`PackageViewModel`、`AboutViewModel` 的公开 DTO 适配；
- 首页、作品列表/详情、服务列表/套餐详情、关于页均不再维护历史作品、价格、活动日期、客服号码或地址示例；
- 作品和套餐详情只传递公开 ID 并重新查询，业务筛选使用服务端 `businessId`；
- 页面已覆盖加载、成功空数据、内容不可用、网络/服务错误和媒体失败占位路径；
- 套餐详情保留“套餐内容 / 温馨提示 / 拍摄须知”三个公开展示区块。

以下状态不能标记为已验收：

- 后端当前仍未提供与 `frontend/api/public.js` 一致的 `/api/v1/public/*` 公开查询实现；
- `frontend/unpackage/dist/dev/mp-weixin` 仍是旧编译产物，包含历史“我的”Tab 和旧硬编码内容，不能作为当前源码构建证据；
- `frontend` 没有标准 `package.json`/可直接调用的 uni-app CLI，HBuilderX 目标构建尚未执行；
- 真实品牌、作品、套餐、联系方式、公开授权资格、受控媒体网关和正式 HTTPS/合法域名尚未提供或确认。

## 8. 当前未决问题

- 阶段一公开数据由何种既有工具或受控流程维护，谁负责审核和发布；
- 公开授权证据在阶段一由何种既有流程收集、由谁核验，以及公开查询需要读取哪些最小资格字段；
- 阶段一图片公开读取格式、大小、压缩/缩略图规则和公开媒体存储契约；
- 内容、作品、套餐和联系方式的首批真实数据由谁提供并确认；
- 是否需要阶段一授权撤回或数据异常通知；若需要，渠道与接收人是谁；
- 小程序正式 HTTPS 域名、合法域名配置、缓存策略和发布环境尚未锁定。

这些问题可在设计中列出安全默认值和替换点，但不得由设计文档伪装成已确认经营事实。
