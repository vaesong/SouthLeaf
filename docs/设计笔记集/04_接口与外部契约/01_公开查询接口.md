# 公开查询接口

> 文档编号：D-401
> 文档状态：评审中（阶段一公开查询草案）
> 适用范围：阶段一为主；阶段二、阶段三继承公开查询边界
> 更新日期：2026-10-09
> 上游需求：A05-A09、A15、A16
> 上游架构：AT04、AT09
> 关联计划：P01

## 1. 设计目标

为阶段一微信小程序提供匿名、只读、可撤回的公开查询能力；普通品牌、业务和套餐文字投影可短时缓存，作品媒体使用 `no-store` 并在展示前复核当前资格。接口只返回已经进入公开数据源、满足发布条件且具备 A15 公开授权资格的内容，不承担内容编辑、媒体上传、后台认证、预约、订单、支付、客户身份或私密交付。

本文字段和路径均为设计草案。评审完成前不视为生产 API 兼容承诺，也不锁定现有后端控制器、数据库表或供应商字段。

## 2. 公开资源范围

允许公开查询的资源：

- 品牌与工作室公开资料；
- 首页公开编排和精选区块；
- 已发布作品/案例及公开媒体；
- 六类摄影业务及其公开说明；
- 已发布套餐及服务项、适用人群、时长、价格说明和注意事项；
- 电话、微信、地址和工作时间等已确认联系资料。

禁止公开查询的资源：

- 草稿、待审核、内部备注、后台任务和未发布版本；
- 客户姓名、联系方式、订单、预约、支付、交付和家庭成员资料；
- 公开授权证据原件、撤回原因、内部审核人和授权内部标识；
- 未确认价格、内部成本、未发布促销和历史测试数据；
- 原始存储 key、私密媒体地址、未受控签名和供应商凭证。

公开资格是服务端派生结果，不接受客户端传入的 `published`、`authorized`、`visible` 或媒体地址作为最终依据。

## 3. 内容、作品、业务和套餐查询

### 3.1 接口草案

| 用途 | 方法与路径草案 | 说明 |
|---|---|---|
| 首页聚合 | `GET /api/v1/public/home` | 返回首页品牌摘要、精选作品、业务摘要、套餐摘要和联系摘要 |
| 品牌资料 | `GET /api/v1/public/brand` | 返回品牌、工作室、联系方式和工作时间 |
| 作品列表 | `GET /api/v1/public/works` | 支持业务、标签、游标/页码和数量限制 |
| 作品详情 | `GET /api/v1/public/works/{workId}` | 重新校验公开资格后返回详情 |
| 摄影业务列表 | `GET /api/v1/public/businesses` | 返回六类业务的公开摘要和已发布套餐概况 |
| 摄影业务详情 | `GET /api/v1/public/businesses/{businessId}` | 返回业务公开说明及可公开关联信息 |
| 套餐列表 | `GET /api/v1/public/packages` | 支持 `businessId`、游标/页码和数量限制 |
| 套餐详情 | `GET /api/v1/public/packages/{packageId}` | 返回已发布套餐公开详情 |

实际前缀、版本和路径命名应与现有工程接口规范统一，但不应把前端当前的 `localhost` 地址写入接口契约。

### 3.2 公共响应外层草案

```json
{
  "requestId": "req_xxx",
  "code": "OK",
  "message": "",
  "data": {},
  "meta": {
    "serverTime": "2026-10-06T10:00:00Z",
    "contentVersion": "public-version-xxx",
    "nextCursor": null
  }
}
```

错误响应仍使用同一外层，`data` 为空或省略；`message` 只用于通用提示，客户端必须按稳定 `code` 分支。服务端日志通过 `requestId` 关联诊断信息。

```text

```

`thumbnailUrl` 和 `previewUrl` 只能是 SouthLeaf 生成的受控媒体网关引用，用于按 `mediaId`、变体和所属公开资源重新读取当前结果；URL 本身不是授权凭证。禁止返回或重定向到供应商直链、公共桶地址、永久签名地址、原始对象 key、私密签名参数、内部供应商信息或未发布媒体。

## 4. 发布、下架、授权撤回和旧链接

查询流程必须在服务端完成以下判断：

```text
资源存在
  → 公开版本已发布
  → 内容未过期/未下架
  → A15 公开授权资格有效
  → 关联媒体绑定及用途有效
  → 生成公开 DTO 和 SouthLeaf 受控媒体网关引用
```

列表接口在查询阶段过滤不满足条件的资源；详情接口即使收到旧链接，也必须重新判断。每次作品媒体网关读取还必须按所属资源、用途、变体和当前时间重新检查发布状态、绑定及授权/资格；任何授权或资格未知均 fail-closed。资源不存在、未发布、已下架、授权撤回、资源级资格未知和资格失效在公开端统一返回 `PUBLIC_RESOURCE_UNAVAILABLE`，不暴露内部原因。授权依赖整体故障导致无法可信计算列表时返回 `PUBLIC_SERVICE_UNAVAILABLE`/503，不将其伪装为正常空列表；所有分支均不得继续旧许可。

下架或授权撤回后的处理要求：

- 停止从列表和首页聚合返回；
- 使相关公开缓存、首页精选和媒体引用失效；
- 旧链接进入不可用提示，不返回客户或授权内部信息；
- 缓存失效、投影重建或通知任务失败时，查询与媒体网关仍按当前事实拒绝，不恢复公开；
- 记录 requestId、资源标识、公开资格检查结果和处理任务状态，但日志脱敏；
- 具体缓存传播时限和任务重试策略在外部服务/缓存设计中确认。

A15 是公开授权事实归属，A06 计算作品公开资格，A05 负责公开内容编排。D-401 只消费资格结果，不创建或修改授权事实。

## 5. 查询输入、分页、排序和筛选

- 资源标识使用不透明公开 ID，长度和字符集由服务端校验；
- `businessId`、标签和筛选条件只允许查询公开字典值，非法或过长参数返回 `PUBLIC_QUERY_INVALID`；
- 列表限制最大页大小，默认排序由公开编排版本或发布时间/排序字段决定，不能由客户端注入任意数据库排序表达式；
- 推荐使用 cursor 分页；如果现有接口统一使用 page/size，也必须限制最大 `size` 并稳定排序；
- 首页聚合不允许用无限制全量查询拼接；服务端需设定区块数量上限；
- 详情请求不接受客户端传入价格、授权、媒体地址或发布状态；
- 所有列表和详情查询都默认只查公开投影/公开数据源，不能先查全量再由客户端过滤。

## 6. 响应 DTO 和缓存

### 6.1 版本与缓存草案

普通品牌、业务、套餐文字投影可短时缓存；作品媒体与这些文字投影采用不同的展示和缓存规则。公开响应可包含 `contentVersion`，普通文字投影可结合 `ETag`/`If-None-Match` 或等价版本协商；作品媒体不得因此跳过当前资格检查。缓存策略必须同时满足：

- 首页、列表和详情中的普通品牌/业务/套餐文字投影可短时缓存，提高匿名浏览稳定性；
- 首页、列表、详情、后台恢复和分享入口中的作品媒体，在每次展示前都须通过 SouthLeaf 受控媒体网关完成当前发布、绑定和授权/资格二次确认；确认完成前隐藏旧图，不先展示旧媒体缓存；
- 作品媒体响应使用 `Cache-Control: no-store`，边缘和客户端不得以 304、Range、旧 URL 或本地文件命中绕过资格检查；
- 服务端资格判断优先于客户端缓存；授权/资格为未知、超时或无法证明时 fail-closed；
- 公开版本变化后旧 DTO 不得继续作为正式详情展示，缓存失效任务失败也不得恢复已下架、撤回或资格失效的资源；
- 不缓存客户业务数据、授权凭证、私密媒体、原始对象 key、供应商直链或永久签名地址。

缓存 TTL、ETag 的具体取值、失效传播目标和 CDN/对象存储能力仍待评审；本文不假定具体数值或供应商能力。此处待定的是性能及传播参数，不是撤回生效后可否继续放行新详情/媒体请求：后者必须按当前事实拒绝，不能等待缓存自然过期。已发送字节、在途流及不可控外部副本的限制沿用 D-205/D-308，需单独验证和记录。

### 6.2 DTO 兼容边界

- 客户端只依赖公开 DTO，不绑定数据库字段名；
- 可选字段新增应保持旧客户端可解析；
- 删除或改义字段必须经过版本策略，不能静默把 `price` 改为另一语义；
- `images`、`imageSrc` 等原型字段不得继续作为新契约的并行正式字段；统一使用 `media`/`coverMedia`；
- API DTO 与小程序展示模型之间保留适配层，避免后端字段变更直接造成页面耦合。

## 7. 错误码和安全边界

阶段一公开错误码固定如下：

| 错误码 | HTTP 映射 | 公开含义 |
|---|---:|---|
| `OK` | 200 | 查询成功；可选媒体缺失按成功响应内的可选字段省略或既有契约表达 |
| `PUBLIC_QUERY_INVALID` | 400 | 查询参数无效 |
| `PUBLIC_RESOURCE_UNAVAILABLE` | 404 | 内容当前不可公开；包含授权/资格未知的 fail-closed 结果 |
| `PUBLIC_SERVICE_UNAVAILABLE` | 503 | 必需公开查询依赖整体暂不可用 |
| `PUBLIC_MEDIA_UNAVAILABLE` | 503 | 资格已确认，但单次媒体网关读取失败 |
| `PUBLIC_RESPONSE_INVALID` | 500 | 服务端响应转换失败；客户端解析失败映射同名本地异常状态 |

`PUBLIC_MEDIA_UNAVAILABLE` 不作为 JSON 聚合响应的“部分成功”状态。部分媒体失败但主资源仍可用时，外层仍为 `OK`/200，并通过成功响应中可选媒体字段缺失或既有契约表达；独立媒体网关读取失败才返回 `PUBLIC_MEDIA_UNAVAILABLE`/503。必需封面或区块不可用时应过滤条目或按必需依赖失败处理，具体策略仍待评审，但不得使用 200/503 二义映射。

错误响应和作品媒体响应使用 `Cache-Control: no-store`；错误不参与 ETag/304 协商，作品媒体也不支持通过 304 或 Range 绕过资格检查。

内部原因可以在服务端日志和审计中保留，但不能通过 HTTP body、响应头、媒体 URL 或错误文案泄露。服务端必须防止：

- 通过资源 ID 枚举草稿、客户或授权记录；
- 通过不同错误响应推断授权撤回、客户身份或内部状态；
- 返回不受控的原始媒体地址；
- 由客户端伪造 `published`、`authorized`、`price`、`visible` 等字段影响结果；
- 把公开接口误作后台写接口或客户业务接口。

阶段一公开接口原则上无需客户身份，但应具备基础限流、请求大小限制、参数校验和异常监控。

## 8. 版本、兼容和废弃

- 生产路径必须使用 HTTPS 和明确 API 版本；当前 `http://localhost:8090` 只能作为开发占位，不能进入小程序生产配置；
- 公开 DTO 首次锁定前标记为草案，评审后记录版本和变更原因；
- 资源下架不是 API 删除，不应返回内部删除原因；
- 旧客户端请求仍能获得安全的公开不可用结果；
- 未来阶段增加客户业务接口时，不能复用公开查询响应承载订单、支付或交付权限；
- 任何破坏性字段变更必须同步 D-602 客户端展示模型和验收测试。

## 9. 测试和验收

1. 列表、详情和首页聚合只返回已发布且满足公开授权资格的资源。
2. 草稿、未发布价格、内部备注、客户信息、内部媒体 key 和私密资源不会出现在任何公开响应。
3. A15 授权撤回或资格失效后，列表、首页、详情和媒体引用均进入下架/不可用路径。
4. 旧链接不能绕过详情二次校验，也不能通过错误差异推断内部授权原因。
5. 六类业务都能表达；某业务无套餐时返回真实空结果或业务说明，不返回伪造套餐。
6. 套餐价格字段能区分固定价、起价、询价和未披露，不把未确认价格映射为 0。
7. `media`、`coverMedia`、`displayPrice` 等字段在首页、列表、详情之间语义一致。
8. 分页、筛选、非法参数、超大页大小和重复请求都有稳定结果和限制。
9. 普通文字投影缓存版本变化后可刷新；作品媒体在首页、列表、详情、后台恢复和分享入口展示前完成当前资格二次确认，待确认、资格未知或缓存失效任务失败均不显示旧图。
10. 媒体网关引用不暴露或重定向到供应商直链、永久签名地址及原始 key；作品媒体响应为 `no-store`，304/Range 不能绕过资格。
11. `PUBLIC_MEDIA_UNAVAILABLE` 固定为 503，`PUBLIC_RESPONSE_INVALID` 固定为 500；主资源仍可用的部分媒体失败以 `OK`/200 内的可选媒体缺失或既有契约表达。
12. 接口返回 requestId，错误信息不泄露堆栈、供应商、授权证据或客户资料。
13. 开发环境地址、生产 HTTPS 域名和合法域名配置分离。

## 10. 待确认问题

- 阶段一公开数据实际维护和发布方式，以及公开数据源的权威存储位置；
- A15 向公开查询提供资格结果的内部端口/查询视图；
- 公开版本、普通文字投影缓存 TTL、ETag 具体取值和撤回后的失效目标；这些数值未确认，不改变作品媒体 `no-store` 与每次资格复核规则；
- SouthLeaf 受控媒体网关的生产域名、缩略图/预览参数和对象存储适配契约；供应商能力未确认，不得改为供应商直链、永久签名地址或原始 key；
- 现有后端统一响应格式、错误码前缀和 API 版本前缀；
- 首页聚合是否与资源列表共用查询模型，或采用独立公开编排投影。

## 11. 当前演示实现与兼容记录

机器可读实现描述为 `docs/接口/public-api.openapi.json`。现有 JSON 路径保持不变，新增 `GET/HEAD /api/v1/public/media/{mediaId}/{variant}/content` 字节读取；媒体 DTO 的 thumbnailUrl/previewUrl 为服务端生成的网关相对引用，不是供应商地址。`meta.dataMode` 是兼容新增字段，取 demo/production；contentVersion 改为目录实际内容 SHA-256，不再只跟 schema 变化。

当前套餐 priceType 使用 FIXED/FROM/INQUIRY/UNDISCLOSED，详情采用 serviceItems/tips/notices；前端暂兼容旧 FROM_PRICE/CONSULT。当前所有公开 JSON 及媒体为 no-store；未实施普通文字 ETag 缓存。演示数据不代表正式经营/授权事实，production 模式和 release 客户端有防误用检查，但不替代生产安全及验收。

本章为当前实现记录；上文 DTO 草案与实现字段差异在生产兼容评审中以 OpenAPI 和源码逐项核对，不将草案直接当作已冻结 API。
