## 1. 职责与运行边界

管理 API 是 admin-runtime 的入站适配器，只调用应用用例；不直接持有 JdbcTemplate、DataSource、迁移或任意 SQL 入口。路径统一 `/api/admin/v1`，与客户 API、公开 API、会话 Cookie 分离。public-api 不代理管理命令或获得 Writer 权限。

admin-web 与 API 同 origin（scheme/host/port）；通过受控 HTTPS 代理部署。应用验证显式 PUBLIC_ADMIN_ORIGIN，不能从不可信 Host/Forwarded 构造允许源；只信任配置的代理。未配置安全 origin/代理/TLS 契约时不开放 Web。

S1 不提供注册、找回密码、改密/禁用/授权 HTTP 接口或公开管理员初始化；这些由受控 CLI 完成。内容、媒体、授权、预约、订单接口随 S2–S6 设计，不返回假成功占位结果。

## 2. 通用契约

- JSON UTF-8；写请求只接受 `application/json`，4 KiB 上限（S1）；重复字段/未知字段和不合法 JSON 拒绝。大小检查必须在解析与 KDF 之前。
- 成功 JSON：`{"code":"OK","data":{...},"requestId":"server-generated-id"}`；204 不返回 body。
- 错误：`{"code":"ERROR_CODE","message":"稳定且不含秘密的提示","requestId":"server-generated-id"}`。不包含 stack trace、SQL、schema、凭据、账号存在性或原 token。
- requestId 由服务端生成或从受信任代理校验后接受，不无界反射客户端内容；响应同时带 `X-Request-Id`。
- 时间为 RFC 3339 UTC，按存储微秒精度输出；标识为不透明字符串，客户端不解析业务含义。
- 所有认证响应（包括错误和 CSRF）为 `Cache-Control: no-store`；无 ETag/304，不由 CDN、Service Worker 或浏览器业务缓存保存。
- 不开放通配或跨站凭据 CORS。S1 无跨源客户端需求；跨源预检不放行，跨源写即使携带有效 Cookie 也拒绝。

## 3. S1-D 端点表

| 方法 / 路径（相对 /api/admin/v1） | 请求 | 成功 | 认证与保护 |
|---|---|---|---|
| GET `/auth/csrf` | 无 body | 200，`data={csrfToken,headerName:"X-CSRF-TOKEN"}`；按需设置 CSRF cookie | 可匿名；同源客户端获取；不签发认证会话 |
| POST `/auth/login` | `{accountId,password}` | 200，身份响应；设置新的认证 Cookie | 必须有效 Origin + CSRF，登录限流/KDF 预算；无须已登录 |
| GET `/auth/session` | 无 body | 200，当前身份响应 | 必须有效后台 Cookie；每次重读当前会话/权限 |
| POST `/auth/logout` | `{}` | 204；清除认证和 CSRF Cookie | 必须 Origin + CSRF；有效会话撤销并审计；未知/已过期 token 也可幂等完成 |

身份响应的 data：`{accountId,permissions:["CONTENT_READ"],expiresAt:"2026-10-18T12:00:00Z"}`；示例仅为协议形状，不代表已分配权限/生产截止时间。permissions 为去重、稳定排序的 capability 代码，不返回 credential_hash、tokenDigest、securityVersion、内部角色配置或数据库字段。HTTP 原 token 仅经 Set-Cookie，不在 JSON 暴露。

### 3.1 登录

accountId 按 D-201 原值匹配，password 不裁剪/归一化。服务端不接受 account/version/permission 的“已验证”参数。未知账号、禁用、密码错误、核验后版本变化一律 401 `INVALID_CREDENTIALS`；服务异常为 503，不拿“密码错误”隐藏依赖故障。

登录不是可自动重放的幂等业务命令；前端提交后禁用重复点击，超时先 GET session 复核，再允许用户手动重试。失败响应不覆盖已有认证 Cookie；已有登录 Cookie 的再次登录先返回 409 `ALREADY_AUTHENTICATED`，避免隐式切换账号/孤儿会话，用户应先退出。无效旧 Cookie 不阻止重新登录。

只有事务提交确认成功才设置新认证 Cookie，清除旧 CSRF cookie；前端随后重新 GET csrf。若响应丢失，不能把该次请求认定成功或自动连续发起 KDF。

### 3.2 当前身份与退出

GET session 不滑动延长会话。未知/到期/撤销/禁用/版本失效返回 401 `AUTHENTICATION_REQUIRED`，清除无效认证 Cookie；数据库故障返回 503，不清除可能仍有效的会话。

logout 对有效会话必须先完成撤销/审计事务，再回 204 并清 cookie。数据库或审计失败返回 503，不能先清客户端 Cookie 后声称服务端已退出；前端保留“退出未确认”状态并允许重试。logout 对无 token/格式错误/已失效 token 不泄露其存在性，CSRF/Origin 仍检查；需要数据库判断的依赖故障不能当作无 token。

## 4. Cookie、CSRF 与安全过滤链

认证 cookie：`__Host-sl_admin_session`，`Secure; HttpOnly; SameSite=Strict; Path=/`，不含 Domain；Max-Age 不超过服务端 expiresAt，服务端时间始终是授权依据。清除必须使用相同名称/Path/属性并 Max-Age=0。

CSRF cookie：`__Host-sl_admin_csrf`，`Secure; SameSite=Strict; Path=/`，无 Domain，HttpOnly=false；它不是认证 token。采用维护框架 CookieCsrfTokenRepository，配置固定 cookie/header 名，不自写 CSRF 签名协议。前端通过 GET csrf 取得框架接受的 token 并仅存在内存；cookie/token 不写日志。登录和退出成功后轮换/清除，浏览器当前 cookie 轮换后，旧 header token 应被拒绝；此 double-submit 机制不声称 token 自身绑定服务端账号或撤销所有已复制的 cookie/token 对，安全边界同时依赖 __Host- cookie、严格 Origin 和同源策略。浏览器多 tab 的 token 过期返回 403，获取新 token 后由用户重试写操作，不自动重放业务命令。

过滤顺序（含例外）须测试：受信代理/请求大小和全局资源限制 → 路由/Content-Type → 写请求 Origin + CSRF → 认证 → capability/资源授权 → 应用用例。缺少 Origin、Origin=null、不匹配源的 S1 写请求均 403；受控 CLI 不通过这些浏览器端点，不以省略 Origin 绕过。

Spring Security 只负责 Web 防护/认证桥接；关闭 default user、formLogin、HTTP Basic、remember-me、额外 HttpSession/JSESSIONID。已有 AdminSessionService 是认证事实来源；请求后清理 SecurityContext，线程复用不得泄露 principal。Web listener 只有 D-506 bootstrap 成功后才启用，不用晚于监听启动的健康检查掩盖失败窗口。

安全头：HTML 使用明确 CSP（脚本/连接默认 self，frame-ancestors none、object-src none、base-uri self；无 unsafe-eval），API nosniff、Referrer-Policy no-referrer；生产 HTTPS 配置 HSTS，是否 includeSubDomains 按部署域名责任确认。CSP 的样式规则须兼容实际组件库并经浏览器测试，不能为方便全面关闭 CSP。

## 5. 状态码与可恢复性

| HTTP / code | 含义 | 客户端行为 |
|---|---|---|
| 400 INVALID_REQUEST | JSON/字段/格式不合法 | 提示检查输入，不自动重试 |
| 401 INVALID_CREDENTIALS | 登录凭据统一失败 | 留在登录页，清密码，不显示账号存在性 |
| 401 AUTHENTICATION_REQUIRED | 受保护读取会话失效 | 清内存身份，回登录；保留同源安全返回路径 |
| 403 CSRF_REJECTED / ORIGIN_REJECTED | 浏览器防护拒绝 | 明确安全校验失败；CSRF 可重新获取，写请求不自动重放 |
| 403 ACCESS_DENIED | 已登录但权限/资源不允许 | 留在拒绝页，不循环跳转登录 |
| 409 ALREADY_AUTHENTICATED | 已登录状态再次登录 | 读取当前身份或提示先退出 |
| 413 PAYLOAD_TOO_LARGE / 415 UNSUPPORTED_MEDIA_TYPE | 体积/类型不支持 | 不执行 KDF，用稳定提示 |
| 429 RATE_LIMITED | 任一限流或 KDF 容量达到上限 | 带 Retry-After 秒数；禁止自动重试风暴 |
| 503 AUTH_SERVICE_UNAVAILABLE | 存储、审计、KDF 基础设施不可用 | 不冒充密码错误/退出成功，带 requestId 便于排查 |

身份与权限错误优先级在契约测试锁定：写请求 CSRF/Origin 不合法先 403；防护通过但无会话时受保护业务接口 401；登录接口按其匿名规则处理。没有合法权限的调用者不能借错误码枚举其他资源，未来资源接口单独定义 403/404 策略。

## 6. 业务管理接口的扩展约束

S2 的上传/草稿/授权/发布/撤回，S3 的版本/内容管理，S4–S6 的客户/档期/预约/订单/补偿分别补充具体路由、DTO、权限、错误和 OpenAPI。每个写命令须声明幂等键作用域、请求摘要、If-Match/预期版本、事务边界和未知提交结果复核方式；不能笼统套用登录的非幂等语义。

权限在服务端用例与资源边界执行；UI 隐藏按钮不是授权。高风险操作必须检查当前主体/状态，不把权限字符串扩展为未经 Q06 确认的生产角色。分页、筛选、导出、批量操作暂不开放，避免无界读取和未审批隐私暴露。

支付、退款、完整履约、私密交付等接口为阶段三，不纳入本轮后台契约。

## 7. 实施门禁与证据

S1-D 的登录/会话契约已由独立 L5 证据验证；该证据不覆盖 S2 业务接口。S2-B 编码前须将 §8 冻结为实际 OpenAPI、补 schema/错误码契约测试，并验证库/框架版本与代理 HTTPS/CSP。独立数据库身份与 S1-C KDF/审计/账号恢复门禁仍是受保护 Web 的前置条件，S2 业务 writer 必须另行验证最小 grants。D-703 中的 Cookie、CSRF、失败退出、禁用竞争、权限即时读取、公开回归与 HTTPS E2E 必须留可复现证据。

## 8. S2-A 单作品上传、草稿、发布与撤回契约（设计态）

| 方法与路径（统一前缀 `/api/admin/v1`） | 用途 | Capability / 前置条件 | 幂等与版本约束 |
|---|---|---|---|
| `POST /media/uploads` | 单文件 multipart 上传、签名/解码校验、固定衍生图处理 | `CONTENT_EDIT`；会话、Origin、CSRF | `Idempotency-Key`；服务端摘要绑定请求；有界字节/像素 |
| `GET /media/{mediaId}` | 查看状态与不含存储 key 的变体元数据 | `CONTENT_READ` | 无写副作用 |
| `GET /media/{mediaId}/{variant}/content` | 管理端私有预览流，仅 `thumbnail`/`preview` | `CONTENT_READ`；逐次检查媒体与作品范围 | `no-store`；不得使用对象直链/Range 旁路 |
| `GET /works`、`POST /works` | 管理端作品列表、建立空草稿 | `CONTENT_READ` / `CONTENT_EDIT` | 建立命令带 `Idempotency-Key` |
| `GET /works/{workId}`、`PUT /works/{workId}` | 读取/保存单作品草稿修订 | `CONTENT_READ` / `CONTENT_EDIT` | 写入必须带强 `If-Match` 修订 ETag |
| `GET /works/{workId}/preview` | 查看当前草稿及可公开字段的预览，不改公开投影 | `CONTENT_READ` | 返回候选修订号；授权未知时标记不可发布，不显示证据 |
| `POST /works/{workId}/publish` | 对指定修订执行一次发布 | `CONTENT_PUBLISH`；全部服务端门禁复核 | `Idempotency-Key` + `If-Match`；同键异 payload 为 409 |
| `POST /works/{workId}/withdraw` | 撤下当前作品发布 | `CONTENT_PUBLISH`；不删除对象/历史 | `Idempotency-Key` + `If-Match`；未知提交先按键复查 |
| `GET /commands/{commandId}` | 复查未知提交结果 | 对应资源 `CONTENT_READ` | 只读命令状态；不重复执行 |

上述表项是 S2-A 设计契约，尚未意味着 Controller 存在。公开小程序复用现有 `GET /api/v1/public/works`、`GET /api/v1/public/works/{id}` 与同源媒体 content route；不引入带签名对象 URL。S2 不开放授权证据上传/修改、客户/订单接口、硬删除、批量操作、分页导出或未经 Q06 确认的生产角色。

统一错误类别：`400 INVALID_REQUEST`、`401 AUTHENTICATION_REQUIRED`、`403 CAPABILITY_REQUIRED`、`404 RESOURCE_UNAVAILABLE`、`409 VERSION_CONFLICT`/`IDEMPOTENCY_KEY_REUSE`、`413 MEDIA_TOO_LARGE`、`415 MEDIA_TYPE_UNSUPPORTED`、`422 MEDIA_REJECTED`/`PUBLICATION_BLOCKED`、`503 AUTHORIZATION_UNAVAILABLE`。错误与普通日志不得包含对象 key、授权证据或私下说明。
