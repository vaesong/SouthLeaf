> 文档状态：评审中

> 更新日期：2026-11-21

> 关联设计：D-310、D-304
> 详细用例：[D-718](用例/用户与足迹/01_用户管理与访客足迹用例.md)
> 初始执行状态：`NOT_RUN`

## 1. 范围

本文只列本期要证明的业务结果。步骤在 D-718。编号使用 `S2-USER` 与 `S2-FOOT`，不改 D-702 的阶段一基线。

场景不使用真实客人的 openid、手机号或头像。预约开关在全部场景中保持关闭。

## 2. 用户管理

| 编号 | 场景 | 前置 | 预期结果 |
|---|---|---|---|
| S2-USER-01 | 进入即登录 | 预约入口关闭；指纹在预约客户表中不存在 | 进入首页。用户表新增一行。预约客户表不新增。短编号为指纹前六位大写 |
| S2-USER-02 | 登录失败 | 微信换码失败，或用户库拒绝写入 | 停在重试页。作品、套餐、「我的」不可达。不插入用户，不写足迹 |
| S2-USER-03 | 客人改资料 | 已有用户，称呼为空 | 「我的」保存称呼和头像后，后台看到同一份。清空称呼后恢复「微信用户」加短编号。不出现「资料未齐」 |
| S2-USER-04 | 后台改资料 | 客人已有称呼和头像 | 后台改称呼后，客人下次打开「我的」看到新称呼。客人响应里没有备注。后台不能撤下头像 |
| S2-USER-05 | 没有档案操作 | 管理员已登录 | 没有新建、删除、停用用户的入口和接口。调用被拒绝，用户行还在 |
| S2-USER-06 | 接上旧预约 | 预约客户已有同一指纹，并有申请；用户表还没有这个人 | 该微信下次登录后出现在用户列表。「我的」和用户详情能看到那些申请。另一指纹看不到 |
| S2-USER-07 | 同名与搜索 | 两个用户称呼相同，短编号不同 | 搜索短编号只命中对应的人。搜索称呼命中两行。两行不合并 |
| S2-USER-08 | 会话与身份隔离 | 同时具备用户凭证和后台凭证 | 用户凭证不能打开后台用户接口。后台凭证不能改「我的」。库和日志没有 openid |
| S2-USER-09 | 回到前台 | 用户已登录 | 从微信聊天切回小程序并成功确认身份后，最近登录更新。未过期时不要求客人再点登录 |

## 3. 访客足迹

| 编号 | 场景 | 前置 | 预期结果 |
|---|---|---|---|
| S2-FOOT-01 | 打开与去重 | 两位已登录用户 | 打开作品详情留下一条，含页面和作品 id。30 秒内再次打开不增加第二行。重试页不产生足迹 |
| S2-FOOT-02 | 发出分享 | 作品详情可分享 | 点开分享后生成卡片编号，路径带 `sls`。记录不表示对方已收到。分享接口失败时，路径仍可发出且不带 `sls` |
| S2-FOOT-03 | 两跳传递 | 两名用户都已登录 | 甲发出 S1，乙从 S1 打开再发出 S2。甲的时间线有发出，乙的时间线有打开和再发出。卡片页能看见这两跳。未知 `sls` 的打开仍保留，上一跳为空 |
| S2-FOOT-04 | 足迹失败不阻断 | 足迹写入被拒绝 | 作品页仍打开。分享路径仍能发出。不产生预约或订单 |
| S2-FOOT-05 | 保留 180 天 | 存在 181 天前的足迹和卡片，以及当天的记录 | 到期任务删除 181 天前的足迹和卡片。当天记录还在。用户、称呼、头像、备注还在。留下的按天次数不含用户 id |
