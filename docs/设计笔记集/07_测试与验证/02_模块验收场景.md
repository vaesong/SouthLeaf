# 模块验收场景

> 文档编号：D-702
> 文档状态：评审中（阶段一验收草案）
> 适用范围：阶段一为主；阶段二、阶段三保留验收入口
> 更新日期：2026-10-06
> 上游需求：A05-A08、A15-A16
> 上游架构：AT04、AT07、AT09
> 关联计划：P01

## 1. 验收组织方式

阶段一验收对象是“微信小程序公开展示 + 只读公开查询支撑能力”，不包含工作室管理后台、客户业务身份、预约、订单、支付和私密成片交付。

每个场景记录：

- 场景编号、业务目的和上游规则；
- 初始公开数据、发布状态和授权资格；
- 客户操作、接口请求和媒体依赖；
- 页面结果、公开 API 结果、日志/requestId 和缓存结果；
- 是否涉及真实品牌/联系方式/价格资料；
- 实际结果、证据和缺陷链接。

验收环境不得把 mock、历史测试套餐、固定 ID 详情或错误联系方式伪装为生产事实。六类摄影业务需要全部可表达，但没有真实套餐资料的业务允许显示真实空状态。

## 2. 小程序导航和公开页面

| 编号 | 场景 | 前置 | 操作 | 预期结果 |
|---|---|---|---|---|
| S1-NAV-01 | 四 Tab 导航 | 小程序阶段一配置已发布 | 依次进入首页、作品、服务、关于 | 四个 Tab 可达、返回路径稳定；不存在“我的”占位 Tab |
| S1-NAV-02 | 首页任务路径 | 首页存在已发布区块 | 从首页进入精选作品、业务/套餐和关于 | 跳转到正确列表/详情，路由只传稳定公开标识 |
| S1-NAV-03 | 深层链接 | 存在可公开作品/套餐 | 通过分享卡片或小程序码打开详情 | 详情重新查询，不依赖本地完整对象或上次登录状态 |
| S1-NAV-04 | 设备切换 | 同一公开链接可访问 | 在另一设备或清缓存后打开 | 重新读取当前公开结果，不依赖旧缓存 |
| S1-NAV-05 | 阶段外入口 | 阶段一构建 | 检查页面、Tab 和按钮 | 不存在可用的登录、预约、订单、支付、相册和私密交付入口 |

## 3. 内容、作品和套餐

### 3.1 品牌与联系

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-CONT-01 | 首页和关于读取同一品牌资料 | 名称、简介、地址、工作时间和联系信息语义一致，不各自硬编码 |
| S1-CONT-02 | 联系资料部分缺失 | 只展示已确认字段，不以原型默认值补齐 |
| S1-CONT-03 | 电话联系 | 系统拨号成功/取消/失败均有反馈，不创建预约或客户账号 |
| S1-CONT-04 | 微信联系 | 只呈现已确认且平台允许的方式；失败可返回，不伪造跳转成功 |
| S1-CONT-05 | 地址信息未确认 | 不显示冲突或错误地址，不用历史地图坐标代替真实资料 |

### 3.2 六类摄影业务

对儿童、亲子全家福、婚纱、写真、孕照、证件照逐类执行：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-BIZ-01 | 业务有已发布资料和套餐 | 列表与详情可达，业务、套餐关联正确 |
| S1-BIZ-02 | 业务已发布但暂无套餐 | 展示业务说明和真实空状态，可联系咨询，不生成测试套餐 |
| S1-BIZ-03 | 业务资料未发布 | 不进入公开查询结果，不以本地硬编码补齐 |
| S1-BIZ-04 | 按业务筛选作品/套餐 | 只返回对应公开资源，非法筛选返回稳定错误或空结果 |

### 3.3 作品与授权资格

| 编号 | 场景 | 前置 | 预期结果 |
|---|---|---|---|
| S1-WORK-01 | 合格作品公开 | 作品已发布，A15 授权有效，媒体可读 | 首页/列表/详情可展示，媒体顺序一致 |
| S1-WORK-02 | 无授权或待核验 | 作品存在但资格未知/无效 | 列表、首页和详情均不返回作品 |
| S1-WORK-03 | 授权撤回 | 作品此前公开 | 列表和首页移除，详情旧链接统一不可用，缓存和媒体引用按策略失效 |
| S1-WORK-04 | 作品下架 | 发布状态变为下架 | 不再返回；公开提示不暴露内部下架原因 |
| S1-WORK-05 | 单张媒体失败 | 详情其余内容可用 | 保留文字和可用媒体，失败项可重试，不泄露原始存储地址 |
| S1-WORK-06 | 固定 ID/对象注入 | 修改路由参数或分享对象 | 服务端按公开 ID 重查，客户端对象不能绕过资格和发布状态 |

### 3.4 套餐与价格

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-PKG-01 | 固定价套餐 | 列表、详情的套餐名、业务、服务项和价格语义一致 |
| S1-PKG-02 | 起价/询价 | 明确展示“起”或“咨询”，不转成固定价或 0 元 |
| S1-PKG-03 | 未确认价格 | 不返回金额，不使用历史 30%/50% 定金或活动价 |
| S1-PKG-04 | 套餐下架或旧链接 | 从列表移除，详情显示安全不可用提示 |
| S1-PKG-05 | 字段兼容 | 首页、列表和详情统一使用公开 DTO；不混用 `images`、`imageSrc` 等正式字段 |

## 4. 公开查询接口和数据安全

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-API-01 | 首页聚合 | 仅返回已发布且满足资格的品牌、作品、业务、套餐摘要 |
| S1-API-02 | 列表分页与筛选 | 参数有上限、排序稳定、无重复或越权结果 |
| S1-API-03 | 详情二次校验 | 旧链接和直接 ID 请求仍校验发布状态与授权资格 |
| S1-API-04 | 非法/超长参数 | 返回 `PUBLIC_QUERY_INVALID` 或锁定后的等价稳定码，不触发内部错误泄露 |
| S1-API-05 | 资源不可用 | 未发布、下架、撤回、过期和不存在统一映射为公开不可用，不可据此枚举内部状态 |
| S1-API-06 | 数据最小化 | 响应不包含客户资料、授权证据、内部备注、原始存储 key、后台角色和私密媒体 |
| S1-API-07 | requestId | 成功/错误请求可关联服务端日志；客户端只在反馈需要时展示简短标识 |
| S1-API-08 | 环境配置 | 生产小程序使用 HTTPS 和合法域名；`localhost` 仅限开发环境 |

## 5. 加载、空态、错误和恢复

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-STATE-01 | 首次加载 | 显示稳定骨架/加载状态，不闪现上一资源或假数据 |
| S1-STATE-02 | 成功空结果 | 显示真实空态，不自动无限重试 |
| S1-STATE-03 | 无网络 | 显示网络提示、返回和主动重试；不回退到生产内置示例数据 |
| S1-STATE-04 | 超时/5xx | 显示服务暂不可用和重试；不会产生请求风暴 |
| S1-STATE-05 | 响应格式错误 | 进入通用异常状态并保留 requestId，页面不崩溃 |
| S1-STATE-06 | 重复点击/快速切换 | 同参数查询可合并或忽略旧响应，旧请求不覆盖新页面状态 |
| S1-STATE-07 | 从后台恢复 | 按缓存年龄和页面类型刷新，不无条件高频请求 |
| S1-STATE-08 | 部分区块失败 | 首页其他区块可继续使用；失败区块有局部降级或重试 |

## 6. 缓存、更新和撤回

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S1-CACHE-01 | 公开版本更新 | `contentVersion`/ETag 或等价机制能识别更新，客户端获取新内容 |
| S1-CACHE-02 | 详情缓存陈旧 | 进入详情时重新校验或确认版本，不继续展示已下架事实 |
| S1-CACHE-03 | 授权撤回 | 服务端投影、首页、列表、详情和媒体缓存按策略失效 |
| S1-CACHE-04 | 更新任务重复 | 重复任务不产生重复公开版本、媒体或审计事件 |
| S1-CACHE-05 | 更新任务失败 | 有脱敏失败记录、有限重试和人工处理入口；旧内容是否继续可见遵守安全默认 |

安全默认：授权资格未知、撤回或失效时按不公开处理；不能因缓存或下架任务失败继续暴露已知不合格作品。

## 7. 阶段外能力验收入口

以下能力不进入阶段一验收，不应因缺失导致阶段一失败；其规则仍由上游文档保留：

- 阶段二：客户身份、预约申请、固定时段、冲突校验、确认成单、订单快照和工作室运营后台；
- 阶段三：支付、退款、履约完成、售后、私密成片交付、下载和完整授权执行；
- 品牌官网：不属于阶段一交付，未来共享公开事实但有独立页面和深层入口设计。

后续阶段展开时，在本文件新增对应场景或拆分阶段验收文档，不得把阶段一匿名公开查询直接当作客户业务权限。

## 8. 阶段一通过条件

阶段一进入编码前的设计验收通过条件：

1. D-601 页面/路由与 D-602 状态模型、D-401 公开 DTO、D-501 事实归属一致。
2. 小程序范围固定为首页、作品、服务、关于/联系；“我的”和客户业务流程未进入 MVP。
3. 公开数据维护来源、审核/发布责任、首批真实资料和授权资格输入形成明确决策或经批准的安全运维方案。
4. 作品公开同时受发布状态和 A15 授权资格约束，撤回/下架/旧链接路径可验证。
5. 六类业务全部可表达，未确认的套餐、价格、地址和联系方式不会被伪造。
6. 公开接口只读、匿名、数据最小化，并具备参数校验、错误码、requestId、缓存和媒体安全边界。
7. 加载、空态、网络失败、服务异常、资源不可用和媒体部分失败均有用户可理解的反馈。
8. 阶段一不要求后台登录、内容 CRUD、媒体上传工作台、预约、订单、支付或私密交付可用。
9. 生产域名、公开媒体策略和关键缓存/撤回时限在实现前完成评审。
10. 以上场景被转成可执行测试用例，并记录评审角色与结论。

阶段一实现验收还必须在真机/目标小程序环境执行关键路径，不能只依赖浏览器或静态代码检查。
