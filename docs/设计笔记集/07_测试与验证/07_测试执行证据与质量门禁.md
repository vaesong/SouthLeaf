# 测试执行证据与质量门禁

> 文档编号：D-707
> 文档状态：评审中
> 适用范围：目标架构、阶段一
> 更新日期：2026-10-09
> 上游需求：A05-A08、A15-A16
> 上游架构：AT04、AT09
> 关联计划：P01

## 1. 目的与结论边界

本文规定阶段一测试批次如何建立、结果如何判定、证据如何留存、缺陷如何分级，以及何时可以作出阶段验收结论。规则与具体编程语言、自动化框架和 CI 产品无关。

必须区分以下结论：

| 结论 | 证明内容 | 不证明内容 |
|---|---|---|
| 测试体系文档编制完成 | D-700～D-708 及详细用例的结构、追踪、数据、门禁和模板已形成并通过完整性检查 | 文档已评审确认、环境已就绪、实现已正确 |
| 测试设计已确认 | 用例、数据和门禁经所需角色评审，可作为执行基线 | 候选版本已执行或产品已验收 |
| 执行批次完成 | 所选用例均有可判定记录，证据和缺陷已归档 | 未选范围、其他环境或整个阶段必然通过 |
| 阶段一产品验收通过 | 对同一候选版本满足本文全部强制门禁并有责任人结论 | 后续阶段能力、所有设备兼容性或未来版本继续有效 |

文档状态为“评审中”时，可以报告“文档已编制并完成结构检查”，不得报告“测试已通过”或“产品验收通过”。设计推演、静态检查、用例数量和自动化通过率均不能替代候选实现的实际执行。

## 2. 执行批次

执行批次是对一个不可变候选版本、确定环境与用例基线的一组执行记录。不得把不同构建、不同域名配置或修复前后结果混为同一验收分母。

### 2.1 批次类型

| 批次类型 | 目的 | 最低选集 |
|---|---|---|
| `DESIGN_REVIEW` | 验证规则可测、追踪完整和待决项清楚 | 受影响的决策表、状态转换、故障序列 |
| `SMOKE` | 判断候选版本是否值得继续测试 | 四 Tab、一个合格公开资源、一个安全拒绝、基础错误反馈 |
| `P0_INVARIANT` | 验证公开资格、隐私、撤回和不可绕过条件 | 全部 P0 主用例及强制变体 |
| `P1_MAIN` | 验证阶段一主要客户路径和恢复 | 全部 P1 主用例及六类业务强制变体 |
| `FAULT_RECOVERY` | 验证依赖失败、任务、重试和恢复收敛 | `S1-FAULT-01`～`S1-FAULT-08` 及适用网络故障 |
| `CONTRACT_REGRESSION` | 验证已锁定公开契约与客户端映射 | API、DTO、分页、错误码、兼容变体 |
| `WECHAT_DEVICE` | 验证微信目标环境和真机行为 | 分享/旧链接、系统联系、网络恢复、后台恢复、媒体资格 |
| `REAL_CONTENT` | 核验真实品牌、六类业务、套餐、价格、联系方式、授权和撤回 | 经责任人确认的首批公开资料及受控撤回样本 |
| `RETEST` | 验证指定缺陷修复且无相关回归 | 缺陷原失败用例、直接影响集、必要 P0 回归 |
| `STAGE_ACCEPTANCE` | 对同一候选版本汇总阶段一门禁 | 本文第 9 节全部强制选集 |

`SMOKE` 成功只允许继续执行，不能作为发布或验收结论。复测必须新建执行记录；若修复产生新构建，则建立新批次或明确子批次并重跑受影响门禁集。

### 2.2 批次标识与冻结项

批次 ID 使用：

```text
TB-S1-<候选版本>-<环境短码>-<YYYYMMDD>-<两位序号>
```

批次创建时冻结：

- 候选构建及来源版本；
- 用例基线版本、数据配方版本和 D-708 追踪快照；
- D-706 的环境实例、`runId`、时钟模式、配置摘要；
- 微信基础库、微信版本、真机型号/系统和网络条件（适用时）；
- HTTPS/合法域名配置版本和发布目标（适用时）；
- 公开内容版本、真实资料确认记录和授权资格版本（适用时）；
- 入选用例、变体、层级、排除项及批准依据；
- 执行人与复核人角色、开始/结束时间。

设备清单、缓存 TTL、媒体供应商和正式发布流程仍待评审；未确认前登记待决项并阻塞对应验收批次，不在批次模板中自行设定。

## 3. 单项执行结果

执行结果仅适用于“某批次中某主用例变体在某层级的一次尝试”。允许值固定为：

| 结果 | 判定条件 | 后续动作 |
|---|---|---|
| `PASS` | 所有适用步骤已执行，全部断言符合预期，所需证据完整且可关联 | 计入该变体已通过；不外推到其他层级或参数 |
| `FAIL` | 至少一个适用断言与预期不符，或观察到禁止结果 | 建立/关联缺陷，保留原始证据；修复后新增复测记录 |
| `BLOCKED` | 已开始或尝试执行，但环境、数据、权限、待决项或依赖使结果无法判定 | 记录阻塞原因、负责人类型和解除条件；不计为通过 |
| `NOT_RUN` | 本批次尚未执行该记录，或只建立了计划条目 | 说明计划或排除依据；不计为通过 |

判定规则：

1. 一个强制断言失败，整条执行记录为 `FAIL`，不能按步骤平均。
2. 证据缺失到无法复核时，不得判 `PASS`；根据是否完成执行判 `BLOCKED` 或 `FAIL`，并说明原因。
3. 环境异常若同时暴露产品缺陷，优先登记 `FAIL`；只有无法判断产品行为时才用 `BLOCKED`。
4. 预期本身有歧义时登记 `BLOCKED` 和 D-708 待决项，不由执行人临时降低断言。
5. 可选 P2 变体未入选为 `NOT_RUN`；强制 P0/P1 变体的 `NOT_RUN` 或 `BLOCKED` 会阻止对应门禁。
6. 参数化用例逐变体记录结果。BIZ 的 24 次强制执行不能用一条汇总 `PASS` 代替。
7. 复测成功不覆盖首次 `FAIL`；验收汇总同时展示最新结果和历史失败/缺陷状态。

## 4. 证据类型与充分性

### 4.1 证据类型

| 证据 ID | 类型 | 最低内容 | 主要证明 |
|---|---|---|---|
| `EV-PLAN` | 批次/选集快照 | 构建、用例版本、环境、runId、入选与排除 | 本次测了什么 |
| `EV-UI` | 页面截图或录屏 | 时间、页面/入口、关键操作与结果 | 客户可见状态与交互 |
| `EV-API` | 脱敏请求/响应 | 方法/语义、参数、状态码、稳定码、requestId、响应摘要 | 公开接口结果 |
| `EV-DATA` | 数据/公开投影观察 | runId、资源、动作前后状态摘要 | 服务端事实与过滤结果 |
| `EV-MEDIA` | 媒体网关观察 | 资源/变体、资格复核结果、响应头摘要、失败状态 | 媒体受控读取、`no-store` 与不可绕过 |
| `EV-LOG` | 脱敏日志 | requestId/runId、时间、结果类别；无敏感原文 | 请求关联、错误脱敏和诊断能力 |
| `EV-TASK` | 任务/审计记录 | 稳定意图、尝试次数、状态、最后错误、恢复结果 | 重试、幂等、补偿和收敛 |
| `EV-CONFIG` | 配置核验 | 环境、HTTPS/合法域名、版本摘要；不含秘密 | 目标环境与域名配置 |
| `EV-DEVICE` | 设备与微信信息 | 设备型号、系统、微信、基础库、网络、候选构建 | 真机代表条件 |
| `EV-CONTENT` | 真实内容来源确认 | 内容版本、确认人角色、来源、确认时间 | 品牌、价格、联系方式等真实准确性 |
| `EV-AUTH` | 授权/撤回核验引用 | 资格结论、范围、有效性、撤回动作和时间；不复制证据原件 | 公开资格与撤回依据 |
| `EV-TIME` | 时钟/序列轨迹 | T0、步进、故障点、恢复点和观察时间 | 边界和故障时序 |
| `EV-DEFECT` | 缺陷与复测引用 | 缺陷 ID、严重度、状态、修复构建、复测记录 | 偏差处理和关闭依据 |

### 4.2 最低证据组合

- 页面显示正确：`EV-UI + EV-API`；若断言涉及服务端资格过滤，再加 `EV-DATA` 或等价服务端证据。
- 敏感字段未公开：公开响应/页面/日志的哨兵负向检查及 `EV-API`；仅截图不充分。
- 撤回/下架/旧链接：动作前后 `EV-AUTH` 或公开事实引用、`EV-API`、`EV-MEDIA`、`EV-UI`，以及失败任务场景的 `EV-TASK`。
- 故障与恢复：`EV-TIME + EV-API/EV-UI + EV-TASK/EV-LOG +` 最终事实证据；只展示错误提示不证明收敛。
- 真机联系：`EV-DEVICE + EV-UI`，分别记录成功、取消、失败的适用路径；联系动作不产生预约事实还需服务端负向观察。
- 真实内容：`EV-CONTENT + EV-UI + EV-API`；作品另需 `EV-AUTH`，不能用测试人员口头确认替代。
- 域名和发布目标：`EV-CONFIG +` 目标环境请求/页面结果；开发地址或 H5 成功不充分。

证据必须可定位到执行记录、断言和时间。证据位置使用受控引用，不在本文或缺陷标题中粘贴令牌、完整签名 URL、客户资料、授权原件、内部堆栈或供应商秘密。证据访问权限和保留期限待评审，不在本文锁定。

## 5. 缺陷严重度与阻断属性

严重度描述业务影响；是否阻断本次阶段验收由门禁规则和“阻断属性”共同决定，不能只按用例优先级推导。

| 严重度 | 定义 | 阶段一示例 |
|---|---|---|
| `S0-致命` | 已造成或可直接造成未授权公开、真实隐私/秘密泄露、不可控破坏，且无可接受隔离 | 资格未知仍展示客户作品；公开响应含客户资料或生产密钥 |
| `S1-严重` | P0 不变量失守、主流程不可用、真实内容错误可能误导客户，或撤回/旧链接可绕过 | 撤回后媒体仍可访问；四 Tab 关键入口不可达；价格语义错误 |
| `S2-一般` | 局部功能错误或恢复性下降，有明确边界且不破坏 P0，可采用受控规避 | 单个非必需区块降级错误、局部重试反馈不清楚 |
| `S3-轻微` | 不影响业务事实、安全和主要可用性的视觉/文案问题 | 非关键信息排版或辅助文案偏差 |

以下缺陷自动标记“阻断阶段一验收”：

- 任一 P0 安全不变量失败；
- 未授权、资格未知、撤回、下架、旧链接或媒体复核可被绕过；
- 公开响应、页面、日志或证据泄露客户隐私、授权原件、内部 key、签名或密钥；
- P1 主流程无法完成且无经评审的同等安全路径；
- 真实品牌、套餐价格语义、联系方式或授权结论错误；
- 微信真机、域名、真实内容、授权或撤回强制门禁无法执行；
- 缺陷使结果不可复核、不可定位或环境污染其他批次。

S0/S1 默认阻断；任何降级必须由业务/产品、相应规则责任人、技术和测试共同记录风险接受依据，且不得豁免 P0 或本文强制门禁。S2/S3 是否阻断取决于影响范围和门禁；“严重度较低”不是自动放行理由。

## 6. 执行准入条件

### 6.1 通用准入

执行批次开始前必须满足：

1. 候选构建唯一、可获取且未在批次中被替换。
2. 入选主用例、变体、设计状态和就绪状态明确；用例来源可追踪。
3. D-706 环境实例、数据基线、`runId`、时钟和清理能力已登记。
4. 所需观察面可用：页面、API、requestId、脱敏日志、任务或数据结果。
5. 替身与真实依赖边界明确，故障注入获准且不影响共享/生产事实。
6. 已知待决项已映射到受阻用例；执行人不得临场猜测 TTL、字段、设备范围或供应商行为。
7. 证据存放位置、访问权限和脱敏检查可用。
8. 执行人与复核人角色明确，安全事件停止条件已知。

### 6.2 验收批次附加准入

阶段一 `STAGE_ACCEPTANCE` 还必须满足：

- D-401、D-602 与实际实现之间的接口/展示映射已形成；字段名仍可变化，但业务断言不得缺失；
- HTTPS、目标小程序合法域名和候选发布目标已评审并可核验；
- 微信目标环境和经评审的真机/网络组合可用；
- 首批真实品牌、六类业务、套餐/价格语义、地址、电话和微信联系方式已有责任人确认；
- 首批真实公开作品有可引用的 A15 资格结论，且存在获准的撤回/下架验证样本与受控流程；
- 公开数据更新、发布、下架和撤回流程已评审并能留痕；本文不规定其具体工具；
- P0、P1、故障恢复、微信真机和真实内容强制选集已冻结。

任何附加准入缺失时，验收批次不得伪装成完整验收；可执行不依赖该条件的预验证批次，并将相关项标为 `BLOCKED`。

## 7. 批次退出条件

一个执行批次只有在以下条件同时满足时才可标记“执行完成”：

- 入选执行记录均为 `PASS`、`FAIL` 或有明确原因的 `BLOCKED`，不遗留无说明的 `NOT_RUN`；
- 每条结果有满足断言的证据引用，失败和阻塞可复核；
- 所有 `FAIL` 已关联缺陷，严重度、阻断属性、负责人类型和当前状态明确；
- 复测使用新记录，原始失败证据未覆盖；
- 数据清理结果已记录，需保留的失败现场已按安全方式固化；
- 批次汇总列出选集、排除、结果分布、未决项和残余风险；
- 执行人与复核人完成签认。

“执行完成”允许包含失败或阻塞，因此不等于“门禁通过”。验收批次还必须满足第 9 节全部门禁，才能给出产品验收通过结论。

## 8. 度量与判定原则

允许报告以下事实指标：

- 主用例计划数、变体计划数、实际执行数；
- `PASS/FAIL/BLOCKED/NOT_RUN` 数量；
- 按 P0/P1/P2、层级、环境、场景组和真实/合成数据拆分的结果；
- 打开缺陷数量、严重度、阻断属性和复测状态；
- BIZ 24 次强制参数化执行完成数；
- 微信目标环境、真机、真实内容、联系方式、域名、授权和撤回门禁状态。

可计算通过率：

```text
观察通过率 = PASS / (PASS + FAIL)
```

`BLOCKED` 和 `NOT_RUN` 必须并列展示，不得从报告中隐藏；该通过率只描述已得到判定的记录，不能作为单独门禁。即使通过率很高，只要存在一个 P0 失败、一个强制项未执行、真实内容未核验或真机/域名/撤回门禁受阻，阶段一仍不能验收通过。

禁止使用以下替代判定：

- 用总体通过率冲抵 P0 失败；
- 用代码覆盖率、接口数量或自动化数量替代业务覆盖；
- 用 H5、模拟器或开发工具结果替代微信真机；
- 用合成联系方式和合成作品替代真实内容/授权核验；
- 用列表过滤替代详情、旧链接和媒体网关复核；
- 用重试后成功覆盖首次失败和重复副作用；
- 用“文档已完成”替代产品验收。

## 9. 阶段一验收门禁

以下门禁全部为 `PASS` 才能给出“阶段一产品验收通过”。任一门禁为 `FAIL`、`BLOCKED` 或 `NOT_RUN`，结论均为“不通过/待补齐”，不得按加权分数或总体通过率放行。

| 门禁 ID | 强制条件 | 通过依据 |
|---|---|---|
| `G-S1-01` 追踪与基线 | 54 个主用例均可追踪；46 个 D-702 场景和 8 个故障补充无缺口；批次冻结同一候选版本 | D-708 快照、`EV-PLAN` |
| `G-S1-02` P0 安全不变量 | 全部 P0 强制变体均已执行且为 `PASS`；零 `FAIL`、零 `BLOCKED`、零 `NOT_RUN`；无未关闭 P0 缺陷 | P0 批次结果、API/数据/媒体/授权证据、缺陷清单 |
| `G-S1-03` P1 主流程 | 全部 P1 强制变体已执行，无 `BLOCKED`/`NOT_RUN`；不存在未关闭阻断缺陷；任何非阻断偏差有明确处置和责任人 | P1 批次、24 次 BIZ 明细、缺陷与风险记录 |
| `G-S1-04` 六类业务与价格 | 六类业务逐类执行；BIZ 四主用例形成 24 次结果；固定价、起价、询价、未披露语义均核验，未确认内容未伪造 | 参数化执行记录、真实内容确认 |
| `G-S1-05` 故障与恢复 | `S1-FAULT-01`～`08` 全执行；未知资格 fail-closed，重复/恢复不生成重复事实，失败任务不恢复不合格内容 | 故障序列、任务、日志和最终事实证据 |
| `G-S1-06` 微信目标环境与真机 | 目标小程序环境及经评审真机/网络组合完成关键路径；H5/模拟器不能替代 | `EV-DEVICE`、录屏、请求与反馈证据 |
| `G-S1-07` 真实内容与联系方式 | 品牌、六类业务、已发布套餐/价格、地址、电话、微信方式由责任人确认并在客户侧核验；联系动作不创建预约 | `EV-CONTENT`、真机联系结果、服务端负向观察 |
| `G-S1-08` HTTPS、域名与发布目标 | 候选版本使用已评审的 HTTPS、合法域名和目标环境；开发地址未进入目标配置；受控发布流程可追踪 | `EV-CONFIG`、目标环境请求、发布记录引用 |
| `G-S1-09` 授权、下架与撤回 | 首批公开作品资格有依据；资格未知不公开；获准样本完成撤回/下架、首页/列表/详情/旧链接/媒体/缓存任务验证 | `EV-AUTH`、`EV-API`、`EV-MEDIA`、`EV-UI`、`EV-TASK` |
| `G-S1-10` 数据安全与证据 | 敏感哨兵零泄露；无真实客户隐私和生产密钥进入 Fixture/报告；证据脱敏可复核 | 哨兵检查、证据复核、安全事件清单 |
| `G-S1-11` 缺陷收敛 | 无未关闭 S0/S1 或其他阻断缺陷；修复项有新复测记录；残余 S2/S3 有影响、责任人和决策 | 缺陷台账、复测证据、风险签认 |
| `G-S1-12` 范围一致 | 阶段一未误开放登录、预约、订单、支付、私密交付等阶段外能力；测试没有因其缺失判失败 | 范围检查、页面/API 负向结果 |

设备清单、媒体供应商、缓存 TTL 和发布流程的具体内容仍待评审；这不允许降低门禁。具体值未定时，相关门禁保持受阻，直至负责人提供关闭依据并更新 D-706/D-708。

## 10. 验收决策

验收结论只允许：

- `PASS`：全部 `G-S1-*` 门禁通过；
- `FAIL`：至少一个门禁已得到失败结论；
- `BLOCKED`：至少一个强制门禁因待决项、环境或证据无法判定，且没有已知失败需要优先报告；
- `NOT_RUN`：尚未建立或完成阶段一验收批次。

验收决策由业务/产品、内容/运营、授权/隐私、技术/发布和测试责任角色按各自范围签认。任何单一角色不得豁免 P0、安全、真实内容、域名、微信真机、授权或撤回门禁。

当前（2026-10-09）只完成测试体系文档编制工作，尚未形成候选实现执行批次；阶段一产品验收状态应记录为 `NOT_RUN`，不能写成 `PASS`。
