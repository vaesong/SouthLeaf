## 1. 测试范围与证据等级

本文件给出用例 ID、可观察断言和层级；各批编码时映射到实际测试类/浏览器用例，不能用设计行数代替覆盖率。

| 层级 | 能证明 | 不能替代 |
|---|---|---|
| L1 纯规则/应用单元 | 状态、时间、端口交互、输入边界 | MySQL 约束/锁/权限 |
| L2 模块/产物/启动 | 编译依赖、运行包内容、配置来源、拒绝生命周期 | 独立账号实际 grants |
| L3 真实 MySQL 事务 | 原子性、唯一约束、并发锁、回滚 | 生产隔离和真实外部平台 |
| L4 独立身份/双 schema | 真实 TLS/身份/权限，跨 schema 发布事务 | 正式部署批准 |
| L5 HTTP/HTTPS 浏览器 | Cookie/CSRF/错误/页面与真实后端联调 | 正式微信、用户验收/灾备 |
| L6 2B 运维与真实接入 | 正式身份、平台、UAT、容量/恢复/回退 | 未测试能力或长期零风险承诺 |

所有拟新增用例状态初始为 NOT_RUN；缺库/账号/证书/依赖分别记 BLOCKED；失败记 FAIL，不能用 skip 汇总为全通过。已有会话 IT 记录引用实施跟踪，不能给本轮新增用例直接标 PASS。

## 5. S1-D HTTP 与后台

| ID | 执行与断言 | 层级 |
|---|---|---|
| S1D-01 | GET csrf→login→session→logout→旧 token 拒绝；身份 DTO 不含内部秘密；使用真实隔离数据库 | L5 |
| S1D-02 | Cookie Secure/HttpOnly/SameSite/host-only/Path/expiry 与清除一致；无 JSESSIONID、localStorage token、缓存认证响应 | L5 |
| S1D-03 | 缺失/错误/当前 cookie 轮换后的旧 header CSRF、缺失/null/跨源 Origin、伪造代理头、跨站 CORS：拒绝；登录/退出后 CSRF 轮换 | L5 |
| S1D-04 | 未登录/过期/撤销/禁用/版本改变 401；有效身份越权 403；数据库/审计异常 503；无账号枚举差异 | L3/L5 |
| S1D-05 | 账号/来源/全局限流与 KDF 并发上限、键容量耗尽和窗口恢复；429 带 Retry-After；重启/多实例限制明确记录 | L1/L5 |
| S1D-06 | 4 KiB/JSON 重复未知字段/类型限制在 KDF 前拒绝；密码不 trim；请求日志/浏览器 trace 不泄露秘密 | L5 |
| S1D-07 | 退出审计失败不清 cookie 不报成功；登录超时先读 session 复核；不自动重放登录/写命令 | L3/L5 |
| S1D-08 | UNKNOWN 不闪受保护内容、403 不循环跳登录、503 不误判退出；多 tab、安全 returnTo、键盘/缩放/焦点可用 | 组件/L5 |
| S1D-09 | public API 与原生微信契约回归，管理依赖不进入公开产物；默认用户/Basic/form login/remember-me 均不存在 | L2/L5 |

CSRF cookie 本身可由 JS 读取，不是认证 token；旧 CSRF header 用真实 CookieJar/轮换后的 cookie 测试，不只手工传一个 header。认证 token 只经安全测试夹具注入，测试报告不得保留其原值。

## 6. S2/S3 发布与授权

- PUB-01：两个编辑者基于同 revision 保存，仅一方成功；失败方不能覆盖。
- PUB-02：伪装格式、超字节/像素、路径穿越、EXIF/GPS、处理失败/重试/重复任务；未 READY 不可发布，无公开原图回退。
- PUB-03：相同命令同输入返回同 release；同键不同输入冲突；旧 revision 发布不改变 active publication。
- PUB-04：私有状态/公开投影/最小授权状态/审计任一步故障，跨 schema 同连接事务全回滚；媒体孤儿保留不可公开并可安全清理。
- PUB-05：授权撤回/到期与发布/历史恢复竞争；提交后新列表/详情/首页引用/GET/HEAD/Range 读取均服从当前资格。已在途读取和已下载字节单独声明，不能承诺追回。
- PUB-06：security/business/publication/reader 各身份做正反权限测试；用受支持同实例 MySQL 验证，不能用两个 mock 数据源声称跨库 ACID。

## 7. S4/S5 预约确认与成单

- RES-01：本人身份由服务端解析，不能枚举他人申请/订单；手机号相同不自动合并，线下记录无凭据不得冒领。
- RES-02：多个待确认申请不占硬档；同幂等键重试仅一条申请，同键不同 payload 冲突。
- RES-03：两客户/两工作人员/线上线下竞争同档，仅一笔确认、一个占用、一张原始订单；不能只统计 HTTP 成功码，须验证最终数据库事实。
- RES-04：确认中订单/审计/outbox 写入故障，预约、占档、快照和任务全回滚；commit 未知按命令结果查询而非新键重发。
- RES-05：过期/封档与确认竞争、重复确认、已取消后确认；按状态/条件更新和全局锁序验证。
- RES-06：套餐变更不影响订单快照；跨日/夏令时/期限边界以明确 UTC/配置时区测试，经营规则由 Q02/Q04 决定。

## 8. S6 修订、通知与补偿

- REV-01：两个改期竞争目标档；失败保留原档与旧订单修订；取消/改期竞争无双占或丢档。
- REV-02：重复取消/重复修订命令结果幂等，旧版本不能覆盖新约定；通知失败不回滚业务事实。
- TASK-01：两个 worker 竞争租约、处理后崩溃、超时未知、重启恢复、有限重试、不可重试错误、人工恢复均有确定状态。
- TASK-02：provider 可能重复送达，测试业务不重复执行、消息去重键和人工记录；不宣称外部 exactly-once/已读。

## 9. 并发夹具与复现约束

使用真实 MySQL 8.4/InnoDB，两个独立连接/事务配合 latch/barrier 明确锁定点和提交顺序；不用 sleep 的偶然时序作为唯一证据。每个竞争用例至少验证两个允许的提交顺序、最终约束及审计/任务计数；死锁/超时的可重试边界需显式断言。

测试数据用唯一 testRunId/固定前缀，按关联逆序清理本次拥有的记录；不 TRUNCATE、重建运行库、关外键、共享生产 fixture。对共享测试 schema 的任务串行执行；独立输出目录不意味着数据库也可并行。强制隔离库名、身份和显式变量缺失即失败。

证据格式：用例 ID→实际测试路径、源版本/哈希、命令/退出码、JDK/MySQL/浏览器版本、环境类别、测试数、失败/跳过、断言摘要、限制。秘密/客户资料不入附件；仅工具链接检查通过不代表语义或业务验证通过。
