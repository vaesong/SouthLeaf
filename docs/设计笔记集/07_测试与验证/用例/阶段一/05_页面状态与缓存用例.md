## 1. 覆盖摘要

本文将 D-702 §5 的 8 个页面状态场景和 §6 的 5 个缓存场景逐个细化，共 13 个主用例。重点验证加载、空态、断网、超时、服务错误、格式错误、快速切换、后台恢复、部分区块失败，以及公开版本更新、陈旧详情、授权撤回、重复更新和更新任务失败。

| 用例范围 | 主用例数 | 重点风险 | 初始状态 |
|---|---:|---|---|
| `S1-STATE-01`～`S1-STATE-08` | 8 | 状态混淆、假数据回填、旧响应覆盖、请求风暴、局部故障扩大、旧作品图片闪现 | `NOT_RUN` |
| `S1-CACHE-01`～`S1-CACHE-05` | 5 | 版本更新不生效、陈旧详情继续展示、撤回后缓存泄露、重复版本/事件、失败任务无限重试 | `NOT_RUN` |
| 合计 | 13 | 页面恢复与缓存安全边界 | `NOT_RUN` |

执行约束：

- 普通品牌、业务和套餐**文字投影**可以按已评审策略短时缓存；作品媒体与文字投影必须采用分离规则。
- 首页、列表、详情、Tab 返回、后台恢复和分享/扫码入口中的作品媒体，在每次展示前均须通过 SouthLeaf 受控媒体网关复核当前发布、绑定及授权/资格；复核前保持 `hiddenPendingEligibility` 或等价隐藏状态。
- 作品媒体和公开错误响应必须按 `Cache-Control: no-store` 消费；不得通过 304、Range、本地文件命中、旧 URL 或缓存元数据绕过资格检查。
- 授权/资格未知、超时或无法证明时 fail-closed。缓存失效或投影重建任务失败不得恢复已下架、撤回或资格失效的作品。
- 普通文字缓存 TTL、ETag 具体值、刷新阈值、失效传播时限、自动重试次数及页面视觉尚未评审，本文不写入数值或像素级预期。可观察预期以状态语义、可操作性、请求顺序和安全结果为准。
- 本文只定义用例，尚未执行，不产生通过结论。

## 2. 页面状态详细用例

### S1-STATE-01 首次加载不闪现旧资源或假数据

- **用例 ID**：`S1-STATE-01`
- **名称**：首次进入页面的加载状态与作品媒体展示前复核
- **优先级**：P0
- **类型/建议测试层**：正向 + 时序；组件/页面、接口消费集成、微信目标环境
- **规则来源**：D-702 §5 `S1-STATE-01`；D-401 §6.1；D-602 §2.3、§3.1、§7、§9；D-701 §5
- **前置条件**：
  - 设备本地存在资源 A 的普通文字缓存和旧作品媒体痕迹；将要进入的是资源 B 或同资源的新公开版本。
  - 资源 B 当前资格有效，资格复核和媒体读取响应可被测试替身延迟控制。
  - 页面状态、渲染数据、媒体请求及网络时序可观察。
- **测试数据/故障注入**：
  - 文字投影 `brand_state_01_v1`、`brand_state_01_v2`。
  - 作品 A `work_state_01_old` 与作品 B `work_state_01_current` 使用明显不同的合成标题和自有测试图。
  - 资格响应延迟，媒体响应在资格确认后再成功；无服务错误。
- **步骤**：
  1. 预置资源 A 的普通文字缓存及旧媒体痕迹，关闭页面后从冷启动进入资源 B 页面。
  2. 在接口响应返回前记录页面状态、当前标题/价格/图片及可操作控件。
  3. 让普通文字响应先返回，继续保持资格复核和媒体响应待定，记录页面状态。
  4. 返回资源 B 的当前资格有效结果，再返回受控媒体网关结果。
  5. 重复执行首页、列表、详情和分享入口，观察状态转换顺序。
- **可观察预期**：
  - 页面进入明确的加载/骨架或等价状态，结构稳定且可返回；具体视觉样式不由本用例锁定。
  - 不把资源 A 的标题、价格或图片显示为资源 B；生产环境不回填内置示例数据。
  - 已允许缓存的普通品牌/业务/套餐文字可按策略显示，但作品媒体始终保持隐藏，直到本次当前资格复核和媒体读取均成功。
  - 媒体最终显示时对应资源 B 的当前受控引用，且媒体响应为 `no-store`。
- **证据要求**：
  - 页面状态时间线、请求/响应时间线和渲染数据快照。
  - 资格复核先于媒体可见的事件记录，以及媒体响应头。
  - 首页、列表、详情、分享入口各一次执行证据。
- **阻塞/待决条件**：
  - 加载骨架、占位内容、动效和尺寸等页面视觉尚未锁定，不作为当前断言。
  - 普通文字缓存 TTL 未锁定；不阻塞“旧资源不得冒充当前资源、作品媒体复核前隐藏、媒体 no-store”的安全断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-02 成功空结果进入真实空态

- **用例 ID**：`S1-STATE-02`
- **名称**：成功空结果与错误状态严格区分
- **优先级**：P1
- **类型/建议测试层**：等价类 + 页面状态；适配层单元、页面集成、微信目标环境
- **规则来源**：D-702 §5 `S1-STATE-02`；D-602 §2.1、§3.2、§4、§9；P01 §3.2、§3.5
- **前置条件**：
  - 作品列表、某一摄影业务套餐列表和首页可选区块均可返回 `OK`/HTTP 200 的空集合或契约定义的空区块。
  - 页面请求计数可观察。
- **测试数据/故障注入**：
  - 当前无公开作品的数据集。
  - 已发布业务 `business_state_02`，当前无已发布套餐。
  - 首页可选作品区块为空，其他品牌/联系区块有有效数据。
  - 无故障注入。
- **步骤**：
  1. 打开作品列表，等待成功空响应完成。
  2. 打开 `business_state_02` 详情及套餐列表，等待成功空响应完成。
  3. 打开首页，观察空作品区块与其他成功区块。
  4. 保持页面静置并切换一次 Tab，记录是否发生自动循环请求。
  5. 使用页面提供的返回、切换业务或联系入口，确认操作仍可用。
- **可观察预期**：
  - `OK`/200 且空集合映射为 `success(empty)` 或等价空态，不映射为网络错误、服务错误或资源不可用。
  - 页面不生成测试作品、测试套餐、0 元价格或历史原型内容。
  - 首页空的可选区块可隐藏或显示简短空态，其他成功区块继续可用；具体视觉方案待决。
  - 空态不会自动无限重试；返回、切换业务或已确认的联系入口可操作。
- **证据要求**：
  - 三类空响应、页面状态记录和请求计数时间线。
  - 页面渲染数据中无示例资源、伪造价格的检查结果。
  - 可操作入口的目标及未创建预约事实的记录。
- **阻塞/待决条件**：
  - 空态文案、插图、区块隐藏方式等页面视觉待评审。
  - 不阻塞成功空结果不得伪装错误、不得回填假数据和不得无限重试的断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-03 无网络时保留安全状态并支持主动重试

- **用例 ID**：`S1-STATE-03`
- **名称**：冷启动及浏览中的断网反馈与恢复
- **优先级**：P1
- **类型/建议测试层**：故障恢复；页面集成、网络模拟、微信目标环境/真机
- **规则来源**：D-702 §5 `S1-STATE-03`；D-602 §4、§7、§8、§9；D-701 §5
- **前置条件**：
  - 可控制设备网络断开和恢复。
  - 分别准备无任何缓存的冷启动环境，以及仅有允许缓存的普通文字投影环境。
  - 设备可能残留旧作品图片，但该图片不得作为可用缓存展示。
- **测试数据/故障注入**：
  - 合格作品 `work_state_03`，断网前后资格保持有效。
  - 在请求发出前断网；另设请求进行中断网变体。
- **步骤**：
  1. 清除允许缓存的数据后断网，冷启动进入作品列表和详情。
  2. 记录页面状态、返回能力、重试控件和是否出现示例/旧作品图片。
  3. 在具有普通文字缓存的环境中断网重入页面，观察文字与作品媒体的独立行为。
  4. 连续点击重试控件，记录并发请求数和控件状态。
  5. 恢复网络后执行一次主动重试，记录新请求、`requestId`、资格复核和最终状态。
- **可观察预期**：
  - 冷启动显示网络不可用语义和返回/主动重试能力，不以生产内置示例数据填充内容区。
  - 允许缓存的普通文字可按已评审策略保留，但旧作品媒体不显示；作品媒体必须等待恢复后的当前资格复核。
  - 重复点击不会形成无界并发请求；失败时不无限自动刷新。
  - 网络恢复后主动重试使用新请求和新 `requestId`，资格确认及媒体读取成功后才显示作品媒体。
- **证据要求**：
  - 冷启动、有文字缓存两种环境的页面状态和网络日志。
  - 重复点击期间请求并发数、按钮状态和恢复时间线。
  - 恢复后新 `requestId`、资格复核及媒体 `no-store` 证据。
- **阻塞/待决条件**：
  - 退避间隔、点击合并窗口、普通文字 TTL 和网络提示视觉未锁定。
  - 不阻塞无假数据、无无限重试、旧媒体隐藏及恢复后重新复核资格的断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-04 超时或 5xx 不产生请求风暴

- **用例 ID**：`S1-STATE-04`
- **名称**：公开查询超时、503 与恢复后的有限重试
- **优先级**：P1
- **类型/建议测试层**：故障恢复 + 请求控制；适配层单元、页面集成、网络模拟
- **规则来源**：D-702 §5 `S1-STATE-04`；D-401 §7；D-602 §4、§6、§8；D-701 §5、§6
- **前置条件**：
  - 请求替身可注入连接超时、响应超时和 `PUBLIC_SERVICE_UNAVAILABLE`/HTTP 503。
  - 可统计单位页面生命周期内的请求发起、取消和完成次数。
- **测试数据/故障注入**：
  - 首页必需查询分别注入连接超时、响应超时、连续 503，之后恢复为 `OK`/200。
  - 内部错误信息带哨兵 `S1_STATE_04_INTERNAL_SERVICE_SENTINEL`。
- **步骤**：
  1. 首次进入页面并分别触发连接超时、响应超时和 503。
  2. 保持故障一段可观测窗口，记录自动请求、页面状态、`requestId` 和错误展示。
  3. 快速多次点击重试并切换 Tab，记录请求合并、取消或忽略情况。
  4. 恢复服务后主动重试，记录新请求和最终页面状态。
  5. 检查客户端日志和页面信息是否包含内部服务哨兵或完整错误。
- **可观察预期**：
  - 超时/503 映射为服务暂不可用或等价可重试状态，页面可返回且不崩溃。
  - 故障期间没有无限自动刷新或并发请求风暴；重复操作受到合并、禁用或等价控制。
  - 每次实际重试获得新的 `requestId`；恢复后只采用当前有效响应更新页面。
  - 内部服务名、堆栈和哨兵不向客户或客户端日志泄露。
- **证据要求**：
  - 三种故障的页面状态、请求计数与并发时间线。
  - 故障及恢复请求的 `requestId` 对照、网络响应和脱敏日志。
  - 内部哨兵扫描结果。
- **阻塞/待决条件**：
  - **BLOCKED（数量/时间断言）**：超时阈值、自动重试是否启用、最大重试次数及退避参数未确认。
  - 不阻塞禁止无限重试/请求风暴、允许主动恢复及错误脱敏的断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-05 响应格式错误进入可恢复异常状态

- **用例 ID**：`S1-STATE-05`
- **名称**：公开响应缺字段、错类型或无法转换时页面不崩溃
- **优先级**：P1
- **类型/建议测试层**：负向契约 + 健壮性；适配层单元、页面集成
- **规则来源**：D-702 §5 `S1-STATE-05`；D-401 §7；D-602 §2.1、§4、§6、§9；D-701 §2、§5
- **前置条件**：
  - API 适配层可注入原始响应，客户端异常和 `requestId` 可观察。
  - 页面已有资源 A，随后导航到资源 B，以检查错误时不会保留错误资源。
- **测试数据/故障注入**：
  - 变体包含：非 JSON、响应外层缺失、`code` 错类型、`data` 结构错、DTO 必需字段缺失、枚举未知、媒体引用非法。
  - 每个变体带独立 `requestId`；响应体含内部哨兵 `S1_STATE_05_PARSE_SENTINEL`。
- **步骤**：
  1. 从资源 A 导航到资源 B，令 B 的响应依次返回各格式错误变体。
  2. 记录适配层错误分类、页面状态、当前渲染资源和可用操作。
  3. 检查页面或客户端日志是否显示完整原始响应、堆栈或内部哨兵。
  4. 对一个失败变体点击重试，返回合法响应并记录恢复过程。
  5. 验证资源 A 的旧标题和作品图片未被当作资源 B 的成功内容。
- **可观察预期**：
  - 服务端返回 `PUBLIC_RESPONSE_INVALID`/HTTP 500 时，或客户端发现无法解析的等价情况时，页面进入通用可恢复异常状态。
  - 页面不崩溃、不显示半解析敏感字段，也不把资源 A 的内容冒充资源 B。
  - 保留可用于反馈的 `requestId`；客户提示与客户端日志不泄露原始响应、堆栈或哨兵。
  - 合法重试响应到达后可恢复当前页面，作品媒体仍遵守展示前资格复核。
- **证据要求**：
  - 每个畸形变体的原始响应、适配结果、页面状态和崩溃监控记录。
  - `requestId` 关联及敏感内容扫描结果。
  - 从错误到合法响应的恢复时间线。
- **阻塞/待决条件**：
  - **BLOCKED（精确 DTO 校验）**：最终响应字段、必填性和枚举需契约锁定后才能确定全部格式错误变体。
  - 页面不得崩溃、不得泄露、不得错误复用上一资源和必须可恢复不受阻塞。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-06 重复点击与快速切换时旧响应不覆盖

- **用例 ID**：`S1-STATE-06`
- **名称**：同参请求合并及跨资源响应时序隔离
- **优先级**：P0
- **类型/建议测试层**：竞态 + 时序；状态管理单元、页面集成、微信目标环境
- **规则来源**：D-702 §5 `S1-STATE-06`；D-602 §3.1、§8、§9；D-701 §5
- **前置条件**：
  - 能精确控制多个请求返回顺序并观察页面当前路由、请求令牌和渲染状态。
  - 准备资源 A、B 和筛选条件 X、Y，内容可明显区分。
- **测试数据/故障注入**：
  - 时序一：A 请求先发、B 请求后发，B 先成功，A 最后成功。
  - 时序二：筛选 X 请求先发、Y 后发，X 最后返回错误。
  - 时序三：同页面同参数连续点击刷新，响应延迟。
- **步骤**：
  1. 打开 A，在其请求未完成时快速切换到 B；先返回 B，再返回 A。
  2. 在作品列表先选择筛选 X，随即切到 Y；先返回 Y，再返回 X 的错误。
  3. 对同一资源和参数快速连续触发刷新，记录实际请求数及响应处理次数。
  4. 在每个阶段记录路由、标题、列表项、错误状态和作品媒体可见性。
  5. 检查被取消或标记过期的响应是否仍改变缓存、页面或媒体状态。
- **可观察预期**：
  - B 成功后，晚到的 A 响应不覆盖 B 的标题、数据、错误或媒体状态；Y 同理不被 X 覆盖。
  - 不再可见页面的旧请求被取消或其结果被忽略；旧错误不会弹到当前页面。
  - 同页面同参数请求可合并、禁用重复触发或以等价方式控制，不形成无界并发。
  - 当前作品媒体仍需当前资源资格复核，旧资源的已加载图片不得闪现或恢复。
- **证据要求**：
  - 三组请求的发起/返回顺序、请求标识、路由状态和渲染状态时间线。
  - 同参请求实际调用次数与响应处理记录。
  - 旧响应未写入当前缓存/媒体状态的状态快照或自动化断言。
- **阻塞/待决条件**：
  - 请求取消还是逻辑忽略、同参合并窗口等实现方式未锁定。
  - 旧响应不得覆盖新页面状态、不得显示旧作品媒体及不得产生请求风暴属于实现无关断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-07 从后台恢复时按类型安全刷新

- **用例 ID**：`S1-STATE-07`
- **名称**：小程序后台恢复后的文字缓存判断与作品媒体重新复核
- **优先级**：P0
- **类型/建议测试层**：生命周期 + 缓存安全；页面集成、微信目标环境/真机
- **规则来源**：D-702 §5 `S1-STATE-07`；D-401 §6.1；D-602 §7、§8、§9；D-701 §2、§5
- **前置条件**：
  - 页面已加载普通文字投影和作品媒体，可控制进入后台、恢复及缓存年龄。
  - 后台期间可改变公开版本、作品授权资格或发布状态。
- **测试数据/故障注入**：
  - 变体 A：后台期间无内容变化，普通文字缓存仍在策略允许范围内。
  - 变体 B：后台期间普通文字版本更新。
  - 变体 C：后台期间作品授权撤回或资格结果变为未知。
  - 资格查询在恢复时可延迟或超时。
- **步骤**：
  1. 加载页面后进入后台，再在无变化条件下恢复，记录文字查询和媒体资格查询。
  2. 重复快速后台/前台切换，记录请求数量。
  3. 在后台期间更新普通文字版本，恢复并观察版本协商和页面更新。
  4. 在后台期间撤回作品授权，恢复时延迟资格响应，观察旧媒体是否先显示。
  5. 令资格读取超时/未知，再恢复网络并重新进入页面。
- **可观察预期**：
  - 普通文字投影按页面类型、获取时间和版本策略决定是否刷新，不因每次生命周期事件无条件高频请求。
  - 所有当前可见作品媒体在恢复时先隐藏，并重新完成当前发布、绑定和授权/资格检查；不得先显示旧图再异步校验。
  - 撤回、超时或资格未知时 fail-closed，旧作品媒体保持不可见且对应资源状态被清理或标记不可用。
  - 普通文字更新和作品媒体资格采用分离逻辑，文字缓存命中不构成媒体资格证明。
- **证据要求**：
  - 生命周期事件、缓存年龄/版本、网络请求和媒体可见状态的联合时间线。
  - 快速恢复期间请求计数，以及撤回/未知变体的 fail-closed 记录。
  - 媒体响应 `no-store` 与未使用 304/Range 绕过复核的网络证据。
- **阻塞/待决条件**：
  - **BLOCKED（刷新频率断言）**：普通文字 TTL、后台停留阈值和允许的刷新频率未确认。
  - 不阻塞恢复时作品媒体先隐藏并复核、资格未知拒绝、文字与媒体规则分离的安全断言。
- **初始执行状态**：`NOT_RUN`

### S1-STATE-08 首页部分区块失败不扩大为整页失败

- **用例 ID**：`S1-STATE-08`
- **名称**：首页区块和可选媒体的局部失败、降级与重试
- **优先级**：P1
- **类型/建议测试层**：组合故障 + 局部恢复；适配层、页面集成、接口联调
- **规则来源**：D-702 §5 `S1-STATE-08`；D-401 §7；D-602 §2.3、§3.2、§4、§9；D-701 §5
- **前置条件**：
  - 首页包含品牌、精选作品、业务、套餐和联系等独立可观察区块。
  - 测试替身可以让单一区块或单个可选媒体失败，而其他区块成功。
- **测试数据/故障注入**：
  - 变体 A：精选作品区块失败，品牌、业务、套餐和联系成功。
  - 变体 B：一个可选媒体字段缺失但聚合响应为 `OK`/200。
  - 变体 C：资格已确认后，单个独立媒体网关读取返回 `PUBLIC_MEDIA_UNAVAILABLE`/503。
  - 变体 D：首页必需依赖整体不可用，返回 `PUBLIC_SERVICE_UNAVAILABLE`/503。
- **步骤**：
  1. 分别触发变体 A～D，保存聚合响应、独立媒体响应和页面状态。
  2. 对变体 A 检查其他成功区块的内容、导航和联系动作。
  3. 对变体 B、C 检查文字、其他已确认媒体及失败媒体项的状态。
  4. 对局部失败执行区块或单项重试，确认不重复加载所有成功区块。
  5. 对变体 D 检查整页服务不可用处理，不把它误判为部分成功。
- **可观察预期**：
  - 可隔离的单一区块失败不阻塞其他成功区块；失败区块提供局部降级或重试能力，具体视觉待定。
  - 主资源仍可用的可选媒体缺失通过 `OK`/200 成功响应内的契约表达处理，不把聚合 JSON 同时解释为 503。
  - 资格已确认后的单项媒体网关失败按 `PUBLIC_MEDIA_UNAVAILABLE`/503 处理；其他文字和已确认媒体仍可使用。
  - 必需依赖整体不可用才进入整页 `PUBLIC_SERVICE_UNAVAILABLE`/503，不用空态掩盖服务故障。
- **证据要求**：
  - 四种变体的接口响应、页面区块状态和请求时间线。
  - 局部重试前后各区块请求次数及状态变化。
  - 媒体资格确认记录和独立媒体 503 响应证据。
- **阻塞/待决条件**：
  - **BLOCKED（局部呈现细节）**：首页哪些区块属于必需依赖、最终部分成功契约和视觉降级/占位方式尚需评审。
  - 不阻塞“可隔离故障不扩大、200/503 不二义、资格未知不作为媒体失败降级”的断言。
- **初始执行状态**：`NOT_RUN`

## 3. 缓存与更新详细用例

### S1-CACHE-01 公开版本更新后普通文字获得新内容

- **用例 ID**：`S1-CACHE-01`
- **名称**：普通文字投影的 contentVersion/ETag 更新识别
- **优先级**：P1
- **类型/建议测试层**：缓存一致性 + 契约；接口集成、页面集成
- **规则来源**：D-702 §6 `S1-CACHE-01`；D-401 §3.2、§6.1；D-602 §7；D-701 §7；P01 §3.3、§3.5
- **前置条件**：
  - 普通品牌、业务或套餐文字投影存在版本 V1，客户端已缓存 V1、资源标识和获取时间。
  - 可发布 V2 并观察版本协商请求、公开投影及页面状态。
- **测试数据/故障注入**：
  - V1/V2 使用明显不同的合成名称、说明和 `contentVersion`。
  - 若实现采用 ETag，则准备匹配与不匹配协商；若采用等价机制，则记录实际版本协议。
  - 关联作品媒体保持相同资格，用于确认其不复用文字缓存协议。
- **步骤**：
  1. 请求 V1 并记录普通文字、版本标识、缓存元数据和响应头。
  2. 在服务端发布 V2，确认权威公开版本已更新。
  3. 从下拉刷新、重新进入和后台恢复分别触发读取，记录版本协商及页面内容。
  4. 在版本未变条件下重复读取，观察实现是否安全复用文字缓存。
  5. 检查同页作品媒体请求，确认未用文字 ETag、304 或本地命中替代当前资格复核。
- **可观察预期**：
  - 客户端能够识别 V2 并最终展示 V2 的普通文字，不把 V1 长期作为当前正式内容。
  - 版本未变化时可按已评审机制复用普通文字缓存，但缓存项包含版本、获取时间和资源标识。
  - 作品媒体始终走独立的当前资格复核和受控网关读取，响应为 `no-store`；文字版本命中不使媒体获得 304/Range 绕过。
- **证据要求**：
  - V1/V2 响应、版本协商请求、缓存元数据和页面更新记录。
  - 文字与作品媒体的网络请求对照及媒体响应头。
  - 重新进入、下拉刷新、后台恢复三种入口证据。
- **阻塞/待决条件**：
  - **BLOCKED（精确缓存协议）**：普通文字 TTL、ETag 值、是否使用 304及刷新时限尚需评审。
  - 不阻塞版本变化可识别、旧文字不得长期覆盖 V2、作品媒体规则独立且 no-store 的断言。
- **初始执行状态**：`NOT_RUN`

### S1-CACHE-02 陈旧详情进入时重新确认当前结果

- **用例 ID**：`S1-CACHE-02`
- **名称**：详情缓存陈旧、版本不一致与晚到旧响应隔离
- **优先级**：P0
- **类型/建议测试层**：缓存安全 + 竞态；接口集成、页面集成、分享深链
- **规则来源**：D-702 §6 `S1-CACHE-02`；D-401 §4、§6.1；D-602 §5、§7；D-701 §3、§5
- **前置条件**：
  - 详情 V1 已被客户端读取，随后服务端发布 V2 或将资源下架。
  - 可延迟 V1 刷新请求，使其晚于 V2/不可用结果返回。
  - 已保存详情旧链接和旧媒体引用。
- **测试数据/故障注入**：
  - 变体 A：V1 更新为仍可公开的 V2。
  - 变体 B：V1 资源下架或授权撤回。
  - 变体 C：旧 V1 请求晚于当前 V2 或 404 返回。
- **步骤**：
  1. 打开 V1 详情并保存普通文字缓存、版本和媒体引用。
  2. 发布 V2，从列表、旧链接和分享入口进入详情，记录重新查询/版本确认。
  3. 从独立基线将 V1 下架或撤回，再通过旧链接进入详情。
  4. 控制旧 V1 响应最后到达，观察当前详情和缓存是否被覆盖。
  5. 在所有步骤检查作品媒体可见状态与资格复核请求。
- **可观察预期**：
  - 进入详情时重新查询或确认当前版本；V2 成为正式详情，V1 不持续覆盖。
  - 下架或撤回后返回统一不可用并清理对应本地缓存项，不继续显示陈旧详情或旧作品图片。
  - 晚到的 V1 响应不覆盖 V2 或当前不可用状态，也不重新写回有效缓存。
  - 作品媒体在每次入口展示前隐藏并重新校验，旧媒体引用及本地文件命中不能作为资格证明。
- **证据要求**：
  - V1/V2/不可用的请求响应、版本、路由和渲染时间线。
  - 晚到响应被忽略及缓存未被回写的状态证据。
  - 旧链接、分享入口和媒体 `no-store`/资格复核记录。
- **阻塞/待决条件**：
  - 详情普通文字在刷新期间是否可短暂展示及其最终交互视觉待评审。
  - 当前服务端结果优先、旧响应不得覆盖、撤回后旧媒体不得显示不受阻塞。
- **初始执行状态**：`NOT_RUN`

### S1-CACHE-03 授权撤回后各入口和媒体缓存安全失效

- **用例 ID**：`S1-CACHE-03`
- **名称**：授权撤回后的投影、页面、受控媒体与旧链接收敛
- **优先级**：P0
- **类型/建议测试层**：跨模块安全 + 缓存失效；领域/应用服务、接口、页面、微信目标环境
- **规则来源**：D-702 §6 `S1-CACHE-03`、§6 安全默认；D-401 §4、§6.1；D-602 §5、§7、§9；D-701 §1、§7；P01 §3.3、§3.5
- **前置条件**：
  - 作品初始已发布且资格有效，首页、列表、详情和分享旧链接均可访问。
  - 客户端曾加载普通文字和作品媒体；可触发 A15 授权撤回并观察公开资格、投影/失效任务及受控媒体网关。
- **测试数据/故障注入**：
  - 作品 `work_cache_03` 与媒体 `media_cache_03`。
  - 变体 A：撤回后失效任务正常完成。
  - 变体 B：撤回后缓存失效/投影重建任务失败或延迟。
  - 变体 C：撤回后的资格读取暂时未知。
- **步骤**：
  1. 在撤回前从首页、列表、详情和分享入口访问作品，记录公开版本和媒体引用。
  2. 执行授权撤回并确认 A15 权威事实已成立。
  3. 在失效任务完成前立即重查首页、列表、详情和旧媒体引用。
  4. 分别执行任务正常、任务失败/延迟及资格未知变体，并从后台恢复、清缓存设备和另一设备复查。
  5. 任务恢复后再次检查所有入口及任务/日志状态。
- **可观察预期**：
  - 撤回事实成立后，公开查询和媒体网关以当前事实拒绝：列表/首页不再返回，详情和旧链接统一不可用，旧媒体不得显示。
  - 缓存失效或投影任务失败不恢复公开；资格读取未知时 fail-closed。
  - 媒体响应为 `no-store`，304、Range、本地文件、旧 URL、后台恢复和跨设备均不能绕过当前资格校验。
  - 失败任务可追踪并可恢复，但不得删除授权撤回事实或泄露撤回原因。
- **证据要求**：
  - 撤回事实、资格结果、公开查询、媒体网关与页面状态的联合时间线。
  - 正常、任务失败/延迟、资格未知三种变体证据。
  - 两设备/清缓存/后台恢复及 304、Range 绕过尝试记录。
- **阻塞/待决条件**：
  - **BLOCKED（时限断言）**：缓存失效传播目标和任务完成时限尚未确认，不能声称在具体秒数内收敛。
  - 不阻塞撤回事实成立后查询与媒体必须立即按当前资格拒绝、未知 fail-closed 及任务失败不得恢复公开的安全断言。
- **初始执行状态**：`NOT_RUN`

### S1-CACHE-04 重复更新任务保持逻辑幂等

- **用例 ID**：`S1-CACHE-04`
- **名称**：同一公开更新意图重复执行不创建重复版本、媒体或审计事件
- **优先级**：P1
- **类型/建议测试层**：幂等 + 任务集成；应用服务、任务执行器、持久化集成
- **规则来源**：D-702 §6 `S1-CACHE-04`；D-704 §3、§4、§6；D-701 §6；P01 §6
- **前置条件**：
  - 可通过受控维护流程提交一个公开文字/编排更新意图，并观察公开版本、媒体登记、任务、执行日志和逻辑审计事件。
  - 同一业务意图具有稳定幂等标识或等价去重依据。
- **测试数据/故障注入**：
  - 更新意图 `update_cache_04`，目标内容 V1→V2。
  - 注入重复投递、首次处理成功后响应丢失、服务重启后再次投递三个变体。
- **步骤**：
  1. 记录 V1 的公开版本、媒体记录、任务和逻辑审计事件基线。
  2. 提交 `update_cache_04`，让首次执行完成但向调用方丢失响应。
  3. 使用同一业务意图和幂等标识重投两次，并在服务重启后再次投递。
  4. 读取最终公开内容、版本、媒体登记、任务执行日志和审计事件。
  5. 从客户端刷新并确认获取唯一的 V2 结果，作品媒体仍执行独立资格复核。
- **可观察预期**：
  - 多次物理执行可形成多条执行日志，但只形成一个逻辑更新结果、一个目标公开版本和一组目标媒体绑定。
  - 不创建重复公开媒体、重复编排项或重复逻辑业务审计事件；同一幂等意图返回可识别的一致结果。
  - 重启后可安全续跑，不回退到 V1，也不跳过作品媒体资格复核。
- **证据要求**：
  - 幂等标识、每次投递/调用次数、任务执行日志及返回结果。
  - 更新前后公开版本、媒体记录和逻辑审计事件数量对照。
  - 客户端最终版本及媒体资格复核证据。
- **阻塞/待决条件**：
  - 幂等键字段、更新接口/任务名称、审计事件模式和保留周期尚需实现设计锁定。
  - 不阻塞同一更新意图只能形成一个逻辑版本/媒体结果的断言。
- **初始执行状态**：`NOT_RUN`

### S1-CACHE-05 更新任务失败遵守安全默认并可人工处理

- **用例 ID**：`S1-CACHE-05`
- **名称**：公开更新、投影重建或失效任务失败后的有限恢复
- **优先级**：P0
- **类型/建议测试层**：故障恢复 + 运维可观测；任务集成、接口、页面联调
- **规则来源**：D-702 §6 `S1-CACHE-05`、§6 安全默认；D-401 §4、§6.1；D-602 §7；D-704 §6；D-701 §6
- **前置条件**：
  - 可使更新任务在读取源、写入投影、失效缓存或确认结果阶段失败。
  - 可观察权威业务事实、公开投影、任务状态、重试记录、错误日志、审计和人工处理入口。
- **测试数据/故障注入**：
  - 变体 A：普通文字 V1→V2 更新失败，V1 仍为最近完整已发布版本。
  - 变体 B：作品下架/授权撤回后的失效任务失败。
  - 故障类型：暂时性超时、明确永久校验失败、进程中断；错误内容含内部哨兵 `S1_CACHE_05_INTERNAL_SENTINEL`。
- **步骤**：
  1. 记录更新前权威事实、公开版本、页面结果和任务基线。
  2. 分别在三个故障点执行变体 A，记录任务状态、重试和公开结果。
  3. 从独立基线执行变体 B，并在失效任务失败期间访问首页、列表、详情、旧链接和媒体。
  4. 恢复暂时性依赖，观察任务续跑；对永久失败进入人工处理并记录原因、操作者与结果。
  5. 检查日志/页面/响应是否泄露内部哨兵，并确认无无限重试。
- **可观察预期**：
  - 任务失败有脱敏错误、当前状态、尝试记录和人工处理入口；仅明确可重试故障进入有限重试，永久失败不循环重试。
  - 普通文字更新失败时是否继续显示最近完整已发布版本，按最终发布原子性设计判定，不展示半成品 V2；该策略需契约确认。
  - 已知作品下架或授权撤回时，即使失效任务失败，查询和媒体网关仍按当前事实拒绝，旧缓存/旧链接不恢复公开。
  - 恢复或人工处理后结果收敛，原始失败记录保留，错误和审计不泄露内部哨兵或敏感数据。
- **证据要求**：
  - 每个故障点的权威事实、公开版本、任务状态、尝试记录和最终结果时间线。
  - 暂时错误与永久错误的处理差异、人工处理审计。
  - 变体 B 的全部公开入口与媒体拒绝证据、敏感哨兵扫描结果。
- **阻塞/待决条件**：
  - **BLOCKED（策略/数量/时限断言）**：普通文字更新失败时旧完整版本的可见策略、最大重试次数、退避、任务超时、升级责任及传播时限尚需评审。
  - 不阻塞禁止半成品公开、禁止无限重试、已知不合格作品必须拒绝及故障可追踪的断言。
- **初始执行状态**：`NOT_RUN`

## 5. 阻塞条件汇总

1. **普通文字缓存参数**：TTL、ETag/版本协商值、后台恢复阈值和失效传播目标未确认；不能在测试中自行填入秒数、次数或供应商能力。
2. **作品媒体规则不阻塞**：`no-store`、每次展示前当前资格复核、复核前隐藏、资格未知 fail-closed、304/Range/本地文件/旧 URL 不得绕过，均为已明确安全断言。
3. **页面视觉**：骨架、空态、错误、局部降级、媒体占位及文案尚未锁定；测试先验证状态可区分、操作可达、内容不串页和敏感信息不泄露，不以像素或具体视觉作为当前门禁。
4. **部分成功契约**：首页必需区块范围、可选媒体缺失字段和局部失败表达仍需 D-401/D-602 联合锁定；`OK`/200 与独立媒体 503 不得二义解释。
5. **任务恢复参数**：最大重试、退避、任务超时、人工升级责任与完成时限未确认；这些为 `BLOCKED` 数量/时限断言，不阻碍有限重试、禁止无限循环、保留日志/审计及安全默认验证。
6. **执行环境**：需要可控网络与响应顺序、生命周期模拟、资格依赖替身、缓存观测、受控媒体网关和微信目标环境。缺失项只阻塞对应执行，不得记为通过。

本文件 13 个主用例当前均为 `NOT_RUN`；执行时每个故障/入口变体应独立记录结果和证据，不以一个变体替代全部组合。
