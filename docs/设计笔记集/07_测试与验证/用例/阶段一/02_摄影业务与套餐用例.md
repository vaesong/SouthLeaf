## 1. 覆盖摘要

| 场景组 | 主用例 | 主用例数 | 参数化/重点覆盖 |
|---|---|---:|---|
| BIZ | `S1-BIZ-01`～`S1-BIZ-04` | 4 | 每个主用例对儿童、亲子全家福、婚纱、写真、孕照、证件照六类独立执行，共 `4 × 6 = 24` 次变体执行 |
| PKG | `S1-PKG-01`～`S1-PKG-05` | 5 | `FIXED`、`FROM`、`INQUIRY`、`UNDISCLOSED`，以及下架/旧链接和 DTO 兼容 |
| 合计 | D-702 对应场景全部落地 | 9 | 9 个主用例；BIZ 24 次强制变体执行；所有记录初始为 `NOT_RUN` |

本文件只定义测试设计，不记录任何“通过”结论。BIZ 的六类业务变体必须分别建立执行记录、结果和证据，不能抽测一类后代表其余五类，也不能把 24 次变体执行误计为 24 个主用例。

D-401 已锁定阶段一六个公开错误码及 HTTP 映射：`OK/200`、`PUBLIC_QUERY_INVALID/400`、`PUBLIC_RESOURCE_UNAVAILABLE/404`、`PUBLIC_SERVICE_UNAVAILABLE/503`、`PUBLIC_MEDIA_UNAVAILABLE/503`、`PUBLIC_RESPONSE_INVALID/500`。接口路径、DTO 字段和响应外层仍为草案；本文使用 `priceType`、`displayPrice`、`media`、`coverMedia` 等名称仅指向 D-401 当前公开 DTO 语义，执行脚本应在契约评审后映射实际字段，不得假定现有代码、API 或表结构。

测试数据名称均表示可重复的合成配方或经负责人确认的公开经营资料，不表示仓库中已存在同名 Fixture。没有真实套餐资料的业务允许显示真实空状态；测试不得创建或展示伪造套餐、金额、服务承诺、历史 30%/50% 定金比例或活动价。

## 3. BIZ 详细用例

### S1-BIZ-01 业务有已发布资料和套餐

- **用例 ID**：`S1-BIZ-01`
- **名称**：六类业务已发布且有套餐时列表、详情和关联均正确
- **优先级**：P1
- **类型/建议测试层**：业务参数化主流程；领域/查询集成 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.2 `S1-BIZ-01`；D-401 §2、§3、§4；D-602 §2；D-701 §1、§5；P01 §1、§3.2
- **前置条件**：
  1. 对六类业务分别建立隔离副本；当前变体中的目标业务已进入公开数据源并已发布。
  2. 目标业务关联至少一个已发布套餐；同时准备一个属于其他业务的已发布套餐作为串联哨兵。
  3. 目标业务、套餐和公开媒体（如有）均使用合成资料或已确认经营资料。
  4. 可观察业务列表、业务详情、套餐入口与公开查询结果；实际路径和字段按评审后的契约映射。
- **测试数据**：参数化总表中的六个 `业务已发布且有套餐` 配方、`其他业务套餐串联哨兵`
- **步骤**（对六类业务逐类独立执行）：
  1. 以当前业务参数启动隔离数据副本，记录目标业务及其已发布套餐的公开标识和关联基准。
  2. 打开服务列表，定位当前业务，记录名称、摘要、封面和“有已发布套餐”语义。
  3. 进入当前业务详情，核对公开说明和关联套餐入口。
  4. 从业务详情进入每个已发布套餐详情，记录套餐所属业务、名称、服务项和价格语义。
  5. 返回服务列表，再次进入同一业务和套餐，检查关联是否稳定。
  6. 检查列表、详情和响应中是否混入其他业务套餐、未发布套餐、内部备注或历史测试数据。
- **预期结果**：
  1. 每个业务变体使用独立可追踪数据，当前业务与其套餐关联基准明确。
  2. 当前已发布业务出现在公开列表，名称和摘要与公开版本一致；封面仅在可公开且可用时显示。
  3. 业务详情可达，且只展示当前业务的公开说明与已发布关联资源。
  4. 套餐详情可达；套餐 `businessId`/业务语义与当前业务一致，服务项和价格取当前公开事实，不由路由对象注入。
  5. 重复进入仍按当前公开标识查询，结果不因页面内存产生串项。
  6. 不返回其他业务套餐、草稿/未发布套餐、内部备注、客户资料或历史测试套餐。
- **证据要求**：六个变体各自的执行记录；服务列表→业务详情→套餐详情连续录屏；业务/套餐公开标识和关联基准对照；脱敏请求/响应及 `requestId`；哨兵资源未出现检查。任何一类的证据不能替代另一类。
- **阻塞/待决条件**：六类首批真实资料或已发布套餐未齐全时，对应真实内容变体阻塞，但可用合成配方验证技术表达；接口路径、DTO 字段尚为草案时精确契约脚本阻塞。
- **初始执行状态**：`NOT_RUN`

### S1-BIZ-02 业务已发布但暂无套餐

- **用例 ID**：`S1-BIZ-02`
- **名称**：六类业务无已发布套餐时展示真实空态且可联系咨询
- **优先级**：P1
- **类型/建议测试层**：业务参数化空态；领域/查询集成 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.2 `S1-BIZ-02`；D-401 §2、§9；D-602 §3；D-701 §5；P01 §3.2
- **前置条件**：
  1. 当前业务已发布且有公开说明，但没有任何已发布套餐。
  2. 可为目标业务放置草稿、已下架或历史测试套餐作为过滤哨兵；这些资源不得公开。
  3. 至少一种已确认且平台允许的联系资料可用；如联系资料也未确认，则按其真实缺失状态展示，不临时补造。
- **测试数据**：参数化总表中的六个 `业务已发布但无套餐` 配方、`不可公开套餐哨兵集`、`已确认联系资料`
- **步骤**（对六类业务逐类独立执行）：
  1. 打开服务列表并进入当前业务详情。
  2. 核对业务名称、公开说明和套餐概况。
  3. 观察套餐区域的页面状态、文案及可操作入口。
  4. 执行可用的电话或微信咨询动作，并返回业务详情。
  5. 刷新页面并检查网络响应、本地状态和页面中是否出现哨兵套餐、默认套餐或示例金额。
  6. 检查联系动作前后是否新增预约、订单、客户账号或支付事实。
- **预期结果**：
  1. 已发布业务仍在服务列表和详情中可见，不因无套餐而被误判为查询失败。
  2. 业务说明按当前公开事实展示，套餐概况表达“暂无已发布套餐”的真实语义。
  3. 套餐区域进入成功空态，不显示错误态，不自动无限重试，不生成测试套餐。
  4. 只呈现已确认且平台允许的联系入口；返回后页面可继续使用，不宣称已预约。
  5. 草稿、下架和历史测试套餐均不出现；空态不使用示例金额、0 元、历史活动价或 30%/50% 定金比例填充。
  6. 咨询动作不创建预约、订单、客户账号、支付或售后事实。
- **证据要求**：六个变体各自的业务详情和空态截图；查询成功且套餐集合为空的脱敏响应语义；不可公开套餐哨兵未出现检查；联系动作录屏；前后业务事实/写请求差异证据。
- **阻塞/待决条件**：联系资料或平台允许方式未确认时，联系动作变体阻塞，但空态和不伪造套餐断言仍可执行；空列表最终 DTO 表达待契约评审。
- **初始执行状态**：`NOT_RUN`

### S1-BIZ-03 业务资料未发布

- **用例 ID**：`S1-BIZ-03`
- **名称**：六类未发布业务不进入任何公开结果且不由客户端硬编码补齐
- **优先级**：P0
- **类型/建议测试层**：公开过滤与负向安全；领域决策表 + 查询集成 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.2 `S1-BIZ-03`；D-401 §2、§4、§5、§7；D-602 §5、§7；D-701 §3
- **前置条件**：
  1. 当前业务存在于隔离数据源但未发布；其名称、摘要和封面带唯一哨兵值。
  2. 首页、服务列表、业务详情直达、套餐筛选和本地缓存均可检查。
  3. 准备不存在的公开标识用于与未发布资源比较，验证公开端不可枚举内部状态。
- **测试数据**：参数化总表中的六个 `业务未发布` 配方、`未发布业务哨兵值集`、`不存在业务公开标识`
- **步骤**（对六类业务逐类独立执行）：
  1. 冷启动首页，检查业务摘要区。
  2. 打开服务列表并搜索/浏览全部公开业务。
  3. 使用未发布业务的受控公开标识直接进入详情语义入口。
  4. 使用不存在的公开标识进入同类详情语义入口，对比公开响应和页面提示。
  5. 清缓存、重新进入首页和服务列表，搜索该业务的哨兵名称、摘要、封面和标识。
  6. 检查客户端资源、默认数组或历史缓存是否补出该业务；检查错误体是否泄露草稿、未发布原因或内部标识。
- **预期结果**：
  1. 未发布业务不出现在首页业务摘要。
  2. 未发布业务不出现在服务列表或任何公开筛选结果。
  3. 直达请求由服务端拒绝，按已锁定契约返回 `PUBLIC_RESOURCE_UNAVAILABLE`/404；页面显示统一“内容暂不可用”语义并可返回。
  4. 不存在与未发布业务在公开端具有相同错误码、HTTP 映射和不泄密提示，不能据此枚举内部状态。
  5. 清缓存后仍不出现哨兵内容，也不回退到生产内置示例或历史缓存。
  6. 客户端硬编码不能补齐未发布业务；响应、页面、日志对客户端可见部分不泄露草稿状态、内部原因、存储信息或后台标识。
- **证据要求**：六个变体各自的首页/列表未出现证据；直达未发布与不存在标识的成对脱敏响应（状态、稳定码、公开文案、`requestId`）；哨兵值搜索；清缓存录屏；服务端过滤或查询观测证据。页面截图不能单独证明服务端过滤。
- **阻塞/待决条件**：实际路径和公开标识格式仍为草案时，自动化调用方式阻塞；但服务端过滤、统一 `PUBLIC_RESOURCE_UNAVAILABLE`/404 和不硬编码补齐的规则已可评审，不得降为客户端过滤。
- **初始执行状态**：`NOT_RUN`

### S1-BIZ-04 按业务筛选作品/套餐

- **用例 ID**：`S1-BIZ-04`
- **名称**：六类业务筛选只返回对应公开资源且非法筛选结果稳定
- **优先级**：P0
- **类型/建议测试层**：参数化筛选隔离与输入校验；领域/查询集成 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.2 `S1-BIZ-04`；D-401 §4、§5、§7；D-602 §4、§5；D-701 §3
- **前置条件**：
  1. 对每个当前业务建立筛选隔离集：至少两个对应公开作品、两个对应已发布套餐、一个其他业务公开作品/套餐、一个未发布或资格无效作品、一个下架套餐。
  2. 所有资源带可识别哨兵值，且目标业务使用服务端认可的公开字典标识。
  3. 准备非法字符、过长值和不存在但格式合法的筛选值；具体长度边界待契约锁定后填入执行数据。
- **测试数据**：参数化总表中的六个 `业务筛选隔离集`、`非法业务筛选值`、`过长业务筛选值`、`不存在但格式合法的业务筛选值`
- **步骤**（对六类业务逐类独立执行）：
  1. 在作品列表选择当前业务筛选，记录全部返回资源及稳定排序。
  2. 翻页或继续加载（如实际设计支持），检查资源重复、遗漏和业务归属。
  3. 在套餐列表选择同一业务筛选，重复步骤 1～2。
  4. 分别提交非法字符和超过已锁定上限的筛选值。
  5. 提交不存在但格式合法的筛选值。
  6. 修改客户端路由/请求中的业务参数，尝试加入其他业务、未发布、授权无效或下架资源的公开标识。
- **预期结果**：
  1. 作品结果只包含当前业务且当前可公开的作品；不合格作品在服务端查询阶段被过滤。
  2. 分页/继续加载排序稳定，无重复或越界到其他业务；精确分页参数待契约锁定后执行。
  3. 套餐结果只包含当前业务的已发布套餐，不包含其他业务或下架套餐。
  4. 非法或过长筛选按已锁定契约返回 `PUBLIC_QUERY_INVALID`/400；错误体不泄露数据库、堆栈或内部字典。
  5. 格式合法但无公开匹配的筛选返回稳定的成功空结果或评审后锁定的等价语义，不生成默认资源；执行时须按最终契约判定，不能预先二选一。
  6. 客户端参数或对象注入不能绕过业务关联、发布状态和作品资格；响应不包含注入资源。
- **证据要求**：六个业务各自的作品和套餐结果集合、排序/分页记录；目标/非目标哨兵对照；非法与过长参数的 `PUBLIC_QUERY_INVALID`/400 脱敏响应；格式合法空匹配结果；服务端查询过滤证据和页面录屏。
- **阻塞/待决条件**：筛选参数名、允许字符、长度上限、分页方式和“合法但无匹配”最终表达尚未锁定时，对应精确变体阻塞；不得把未知契约硬写为某条现有 API。六类业务的正确关联基准未准备时，相应变体阻塞。
- **初始执行状态**：`NOT_RUN`

## 4. PKG 详细用例

### S1-PKG-01 固定价套餐

- **用例 ID**：`S1-PKG-01`
- **名称**：`FIXED` 套餐在首页、列表和详情保持固定价及服务语义一致
- **优先级**：P1
- **类型/建议测试层**：价格语义与跨入口一致性；领域/适配层单元 + 接口契约 + 页面自动化 + 真实内容核验
- **规则来源**：D-702 §3.4 `S1-PKG-01`；D-401 §3.3、§6.2、§9；D-602 §2；P01 §3.2
- **前置条件**：
  1. 一个经确认并已发布的固定价套餐关联到已发布业务，具有套餐名、服务项和可识别固定金额。
  2. 套餐被首页摘要（若实际编排包含）、套餐列表和套餐详情引用。
  3. 测试人员拥有金额与服务项的公开来源确认记录。
- **测试数据**：`已确认FIXED套餐`、`固定价相邻金额哨兵套餐`
- **步骤**：
  1. 记录固定价套餐的公开来源、业务关联、名称、服务项和金额基准。
  2. 在首页套餐摘要中记录名称、业务和价格展示（若当前编排包含该套餐）。
  3. 在套餐列表中定位该套餐并记录相同信息。
  4. 进入套餐详情，核对业务名称、服务项、适用人群、时长、价格和注意事项中已发布的部分。
  5. 对比三个入口与公开响应的价格类型和展示值，搜索相邻金额哨兵值及历史定金/活动价。
- **预期结果**：
  1. 基准来自已确认公开事实，不从原型或订单规则反推。
  2. 首页摘要（若有）将该套餐表达为固定价，不增加“起”或“咨询”语义。
  3. 列表名称、业务和固定价格与首页/公开版本一致。
  4. 详情属于同一业务，服务项与已发布资料一致；固定价格不被解释为定金、尾款或订单总价承诺之外的其他事实。
  5. 各入口的 `FIXED` 语义和金额一致，不出现相邻哨兵金额、历史 30%/50% 定金比例或未发布活动价。
- **证据要求**：经营资料确认记录；首页/列表/详情成对截图；脱敏公开响应；价格类型与展示值对照；历史值/哨兵值未出现检查。
- **阻塞/待决条件**：真实固定价资料或首页套餐编排未确认时，相应真实内容/首页路径阻塞；可用合成套餐验证技术语义，但不能证明经营金额准确。
- **初始执行状态**：`NOT_RUN`

### S1-PKG-02 起价/询价

- **用例 ID**：`S1-PKG-02`
- **名称**：`FROM` 与 `INQUIRY` 分别展示“起”和“咨询”语义且不转成固定价或 0 元
- **优先级**：P1
- **类型/建议测试层**：价格类型决策表；领域/适配层单元 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.4 `S1-PKG-02`；D-401 §3.3、§9；D-602 §2；D-701 §2
- **前置条件**：
  1. 准备一个已发布 `FROM` 套餐，具有已确认起始展示金额。
  2. 准备一个已发布 `INQUIRY` 套餐，不提供固定金额；如最终契约允许咨询说明文本，则该文本已确认。
  3. 两个套餐均可从列表和详情访问；若首页编排包含，则一并覆盖。
- **测试数据**：`已确认FROM套餐`、`已确认INQUIRY套餐`、`零金额哨兵值`
- **步骤**：
  1. 打开 `FROM` 套餐的首页摘要（如有）、列表项和详情，记录所有价格表达。
  2. 对比 `FROM` 的价格类型、已确认金额和页面修饰语义。
  3. 打开 `INQUIRY` 套餐的首页摘要（如有）、列表项和详情，记录所有价格表达和联系入口。
  4. 对比 `INQUIRY` 的价格类型、金额字段存在性和页面文案。
  5. 搜索两个套餐在响应、页面和可访问文本中是否被转为固定价、`0`、`0.00` 或“免费”。
  6. 刷新并跨入口往返，确认价格语义不因页面适配产生变化。
- **预期结果**：
  1. `FROM` 在所有入口明确表达“起价”语义，而不是固定成交价。
  2. `FROM` 的展示金额只使用已确认公开值；不附加历史定金或活动价。
  3. `INQUIRY` 在所有入口明确表达“咨询/询价”语义，并只提供已确认联系路径。
  4. `INQUIRY` 不返回或展示虚构固定金额；最终字段缺省方式按评审后的契约执行。
  5. 两类套餐均不转为 0 元、免费或固定价，`FROM` 与 `INQUIRY` 不互换。
  6. 首页、列表、详情和刷新后的语义一致。
- **证据要求**：两个类型在各入口的截图；脱敏响应中的价格类型与金额存在性对照；零金额/“免费”哨兵搜索；跨入口录屏。每个价格类型必须有独立执行结果。
- **阻塞/待决条件**：价格显示文案和 DTO 精确可选字段表达仍待联合评审时，精确字符串/字段断言阻塞；`FROM` 不得变固定价、`INQUIRY` 不得变 0 元的语义断言不阻塞。
- **初始执行状态**：`NOT_RUN`

### S1-PKG-03 未确认价格

- **用例 ID**：`S1-PKG-03`
- **名称**：`UNDISCLOSED` 或价格未确认时不返回金额且不使用历史规则补齐
- **优先级**：P0
- **类型/建议测试层**：未知价格安全默认；领域决策表 + 查询集成 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.4 `S1-PKG-03`；D-401 §2、§3.3、§9；D-602 §2、§3；D-701 §1；P01 §3.2
- **前置条件**：
  1. 一个已发布套餐的价格事实未确认，公开价格类型按最终契约表达为 `UNDISCLOSED`，或在规则确认后使用 `INQUIRY`；本用例不预先替业务作二选一决策。
  2. 数据中放置历史原型金额、30%/50% 定金比例、活动价和数值 0 作为泄漏哨兵。
  3. 套餐可从首页（若编排）、列表和详情访问。
- **测试数据**：`UNDISCLOSED未确认价格套餐`、`历史价格与定金哨兵值集`
- **步骤**：
  1. 记录该套餐“价格未确认”的数据基准和最终评审允许的公开价格类型。
  2. 打开首页套餐摘要（如有）、套餐列表和套餐详情，记录价格区域。
  3. 检查脱敏公开响应中的价格类型和金额值/字段存在性。
  4. 搜索页面、响应、本地缓存和分享载荷中的 `0`、历史金额、30%/50% 定金比例及活动价哨兵。
  5. 修改客户端展示对象或路由参数，注入 `0`、固定金额和 `FIXED`，重新进入详情。
  6. 清缓存后再次访问，核对结果。
- **预期结果**：
  1. 未确认价格不会被测试人员或客户端推导为经营事实。
  2. 各入口不显示金额；仅按评审后的 `UNDISCLOSED` 或 `INQUIRY` 语义展示，不使用“0 元”代替未知。
  3. 服务端公开结果不提供未确认金额；字段缺省/空值方式按最终契约一致表达。
  4. 哨兵金额、定金比例、活动价和 0 不出现在公开结果或分享载荷中。
  5. 客户端注入不能改变服务端当前价格事实；重新查询后仍是未披露/询价语义。
  6. 清缓存不会恢复历史价格或内置示例。
- **证据要求**：各入口价格区域截图；脱敏响应字段存在性与类型检查；全哨兵搜索结果；对象/路由注入前后成对证据；清缓存录屏与 `requestId`。
- **阻塞/待决条件**：该业务最终选择 `UNDISCLOSED` 还是 `INQUIRY`、以及精确 DTO 表达尚待评审时，精确类型判定阻塞；“未知价格不返回金额且绝不映射为 0”的断言已明确，不得阻塞或放宽。
- **初始执行状态**：`NOT_RUN`

### S1-PKG-04 套餐下架或旧链接

- **用例 ID**：`S1-PKG-04`
- **名称**：套餐下架后从公开入口移除且旧链接统一安全不可用
- **优先级**：P1
- **类型/建议测试层**：状态转换与旧链接；查询集成 + 接口契约 + 页面自动化 + 真机深链
- **规则来源**：D-702 §3.4 `S1-PKG-04`；D-401 §4、§6、§7、§8；D-602 §5、§7；D-701 §3、§7
- **前置条件**：
  1. 一个当前已发布套餐出现在服务列表、业务详情及可用深层链接中。
  2. 能通过受控流程把该套餐变为下架，并记录事实生效点；准备一个不存在的套餐公开标识作枚举对照。
  3. 可检查普通文字缓存、本地缓存和公开查询结果。
- **测试数据**：`即将下架的已发布套餐`、`套餐旧深链`、`不存在套餐公开标识`
- **步骤**：
  1. 下架前从列表、业务详情和旧深链访问套餐，记录公开标识和当前内容。
  2. 通过受控流程执行下架，并确认当前服务端事实已经变更。
  3. 刷新首页（如引用）、套餐列表和业务详情。
  4. 使用下架前保存的旧链接直接访问套餐详情。
  5. 使用不存在的套餐标识访问同类详情，对比公开结果。
  6. 清缓存并在另一设备或新会话重复步骤 3～5；检查旧内容是否由缓存恢复。
- **预期结果**：
  1. 下架前基准可追踪，旧链接只保存公开定位信息，不保存可决定显示的完整对象。
  2. 下架事实的生效点可观察；未锁定传播 SLA 时只记录实际时间。
  3. 当前公开首页、列表和业务详情不再返回该套餐。
  4. 旧链接由服务端重新判断并返回 `PUBLIC_RESOURCE_UNAVAILABLE`/404；页面显示统一安全不可用提示，不展示旧价格或服务项。
  5. 不存在与已下架套餐对匿名访问者具有相同稳定码、HTTP 映射和不泄密提示，不暴露下架原因。
  6. 清缓存、换设备或旧版本元数据不能恢复套餐；错误响应使用 `no-store` 且不参与 ETag/304 协商。
- **证据要求**：下架前后列表/详情对照；受控下架记录；旧链接与不存在标识的成对脱敏响应、响应头、页面截图和 `requestId`；清缓存/跨设备录屏；缓存未恢复旧内容的证据。
- **阻塞/待决条件**：阶段一公开数据维护/下架流程、普通文字缓存传播目标或深链格式未就绪时，相应执行阻塞；不得以直接修改未知数据库字段替代受控下架动作。
- **初始执行状态**：`NOT_RUN`

### S1-PKG-05 字段兼容

- **用例 ID**：`S1-PKG-05`
- **名称**：首页、列表和详情统一消费公开 DTO 语义且不并行使用原型字段
- **优先级**：P1
- **类型/建议测试层**：DTO 契约与客户端适配兼容；适配层单元 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.4 `S1-PKG-05`；D-401 §3.3、§6.2；D-602 §2.2；D-701 §2、§7
- **前置条件**：
  1. D-401 的正式 DTO 版本已完成评审后，方可执行精确字段契约断言；评审前仅可做设计级检查。
  2. 准备包含封面、服务项、不同价格类型和可选字段缺失的公开套餐响应样本。
  3. 准备只含原型字段 `images`、`imageSrc` 和冲突值的负向样本，且不得让该样本进入生产公开源。
- **测试数据**：`正式公开套餐DTO完整样本`、`正式公开套餐DTO可选字段缺失样本`、`原型字段冲突负向样本`
- **步骤**：
  1. 将正式完整样本分别输入首页、套餐列表和套餐详情的实际 API 适配层并打开对应页面。
  2. 对比三个入口的套餐标识、业务关联、名称、封面和价格语义。
  3. 输入正式可选字段缺失样本，观察三个入口的解析和展示。
  4. 输入仅含 `images`、`imageSrc` 等原型字段的负向样本，观察适配层和页面结果。
  5. 输入正式字段与原型字段值冲突的样本，检查实际契约字段是否具有唯一语义来源，并记录响应格式异常处理。
  6. 检查页面模型、缓存和分享载荷中是否并行持久化原型字段作为正式回退。
- **预期结果**：
  1. 三个入口都通过 API 适配层消费评审后的公开 DTO，不直接绑定数据库字段。
  2. 同一套餐在首页、列表和详情中的标识、业务、封面和价格类型语义一致；详情可增加契约允许的明细但不改义。
  3. 可选字段缺失按契约安全降级，不凭默认值伪造图片、价格或服务内容。
  4. `images`、`imageSrc` 等原型字段不被当作并行正式字段；仅有旧字段的无效响应不得静默展示为有效套餐。
  5. 冲突样本不能让旧字段覆盖正式字段；不符合锁定契约的响应进入 `PUBLIC_RESPONSE_INVALID`/500 对应的安全异常语义或最终契约规定的等价服务端转换失败路径，页面不崩溃、不泄露原始响应。
  6. 页面模型、缓存和分享载荷不保留原型字段作为生产回退，也不通过字段混用绕过当前价格或发布事实。
- **证据要求**：适配层单元结果；三入口截图；完整/缺失/旧字段/冲突四类脱敏样本及解析结果；`PUBLIC_RESPONSE_INVALID`/500 映射证据（适用时）；页面模型和缓存检查摘要。
- **阻塞/待决条件**：D-401 路径和 DTO 尚为草案，因此精确字段兼容执行在正式契约锁定前阻塞；本用例不得反向把当前草案字段锁定为生产实现。正式响应转换失败发生在服务端还是客户端本地解析的观察点应按最终实现分别映射。
- **初始执行状态**：`NOT_RUN`

## 6. 总体阻塞与待决条件

1. 六类业务的首批真实说明、已发布状态、业务标识及套餐资料未确认时，真实内容核验按业务逐类阻塞；合成数据可验证技术表达，但不得被描述为经营资料已验收。
2. 某业务没有真实套餐并非产品失败，应执行 `S1-BIZ-02` 的真实空态；测试不得为凑齐覆盖而生成生产测试套餐。
3. D-401 的六个稳定错误码和 HTTP 映射已锁定；路径、DTO、分页/筛选参数、字段可选性和响应外层仍是草案。精确契约脚本需等待锁定，但不能改变服务端过滤、数据最小化和未知价格不为 0 的规则。
4. `UNDISCLOSED` 与 `INQUIRY` 在具体未确认价格业务上的选择、公开价格文案及字段缺省方式仍需业务/接口联合评审；无论选择为何，未知价格都不得变成数值 0、免费或固定价。
5. 公开数据维护、审核、发布和下架流程未就绪时，状态转换类执行阻塞；不得直接假定某张表或通过未受控改数代替正式动作。
6. 普通业务/套餐文字缓存 TTL、ETag 和传播目标尚未锁定时，只记录实际观察值，不声称满足未定义时限；错误响应必须 `no-store` 的规则已锁定。
7. 服务端日志、`requestId`、筛选查询和副作用观测能力未就绪时，P0 服务端过滤/注入断言不可只靠页面截图判定。
8. 本文件 9 个主用例及 24 个 BIZ 变体均保持 `NOT_RUN`，直至存在候选版本、独立执行记录和证据。设计评审或数据准备完成不等于产品测试通过。
