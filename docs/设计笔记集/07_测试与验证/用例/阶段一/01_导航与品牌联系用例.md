测试数据名称均表示可重复的合成配方或经负责人确认的公开经营资料，不表示仓库中已经存在同名 Fixture。涉及品牌、电话、微信、地址和工作时间的准确性，必须取得资料责任人的来源确认；技术合成数据只能证明展示与缺失语义，不能证明真实经营资料正确。

## 2. 详细用例

### S1-NAV-01 四 Tab 导航

- **用例 ID**：`S1-NAV-01`
- **名称**：阶段一四 Tab 均可达且无“我的”占位入口
- **优先级**：P1
- **类型/建议测试层**：页面导航；页面自动化 + 微信目标环境真机验收
- **规则来源**：D-702 §2 `S1-NAV-01`；D-701 §5；P01 §3.2、§3.4
- **前置条件**：
  1. 待测物是可识别版本的阶段一候选构建，未混入阶段二或阶段三功能开关。
  2. 首页、作品、服务、关于四个公开页面具备可加载的受控公开数据或明确空态。
  3. 已记录设备、操作系统、微信版本、基础库版本、网络和测试环境。
- **测试数据**：`阶段一四Tab候选构建`、`公开导航最小内容集`
- **步骤**：
  1. 清除小程序本地缓存后冷启动待测构建。
  2. 观察默认落地页和底部 Tab 数量、名称及选中状态。
  3. 依次进入“作品”“服务”“关于”，每次确认页面完成加载或进入明确空态。
  4. 在四个 Tab 间按“首页→作品→服务→关于→首页”顺序快速切换一次。
  5. 从非首页页面执行系统返回动作，再重新进入各 Tab。
  6. 检查 Tab、页面主要操作区和可达菜单中是否存在“我的”或其他阶段外占位入口。
- **预期结果**：
  1. 冷启动落入阶段一约定的公开页面，不要求登录，不闪现历史示例内容。
  2. 底部仅呈现首页、作品、服务、关于四个 Tab；当前选中状态与可见页面一致。
  3. 四个 Tab 均可达，且各自显示对应内容、加载状态或真实空态；无白屏、错误页面串页或无响应点击。
  4. 快速切换不改变 Tab 数量和顺序，不让旧页面响应覆盖当前页面。
  5. 返回后导航状态可预测，重新进入仍能到达目标页面，不形成无法退出的循环。
  6. 不存在“我的”占位 Tab，也不存在可操作的登录、预约、订单、支付、相册或私密交付入口。
- **证据要求**：候选构建标识与环境记录；覆盖冷启动、四 Tab 切换和返回动作的连续录屏；四个页面及 Tab 全景截图；必要时提供脱敏后的页面路由/生命周期日志。单张截图不能替代返回路径和快速切换证据。
- **阻塞/待决条件**：阶段一候选构建、最终 Tab 名称/顺序或微信真机环境未就绪时，页面与真机执行阻塞；可先做设计评审，但不得将评审结果记为执行通过。
- **初始执行状态**：`NOT_RUN`

### S1-NAV-02 首页任务路径

- **用例 ID**：`S1-NAV-02`
- **名称**：首页可进入精选作品、业务/套餐和关于页面且只传稳定公开标识
- **优先级**：P1
- **类型/建议测试层**：页面流程与接口消费；页面自动化 + 接口观察 + 真机
- **规则来源**：D-702 §2 `S1-NAV-02`；D-401 §4、§5；D-602 §2、§5；P01 §3.2
- **前置条件**：
  1. 首页已发布至少一个精选作品、一个业务入口、一个套餐入口和品牌/联系入口。
  2. 对应资源均有独立、稳定、不透明的公开标识；实际路由与公开查询映射可观察。
  3. 作品和套餐详情可由当前公开事实重新查询，不依赖客户端内置完整对象。
- **测试数据**：`首页完整任务路径公开集`、`可公开精选作品`、`已发布业务与套餐`、`已确认品牌联系资料`
- **步骤**：
  1. 冷启动进入首页，等待首页当前版本加载完成。
  2. 点击精选作品入口，记录页面目标、路由参数和随后发生的公开查询。
  3. 返回首页，分别点击业务入口和套餐入口，记录各自页面目标、参数和公开查询。
  4. 返回首页，点击品牌介绍或联系入口进入关于页面。
  5. 对步骤 2～4 重复一次，并对比首次与再次进入所展示的资源标识和内容语义。
  6. 检查路由参数、分享参数、本地存储和请求参数中是否携带完整资源对象、价格、发布状态、授权状态或媒体原始地址。
- **预期结果**：
  1. 首页只展示当前公开版本中已发布且可公开的入口。
  2. 精选作品进入与所点项目一致的详情；详情发生当前公开事实查询，客户端传入内容不替代服务端判断。
  3. 业务和套餐分别进入正确列表或详情，业务与套餐关联不串项。
  4. 品牌/联系入口进入关于页面，返回首页后位置和导航仍可用。
  5. 重复进入结果由当前公开数据决定，不依赖上一次页面内存中的完整对象。
  6. 路由仅承载实际契约允许的稳定公开标识或必要导航上下文；客户端提供的价格、`published`、`authorized`、`visible`、媒体地址等内容不能决定展示结果。
- **证据要求**：首页到四类目标的连续录屏；每次点击前后的资源标识对照；脱敏路由参数、网络请求/响应和本地存储检查结果；通过 `requestId` 可关联的服务端查询记录（观测能力就绪后）。证据不得保留完整签名参数、供应商直链或真实私人信息。
- **阻塞/待决条件**：实际路由和 DTO 仍未评审时，精确参数名断言阻塞，但“不得传入完整对象绕过服务端查询”的安全断言不取消；首页首批公开内容未就绪时阻塞真实内容核验。
- **初始执行状态**：`NOT_RUN`

### S1-NAV-03 深层链接

- **用例 ID**：`S1-NAV-03`
- **名称**：作品/套餐分享或扫码深层入口重新查询当前公开详情
- **优先级**：P1
- **类型/建议测试层**：深层链接与生命周期；页面自动化 + 微信目标环境真机 + 接口观察
- **规则来源**：D-702 §2 `S1-NAV-03`；D-401 §4、§5；D-602 §5、§7；D-701 §2、§5
- **前置条件**：
  1. 存在一个当前可公开作品和一个当前可公开套餐。
  2. 待测环境能生成或提供受控的作品、套餐分享卡片或小程序码；入口参数与实际契约一致。
  3. 接收设备未登录客户业务身份，且可清除小程序缓存。
- **测试数据**：`可公开作品深链`、`可公开套餐深链`、`无客户登录新设备`
- **步骤**：
  1. 在设备 A 从当前可公开作品详情创建受控分享入口，记录被分享资源的公开标识。
  2. 清除设备 B 的小程序缓存，在设备 B 直接打开该入口。
  3. 记录启动页、详情查询、作品媒体资格确认和最终页面状态。
  4. 关闭并重新打开小程序，再次使用同一作品入口。
  5. 对当前可公开套餐重复步骤 1～4。
  6. 检查两类入口是否读取了设备 A 的页面完整对象、登录态、旧本地缓存或非公开字段。
- **预期结果**：
  1. 分享入口只包含定位公开资源所需的受控信息，不包含完整作品/套餐对象或内部状态。
  2. 设备 B 无需继承设备 A 的登录态或本地状态；入口能够启动并进入正确详情或明确的安全提示。
  3. 作品详情由服务端按当前公开标识重新判断；作品媒体在展示前完成当前资格复核，确认前不显示旧图。
  4. 重复打开仍重新取得当前结果，不以首次打开结果作为永久资格。
  5. 套餐入口重新查询当前已发布套餐；价格和服务项不取自分享载荷中的历史值。
  6. 无客户账号、预约、订单或支付事实被创建；客户端对象不能改变发布、授权、价格或媒体结果。
- **证据要求**：发送端与接收端连续录屏；分享/扫码入口的脱敏参数摘要；接收端冷启动请求序列、作品媒体资格复核证据和 `requestId`；无客户业务写入的可观察记录。禁止在证据中保存完整外部签名 URL 或真实客户资料。
- **阻塞/待决条件**：微信分享/小程序码能力、合法域名、实际入口格式或真机环境未就绪时阻塞真机变体；接口路径和 DTO 未定不影响按资源语义设计，但执行脚本须等待契约评审。
- **初始执行状态**：`NOT_RUN`

### S1-NAV-04 设备切换

- **用例 ID**：`S1-NAV-04`
- **名称**：另一设备或清缓存后读取当前公开结果而非旧缓存
- **优先级**：P1
- **类型/建议测试层**：缓存与跨设备流程；集成 + 页面自动化 + 微信真机
- **规则来源**：D-702 §2 `S1-NAV-04`；D-401 §6；D-602 §7；D-701 §7
- **前置条件**：
  1. 受控公开数据源中存在可更新的普通品牌、业务或套餐文字内容。
  2. 能通过受控发布流程把测试内容从版本 A 更新为版本 B，并能判断新版本何时生效。
  3. 准备设备 A、设备 B，或一个可可靠清除缓存的目标设备；两者访问同一环境。
- **测试数据**：`公开文字版本A`、`公开文字版本B`、`跨设备同一公开入口`
- **步骤**：
  1. 在设备 A 打开受控公开入口，记录版本 A 的可识别文案、资源标识和实际版本观察值（如实现提供）。
  2. 通过受控流程发布版本 B，等待系统已声明的生效条件满足；不自行假定固定传播时限。
  3. 在从未打开该入口的设备 B 上进入同一公开入口。
  4. 清除设备 A 的小程序缓存后，再次进入同一入口。
  5. 分别在设备 A、B 返回首页并再次进入目标页面，记录请求和展示结果。
  6. 检查是否因旧 URL、本地文件、页面内存或旧版本元数据恢复版本 A。
- **预期结果**：
  1. 首次记录明确对应版本 A，不把客户端示例数据当作公开事实。
  2. 发布动作与版本 B 的生效点可观察；传播目标未锁定时只记录实测值，不擅自判定时限达标。
  3. 设备 B 在生效后读取版本 B，不依赖设备 A 的状态。
  4. 清缓存后的设备 A 读取版本 B，不恢复版本 A 或内置示例。
  5. 后续导航仍以当前服务端公开结果为准；普通文字缓存不能覆盖已确认的新版本。
  6. 若当前结果不可证明，页面进入明确加载/错误状态而非展示伪造或过期内容；作品媒体不属于本用例的普通文字缓存放宽范围。
- **证据要求**：两个设备/两次清缓存执行的环境记录和录屏；版本 A、B 的受控发布记录；展示内容对照；脱敏请求/响应、缓存键摘要及版本观察值。若传播时限未锁定，证据必须保留实际时间点但不得据此声称满足未定义 SLA。
- **阻塞/待决条件**：公开内容受控更新流程、版本观察方式、缓存 TTL/ETag 细节和传播目标尚待评审；没有可识别生效点时阻塞结果判定。
- **初始执行状态**：`NOT_RUN`

### S1-NAV-05 阶段外入口

- **用例 ID**：`S1-NAV-05`
- **名称**：阶段一构建不暴露登录、预约、订单、支付、相册和私密交付入口
- **优先级**：P1
- **类型/建议测试层**：范围与负向页面检查；静态路由审查 + 页面自动化 + 网络观察 + 真机
- **规则来源**：D-702 §2 `S1-NAV-05`、§7；D-602 §1、§9；D-701 §1、§3；P01 §3.4
- **前置条件**：
  1. 阶段一候选构建及其可达页面、Tab、菜单、按钮和分享入口清单可检查。
  2. 能观察测试期间的客户端导航和网络请求语义。
- **测试数据**：`阶段一入口清单`、`阶段外能力关键字集`
- **步骤**：
  1. 遍历四个 Tab、首页区块、作品/业务/套餐详情、关于/联系及所有可见按钮。
  2. 展开可见菜单、分享入口、错误页、空态和返回路径，记录全部可操作入口。
  3. 搜索或审查候选构建的可达路由配置与导航配置，定位登录、预约、订单、支付、退款、相册、下载、私密交付相关入口。
  4. 在完整遍历期间记录网络请求，按业务语义检查是否调用客户身份或阶段二/三业务能力。
  5. 执行电话和微信联系入口，确认其结果仍是外部联系动作。
- **预期结果**：
  1. 可见流程仅支持匿名公开浏览和联系，不出现可用阶段外入口。
  2. 错误页、空态、菜单和分享入口不会旁路进入“我的”或阶段外流程。
  3. 阶段一导航配置不存在可达的登录、预约、订单、支付、退款、相册或私密交付页面；历史占位内容不作为可用入口保留。
  4. 浏览过程不调用客户身份、预约、订单、支付、退款或私密交付业务接口；必要技术日志不等于业务写入。
  5. 联系动作不创建客户账号、预约、订单、支付、售后或交付事实。
- **证据要求**：可达入口清单；全流程录屏；路由/导航配置审查摘要；按业务语义分类的脱敏网络请求清单；联系动作前后业务事实无新增的可观察证据。未锁定 API 路径时不得仅凭 URL 名称下结论。
- **阻塞/待决条件**：候选构建或网络观察能力未就绪时阻塞动态执行；阶段外路由是否保留为不可达代码属于实现评审问题，本用例只对可达性和业务调用作验收断言。
- **初始执行状态**：`NOT_RUN`

### S1-CONT-01 首页和关于读取同一品牌资料

- **用例 ID**：`S1-CONT-01`
- **名称**：首页与关于页面的品牌和联系事实语义一致
- **优先级**：P1
- **类型/建议测试层**：公开内容一致性；接口契约 + 页面自动化 + 真实内容核验
- **规则来源**：D-702 §3.1 `S1-CONT-01`；D-401 §2、§3、§6；D-602 §2、§3；P01 §3.2
- **前置条件**：
  1. 经资料责任人确认的品牌名称、简介、地址、工作时间、电话和微信资料已通过受控流程发布。
  2. 首页与关于页面能读取同一公开版本，且可观察其资源语义或版本信息。
- **测试数据**：`已确认完整品牌资料`、`同一品牌公开版本`
- **步骤**：
  1. 记录责任人确认的品牌资料来源和本次公开版本。
  2. 冷启动首页，逐项记录品牌名称、简介、地址、工作时间和联系方式的展示值。
  3. 进入关于页面，逐项记录相同语义字段及对应联系操作目标。
  4. 对比两页显示和实际公开响应中的语义；允许为页面布局进行不改义的截断或格式化。
  5. 通过受控流程只更新一个品牌字段并发布新版本，在生效后刷新首页和关于页面再次对比。
- **预期结果**：
  1. 核验基准来自已确认公开资料，不来自原型默认值或测试人员口头补录。
  2. 首页展示的各项事实与该公开版本一致。
  3. 关于页面与首页对相同事实的表达语义一致，电话/微信操作目标与显示资料对应。
  4. 两页不各自维护冲突事实；格式差异不改变名称、地址、工作时间或联系目标含义。
  5. 新版本生效后两页取得同一更新结果，不出现一页更新、一页长期保留硬编码旧值的情况。
- **证据要求**：资料责任人的来源确认记录编号或脱敏摘要；首页和关于页面成对截图；同一版本的脱敏公开响应/内容版本观察值；单字段更新前后对照及 `requestId`。不得将真实私人联系方式扩散到超出授权的测试证据中。
- **阻塞/待决条件**：首批真实品牌资料、维护/发布责任和受控更新流程未确认时，真实内容核验阻塞；可用合成资料执行技术一致性变体，但不能替代经营准确性验收。
- **初始执行状态**：`NOT_RUN`

### S1-CONT-02 联系资料部分缺失

- **用例 ID**：`S1-CONT-02`
- **名称**：联系资料缺失时只展示已确认字段且不使用默认值补齐
- **优先级**：P1
- **类型/建议测试层**：空值/可选字段；单元适配层 + 接口契约 + 页面自动化
- **规则来源**：D-702 §3.1 `S1-CONT-02`；D-401 §2、§3；D-602 §3；D-701 §5
- **前置条件**：
  1. 可在隔离环境发布一份只有部分字段已确认的品牌联系资料。
  2. 已收集历史原型默认电话、微信、地址等哨兵值，仅用于断言“不出现”，不得作为回填数据。
- **测试数据**：`仅电话已确认的联系资料`、`仅微信已确认的联系资料`、`联系方式全部未确认`、`历史原型哨兵值集`
- **步骤**：
  1. 发布“仅电话已确认”的资料，打开首页与关于页面。
  2. 记录可见字段、按钮及电话动作目标，搜索历史原型哨兵值。
  3. 发布“仅微信已确认”的资料，重复步骤 1～2。
  4. 发布“联系方式全部未确认”的资料，重复检查首页、关于和联系区域。
  5. 检查缺失字段是否生成可点击但目标为空、默认或错误的操作控件。
- **预期结果**：
  1. 仅展示已确认电话；未确认微信、地址等不由默认值补齐。
  2. 页面和公开响应中均不出现历史原型哨兵值或虚构字段。
  3. 仅展示已确认微信；未确认电话不生成伪造拨号目标。
  4. 全部联系方式未确认时显示真实缺失状态或隐藏相应区域，不伪造任一联系方式。
  5. 不存在指向空值、默认值或历史值的可操作联系按钮；页面布局保持可读并可返回。
- **证据要求**：三种数据配方各自的页面截图；脱敏响应字段存在性检查；历史哨兵值全局搜索结果；可操作控件及其目标检查记录。截图必须与对应公开版本和配方关联。
- **阻塞/待决条件**：可选字段的最终 DTO 表达尚属草案，精确字段存在性脚本等待契约锁定；“只展示已确认事实、不默认补齐”的业务断言不受此待决项影响。
- **初始执行状态**：`NOT_RUN`

### S1-CONT-03 电话联系

- **用例 ID**：`S1-CONT-03`
- **名称**：电话联系成功唤起、取消和失败均有真实反馈且不创建业务事实
- **优先级**：P1
- **类型/建议测试层**：系统能力交互；组件/页面测试 + 微信目标环境真机
- **规则来源**：D-702 §3.1 `S1-CONT-03`；D-602 §6、§8；D-701 §5；P01 §3.2、§3.4
- **前置条件**：
  1. 已确认并获准用于测试的电话资料已发布；证据展示时可脱敏。
  2. 测试设备支持微信小程序电话系统能力；可分别制造允许唤起、用户取消和系统调用失败结果。
  3. 可观察联系动作前后的客户、预约、订单等业务事实或相关网络写请求。
- **测试数据**：`已确认可拨测试电话`、`电话唤起成功结果`、`用户取消拨号结果`、`系统拨号失败结果`
- **步骤**：
  1. 记录动作前的公开页面状态和业务写请求基线。
  2. 点击电话联系并允许系统能力正常唤起；返回小程序。
  3. 再次点击电话联系，在系统确认阶段取消；返回小程序。
  4. 在可控失败条件下再次点击电话联系。
  5. 每个变体后检查页面反馈、返回路径、按钮可用状态和网络/业务事实变化。
- **预期结果**：
  1. 页面显示的电话与已确认资料一致，不从历史原型取值。
  2. 正常变体仅表示系统拨号能力已真实唤起；返回后页面可继续操作，不把“唤起”描述为通话或预约成功。
  3. 取消变体不显示联系成功或预约成功；用户可停留或安全返回原页面。
  4. 失败变体给出可理解、可返回或可重试的反馈，不伪造系统跳转成功。
  5. 三个变体均不创建客户账号、预约、订单、支付或售后事实，也不触发对应业务写请求；按钮不会因重复操作永久锁死。
- **证据要求**：三个变体各自的连续真机录屏；系统能力结果或可控替身结果记录；页面反馈截图；联系动作前后脱敏网络请求与业务事实差异。不得以模拟器成功代替真机系统能力验收。
- **阻塞/待决条件**：可用于测试的确认电话、真机权限或可控失败方法未就绪时，相应变体阻塞；不得拨打未经授权的真实客户或个人号码。
- **初始执行状态**：`NOT_RUN`

### S1-CONT-04 微信联系

- **用例 ID**：`S1-CONT-04`
- **名称**：微信联系仅呈现已确认且平台允许的方式并如实处理失败
- **优先级**：P1
- **类型/建议测试层**：平台能力与内容合规；组件/页面测试 + 微信目标环境真机
- **规则来源**：D-702 §3.1 `S1-CONT-04`；D-401 §2；D-602 §6、§8；P01 §3.2、§3.4
- **前置条件**：
  1. 工作室已确认本次测试使用的微信联系资料和允许的呈现/操作方式。
  2. 该方式符合待测微信平台能力与当前评审结论；不预设必须复制、跳转或展示二维码。
  3. 可制造正常完成、用户取消/返回和平台能力失败结果。
- **测试数据**：`已确认且平台允许的微信联系方式`、`未确认微信联系方式`、`微信联系正常结果`、`微信联系取消结果`、`微信联系失败结果`
- **步骤**：
  1. 发布已确认且平台允许的微信联系方式，进入首页和关于页面检查呈现。
  2. 执行当前设计允许的微信联系动作并正常完成，然后返回小程序。
  3. 再次执行并在平台交互中取消或返回。
  4. 在可控失败条件下执行同一动作。
  5. 切换为“未确认微信联系方式”配方后刷新两页，检查展示和操作入口。
  6. 检查所有变体是否产生客户、预约、订单或其他业务写入。
- **预期结果**：
  1. 只显示已确认且平台允许的内容；首页与关于页面的联系目标一致。
  2. 正常完成时反馈与真实平台结果一致，不把复制、展示或系统唤起表述为已添加联系人或已预约。
  3. 取消/返回时可回到原页面，不显示伪造成功。
  4. 失败时提供可理解的失败反馈和返回路径，页面不会卡死或循环唤起。
  5. 未确认资料不展示，也不由原型默认值、二维码或历史账号补齐。
  6. 所有联系动作均不创建客户账号、预约、订单、支付或售后事实。
- **证据要求**：资料确认与平台允许方式的评审记录；正常、取消、失败三个变体的真机录屏；首页/关于页面截图；未确认配方下的入口缺失证据；脱敏网络请求/业务事实检查。涉及账号或二维码的证据按最小权限脱敏保存。
- **阻塞/待决条件**：最终微信联系方式、平台合规结论或失败注入方法未确定时阻塞相应执行；测试不得自行选择未经确认的跳转方式或账号。
- **初始执行状态**：`NOT_RUN`

### S1-CONT-05 地址信息未确认

- **用例 ID**：`S1-CONT-05`
- **名称**：地址未确认时不显示冲突地址或用历史坐标替代
- **优先级**：P1
- **类型/建议测试层**：内容安全与缺失处理；接口契约 + 页面自动化 + 真机系统能力检查
- **规则来源**：D-702 §3.1 `S1-CONT-05`；D-401 §2；D-602 §3；D-701 §5
- **前置条件**：
  1. 可发布地址未确认的隔离品牌资料。
  2. 已收集历史原型地址、冲突地址和地图坐标哨兵值，仅用于“不出现”检查。
  3. 如页面具有位置/地图操作，可观察其系统能力调用参数。
- **测试数据**：`地址未确认品牌资料`、`相互冲突的候选地址`、`历史地址与地图坐标哨兵值集`
- **步骤**：
  1. 发布地址未确认的品牌资料，清缓存后进入首页和关于页面。
  2. 检查地址文案、联系区块、位置按钮及页面可访问性。
  3. 在页面文本、公开响应、本地缓存和可观察调用参数中搜索历史地址与坐标哨兵值。
  4. 使用“相互冲突的候选地址”配方但不将任何候选标记为已确认，重复步骤 1～3。
  5. 如仍出现位置/地图操作入口，尝试触发并记录是否传入未确认地址或坐标。
- **预期结果**：
  1. 首页和关于页面不展示未确认地址，且不从旧缓存恢复地址。
  2. 地址缺失不会影响已确认品牌信息的浏览；不存在指向未知位置的可操作按钮。
  3. 历史地址、冲突地址和历史地图坐标不出现在响应、页面或调用参数中。
  4. 多个冲突候选不会被客户端任选其一展示；仍按地址未确认处理。
  5. 不向系统位置能力传入未确认或历史坐标；若入口错误存在，执行应记录为缺陷而非继续导航并宣称成功。
- **证据要求**：两种未确认配方的首页/关于截图；哨兵值搜索结果；脱敏响应与本地缓存检查；位置操作入口及调用参数记录（如存在）。证据应显示配方版本，避免把环境中无数据误当作正确过滤。
- **阻塞/待决条件**：真实地址是否确认、最终地址呈现方式和位置能力设计尚未评审时，真实内容与系统位置变体阻塞；“不得用历史地址/坐标补齐”断言不阻塞。
- **初始执行状态**：`NOT_RUN`

## 4. 总体阻塞与待决条件

1. 阶段一候选构建、正式 HTTPS/小程序合法域名、目标真机设备和微信版本组合未就绪时，相关真机用例阻塞。
2. D-401 的错误码及 HTTP 映射已锁定，但路径、DTO 和响应字段仍为草案；精确自动化映射须等待契约评审，不得据此虚构现有 API。
3. 首批真实品牌、电话、微信、地址和工作时间资料，以及维护、审核和发布责任尚未确认时，真实内容准确性验收阻塞；合成数据执行不能替代负责人核验。
4. 微信联系的最终平台允许方式、分享/小程序码格式和系统失败注入方式未确认时，相应变体阻塞。
5. 普通文字缓存 TTL、版本协商和传播目标未锁定时，可以记录实际刷新时间，但不能据此声称达到未定义时限。
6. 服务端日志、`requestId` 关联和业务事实只读观测能力未就绪时，涉及“未创建预约/订单”等服务端证据的结果判定阻塞；仅凭页面无跳转不足以证明无副作用。
7. 本文件所有用例保持 `NOT_RUN`，直至按候选版本建立独立执行记录、保存证据并由约定角色评审。文档完整性评审不等于产品测试通过。
