# ADR-002 阶段一原生微信与演示验收范围

- 日期：2026-10-18
- 决策：用户批准，适用于阶段一；不是所有客户端和后续后台的统一框架选择。

## 背景与选择

阶段一只做微信公开展示。既有 uni-app 工具链受框架依赖约束并存在安全告警；用户同意原生迁移。保留已批准 UI、四 tab/两详情、新版公开 API、数据库读模型和媒体资格约束，不保留长期双轨。

客户端采用微信原生 App/Page/Component、JS/JSON/WXML/WXSS，单一正式源码 frontend。零 npm 运行依赖；Prettier 为锁定的开发依赖。原生不天然等于安全：仍需锁定安装、审计、真实契约、微信编译和 UI 回归。后台未来技术栈单独设计，不反向强制 Vue 后台也改为小程序技术。

## 范围

阶段一验收虚构演示内容与工程能力。真实资料、媒体权属和客户公开授权材料、后台上传维护、正式 AppID/合法域名/TLS/生产凭据转入阶段二必须交付。保留公开资格规则、撤回、演示标识及 production 守卫；演示授权不能当作真实同意。

## 代价与约束

原生页面需要独立维护，不能声称已具备 H5/跨端复用。WeChat 专有 API 局限于客户端；服务端契约保持独立。构建生成 runtime 配置和 project.config，不能直接导入源码或提交生成物。模板语法需经过真实微信编译，Node 语法/静态检查不能替代。

后续新增后台必须有管理 API、权限、审计、上传处理与受控发布，不能直接给只读仓储加匿名写接口。阶段一有限规模快照不是订单写模型或生产容量承诺。

本决策取代 AT02 中阶段一继续 uni-app、JPA/旧运行说明的相关实现建议；总体模块与后续官网/后台讨论仍保留其原有适用范围。当前版本、命令和证据见[交付记录](../../开发与演示/阶段一收敛交付记录.md)。
