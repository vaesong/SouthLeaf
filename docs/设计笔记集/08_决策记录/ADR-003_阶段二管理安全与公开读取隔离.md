# ADR-003：阶段二管理安全与公开读取隔离

> 日期：2026-10-18；状态：安全内核及 JDBC 持久化已实现；运行时模块/组合根与隔离守卫见 D-104/D-506（设计草稿），正式接线待后续切片。
> 依据：[P02](../../计划/P02_阶段二目标与实施计划.md)、[认证与会话](../02_通用后端/01_认证与会话设计.md)、[权限与资源访问](../02_通用后端/02_权限与资源访问设计.md)。

## 背景

用户已授权按“2A 基本功能开发联调，2B 集中真实对接”执行。现行公开进程使用 SELECT-only 身份和 read-only 连接池，启动拒绝更大权限；其发布缓存和当前授权读取已有边界。不得为后台功能关闭守卫或把运行账号扩大成全库读写。

## 决策

1. 新建 `adminsecurity` 逻辑模块：domain/port/application/adapter。会话及权限用例保持 plain Java，配置根未来显式组装；不依赖公开 DTO、Web、SQL、存储实现或客户身份。
2. 会话使用 256-bit 随机不透明秘密，服务端只存 SHA-256 摘要；不是自包含 JWT，不把权限和长期有效身份放入客户端可携带的声明。SHA-256 仅用于高熵随机 token，不用于密码。
3. 固定绝对有效期，无隐式滑动或刷新。允许配置 1 分钟至 8 小时；默认建议 2 小时（当前测试配置，不是已部署参数）。有效区间 `[issuedAt, expiresAt)`；时钟回退到签发前拒绝。
4. 每次核验当前账号启用状态、securityVersion 和权限；修改密码/禁用/权限变更须递增版本，旧会话失效。既有会话内不缓存权限；即使上游漏增版本，当前权限移除仍影响后续核验。
5. 权限是显式能力集合，默认空集合拒绝。不硬编码 owner/admin 名称自动提权，暂不擅自批准负责人/运营/摄影师实际角色分配。业务模块另外负责资源和状态校验。
6. 未来持久化适配器在一个事务中锁定/检查当前账号版本、插入唯一会话及安全审计。credential verifier 捕获的版本必须与签发时相同，以拒绝并发改密/禁用；不可 upsert token 摘要。
7. 管理写入使用独立最小授权 Writer 和独立连接池；首选独立管理运行入口/部署配置，不让管理启动依赖出现在现行公开 Reader 进程中。具体 Spring Boot 启动扫描和 schema 检查在运行切片落地前测试冻结；当前不新增连接池或自动发现 Bean，不改变运行服务。
8. 不引入通用 RBAC 平台、Redis、OAuth 授权服务器或消息队列。将来有多个应用/单点登录需求再以证据评审，不为了“可扩展”提前增加平台。

## 当前实现与非实现

已实现：不可变账号/权限/会话、版本及绝对过期校验、显式权限判定、会话用例、随机 token 适配器、JDBC 存储、独立管理 V2 迁移与历史、会话签发/撤销安全审计、真实 MySQL 事务/并发测试及显式迁移工具。

未实现：密码校验、账号初始化、登录限流、HTTP/Cookie/CSRF、安全头、后台页面、角色配置、独立管理库/Writer 授权部署和生产接线。安全审计不等于完整业务审计。`openForVerifiedCredentials` 是内部用例，不得直接映射成接受 accountId/version 的签发 HTTP 接口。禁止将测试 MemoryStore 注册成运行适配器。

## 后续 HTTP 与凭据方案

后台同站部署优先使用 `HttpOnly; Secure; SameSite=Strict` host-only Cookie，结合明确的 Origin 检查和 CSRF token；不得将 bearer token 存 localStorage、URL 或日志。Cookie Path 与部署入口在 HTTP 切片统一定义，登出用 POST 且受 CSRF 防护；禁止通配凭据 CORS。未实现 HTTP 前这些都是强制后续验收项，不冒充当前防护。

密码方案使用受维护安全库提供的自适应 KDF（优先评估 Argon2id 的依赖及资源成本，或经论证的 PBKDF2），参数和限流以负载与安全验证冻结。不得自制密码算法、明文/可逆存储或使用 token 摘要算法代替密码 KDF。首个负责人经显式本机工具/受控部署步骤初始化，不随应用启动自动创建默认账号。

## 一致性与撤销边界

存储端口要求会话与当前账号/权限来自同一一致性视图，无陈旧缓存或副本延迟。依赖失败原样向上报告，未来 HTTP 映射为安全的依赖不可用错误，不能降级认证成功。

认证返回的 principal 仅适用于当前操作；敏感业务写入仍应在相应事务内重检安全版本、权限和业务状态。不能承诺对已授权且已开始执行的请求实现绝对瞬时撤销。核心 fake store 单测只验证规则与调用，不证明 SQL 隔离、并发事务或审计原子性。
