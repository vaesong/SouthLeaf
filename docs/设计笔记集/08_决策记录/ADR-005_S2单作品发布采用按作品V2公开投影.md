# ADR-005：S2 单作品发布采用按作品 V2 公开投影

> 状态：已确认（仅 S2 2A 单作品切片的工程存储决策；不代表业务规则、真实授权、2B 或生产批准）。
> 日期：2026-10-25；范围：P02/P03 的 S2-A/S2-B；后续 S3/2B 变化须重新评估。
> 关联：[P03](../../计划/P03_阶段二分批交付与编码执行计划.md)、[D-205 媒体](../02_通用后端/05_文件与对象存储设计.md)、[D-302 作品](../03_业务模块/02_作品与案例设计.md)、[D-403 后台接口](../04_接口与外部契约/03_后台管理接口.md)、[D-507 写模型/公开投影](../05_数据与存储/07_阶段二业务写模型与公开投影隔离设计.md)、[D-106 事务](../01_总体设计/06_阶段二2A关键用例与事务边界设计.md)。

## 1. 背景

当前公开 V1 以全局 `catalog_release`/`active_publication` 管理目录，作品关联业务/媒体表，公开授权由 V1 `public_authorization` 与 `authorization_media` 评估。S2 只需把第一个后台维护作品真实发布至既有小程序作品页；必须保留 V1 数据、DTO、Reader 身份、媒体资格复核和撤回语义，不让 admin business writer 直接改 Reader 表。

此前 public V2 per-work overlay 仅为候选。本 ADR 比较替代方案后，把它确认为 S2 的有限工程决策；不将其延伸为全阶段内容模型，也不宣称代码或数据库验收完成。

## 2. 决策

S2 采用**按作品版本化的 public V2 additive overlay**：以新增公开投影表承载 S2 发布的作品修订、媒体绑定、最小授权资格投影和每作品 active pointer；public-api 在现有 `CatalogSnapshot`/summary/detail 白名单上合并 V1 基础目录与 V2 活跃作品。public V1 表/迁移保持不变。业务写模型新增于 admin schema V5（既有安全迁移 V2–V4 保持不变）；发布通过 D-507 的独立 publication writer，在同一 MySQL 实例 InnoDB 的单个本地事务内跨 admin/public schemas 更新投影、pointer、epoch、命令结果和审计。

S2 公开游标版本由 V1 release 版本与 public V2 projection epoch 共同组成。V2 作品的授权来源显式标记；V2 资格缺行或依赖异常时 fail-closed，不能回退到 V1 许可。公开 DTO 仍复用现有白名单字段与同源媒体网关，不提供存储地址、授权证据或原图直链。

## 3. 备选方案与取舍

| 方案 | 取舍 |
|---|---|
| 原地改写 public V1 表/迁移 | 不采用。扩大已应用 V1 契约/Reader 影响面，混淆既有发布事实与 S2 草稿 owner；违反本批保持 V1 不变的兼容边界。 |
| 发布时重建/复制完整 public V2 catalog | 不采用。S2 仅新增首个作品，却需完整复制并校验已有 V1 目录、公开资格和历史版本；扩大事务、数据迁移、回滚与测试范围，且无 S2 需求收益。 |
| 按作品追加 public V2 overlay | 采用。只追加新作品安全投影，保持旧 V1 读取不变；符合 S2 单作品范围；通过同一快照读取、组合游标 epoch 和显式资格来源控制新增复杂度。 |
| admin business writer 直接写 public V1/由定时同步公开 | 不采用。绕开 publication port 与精确 grants，出现授权事实/投影异步窗口，无法证明原子撤回和未知提交复查。 |

## 4. 不变量与实施条件

1. V1 结构和既有公开授权路径不改；V2 overlay 采用新增迁移/表，不复用 V1 授权缺省作为 V2 fallback。
2. public-api 在单一一致性读视图中读取 V1 release 与 V2 active overlay；合并后的 `contentVersion` 必须覆盖两者，游标与缓存对任一版本变化失效。若当前 Repository 边界无法实现同一事务快照，先扩展只读 repository port，不靠两次非原子读取伪装一致。
3. admin-publication writer 与 public reader 身份独立，按 D-507 表级 grants 最小授权；两个 schema 必须是同一 MySQL/InnoDB 实例以支持单连接本地事务。不得使用 XA 或失败后异步双写。
4. public V2 授权投影只存资格判定所需的非 PII 字段；不含 `evidence_ref`、主体姓名、联系方式、私下说明、撤回原因、管理员身份。发布与撤回后的 GET/HEAD、对象缓冲前后 access-stamp 复核和自然到期 fail-closed 均按 D-205/D-507 测试。
5. public V2 游标兼容、授权来源选择、撤回、故障回滚、精确 grants 及双 schema 事务必须由 S2-B 的真实隔离 MySQL/HTTP/小程序闭环证据验证。H2/mock/页面演示不构成验收。

## 5. 后果与边界

新增 admin schema V5 业务表与 public V2 repository/投影映射及 epoch 维护，公开查询需要合并结果并测试分页/游标失效；这是维持 V1 不变所需的成本。该 overlay 只为 S2 先发布一个作品，S3 的品牌、成员、业务、套餐及后续批量内容管理不自动继承所有字段或所有权假设；进入相关切片前仍需复核需求并按需新增 ADR。

本决策只冻结 S2 的存储演进方向。S2-B 代码、迁移、精确 grants、真实 HTTP 测试、合成作品小程序读取/撤回闭环仍待实现和验收；生产、真实主体授权/资料、2B 平台与运维门禁未通过前不得公开真实素材。
