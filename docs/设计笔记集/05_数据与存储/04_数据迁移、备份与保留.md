# 阶段一数据迁移、备份与保留

> 文档编号：D-504。状态：阶段一实施与本地恢复演练说明；生产灾备、RPO/RTO 和真实资料保留规则未验收。不存在旧 JSON/旧库兼容或运行时恢复兜底。

## 1. 迁移边界

原 southleafdb 保留；新建 southleaf_public 与 southleaf_public_it。应用只校验 schema/发布，不建表、补种子、repair 或 clean。独立工具显式执行 Flyway 迁移；V1 已应用，必须新增 V2+，不可重写校验和。MySQL DDL 不保证事务回滚，失败时先冻结写入并核查实际 schema，禁止自动重置。

演示种子不混在迁移里。--seed-demo 仅在 catalog_release 为空时允许，生成并核验预制媒体；已有发布明确拒绝。真实内容不能用演示导入器填上 VERIFIED_AUTHORITY 伪造同意。

## 2. 备份内容与访问

备份应包含数据库一致性快照、Flyway 历史、引用对象与 SHA-256 清单、发布身份、恢复环境/版本和操作者记录。数据库及媒体备份不是公开素材，放私有目录，独立控制访问，不写入客户端、Git 或 HTTP 根。

内容寻址对象不可覆盖，在线备份仍需明确数据库快照与引用对象的对应关系。生产的备份频率、RPO/RTO、加密/密钥、异地副本、保留期及恢复负责人须由工作室确认，不以开发演练推定达标。

## 3. 本地隔离恢复演练（已执行）

脚本只接受显式确认，并硬性操作 southleaf_public_it；不接受任意库名，不修改演示库或旧库。运行前必须停止其他测试库写入，并确认有可用 MySQL 客户端：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-BackupRestore.ps1 -ConfirmIsolatedTestRestore
```

流程：确认 DATABASE() → mysqldump 单事务且无表锁/全局 GTID 改动 → 复制 42 个唯一媒体并核对内容 SHA → 修改测试库品牌字段作为恢复探针 → 从 SQL 真实恢复 → 核对探针恢复、作品/变体/Flyway 行数 → 在另一媒体目录复建并逐文件校验。

本次 j248 返回 BACKUP_RESTORE_PASS，6 作品/70 变体对应 42 个唯一媒体；备份留在 E:\SouthLeaf-data\backups 下带 UTC 时间戳目录，SQL 与 manifest 保留。首次开发运行的脚本平台属性错误发生在数据库改动前，未算通过；修正为显式 UTF-8 字节流后完整演练通过。

若导入失败，不自动清库或伪装恢复成功：保留备份、停止对测试库写入，检查 mysql 错误和清单后由操作者恢复；重新执行只会创建新的备份目录，不覆盖旧证据。

## 4. 正式恢复门禁（未通过）

正式恢复必须在独立目标环境验证版本/权限、数据和文件完整性、授权当前性、应用协议与实际恢复耗时，经审批才能切换流量。开发脚本使用同一 Windows 用户的测试凭据不是生产 OS/密钥隔离。当前未执行正式灾备切换或真实客户数据恢复，不标为已通过。

## 5. 保留、撤回与删除

授权撤回是当前公开资格变更；隐私删除、审计留痕、法律保留与备份到期销毁须分别审批。删除前枚举发布/媒体/备份引用，保留可核验记录；不得把撤回当作自动物理清理，也不得因需要审计而永久保留全部真实照片。原 root 历史凭据仍需核查轮换，不能以新账号隔离替代。

后续阶段新增 schema 用版本迁移，不引入旧读取路径或失败降级。当前发布与审核主体、真实证据、生产保留规则及负责人签认都是明确阻塞，而不是默认批准。
