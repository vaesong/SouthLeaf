# 后台安全持久化与事务设计

> 编号 D-505；日期 2026-10-18；状态：本批实现基线，真实数据库验证结果见实施跟踪。
> 范围：阶段二 2A / S1；依据：[ADR-003](../08_决策记录/ADR-003_阶段二管理安全与公开读取隔离.md)、[D-201](../02_通用后端/01_认证与会话设计.md)、[D-202](../02_通用后端/02_权限与资源访问设计.md)。

## 1. 数据与迁移隔离

现有 Reader 的 schema.* SELECT 不足以隐藏同库中的管理凭据。因此正式管理安全数据必须使用独立 schema、Writer 与迁移身份，公开 Reader 不获得任何管理库授权。当前不创建或修改正式管理库，也不扩权运行 Reader。

管理迁移位于 `db/admin-migration/V2__admin_security.sql`，使用独立历史表 `flyway_admin_schema_history`；不会由公开 `db/migration` 扫描或执行。V2 是独立管理迁移序列的首个版本，不伪装成公开 V1 的续迁或修改 V1。后续只追加版本，禁止修改已应用脚本、自动 repair 或 clean。

集成测试严格限定现有 `southleaf_public_it`，借用测试 Writer 验证 admin_* 表与事务；这是测试权限下的共库验证，不是正式部署布局，也不证明跨库授权隔离已部署。公开运行库 `southleaf_public` 不执行管理迁移。

## 2. 表及约束

| 表 | 归属与主要字段 | 约束/索引 |
|---|---|---|
| admin_account | 内部 account_id、enabled、security_version、credential_hash、created_at | 主键、非负版本、启用布尔；凭据非空但本批没有凭据验证或账号初始化工具 |
| admin_account_permission | account_id、permission_code | 联合主键、账号外键、明确能力词表 CHECK；不是实际人员角色已批准 |
| admin_session | 仅 token_digest、内部 session_id、账号、验证版本、签发/截止/撤销时间 | 摘要主键、session_id 唯一、账号外键、版本非负、生命周期为正且不超过 8 小时、账号/截止索引 |
| admin_security_audit | event_id、actor_account_id、target_session_id、action、occurred_at | 事件主键、每会话每动作唯一、动作白名单、账号时间索引；不保存 token/摘要/凭据 |

账号 ID、会话 ID 和摘要使用 ASCII 二进制比较，不能大小写折叠。时间使用 UTC DATETIME(6)。应用签发时间先截到微秒，再计算截止时间，避免数据库精度导致响应截止值与落库不一致。

audit 不外键依赖可清理的会话，不级联删除；账号/会话不做破坏性自动清理，保留策略后续确定。当前安全审计只覆盖会话签发/撤销，不冒充已经实现完整业务审计、requestId/来源追踪、不可篡改存储。

## 3. 适配器与连接边界

`JdbcAdminSessionStore(DataSource writer)` 自己以同一 DataSource 构造 JdbcTemplate 和 DataSourceTransactionManager，避免 JDBC 与事务管理器误绑不同连接池。无 Component/Bean 注解，不被公开启动扫描激活。

每个写操作独立 REQUIRES_NEW 事务，隔离级别 repeatable-read；读取使用独立只读 repeatable-read 事务。调用方不能用外层只读事务或弱隔离改变安全存储语义。事务必须在返回成功前提交，提交失败不得返回成功。此独立事务是会话生命周期边界；未来业务命令的审计仍须与业务命令同事务，不能直接复用此事务模板拆散业务原子性。

## 4. 会话签发

1. 凭据流程先核验账号凭据并捕获 securityVersion（本批尚未实现该流程）。
2. 开始存储事务，以 SELECT … FOR SHARE 对账号行加共享锁，并在锁内读取当前 enabled/security_version。签发不更新账号，不使用需要额外写权限的 FOR UPDATE。
3. 账号不存在、禁用或版本不同，返回 false，不写会话/审计。
4. 插入唯一摘要、随机 session_id 及会话事实；重复摘要必须失败，禁止 upsert。
5. 写签发审计，提交后才能把原 token 返回安全响应。

账号禁用/改密/权限变更的后续命令必须先锁账号、更新相关事实并递增版本，以排他写锁与签发的共享锁在同一账号行协调；不同会话签发可以并行持有共享锁。若重置先提交，旧版本签发失败；若签发先提交，随后重置使已有会话在下一次读取失效。不能只依赖凭据验证前的一次读取。

## 5. 当前会话读取

单条参数化 SELECT 联接未撤销会话、账号与其能力集合，提供同一语句一致性快照；不选 credential_hash，无 N+1、无权限缓存或副本降级。未知/已撤销会话为空，禁用/版本/有效期由领域层统一拒绝。

未知能力码或损坏映射是依赖/数据异常，不静默当作授权成功。数据库异常包装为 AdminSecurityStorageException，未来 Web 映射为安全的依赖不可用错误，不混成登录成功或“账号不存在”。

已返回 principal 不承诺请求执行期间绝对即时撤销；敏感业务写入仍在业务事务内重核版本、能力及状态。

## 6. 撤销与审计

锁定目标 session 行；未知或已撤销不写新审计。活跃行 UPDATE revoked_at，写撤销事件并一起提交。并发撤销仅一次状态变化和一次撤销审计；审计 SQL 失败时撤销也回滚。

锁顺序：签发先 account 后新 session；撤销只锁 session，不反向锁 account。未来账号修改不能用未约定的反向锁序批量改会话；版本失效无需批量更新每条 session。死锁/锁超时向上报告，不无限重试，不默认重新签发。

## 7. 真实数据库测试

必须使用显式环境提供的隔离 MySQL，缺少环境或库名不匹配直接失败，不 skip、不 H2、不修改公开运行库。测试只创建本批独立迁移和 it-admin-* 账号，按自己的账号/会话/事件 ID 清理 fixture，不截断/重建表或清理其他人的数据。

覆盖：增量迁移重复执行、公开历史不变、摘要和内部 ID 存储、当前权限、跨实例读取、未知/禁用/版本、唯一约束、撤销幂等、审计失败原子回滚、并发撤销，以及账号锁控制下的两种重置/签发提交顺序。审计故障通过测试专用 DataSource 在准备审计 SQL 时抛错，业务 INSERT/UPDATE 和回滚均发生在真实 MySQL；不代表真实网络故障或数据库宕机演练。

新增显式工具 `tooling/AdminDatabaseMigrationMain`：只接受 --migrate/--validate；目标实际 schema 必须与显式 SOUTHLEAF_ADMIN_MIGRATION_SCHEMA 一致且为 southleaf_admin 或其下划线后缀；拒绝 public/system schema、root、无 TLS 和非 VERIFY_IDENTITY URL。URL 参数采用小白名单，拒绝内嵌/编码凭据参数与重复参数；凭据由独立环境变量注入。无自动建库/种子/默认账号/repair/clean/baseline。工具用例和拒绝策略已做单元测试，未在正式环境执行，不等于正式最小授权已经核验。

正式执行前由运维创建独立管理库、迁移身份及外部信任材料，配置 SOUTHLEAF_ADMIN_MIGRATION_URL / USERNAME / PASSWORD / SCHEMA，基于构建后运行类路径显式调用 main；不在本计划写秘密。已有非空库无本历史时会拒绝自动 baseline，应人工审查，不用测试中的显式 baseline 作为生产绕过。

正式库隔离授权与 Writer 启动守卫的运行边界见 [D-506](06_后台管理运行隔离与Writer最小权限设计.md)（非 Web 守卫已实现，真实隔离验收正在进行）。凭据验证、HTTP 与后台页面仍属后续切片；本批不对外开放登录。

## 8. S1-B 实际最小权限反馈：共享账号锁

2026-10-18 的隔离 MySQL 8.4.11 验证发现：仅有 admin_account SELECT 的 Writer 执行原 FOR UPDATE 报 1142/42000；同身份 FOR SHARE 成功。用户明确委托助手自主作专业架构决策。本次选择修正锁契约而不扩权：签发只读取账号状态，用共享记录锁阻止账号写事务在签发/审计提交前改变 enabled 或 security_version；管理侧更新仍用排他锁。撤销的 session FOR UPDATE 与其 UPDATE 权限保持。

验证须同时覆盖：改密/禁用先持锁时旧版本或禁用账号签发失败；签发先持共享锁时改密/禁用等待至会话与审计提交后，再令会话失效；两个不同会话签发都能同时通过账号共享锁且各自原子提交。新增真实事务竞争测试，不以普通读或无锁重试替代。生产账号表仍只有 SELECT，六项权限矩阵不变；V2 不改。
