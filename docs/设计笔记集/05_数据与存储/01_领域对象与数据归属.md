## 1. 设计目标

明确公开展示涉及的领域对象、事实归属、生命周期和跨模块读取边界，为阶段一小程序公开查询提供稳定的数据来源。本文只形成领域和数据模型草案，不锁定最终数据库表、字段、ORM 映射或迁移脚本。

当前阶段一只开放公开内容读取。后台编辑、媒体上传、客户身份、预约、订单、支付、私密交付和售后对象属于目标架构或后续阶段，不因为本文件列出对象就进入 MVP。

## 2. 领域对象总表

| 对象 | 领域含义 | 阶段一用途 | 权威归属 |
|---|---|---|---|
| `BrandProfile` | 工作室品牌与公开资料 | 首页、关于/联系 | 内容与品牌模块 A05 |
| `PublicContentVersion` | 可被公开查询的品牌/首页内容版本 | 首页和内容区块 | 内容与品牌模块 A05 |
| `PhotoBusiness` | 摄影业务类别 | 六类业务展示和筛选 | 摄影业务模块 A07 |
| `Package` | 摄影套餐及服务说明 | 套餐列表与详情 | 摄影业务模块 A07 |
| `WorkCase` | 作品/案例及公开说明 | 作品列表与详情 | 作品模块 A06 |
| `MediaAsset` | 图片等媒体的登记和引用 | 封面、预览和媒体列表 | 文件/媒体能力；业务模块持有关联 |
| `PublicAuthorizationFact` | 公开授权主体、范围、渠道、期限和证据 | 公开资格判断 | 成片交付与授权模块 A15 |
| `PublicEligibility` | 面向公开查询的授权/发布资格派生结果 | 查询过滤和详情校验 | A06 消费 A15 事实并派生 |
| `Publication` | 资源是否进入公开版本的发布事实 | 查询过滤和下架 | 各资源模块，统一发布约束 |
| `PublicProjection` | 供公开查询读取的安全投影 | API DTO 来源 | 查询/内容投影层，不拥有业务事实 |
| `ContactProfile` | 电话、微信、地址、工作时间等公开联系信息 | 关于和联系入口 | 内容与品牌模块 A05 |

`PublicAuthorizationFact` 与 `PublicEligibility` 必须分开：前者是授权事实，后者是作品/案例是否可公开的派生判断。作品模块不能创建另一份授权事实覆盖 A15。

## 3. 对象权威归属

### 3.1 内容与品牌

A05 负责 `BrandProfile`、`PublicContentVersion`、`ContactProfile` 和首页公开编排事实。小程序只读已发布投影，不直接修改内容。品牌电话、地址和工作时间没有确认时，不用历史原型值或代码默认值补齐。

### 3.2 摄影业务与套餐

A07 负责 `PhotoBusiness`、`Package`、服务项和公开版本。六类业务必须可表达：儿童、亲子全家福、婚纱、写真、孕照、证件照。业务存在不代表一定存在已发布套餐；无套餐时由公开查询返回真实空结果或业务说明。

套餐价格只有在经营事实确认并进入公开版本后才可作为 `displayPrice`。未确认价格不应落成 0、历史测试值或前端默认值。

### 3.3 作品与案例

A06 负责 `WorkCase`、作品分类/标签、排序和作品与业务/套餐的公开关联。A06 不拥有授权同意、撤回、主体关系或证据原件，只消费 A15 的授权事实或资格端口。

### 3.4 公开授权

A15 负责 `PublicAuthorizationFact`，包括授权主体、对象范围、用途、渠道、有效期、撤回和证据引用。默认不公开；授权未核验、撤回、过期或主体关系不明确时不能形成有效公开资格。

A06 根据 A15 事实和作品规则生成 `PublicEligibility`。D-401 只读取资格结果，不能通过客户端参数或公开 DTO 修改它。

### 3.5 文件与媒体

`MediaAsset` 记录媒体的类型、尺寸、完整性、存储引用和状态，但公开查询只读取经过公开资格和发布状态过滤后的 `PublicMediaReference`。原始文件 key、私密文件、上传凭证和供应商字段不进入公开投影。

## 4. 对象关系和生命周期

### 4.1 阶段一公开内容路径

```text
领域事实/受控维护来源
  → 草稿或待审核版本
  → 发布前规则检查
  → 已发布公开版本
  → PublicProjection
  → 公开查询 DTO
  → 小程序展示
```

阶段一不交付管理后台，因此“受控维护来源”必须由另行确认的现有工具、导入流程或运维操作承载。无论具体工具为何，小程序都不能直接写入领域事实或发布状态。

### 4.2 作品公开路径

```text
WorkCase
  + Publication 已发布
  + A15 PublicAuthorizationFact 有效
  + A06 PublicEligibility = eligible
  + 公开 MediaAsset 可读取
  → PublicProjection.WorkCase
```

任一条件失效，公开投影不得继续返回。授权撤回不等同于删除客户私密文件；它只阻止受影响作品继续作为公开案例展示。

### 4.3 业务与套餐路径

```text
PhotoBusiness
  → 已发布业务版本
  → PublicProjection.Business

Package
  + 所属业务已公开
  + 套餐版本已发布
  + 服务项/价格说明已确认
  → PublicProjection.Package
```

套餐后续修改不应改变阶段二未来订单快照；阶段一只展示当前公开版本，订单快照规则在后续阶段另行实现。

### 4.4 媒体生命周期

```text
registered
  → validated
  → referenced_by_public_version
  → publicly_readable
  → replaced / withdrawn / unavailable
```

媒体不可用时可以让公开资源进入部分可用或不可用路径，但不能返回未受控原始地址。替换和下架需要使公开投影、缓存和分享入口按规则失效。

## 5. 快照、版本和不可变事实

- `PublicContentVersion`、业务/套餐公开版本和作品公开版本保存公开展示所依据的版本标识；
- 公开查询返回 `contentVersion`，客户端不能自行拼接版本；
- A15 的授权事实和撤回记录是可追溯事实，不通过覆盖字段抹除历史；
- `PublicEligibility` 是可重新计算的派生结果，应记录计算时间/版本或等价可追踪信息，但不把它当作授权证据；
- 阶段一不创建订单快照；未来订单必须在确认成单时复制业务、套餐、价格和时间等事实，不能依赖公开投影回溯；
- 公开投影可以按版本重建，重建不得改变授权事实、业务事实或历史审计。

## 6. 状态与派生摘要

公开查询至少需要区分以下服务端状态，客户端不必获得全部原始状态：

| 服务端概念 | 可能状态 | 是否进入公开投影 |
|---|---|---|
| 内容/资源发布 | draft、review、published、withdrawn、expired | 仅 published 且符合资格 |
| 公开授权 | unverified、valid、withdrawn、expired、unclear | 仅 valid 参与资格计算 |
| 作品公开资格 | eligible、ineligible、unknown | 仅 eligible |
| 媒体可读性 | registered、validated、readable、unavailable | 仅可受控读取的媒体 |
| 业务/套餐版本 | draft、published、withdrawn | 仅 published |

`unknown`、`unverified`、`withdrawn` 和 `expired` 默认按不公开处理。对外统一返回资源不可用，不暴露内部原因。

## 7. 跨模块引用和只读投影

模块之间通过应用服务、明确的只读端口或公开投影协作，不通过互相直接读表形成隐式耦合：

- 公开查询层读取 `PublicProjectionReader`；
- 作品模块通过授权资格查询端口读取 A15/A06 的结果；
- 内容编排通过作品/业务/套餐的公开摘要端口组装首页；
- 媒体能力提供受控公开引用，不把对象存储实现泄露给小程序；
- 发布/撤回事件或等价任务触发投影和缓存失效；
- 公开查询层不能调用后续订单、支付、交付或客户资料写操作。

建议的层次：

```text
领域模型
  → 持久化模型
  → 公开投影/查询模型
  → API DTO
  → 小程序展示模型
```

每层可以有转换和过滤，不能把数据库实体直接序列化给客户端。

## 8. 隐私、审计和删除边界

- 公开投影不包含客户姓名、联系方式、授权证据、内部备注、订单、支付、交付和家庭成员信息；
- 授权撤回必须能追溯触发时间、对象范围、处理结果和失败任务，但公开端只显示不可用；
- 公开资源下架不自动删除原始媒体或私密交付文件；删除策略由 A15、文件与存储设计及后续阶段规则共同决定；
- 日志记录资源标识、requestId、资格结果摘要和处理状态时必须脱敏，不能写入原始授权文本、私密地址或签名 URL；
- 客户个人数据、私密媒体和业务交易数据即使未来与公开资源有关联，也不能通过公开 ID 反查；
- 备份、保留和物理删除遵循 D-数据迁移/备份设计及法律/经营确认，不在阶段一公开查询中擅自删除。

## 9. 阶段开放映射

| 对象/能力 | 阶段一 | 阶段二 | 阶段三 |
|---|---|---|---|
| 品牌、业务、套餐公开投影 | 开放读取 | 继承 | 继承 |
| 作品公开投影 | 开放，须满足授权资格 | 继承 | 继承 |
| 公开授权事实维护 | 由受控流程提供前置事实，不交付后台 | 运营后台可纳入 | 完整授权执行和撤回 |
| 客户身份/资料 | 不开放 | 开放 | 继承 |
| 预约/订单快照 | 不开放 | 开放 | 继承 |
| 支付/退款事实 | 不开放 | 不开放 | 开放 |
| 私密交付媒体 | 不开放 | 不开放 | 开放 |
| 公开媒体读取 | 开放受控读取 | 继承 | 继承 |

## 10. 待确认问题

- 阶段一公开数据的权威维护来源、导入方式、审核人和发布责任；
- A15 公开授权事实向 A06/A04 提供结果的端口、查询时效和撤回通知方式；
- `PublicProjection` 是否独立持久化、按请求实时组装或由缓存/事件任务构建；
- 公开版本、媒体版本、缓存失效和旧链接安全处理的时限；
- 六类业务首批真实资料、套餐价格说明、品牌联系信息的确认人；
- 未来后台阶段如何复用这些事实而不让管理操作绕过授权和发布规则。
