# SouthLeaf 摄影业务与目标用户分析

> 文档编号：A03  
> 类型：专题需求分析  
> 状态：业务目录已确认，套餐与场景规则待进一步确认  
> 更新日期：2026-10-02  
> 上游：[A01_需求全景分析论证](A01_需求全景分析论证.md)、[A02_深入需求分析框架](A02_深入需求分析框架.md)

## 1. 分析目的

本专题用于确认 SouthLeaf 历史版本曾表达过哪些摄影业务、作品分类、套餐线索和客户入口，并进一步区分：

- 历史原型可以直接证明的内容；
- 仅能作为候选方向的弱线索；
- 仍需要工作室负责人或真实经营材料确认的业务事实。

本专题不把历史页面中的占位数据自动视为当前经营规则，也不在本篇确定实施阶段、技术架构或数据库结构。

## 2. 证据口径

| 状态 | 含义 |
|---|---|
| 已有原型证据 | 在现有前端代码、后端种子数据或页面交互中明确出现，只能证明历史版本表达过该内容 |
| 弱线索 | 在宣传文案、成员履历或规划材料中出现，但缺乏完整业务对象、套餐或真实成交证据 |
| 待验证 | 需要工作室负责人、现行价目表、服务记录或客户访谈确认，不能凭行业惯例补全 |

需要特别注意：当前仓库没有真实订单、完整现行价目表、客户访谈或经营数据。因此，以下结论主要回答“历史原型表达了什么”，不等同于“工作室现在实际销售什么”。

## 3. 历史版本业务候选清单

### 3.1 已确认保留的业务目录

根据当前需求确认，以下六类业务全部保留，作为 SouthLeaf 的摄影业务范围：

| 业务类型 | 历史证据 | 当前状态 |
|---|---|---|
| 儿童 | 作品分类和套餐分类均出现；有儿童分类套餐实例 | 已确认保留 |
| 亲子全家福 | 作品分类和套餐分类均出现 | 已确认保留 |
| 婚纱 | 作品分类和套餐分类均出现 | 已确认保留 |
| 写真 | 作品分类和套餐分类均出现；作品条目和写真套餐实例均出现 | 已确认保留 |
| 孕照 | 作品分类和套餐分类均出现 | 已确认保留 |
| 证件照 | 作品分类中出现；套餐页历史数据中未形成可靠的同名业务分类 | 已确认保留 |

“全部保留”的含义是：历史版本明确出现的六类业务不因当前原型数据不完整而删除。是否已经为每类业务准备了现行套餐、作品和完整经营规则，仍需在后续专题中分别确认。

主要证据：

- 作品页分类包括“儿童、亲子全家福、婚纱、写真、孕照、证件照”：`frontend/pages/works/works.vue:88-97`。
- 套餐页分类包括“儿童、亲子全家福、婚纱、写真、孕照”：`frontend/pages/package/package.vue:105-117`。
- 儿童和写真分别有套餐实例：`frontend/pages/package/package.vue:119-176`。
- 作品条目中出现“男孩写真”和“圣诞女孩”，并关联“写真”套餐：`frontend/pages/works/works.vue:103-216`。

### 3.2 不应直接视为摄影业务的分类

“创始人档”在历史作品页中作为分类出现，作品条目也使用该分类；但从语义上看，它更接近作品集档位、作者/品牌栏目或内部作品分组，不足以证明是一种客户可以购买的摄影业务。

当前建议：

- 在作品展示分析中保留“创始人档”作为历史分类线索；
- 在业务目录和套餐目录中暂不把它当作独立摄影业务；
- 待负责人确认其真实含义后，再决定它是作品分类、服务档位还是品牌栏目。

证据：`frontend/pages/works/works.vue:88-110`、`frontend/pages/works/works.vue:118-216`。

### 3.3 未纳入当前业务范围的其他线索

根据当前确认，以下内容暂不纳入 SouthLeaf 当前业务目录：

- 婚礼摄影；
- 家庭聚会；
- 个人肖像；
- 情侣或夫妻摄影；
- 商业摄影。

这些内容可以保留为历史材料中的背景线索，但当前不作为业务目录、套餐目录或预约入口设计依据。证据包括：`frontend/pages/about/about.vue:16,92,98`、`docs/计划/01_重构.md:101-109`。

## 4. 历史套餐和服务线索

### 4.1 原型中表达过的套餐结构

历史套餐页面表达过以下字段和信息：

- 套餐名称、简介、业务分类和封面图；
- 原价、活动价、活动开始和结束时间；
- 拍摄时长、原片数量、精修数量和当日预告；
- 化妆、服装、相册、相框、U 盘或电子文件等服务/交付内容；
- 快修、增加机位等附加服务；
- 定金、尾款和交付时间提示；
- 选片和相册重做等服务约束。

证据主要来自：`frontend/pages/package/package.vue:119-204`、`frontend/pages/package/pkgdetail.vue:117-132`，以及后端套餐实体 `backend/src/main/java/cn/zhinan/uniapp/entity/Package.java:18-34`。

### 4.2 具体数值的可信度限制

历史页面中的具体价格、数量和规则不能直接当成当前需求，原因包括：

- 套餐名称与描述存在明显错配，例如秋日套餐使用圣诞文案，圣诞套餐使用秋日婚礼文案；
- 图标和正文中的拍摄数量、精修数量不一致；
- 同一套餐在不同页面出现不同活动价格或定金比例；
- 活动结束年份和页面数据明显具有测试或占位痕迹；
- 页面存在重复套餐实例，不能据此判断真实套餐数量。

因此，当前只能确认产品曾经需要表达“标准套餐及其服务包含项”，不能确认现行价格、拍摄时长、成片数量、定金比例、交付时限或附加服务价格。

## 5. 目标用户初步分析

### 5.1 已能从历史原型推断的用户任务

历史页面至少支持以下客户任务：

1. 按摄影分类浏览作品；
2. 查看作品多图和文字说明；
3. 查看套餐价格、服务内容和注意事项；
4. 通过电话或微信联系工作室；
5. 查看工作室介绍、位置和服务入口。

这些是产品入口和页面能力的证据，不等于真实客户已经按此路径完成过交易。

### 5.2 按业务候选推导的用户场景

| 场景 | 目标用户线索 | 需要进一步确认的内容 |
|---|---|---|
| 儿童摄影 | 家长或家庭成员 | 是否以儿童单人、亲子或家庭组合区分；是否需要监护人信息 |
| 亲子全家福 | 家庭客户 | 拍摄人数、年龄范围、服装/造型和场地要求 |
| 婚纱或婚礼相关摄影 | 新人或婚礼相关客户 | 婚纱、婚礼是否是两类不同服务；是否涉及外拍、档期和团队配置 |
| 写真 | 个人客户 | 风格、服装、妆造、拍摄地点和套餐差异 |
| 孕照 | 孕期客户及陪同家属 | 孕周、身体情况、陪同人员和拍摄安全注意事项 |
| 证件照 | 有证件或正式肖像需求的客户 | 是否实际提供；规格、拍摄时长和交付方式 |

这些场景是需求分析用的待验证模型，不是已经确认的用户画像。

## 6. 当前确认、建议与待验证事项

### 6.1 已有原型证据

- 历史版本出现过儿童、亲子全家福、婚纱、写真、孕照、证件照等分类，用户已确认六类业务全部保留。
- 儿童和写真有相对完整的套餐或作品实例支撑。
- 历史套餐结构包含价格、服务项、附加服务、定金/尾款和交付提示。
- 历史客户入口包括电话、微信、工作室介绍和位置查看。
- 在线预约、日历、订单和客户相册在历史界面中存在入口，但部分仍是“开发中”或占位交互。

### 6.2 产品分析建议

- 业务目录、作品分类和套餐分类应作为三个可以关联但不必一一对应的对象分析。
- “创始人档”暂按作品/品牌分类处理，不按摄影业务处理。
- 固定套餐应保留标准价格和服务内容的整体表达；是否存在需要先沟通的特殊业务，待逐类确认。
- 作品可以帮助客户判断风格和能力，但作品分类不应自动等于可预约业务。
- 历史页面中的价格和服务条款只作为字段和信息结构参考，不作为现行经营规则。

### 6.3 必须向工作室确认的问题

1. 六类已确认业务分别适用什么客户场景、服务范围和预约前置条件？
2. 婚礼摄影、家庭聚会、个人肖像、情侣/夫妻和商业摄影暂不纳入当前业务范围；未来如需增加，应另行确认并更新业务目录。
3. “创始人档”究竟是作品分类、品牌栏目、套餐档位，还是其他概念？
4. 每类业务是否存在固定套餐；哪些业务必须先沟通后确定服务内容？
5. 当前有效套餐的价格、拍摄时长、服务包含项、交付内容、固定定金金额和尾款说明是什么？
6. 业务是否存在地点、人数、档期、团队配置或服务区域限制？
7. 客户选择作品后，工作室是否允许按同一风格提供服务，还是只能选择已有套餐？

## 7. A03 的完成标准

A03 在以下信息得到确认后，才适合从“证据基线稿”升级为需求基线：

- 完整且按当前经营有效性确认的业务目录；
- 每类业务对应的目标客户和主要场景；
- 固定套餐与先沟通业务的边界；
- 套餐和作品之间的关联规则；
- 现行套餐的核心服务信息和约束；
- 需要提前收集的客户信息及不应在公开页面展示的内容。

在上述信息确认前，A03 不应被用来推导完整预约字段、订单状态或支付规则。
