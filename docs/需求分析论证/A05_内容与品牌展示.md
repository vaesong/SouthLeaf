## 1. 专题目的

本专题分析 SouthLeaf 的品牌内容、首页编排、工作室资料、团队公开信息、服务流程、联系方式、地址地图及公共内容发布要求。

本文件回答：

- 潜在客户需要通过哪些公开信息理解并信任工作室；
- 工作室需要维护哪些品牌和公共内容；
- 首页如何引用作品、摄影业务和套餐，而不复制它们的业务事实；
- 内容如何经历编辑、预览、发布、下架和恢复；
- 小程序和官网如何共享统一内容口径；
- 联系入口和预约入口如何避免误导；
- 当前工程有哪些硬编码、占位和内容冲突需要淘汰；
- 内容模块需要满足哪些可验证的验收标准。

本文件不定义数据库表、API、对象存储厂商、后台组件或视觉配色，也不重新定义作品案例、套餐、预约、订单、支付和成片交付规则。

## 2. 专题边界

### 2.1 A05 拥有的需求

A05 负责以下公开内容及其维护需求：

- 品牌名称、Logo、标语和品牌介绍；
- 首页区块与展示编排；
- 工作室介绍、特色和服务区域；
- 团队成员的公开资料；
- 面向客户的通用服务流程；
- 联系电话、微信联系说明和其他公开联系渠道；
- 工作室地址、地图位置、营业或联系时间；
- 常见问题、公开通知或预约须知入口；
- 内容草稿、预览、发布、下架、排序和变更记录；
- 小程序与官网的统一内容事实及端侧编排差异。

### 2.2 A05 只引用、不拥有的需求

| 对象或规则 | 主归属 | A05 允许做什么 | A05 不得定义什么 |
|---|---|---|---|
| 作品案例 | A06 | 配置首页展示位并引用公开资格有效的案例 | 案例图片集合、分类和授权结果触发的展示处理 |
| 摄影业务与套餐 | A07 | 引用已发布业务或套餐作为首页入口 | 价格、服务内容、定金、版本和预约资格 |
| 小程序客户体验 | A08 | 提供品牌内容和入口需求 | 页面导航、登录时机和完整交互方案 |
| 品牌官网体验 | A09 | 提供统一内容源和公开信息要求 | SEO 技术实现和官网预约方式 |
| 身份与隐私 | A11 | 要求敏感内容受权限控制 | 客户身份绑定和敏感资料规则 |
| 预约与档期 | A12 | 提供预约入口或联系入口 | 固定时段、占档、冲突和改期规则 |
| 订单、支付和交付 | A13-A15 | 在公开内容中解释一般服务流程 | 订单状态、金额、退款和私密成片访问 |

### 2.3 A05 的唯一主规则

工作室品牌与公共内容由统一内容域维护。内容经过草稿、预览、发布或下架生命周期后，公开端只能读取已发布版本；小程序与官网共享同一内容事实，但允许按端侧场景采用不同编排。电话、微信、地址和地图入口只表达联系，不产生预约、订单或支付事实。

### 4.5 当前问题结论

| 问题 | 当前表现 | 产品风险 |
|---|---|---|
| 内容硬编码 | 品牌、团队、电话、地址、作品推荐写在页面中 | 每次更新依赖开发者，无法持续运营 |
| 多处内容源 | 关于页和底部各维护一套联系方式 | 客户看到不同电话或地址 |
| 测试或占位内容 | 用户评价占位、预约入口开发中、历史测试文案 | 正式发布后损害可信度 |
| 无发布生命周期 | 接口查到什么就直接展示 | 草稿、错误或未授权内容可能公开 |
| 无首页编排 | 推荐作品和区块写死 | 无法按经营重点调整首页 |
| 无图片管理 | 轮播依赖固定文件目录 | 无法上传、排序、替换和追溯 |
| 无权限审计 | 没有可验证的后台内容角色和操作记录 | 无法追溯谁修改了联系方式或发布内容 |
| 跨端口径未建立 | 官网和小程序统一内容源尚未落地 | 后续容易出现两套品牌文案和联系方式 |

## 5. 用户问题与产品价值

### 5.1 潜在客户的问题

潜在客户需要快速回答：

- 这是谁的工作室；
- 擅长什么风格和业务；
- 是否可信；
- 有哪些代表作品；
- 大致提供什么服务；
- 位于哪里、服务什么区域；
- 如何电话或微信联系；
- 下一步是联系咨询还是提交预约。

如果品牌、作品、套餐和联系信息不一致，客户无法建立信任，也无法判断下一步操作。

### 5.2 工作室的问题

工作室需要：

- 不修改源码即可更新品牌和公共资料；
- 一处修改联系方式后同步小程序和官网；
- 在发布前预览内容；
- 控制内容何时公开或下架；
- 调整首页重点作品、业务和套餐；
- 追溯谁修改、发布或下架了重要内容；
- 避免未确认、未授权或已过期内容公开展示。

### 5.3 产品价值

A05 的目标不是建立大型内容管理平台，而是让 SouthLeaf 成为一个可以真实运营的单工作室品牌入口：内容权威、更新可控、公开状态清楚、联系路径可信、跨端口径一致。

## 6. 目标内容地图

### 6.1 品牌基本资料

| 内容 | 用途 | 状态 |
|---|---|---|
| 品牌正式名称 | 导航、首页、关于页、分享信息 | 必需，具体内容待负责人确认 |
| Logo | 首页、关于页、分享或加载场景 | 必需，正式素材待确认 |
| 品牌标语 | 首屏辅助表达 | 可选，现有文案只作原型证据 |
| 品牌介绍 | 说明定位、风格和价值 | 必需，正式文案待确认 |
| 核心特色 | 帮助客户理解差异 | 产品建议，内容待确认 |
| 服务区域 | 说明可提供服务的地域 | 建议独立维护，不与工作室地址混用 |
| 品牌版权/备案信息 | 官网或页脚所需公共信息 | 按正式上线要求确认 |

### 6.2 工作室资料

| 内容 | 用途 | 规则 |
|---|---|---|
| 工作室介绍 | 关于页和官网品牌页 | 共享统一正文，可按端侧摘要展示 |
| 工作室地址 | 联系和到店信息 | 与地图坐标、地点名称保持一致 |
| 地图位置 | 打开地图导航 | 地址或坐标变更需要一致性校验 |
| 营业/联系时间 | 管理客户联系预期 | 支持普通时间和特殊说明 |
| 服务区域 | 说明到店、外拍或地区范围 | 不直接等同于工作室地址 |
| 联系须知 | 说明电话/微信适用时间和方式 | 不承诺预约成功 |

### 6.3 团队公开资料

团队成员公开信息建议支持：

- 姓名或公开称呼；
- 对外职务；
- 头像；
- 简介；
- 擅长方向；
- 展示顺序；
- 是否公开；
- 在职/停用状态；
- 可选的关联公开作品。

团队公开资料不等同于后台账号、摄影师排班资源或预约可指定人员。成员能否被指定、是否参与排班及其履约权限由后续专题确认。

### 6.4 联系渠道

每个公开联系渠道应独立维护：

| 渠道 | 建议字段 | 公开动作 |
|---|---|---|
| 电话 | 标签、号码、适用时间、是否公开 | 一键拨打 |
| 微信 | 微信号、二维码、说明、是否公开 | 展示二维码或复制说明 |
| 小红书 | 账号名、链接/二维码、是否公开 | 打开或展示对应渠道 |
| 微博 | 账号名、链接/二维码、是否公开 | 打开或展示对应渠道 |
| 抖音 | 账号名、链接/二维码、是否公开 | 打开或展示对应渠道 |
| 其他渠道 | 名称、图标、链接/二维码、说明 | 按端能力展示 |

不同渠道不得复用错误二维码或把微信二维码标成其他平台账号。无有效账号配置时，不展示相应入口。

### 6.5 通用服务流程

通用流程用于帮助潜在客户理解服务如何进行，建议表达：

1. 浏览作品与服务；
2. 电话/微信沟通或提交预约申请；
3. 工作室确认并形成订单；
4. 支付定金；
5. 拍摄准备与拍摄；
6. 拍摄完成后支付尾款；
7. 后期制作与成片交付。

A05 只维护面向公众的流程说明和展示顺序。预约、订单、支付和交付的真实状态及异常规则以 A04、A12-A15 为准，不能由公共流程文案改变。

不同摄影业务是否需要不同服务流程，在 A07 分析；A05 可以引用已发布的业务特有流程摘要。

### 6.6 FAQ 与公开须知

FAQ/公开须知作为建议内容类型，可用于回答：

- 如何联系工作室；
- 如何预约；
- 提交申请是否代表预约成功；
- 拍摄前需要准备什么；
- 支付和交付的一般顺序；
- 工作室地址、联系时间和服务区域。

FAQ 不应取代正式套餐条款、订单约定、退款规则或隐私授权。是否在首版单独建设 FAQ，由工作室内容量决定。

### 6.7 用户评价与信任内容

当前首页只有用户评价占位图片，无法证明存在真实、已授权的评价数据。

如后续需要展示评价，必须确认：

- 评价来源；
- 是否取得公开展示授权；
- 是否匿名或脱敏；
- 是否允许工作室编辑摘要；
- 关联业务或作品方式；
- 审核、下架和客户撤回方式。

在上述规则未确认前，不应发布虚构评价、测试评价或无法验证来源的评分。

## 7. 首页内容与编排需求

### 7.1 首页目标

首页应在首屏和首轮浏览中帮助客户：

- 识别品牌和摄影定位；
- 快速感受代表风格；
- 进入主要摄影业务或套餐；
- 找到电话、微信、地址或预约入口；
- 理解联系、咨询和预约之间的区别。

首页不是静态轮播图集合，也不是把所有内容无差别堆在一个页面。

### 7.2 首页候选区块

| 区块 | 主要内容 | 状态 |
|---|---|---|
| 品牌首屏 | Logo、品牌名、核心文案、代表视觉和主要行动入口 | 已确认需要，具体内容待定 |
| 代表作品 | 引用已发布且授权有效的作品案例 | 已确认需要，规则由 A06 提供 |
| 重点业务/套餐 | 引用已发布摄影业务或套餐 | 已确认需要，规则由 A07 提供 |
| 工作室特色 | 公开优势和可信度信息 | 产品建议，内容待确认 |
| 服务流程 | 通用客户旅程摘要 | 已确认需要，详细文案待确认 |
| 工作室/团队摘要 | 简要介绍与详情入口 | 已确认需要 |
| 联系与位置 | 电话、微信、地址、地图和联系时间 | 已确认需要 |
| FAQ/须知 | 高频公共问题 | 产品建议 |
| 用户评价 | 已授权真实评价 | 待确认，不以原型占位图为需求事实 |

### 7.3 首页编排规则

后台至少需要：

- 控制区块是否展示；
- 调整区块顺序；
- 设置区块标题和必要的辅助文案；
- 选择引用的已发布作品、业务或套餐；
- 调整引用项顺序；
- 在发布前预览小程序展示效果；
- 在引用内容失效时得到提示。

### 7.4 推荐内容策略

首版建议采用人工选择，而不是“热门”或复杂自动推荐，原因是当前没有可靠浏览、收藏、预约或成交数据。

推荐项必须满足：

- 引用对象已发布；
- 作品公开授权有效；
- 套餐或业务允许公开展示；
- 被引用内容下架后，首页不得继续展示不可访问卡片；
- 内容后台应提示推荐位缺失或引用失效。

当没有配置推荐内容时，首版建议隐藏对应区块，而不是自动使用未经选择的随机内容。是否允许“最新内容”兜底，可在 A08/A09 页面专题中确认。

### 7.5 跨端编排

小程序和官网共享：

- 品牌基本资料；
- 工作室介绍；
- 团队公开资料；
- 联系方式、地址和地图数据；
- 服务流程；
- 已发布作品、业务和套餐引用。

端侧允许：

- 不同区块顺序；
- 不同展示数量；
- 不同摘要长度；
- 官网增加 SEO 标题、摘要、分享图等公开元数据；
- 小程序使用更直接的电话、微信和后续预约入口。

端侧编排不能复制并修改品牌事实、联系方式、价格或授权状态。

## 8. 内容生命周期

### 8.1 内容状态

首版至少需要：

| 状态 | 含义 | 公开端可见 |
|---|---|---:|
| 草稿 | 内容正在编辑，尚未公开 | 否 |
| 已发布 | 当前生效的公开版本 | 是 |
| 已下架 | 停止公开展示，保留内容和历史 | 否 |

“预览”是对草稿或待发布版本的查看能力，不等同于公开状态。

定时发布、归档、完整版本回滚可以作为扩展能力，不应成为阶段一轻量后台的前置条件。

### 8.2 编辑和保存

内容编辑需要：

- 明确必填项和格式要求；
- 支持保存草稿；
- 保存失败时保留用户输入或明确告知；
- 重要字段变更前提示影响范围；
- 不因保存草稿直接改变公开端；
- 记录最近修改人和修改时间。

### 8.3 预览

发布前预览至少需要覆盖小程序当前目标页面。官网进入范围后，应支持对应官网展示预览或等价检查。

预览必须：

- 使用待发布内容；
- 明确标识为预览；
- 不被公开访客访问；
- 能发现缺图、超长文本、无效引用和联系方式缺失。

### 8.4 发布

发布操作需要：

- 验证必填字段、图片和引用对象；
- 记录发布人和发布时间；
- 产生新的公开版本；
- 在小程序和官网读取同一份已发布事实；
- 发布失败时保持原公开版本，不出现半发布状态；
- 对联系方式、地址等高影响字段的发布进行清晰确认。

### 8.5 下架

内容下架后：

- 公开列表和首页不再显示；
- 直接访问公开详情时得到统一的不可用结果；
- 引用该内容的首页区块获得失效提示或自动隐藏失效项；
- 历史内容和审计记录保留；
- 下架作品或套餐不修改既有订单事实。

### 8.6 恢复

首版可以通过重新发布已下架内容完成恢复。恢复前需要重新执行发布校验，避免恢复过期联系方式、无效图片或失效引用。

## 9. 内容编辑和发布权限

### 9.1 负责人

工作室负责人可以：

- 编辑、预览、发布和下架品牌内容；
- 修改联系方式、地址和营业时间；
- 管理团队公开资料；
- 调整首页编排；
- 查看内容发布和变更审计；
- 处理失效引用和异常内容。

### 9.2 管理员

管理员可以承担日常内容编辑和预览。是否允许管理员直接发布和下架，由工作室在后台权限专题中最终确认。

阶段一至少需要一个可执行发布操作的负责人或管理员角色，不能因为审批模型未确定而使内容无法运营。

### 9.3 摄影师

摄影师默认不能修改品牌资料、联系方式、地址、首页编排或内容发布状态。是否允许摄影师提交作品草稿由 A06 分析，不在 A05 扩大其权限。

### 9.4 审计要求

至少记录：

- 创建和修改内容；
- 发布、下架和恢复；
- 联系电话、微信、地址、地图和营业时间变更；
- 首页区块和推荐引用变更；
- 团队成员公开状态变化。

审计包含操作者、时间、动作、资源和必要的变更摘要，不记录密码、令牌或永久私密文件地址。

## 10. 联系、地址和地图规则

### 10.1 单一权威来源

电话、微信、地址、坐标、地点名称、营业/联系时间和社交账号必须从统一内容源读取，不得由首页、关于页和底部组件分别硬编码。

### 10.2 电话

- 支持一个或多个公开电话；
- 每个号码有用途标签和适用时间；
- 隐藏或下架后所有公开端同步停止展示；
- 空号码或格式错误不能发布；
- 点击拨号只表示发起联系，不表示预约成功。

### 10.3 微信

- 维护微信号、二维码和添加说明；
- 二维码与微信号应属于同一联系渠道；
- 二维码失效时可替换并重新发布；
- 不使用测试二维码或把一个二维码冒充多个平台；
- 打开或复制微信信息不产生预约状态。

### 10.4 地址和地图

- 公开地址、地点名称、经纬度和导航提示保持一致；
- 可分别维护工作室地址和服务区域；
- 地址变更发布前提示检查地图坐标；
- 地图能力不可用时仍显示可复制的文字地址；
- 暂不支持多个门店，未来有真实经营需求再扩展。

### 10.5 社交渠道

没有真实账号、链接或二维码时，不展示对应社交图标。每个平台使用独立配置和资源，不能通过一个通用占位二维码假装已开通。

## 11. 团队公开资料规则

- 团队成员是否公开由工作室控制；
- 公开履历、奖项、从业年限和案例数量必须有负责人确认，不从原型文案直接继承；
- 成员头像和介绍需要获得适当的公开许可；
- 停用成员后不再出现在团队列表，但历史案例中的作者署名处理由 A06 确认；
- 团队展示顺序可维护；
- 对外职位与后台角色可以不同，不能因公开显示“摄影师”自动获得后台权限；
- 是否允许客户指定摄影师不在 A05 定义。

## 12. 媒体和图片需求

A05 只定义公开品牌媒体的产品需求：

- Logo、首屏图、工作室图片、团队头像、二维码和流程配图支持上传或选择；
- 图片具备用途、替代文本/说明、展示顺序和公开状态；
- 发布前校验文件是否存在、是否完成必要处理；
- 支持替换图片而不要求修改页面源码；
- 被公开页面引用的图片删除前提示影响范围；
- 公开品牌媒体与客户私密成片隔离；
- 图片裁切、压缩和多尺寸策略由技术设计确定。

轮播图不再通过扫描开发机固定目录作为正式管理方式。

## 13. 跨端一致性规则

### 13.1 统一事实

以下内容在小程序和官网中必须一致：

- 品牌名称；
- 品牌介绍的权威正文；
- 工作室地址、地图地点和服务区域；
- 电话、微信和公开社交账号；
- 团队成员公开状态和权威资料；
- 内容发布与下架状态。

### 13.2 允许差异

不同端可以有：

- 不同首页区块顺序；
- 不同摘要长度；
- 不同作品或套餐展示数量；
- 不同联系按钮形式；
- 官网专用的 SEO 和分享元数据；
- 小程序专用的后续预约入口。

### 13.3 不允许差异

不同端不得：

- 展示不同电话号码却没有明确用途标签；
- 展示相互矛盾的地址、坐标或营业时间；
- 修改套餐价格或服务内容副本；
- 绕过作品公开授权；
- 展示已下架内容；
- 把“联系”描述成“预约已成功”。

## 14. 异常与空状态

### 14.1 内容缺失

- 必需品牌资料未完成时，不允许正式发布整个品牌入口；
- 可选区块没有内容时隐藏区块，不展示测试文案、空卡片或占位评价；
- 联系方式不可用时至少保留一个经过确认的公开联系渠道；
- 地图失败时展示文字地址和其他联系方法。

### 14.2 引用失效

首页引用的作品、业务或套餐被下架或失去公开资格时：

- 公开端不再展示失效项；
- 后台标记引用异常；
- 管理员可以替换或移除；
- 不复制对象数据制造无法同步的首页副本。

### 14.3 发布失败

发布失败时：

- 保持原已发布版本；
- 告知失败原因和可执行操作；
- 不出现部分区块已更新、部分仍旧的不可解释状态；
- 允许管理员修复后重试；
- 重复点击发布不产生重复版本或重复记录。

### 14.4 图片异常

图片上传、处理或读取失败时：

- 后台明确标识异常图片；
- 未完成校验的图片不能发布；
- 公开端使用合理降级或隐藏，不显示本机路径和内部错误；
- 删除或替换失败进入可重试或人工处理状态。

## 15. 信息和体验要求

### 15.1 可信度

- 正式内容不得混入“哈哈哈测试”“开发中”或明显占位文案；
- 奖项、年限、服务数量和客户评价需有负责人确认；
- 电话、微信、地址和地图信息在发布前进行一致性检查；
- 公开图片应真实呈现工作室、团队或摄影风格，不使用与内容无关的占位图。

### 15.2 可理解性

- “电话联系”“添加微信”“提交预约”使用不同文案和反馈；
- 服务流程使用客户能理解的语言，不暴露内部状态码；
- 下架或不存在的内容返回安全、明确提示；
- 首页推荐卡片说明其是作品、业务还是套餐，避免混淆。

### 15.3 可维护性

- 高频字段不要求开发者修改源码；
- 后台表单名称与公开端含义一致；
- 内容列表可以按类型、状态和更新时间查找；
- 发布前可以确认影响的页面和端；
- 修改默认编排不改变作品、套餐等被引用对象的权威内容。

## 16. 功能需求清单

### 16.1 品牌与工作室资料

- 新建和编辑品牌资料草稿；
- 上传或选择 Logo 和品牌图片；
- 编辑工作室介绍、服务区域和特色；
- 维护地址、地图地点、营业/联系时间；
- 预览、发布、下架和恢复；
- 查看最近修改和发布信息。

### 16.2 团队

- 新建、编辑、排序和停用团队公开资料；
- 上传头像；
- 控制是否公开；
- 预览团队列表和成员信息；
- 停用不删除历史审计。

### 16.3 联系渠道

- 维护电话和用途标签；
- 维护微信号、二维码和说明；
- 独立维护社交账号、链接或二维码；
- 控制渠道是否公开；
- 发布前验证必填字段和资源；
- 公开端按能力发起拨号、显示二维码或打开链接。

### 16.4 首页编排

- 显示/隐藏区块；
- 调整区块顺序；
- 编辑区块标题和摘要；
- 选择已发布作品、业务和套餐；
- 调整引用项顺序；
- 预览小程序首页；
- 提示失效引用；
- 发布后公开端读取新版本。

### 16.5 服务流程与 FAQ

- 维护流程步骤、标题、说明和排序；
- 支持隐藏或下架；
- 可选维护 FAQ 分类、问题、答案和排序；
- 不在流程/FAQ 中复制会频繁变化的套餐价格和订单规则。

## 17. 验收标准

### 17.1 内容可维护

1. 负责人或有权限管理员无需修改源码，即可维护品牌名称、Logo、介绍、团队、电话、微信、地址、地图和联系时间。
2. 首页区块、区块顺序及引用的作品/业务/套餐可以在后台调整。
3. 内容草稿保存不会直接改变公开端。
4. 发布后，小程序能够读取并展示新的已发布内容。
5. 官网进入范围后，与小程序读取同一品牌和联系方式事实。

### 17.2 发布生命周期

1. 内容支持草稿、预览、发布和下架。
2. 未发布和已下架内容不会出现在公开查询或首页。
3. 发布失败时保留原公开版本。
4. 重复发布操作不会产生不可解释的重复内容。
5. 发布、下架和高影响字段变更留有审计记录。

### 17.3 内容一致性

1. 首页、关于页和公共底部不再分别硬编码电话、微信和地址。
2. 同一电话、地址、品牌名和团队资料在小程序不同页面保持一致。
3. 地址文本、地图地点和坐标属于同一配置并经过校验。
4. 社交平台分别使用自己的账号信息和二维码，不复用错误资源。
5. 作品或套餐下架后，首页不保留失效卡片。

### 17.4 公开边界

1. 公开访客无需登录即可查看已发布品牌内容。
2. 草稿、后台备注、客户资料和私密文件不会通过公共接口返回。
3. 首页只能引用公开状态有效的作品、业务和套餐。
4. A05 不绕过作品公开授权，不复制订单、支付或交付状态。
5. 联系电话、微信或地图操作不会被记录为预约成功。

### 17.5 异常和空状态

1. 可选区块无内容时隐藏，不展示测试文案或占位评价。
2. 图片异常或引用失效时，后台可以识别并修复。
3. 地图不可用时仍能查看文字地址和其他联系方式。
4. 没有正式社交账号配置时不显示对应入口。
5. 错误响应不暴露本机目录、内部异常或未发布内容。

### 17.6 阶段一可运营性

A05 对 P01 阶段一的最低支持结果是：

```text
工作室能够自主维护品牌和公共资料
    +
内容经过预览和发布后出现在小程序
    +
公开端只展示已发布内容
    +
电话、微信、地址和地图口径一致
    +
首页可以引用已发布作品和套餐
```

这不表示在 A05 中提前实现预约、订单、支付或成片交付。

## 19. 后续专题输入

A05 为后续专题提供以下输入：

- A07：摄影业务和套餐在首页展示时的公开字段与版本边界；
- A08：小程序首页、工作室页、联系入口和空状态；
- A09：官网内容深度、SEO、分享信息及与小程序编排差异；

## 20. 结论

当前工程已经证明 SouthLeaf 需要品牌首页、工作室介绍、团队、联系和地图等公开展示能力，但现有实现仍以硬编码和占位内容为主，不能作为正式内容后台或现行经营事实。

A05 确立的目标是：建立单一权威内容源，让工作室能够自主维护、预览、发布和下架品牌与公共内容；小程序和官网共享一致事实，公开端只读取已发布内容；首页可以引用作品、业务和套餐，但不复制或篡改它们的权威规则；联系入口清晰可信且不冒充预约结果。
