## 1. 专题目的

本专题分析 SouthLeaf 品牌官网如何面向搜索引擎、社交分享、外部链接和桌面/移动 Web 访问，帮助潜在客户认识工作室、浏览作品、理解摄影业务和套餐、确认联系方式，并进入电话/微信咨询、小程序或预约流程。

官网和微信小程序都服务公开客户，但使用情境不同：

- 官网更适合通过搜索、外部分享、浏览器直接访问和较深的信息阅读发现工作室；
- 小程序更适合微信环境中的连续访问、身份确认、预约跟进、订单、支付和私密交付；
- 两者必须共享统一的已发布品牌、作品、业务、套餐和联系方式事实；
- 两者可以有不同的信息层级、页面编排、行动入口和摘要长度。

A09 关注官网访客如何发现、理解、比较、分享和进入下一步，不锁定 Nuxt、uni-app H5 或其他具体技术，也不把当前小程序页面直接复制成官网。

本文件回答：

- 官网服务哪些访客和访问情境；
- 官网相比小程序承担什么独立产品职责；
- 品牌、作品、业务、套餐、团队和联系信息如何组织成可访问的公开页面；
- 搜索结果、外部分享、直接访问和旧链接进入时，客户应看到什么；
- 官网是否直接提交预约，还是引导至小程序、电话和微信；
- 官网如何处理下架、授权撤回、套餐失效、内容为空和服务异常；
- 官网与小程序哪些内容必须一致，哪些体验可以不同；
- 官网体验如何通过内容核验、搜索验证和可用性测试验收。

A09 的核心判断是：

```text
官网负责被发现、被理解、被分享和被联系；
小程序负责在微信环境中持续完成客户业务任务；
统一业务服务负责解释预约、订单、支付、交付和授权事实；
统一内容源负责保证品牌、作品、业务、套餐和联系信息可信。
```

## 2. 专题边界与规则归属

### 2.1 A09 拥有的需求

A09 负责以下品牌官网体验需求：

- 官网访客角色、访问来源和任务地图；
- 官网信息架构、栏目关系和页面层级；
- 官网首页、品牌/工作室页、作品案例页、摄影业务页、套餐页、团队页、服务流程页和联系页的客户体验；
- 搜索结果、外部分享、直接链接、移动浏览器和桌面浏览器的公开访问体验；
- 页面标题、摘要、分享信息和公开内容可发现性的产品要求；
- 公开内容与小程序的共同事实和差异化编排；
- 官网到电话、微信、小程序和预约入口的导流关系；
- 官网公开页面的加载、空状态、下架、失效、错误和降级反馈；
- 官网公开内容、链接和页面可访问性的验收要求；
- 官网体验的内容验证、外部访问验证、分享验证和可用性测试。

### 2.2 A09 只引用、不拥有的需求

| 对象或规则 | 主归属 | A09 允许做什么 | A09 不得定义什么 |
|---|---|---|---|
| 品牌和公共内容 | A05 | 组织已发布品牌、团队、地址、流程、联系方式和首页内容 | 品牌事实、联系方式、内容发布、下架和审计主规则 |
| 作品与案例 | A06 | 展示有效案例、分类、图片、署名和关联服务入口 | 案例粒度、图片公开授权、公开资格和撤回事实 |
| 摄影业务与套餐 | A07 | 展示已发布业务、套餐、价格、固定定金和公开须知 | 业务目录、套餐版本、价格规则、选择资格和订单快照 |
| 小程序客户体验 | A08 | 提供官网到小程序的上下文导流和一致状态反馈 | 小程序导航、身份触发、客户中心和移动端业务页面主规则 |
| 客户身份与隐私 | A11 | 在需要时引导身份确认或转入小程序 | 客户身份绑定、联系人/拍摄人关系、敏感资料和权限主规则 |
| 预约与档期 | A12 | 展示预约说明，必要时承载预约入口 | 日期、固定时段、申请失效、占档、冲突、改期和预约状态转换 |
| 订单与履约 | A13 | 在合适情况下引导客户查看小程序订单或当前记录 | 订单生成、快照、履约状态、改期修订和异常终止 |
| 支付与退款 | A14 | 引导客户进入受支持的支付入口并展示安全状态 | 支付事实、支付回调、金额校验、退款责任和对账 |
| 成片交付与公开授权 | A15 | 引导客户进入小程序私密交付，展示公开授权结果影响 | 交付批次、访问授权、下载、期限、公开授权和撤回事实 |
| 错误、权限和可靠性 | AT01-AT09 | 将统一业务结果转为公开端可理解的页面反馈 | API、数据库、事务、并发、重试和错误码实现契约 |
| 衡量与运营 | A16 | 定义官网侧体验观察点和验证任务 | 业务指标最终口径、采集实现和营销策略 |

### 2.3 A09 的唯一主规则

官网是公开品牌和业务信息入口。它可以展示和导流，但不能绕过统一业务规则直接承诺预约成功、创建订单、确认支付或开放私密交付。

官网上的以下动作必须明确区分：

```text
搜索结果点击 ≠ 已进入工作室官网全部内容
查看作品 ≠ 获得私密成片
查看套餐 ≠ 已选择服务
电话/微信联系 ≠ 预约成功
提交预约申请 ≠ 预约成功
预约确认 ≠ 定金已支付
查看支付页 ≠ 支付事实已确认
公开案例授权 ≠ 私密交付授权
小程序入口到期 ≠ 工作室原文件已删除
```

官网无论直接承载预约还是引导至小程序，都必须使用 A12-A15 和 AT05-AT09 的统一业务状态、权限和异常语义。

## 3. 证据口径

| 标记 | 含义 |
|---|---|
| 已确认需求 | 已由用户讨论、A01-A08 或架构基线明确的产品方向和业务约束 |
| 原型证据 | 当前代码、旧计划或页面中确实存在的内容，只能证明历史原型曾表达过该方向 |
| 产品建议 | 为形成可运营官网提出的候选体验，仍需结合经营目标确认 |
| 待验证行为 | 尚无搜索数据、访谈、分享数据或可用性测试支持的用户行为判断 |
| 待确认经营内容 | 品牌文案、正式案例、套餐、联系方式和服务承诺等需要负责人提供权威答案的内容 |

当前仓库没有正式独立官网应用、真实域名、搜索数据、外部访问日志、分享点击数据、官网内容运营记录或客户访谈。因此，A09 可以确立官网的产品职责和验收边界，但不能据此假设自然搜索流量、客户来源、最有效的栏目顺序或官网预约转化率。

## 4. 当前工程证据与问题

### 4.1 当前没有独立官网应用

工程目录中主要存在 `frontend/` 下的 uni-app 项目、后端 Spring Boot 项目和公开文档，没有独立的 Nuxt、独立 Web 应用目录或官网页面集合。

当前 `frontend/index.html` 是 uni-app 构建入口，具有以下原型证据：

- HTML 文档语言仍为 `en`；
- 页面 `<title>` 为空；
- `viewport` 主要服务移动端适配；
- 页面只挂载现有 uni-app 应用；
- 没有官网品牌描述、分享信息、页面级标题或公开入口结构。

这些内容只能证明当前前端具备 H5 构建入口，不能证明已经存在可运营的品牌官网。

### 4.2 当前工程定位偏向小程序原型

`frontend/pages.json` 当前注册的页面和 TabBar 以小程序公开展示为中心：

```text
首页 / 作品 / 套系 / 关于 / 我的
```

当前没有：

- 官网独立首页和栏目导航；
- 案例可直接分享的公开详情路由体系；
- 品牌页面、服务页面和套餐页面的搜索摘要；
- 官网专用的团队、服务流程、FAQ 和联系方式页；
- 官网访客到小程序的上下文跳转；
- 官网预约方式和外部访问状态；
- 页面级分享卡片和旧链接处理规则。

### 4.3 当前页面内容不能直接作为官网内容

当前小程序页面存在与官网同样需要治理的问题：

- 首页作品硬编码，作品列表和详情不是同一权威数据；
- 作品详情只支持固定 ID，其他链接可能空白；
- 套餐列表和详情存在名称、图片、价格、活动时间和服务项漂移；
- 套餐历史文案出现 50% 和 30% 定金比例，不符合当前固定金额定金规则；
- 关于页与 Footer 的电话、地区和地址不一致；
- 社交渠道弹窗存在错误复用二维码资源；
- 用户评价、在线预约和搜索入口存在占位内容；
- 当前没有正式发布、下架、授权撤回和失效链接处理。

因此，官网不能把小程序页面复制为正式内容，必须消费 A05-A07 的已发布事实和公开资格结果。

### 4.4 当前技术选型仍保留两种官网方向

AT02 记录了以下待验证候选：

1. 独立 Web 方案，优先评估 Nuxt 3，适合搜索引擎收录、品牌内容长期运营和服务端渲染/静态生成需求；
2. 复用 uni-app H5，适合官网只是小程序轻量同步展示且优先复用现有代码的场景。

A09 不直接替这两种方案做技术定案。技术选择应由官网的搜索获客目标、页面内容深度、分享需求、交互深度、运营维护能力和与小程序的复用边界验证后决定。

### 4.5 当前问题结论

| 问题 | 当前表现 | 官网体验风险 |
|---|---|---|
| 没有独立官网 | 只有 uni-app H5 入口，未形成官网信息架构 | 外部访问和品牌定位不清楚 |
| 页面元信息缺失 | HTML `lang` 为 `en`、标题为空 | 搜索结果、浏览器标题和分享识别不可信 |
| 内容源未正式统一 | 页面中存在多处硬编码和副本 | 搜索和分享页面可能展示过期或矛盾事实 |
| 公开详情不稳定 | 作品/套餐详情依赖固定 ID 或硬编码 | 外部深链点击后可能空白或展示错误内容 |
| 没有下架和失效体验 | 无统一旧链接、授权撤回和套餐失效处理 | 搜索缓存和分享链接可能继续误导客户 |
| 官网职责未确定 | 是否直接预约、是否引导小程序待确认 | 入口设计可能重复建设或割裂客户路径 |
| 没有 SEO/分享验证 | 无真实域名、搜索数据和分享元信息 | 无法判断自然流量和外部传播价值 |
| 联系内容冲突 | 电话、地址、微信在不同页面不一致 | 外部访客无法确认有效联系渠道 |
| 公开/私密边界未建立 | 作品页面与未来交付入口尚未分域 | 存在隐私和授权误导风险 |
| 运营后台尚未支持 | 官网内容无统一发布、预览和审计能力 | 每次更新依赖开发者，难以持续维护 |

## 5. 官网用户与访问情境

### 5.1 搜索发现者

用户通过搜索工作室名称、地域、摄影业务、摄影风格或相关问题进入某个官网页面，通常不会从首页开始浏览。其主要任务是：

- 判断当前页面是否属于目标工作室；
- 快速理解工作室所在地域、业务方向和服务对象；
- 查看真实案例和服务说明；
- 找到联系方式、工作室地址或下一步入口；
- 在页面不符合预期时返回搜索结果或查看其他栏目。

官网必须支持深层页面独立理解，不能要求用户先从首页按固定顺序点击才能理解页面含义。

### 5.2 社交分享访客

用户从朋友圈、社交平台、聊天或客户转发链接进入作品、案例、套餐或品牌页面。其主要任务是：

- 识别分享内容的标题、图片和工作室来源；
- 直接查看对应案例或套餐，不被送回无关首页；
- 从内容继续浏览相似案例或相关服务；
- 联系工作室或进入预约/小程序；
- 在内容已下架或授权撤回时看到安全、明确的替代路径。

分享链接不能暴露客户私密交付文件、内部订单、授权证据或永久文件地址。

### 5.3 对比和决策访客

用户可能同时打开多个摄影工作室或多个套餐页面，需要比较：

- 摄影业务和适用场景；
- 作品风格和案例完整度；
- 服务项、价格、固定定金和尾款说明；
- 拍摄地点、时长、参与人数和服务范围；
- 联系方式和预约方式；
- 服务流程、交付说明和公开案例可信度。

官网不应使用模糊的活动价、历史价格、占位图片或无法证明的服务承诺增加比较成本。

### 5.4 已被推荐的访客

用户可能通过客户、团队成员或合作方推荐进入官网，通常对工作室有初步信任，但需要验证：

- 推荐的摄影业务是否仍然提供；
- 作品、团队和地址是否真实；
- 如何咨询和预约；
- 官网与小程序的关系；
- 是否能在微信环境中继续完成业务。

官网应在公共页面清楚提供品牌、联系和小程序入口，不能只依赖社交平台账号或一次性二维码。

### 5.5 已有客户或预约客户

已有客户可能通过官网访问品牌内容、查找联系方式或从外部链接回到工作室，但预约、订单、支付和私密交付记录原则上应回到受控的客户业务入口。

官网可以：

- 提供“进入小程序查看预约/订单/成片”的入口；
- 通过安全的业务链接引导到小程序；
- 显示公共帮助、联系方式和服务流程。

官网不应在没有明确身份、权限和业务规则支持的情况下展示客户订单或成片。

## 6. 官网任务地图

| 客户任务 | 典型入口 | 官网成功结果 | 后续行动 |
|---|---|---|---|
| 识别工作室 | 搜索结果、分享、首页 | 理解品牌、地域和摄影定位 | 查看作品/业务/联系 |
| 判断风格 | 首页、作品、案例详情 | 看到有效公开案例和作者/工作室说明 | 查看关联业务/套餐 |
| 理解服务 | 业务列表、业务详情 | 理解六类业务和适用范围 | 查看套餐或咨询 |
| 比较套餐 | 套餐列表、套餐详情 | 看到有效价格、固定定金、服务项和限制 | 联系或进入预约 |
| 查看工作室 | 关于、团队、流程、地址 | 建立信任并确认位置和联系方式 | 电话/微信/地图 |
| 分享案例 | 案例详情、套餐详情 | 分享内容标题和图片清楚，链接可直接访问 | 继续浏览或联系 |
| 咨询工作室 | 联系、套餐、业务、案例 | 拨号、查看微信或其他渠道 | 形成线下沟通，不等于预约 |
| 提交预约 | 套餐/业务/联系入口 | 进入受支持的预约流程 | 官网表单或小程序，方案待确认 |
| 查看业务记录 | 外部链接、客户入口 | 转到身份受控的小程序 | 查看预约、订单、交付 |
| 找回失效内容 | 搜索旧链接、历史分享 | 看到安全的不可用提示和替代入口 | 查看当前内容或联系 |

## 7. 官网与小程序的产品分工

### 7.1 官网更适合承担的任务

产品建议官网重点承担：

- 品牌故事和工作室定位的完整表达；
- 面向搜索的业务和地域信息；
- 作品案例的更深浏览和分享；
- 摄影业务、套餐、服务流程和 FAQ 的公开阅读；
- 团队、地址、服务区域和联系方式的可信展示；
- 外部链接、搜索结果和社交分享的落地页面；
- 联系工作室和进入小程序的公开入口。

是否增加文章、拍摄指南、业务问答或专题内容，需要根据真实内容维护能力和搜索目标确认，不能仅因官网存在就默认建设内容社区。

### 7.2 小程序更适合承担的任务

小程序更适合重点承担：

- 微信环境中的持续访问；
- 客户身份确认；
- 预约申请和结果跟进；
- 订单、支付、履约和交付入口；
- 微信内的联系、通知和业务待办。

A08 已定义小程序客户任务和状态反馈，A09 不复制这些页面规则，只负责官网到小程序的导流和上下文衔接。

### 7.3 必须共享的公开事实

官网与小程序必须共享：

- 品牌正式名称、Logo 和公开介绍；
- 工作室地址、地点名称、地图信息和服务区域；
- 电话、微信和已配置的社交渠道；
- 团队公开资料和公开状态；
- 服务流程和正式 FAQ；
- 已发布且具有公开资格的作品案例；
- 已发布的摄影业务和套餐；
- 当前有效价格、活动有效期和固定定金说明；
- 作品、业务、套餐的公开下架和失效结果。

官网不能因为需要 SEO 或更长内容就复制一份可单独修改的价格、服务项、联系方式或授权状态。

### 7.4 允许存在的体验差异

官网和小程序可以有：

- 不同导航方式和页面层级；
- 不同首页区块顺序；
- 不同作品、业务和套餐展示数量；
- 不同摘要长度和内容阅读深度；
- 官网专用的搜索标题、摘要和分享信息；
- 官网更强的桌面端图片浏览和外部链接体验；
- 小程序更直接的电话、微信、预约和客户中心入口；
- 官网把预约导向小程序，而小程序直接承载预约表单。

差异不能造成业务事实不一致，也不能让一个端把“联系”显示成“预约成功”。

## 8. 目标信息架构

### 8.1 顶层栏目

官网建议以客户理解和外部访问为主，候选顶层栏目包括：

```text
首页
作品案例
摄影业务
服务套餐
工作室
服务流程/常见问题
联系与预约
进入小程序
```

“作品案例”“摄影业务”和“服务套餐”应在公开含义上区分：

- 作品案例回答“工作室拍出了什么”；
- 摄影业务回答“工作室提供什么方向的服务”；
- 服务套餐回答“某类业务下当前公开承诺的标准服务是什么”。

如实际内容量较小，摄影业务和服务套餐可以在同一导航区下展示，但页面标题、内容结构和入口关系仍需清楚。

### 8.2 页面层级

| 页面层级 | 页面目的 | 适合独立访问/分享 |
|---|---|---:|
| 首页 | 识别品牌、展示重点内容和主要行动 | 是 |
| 作品列表 | 浏览公开案例和分类 | 是 |
| 案例详情 | 深入查看一组作品和关联服务 | 是，重点支持 |
| 业务列表 | 查看六类摄影业务 | 是 |
| 业务详情 | 理解业务适用场景、作品和套餐 | 是 |
| 套餐列表 | 比较当前公开标准套餐 | 是 |
| 套餐详情 | 了解具体服务、价格、固定定金和入口 | 是，重点支持 |
| 工作室/团队 | 建立信任、了解人员和定位 | 是 |
| 服务流程/FAQ | 理解咨询、预约、订单、拍摄和交付顺序 | 可独立访问 |
| 联系页 | 电话、微信、地址、地图和联系时间 | 是 |
| 预约说明 | 解释预约申请和确认关系 | 可独立访问 |
| 客户业务入口 | 转至小程序身份受控页面 | 不直接公开记录 |

每个可被搜索或分享的深层页面都应包含：

- 工作室品牌识别；
- 当前页面主题；
- 返回上层或继续浏览路径；
- 相关作品/业务/套餐入口；
- 联系工作室入口；
- 合适的下一步行动。

### 8.3 首页信息编排

官网首页的目标不是把所有内容全部堆叠，而是在首屏和首轮浏览中帮助访客：

- 识别工作室和摄影定位；
- 看到有公开资格的代表作品；
- 进入六类摄影业务或当前重点套餐；
- 了解服务流程和工作室差异；
- 找到电话、微信、地址和小程序入口；
- 理解预约需要工作室确认。

首页候选区块：

1. 品牌首屏与主要行动；
2. 代表作品；
3. 摄影业务；
4. 重点套餐；
5. 工作室特色或可信信息；
6. 服务流程；
7. 团队/工作室摘要；
8. 联系与位置；
9. FAQ/预约须知；
10. 经授权的真实评价。

首页只能引用 A05-A07 的有效内容，不应复制案例、套餐或联系方式。没有有效内容的可选区块应隐藏或显示可信空状态，不使用测试图片、虚构评价或旧数据填充。

## 9. 页面需求

### 9.1 官网首页

首页应满足：

- 在页面标题、首屏和品牌视觉中明确表达 SouthLeaf/工作室正式名称；
- 让访客知道服务地域或主要服务范围，但不把地址和服务区域混为一谈；
- 展示当前有效的代表作品和摄影业务；
- 允许进入套餐、案例、关于和联系页；
- 主要行动清楚区分“浏览作品”“了解服务”“联系工作室”“进入小程序”；
- 如提供预约入口，明确“提交预约申请，等待工作室确认”；
- 只消费已发布、公开资格有效的内容；
- 失效推荐不会继续展示空链接或错误摘要；
- 移动端和桌面端都能在合理浏览路径内找到联系信息；
- 页面异常时保留品牌识别、文字导航和至少一个经过确认的联系渠道。

首页不得：

- 以轮播图代替品牌定位和可理解的服务入口；
- 展示与小程序不同的电话、地址、套餐价格或授权状态；
- 把搜索访客强制送到小程序后才允许查看公开内容；
- 把“进入小程序”表达为已登录或已有客户记录；
- 用无法验证的评价、奖项、客户数量或服务承诺提升可信度。

### 9.2 作品列表页

作品列表应帮助访客按作品分类浏览有效案例，并支持从搜索、首页和分享返回。

要求：

- 匿名可访问；
- 只展示 A06 已发布且公开资格有效的案例；
- 分类、标签和摄影业务关联有清晰含义；
- “全部”表示有效案例聚合，不是业务分类；
- 每个案例卡片可以独立理解，至少有标题、封面和必要摘要；
- 可根据内容数量决定是否提供标签筛选或搜索；
- 无结果时展示当前条件和返回全部的操作；
- 作品下架、授权撤回或图片失效后不能通过缓存继续展示；
- 列表布局适应桌面端和移动端，图片加载失败有稳定降级；
- 案例卡片提供关联业务/套餐或联系入口时，不写死历史价格和服务内容。

官网作品搜索是否建设、搜索哪些字段以及是否支持按地区/风格筛选，待 A06、负责人和真实内容规模验证。

### 9.3 案例详情页

案例详情是官网最重要的外部分享页面之一，应支持直接访问和脱离首页理解。

详情至少需要展示：

- 工作室品牌识别和案例标题；
- 一组有序的有效公开图片；
- 公开说明、作品分类和可公开标签；
- 经过确认的作者/工作室署名；
- 可选的业务或套餐关联；
- 继续浏览相关作品；
- 联系工作室和进入小程序/预约的入口；
- 清晰的返回作品列表或分类路径。

详情要求：

- 分享标题和摘要能够说明这是 SouthLeaf 的公开案例，而不是客户私密相册；
- 案例级或人物级公开授权撤回后，详情不再展示内容；
- 单图失去公开资格时，根据 A06 规则重新计算案例公开资格；
- 失效案例直接访问时显示统一不可用结果，不显示客户身份、撤回原因、内部订单或授权证据；
- 业务/套餐关联失效时移除失效入口，不复制旧业务事实；
- 公开案例图片不得提供原片或私密交付下载；
- 图片加载失败、部分资源不可用和完整案例不可用有可理解的不同反馈。

### 9.4 摄影业务列表和详情页

官网业务页需要完整呈现已确认保留的六类摄影业务：

```text
儿童、亲子全家福、婚纱、写真、孕照、证件照
```

每类业务可以表达：

- 对外名称和定位；
- 适用对象或场景；
- 公开说明；
- 代表作品；
- 已发布套餐；
- 是否需要先咨询；
- 地点、服务区域和预约前置提示；
- 联系、套餐和小程序入口。

业务页要求：

- 没有有效套餐时显示暂无标准套餐或咨询入口；
- 不使用其他业务的套餐和作品填充空业务；
- 不承诺当前一定有可用日期或固定时段；
- 不把“创始人档”在未确认前作为正式摄影业务；
- 不把业务查看或点击按钮反馈为预约成功；
- 业务、作品分类和套餐所属业务在页面表达上保持可区分。

### 9.5 套餐列表和详情页

官网套餐页应帮助访客比较当前可理解、可验证的标准服务。

套餐列表至少展示：

- 套餐名称和所属摄影业务；
- 当前价格表达；
- 固定定金说明；
- 关键服务摘要；
- 适用范围、时长或地点说明；
- 当前状态：可了解、可咨询、可提交预约或已下架；
- 详情、联系和预约/小程序入口。

套餐详情至少展示：

- 套餐名称和版本对应的公开事实；
- 标准价、活动价、起始价、区间价或咨询报价的明确含义；
- 活动有效条件和时间；
- 固定定金金额和尾款说明；
- 服务项、数量、单位、包含/不包含内容和附加服务；
- 拍摄时长、参与人数、地点和服务区域；
- 交付说明和预约前置提示；
- 关联公开案例；
- 联系、预约或进入小程序入口。

官网套餐要求：

- 列表和详情读取同一有效套餐版本；
- 价格和定金说明不能使用历史 30%/50% 比例替代当前固定金额规则；
- 过期活动价不能继续作为当前价格展示；
- 没有正式价格时显示需咨询，不显示虚构数字；
- 固定定金缺失或版本不能用于新选择时，不显示为可直接预约；
- 下架旧链接显示不可选择提示和当前联系入口；
- 套餐不因公开展示而生成预约、订单或支付事实；
- 关联作品失效时不显示空链接，不把私密成片替代为公开案例；
- 分享套餐链接时，摘要、价格和服务信息不得与当前有效版本矛盾。

### 9.6 工作室、团队和服务流程页

工作室页面应帮助访客确认：

- 工作室正式名称和定位；
- 团队公开称呼、职位和经确认的简介；
- 服务区域和工作室地址的区别；
- 联系时间和服务流程；
- 如何从浏览、咨询、预约、确认、订单、拍摄、尾款和交付完成服务。

团队公开资料不自动代表：

- 可指定的摄影师；
- 可预约的排班资源；
- 后台账号权限；
- 客户可见的内部工作记录。

通用流程页面只解释公开服务顺序，不代替套餐条款、订单约定、退款规则、隐私授权或交付访问规则。流程文案中的“预约”必须明确是申请还是工作室已确认。

### 9.7 联系和位置页

联系页及全站公共区域应统一消费 A05 的：

- 电话和用途标签；
- 微信号、二维码和添加说明；
- 社交账号和独立链接/二维码；
- 工作室地址、地点名称、地图和可复制文字地址；
- 服务区域；
- 联系时间和联系须知；
- 小程序入口。

要求：

- 电话、地址、微信和地图在官网所有页面一致；
- 点击拨号只表示发起联系；
- 微信二维码必须与微信渠道对应，不能复用其他平台图片；
- 没有真实社交账号时不显示对应入口；
- 地图不可用时保留文字地址和其他联系渠道；
- 联系页提供预约说明，但不把联系动作表示为预约成功；
- 页面可以提供“进入小程序预约”的明确入口，并说明需要身份确认/工作室确认的关系。

### 9.8 预约入口

官网是否直接承载完整预约，当前保持两种候选方案：

| 方案 | 官网行为 | 优点 | 待验证问题 |
|---|---|---|---|
| 官网引导小程序 | 官网展示预约说明和套餐上下文，点击后进入小程序预约 | 复用微信身份和客户业务入口，减少重复业务页面 | 搜索访客是否愿意切换环境，链接上下文是否稳定 |
| 官网直接预约 | 官网承载身份确认、日期/固定时段选择和预约提交，统一写入预约域 | 外部访客路径更短，桌面端操作连续 | 身份方式、网页预约维护、与小程序体验一致性和安全要求 |

无论采用哪种方案，官网必须：

- 让客户知道提交的是预约申请而不是成功预约；
- 使用 A07 有效套餐版本和 A12 可用日期/固定时段；
- 不在客户端自行判断冲突或最终价格；
- 提交后显示待确认和实际失效时间；
- 预约确认后才能进入订单和支付；
- 预约冲突、失效、套餐变化和身份失败有明确反馈；
- 若导向小程序，尽量传递业务、套餐版本和来源上下文，但由小程序/服务端重新读取当前有效事实；
- 若官网直接预约，客户可以在官网或小程序查看同一预约记录，不形成两套相互矛盾的入口。

官网不得为了追求转化，把“立即预订”“立即下单”作为已确认业务能力的承诺，除非其真实含义和后续状态已经明确。

### 9.9 客户业务入口

官网可以在全站或订单帮助区域提供：

```text
进入小程序查看预约 / 订单 / 支付 / 成片
```

该入口要求：

- 不在公开页面展示客户姓名、订单号、金额或文件数量；
- 不在没有身份确认时展示业务记录；
- 外部链接无法携带安全的客户授权时，统一要求客户在小程序重新确认身份；
- 客户从官网进入小程序后，能够理解自己要继续的任务；
- 预约、订单、支付和交付状态由业务域重新读取，不使用官网缓存结果；
- 小程序入口失效时提供联系工作室的替代路径。

## 10. 搜索、分享和外部访问需求

### 10.1 页面可独立被发现

官网的公开页面可能从搜索结果或外部分享直接打开，因此每个公开页面至少要具备：

- 明确的页面主题和工作室名称；
- 适合该页面的标题和摘要；
- 公开图片和替代说明；
- 面包屑或其他返回上层路径；
- 相关作品/业务/套餐入口；
- 联系或进入小程序入口；
- 失效和下架后的安全结果。

不能假设用户一定从官网首页进入，也不能只依赖导航栏让用户理解页面。

### 10.2 搜索内容边界

可以考虑被搜索引擎发现的公开内容包括：

- 工作室正式名称和品牌介绍；
- 目标服务区域；
- 六类摄影业务的公开说明；
- 已发布且有授权的作品案例；
- 已发布套餐的公开名称、价格表达和服务摘要；
- 团队公开资料；
- 联系方式、地址和服务流程；
- 经确认的 FAQ 或拍摄指南。

不应被公开索引或进入搜索摘要的内容包括：

- 草稿、下架内容和未发布价格；
- 客户姓名、电话、订单号和内部备注；
- 私密成片、原片和精修图下载地址；
- 授权证据、撤回原因和内部审核意见；
- 支付、退款、订单和交付的客户记录；
- 本机目录、内部错误和服务端实现信息。

官网是否需要投入自然搜索获客、重点地域关键词、文章内容和专题页，需要负责人结合实际获客方式确认。

### 10.3 分享信息

作品、套餐、业务和品牌页面在被分享时应提供与页面一致的：

- 标题；
- 摘要；
- 代表图片；
- 工作室品牌识别；
- 可访问的公开链接。

分享信息要求：

- 案例分享不得使用已经撤回授权或已下架图片；
- 套餐分享不得显示过期活动价或历史固定定金；
- 公开图片被撤回后，旧分享链接不能继续直接展示失效内容；
- 分享摘要不包含客户隐私或内部订单信息；
- 点击分享链接后落到对应公开页面，而不是无条件返回首页；
- 链接失效时展示当前可用内容或联系入口。

### 10.4 旧链接和页面替代

公开内容可能因为下架、授权撤回、套餐版本替代或品牌资料变更而失效。旧链接处理要求：

- 页面可以明确显示“内容已下架/当前不可用”；
- 不泄露内部下架原因和客户授权细节；
- 允许返回上级列表、查看当前有效内容或联系工作室；
- 旧套餐链接不能静默变成完全不同的套餐；
- 已被客户业务记录引用的历史版本只在有权限的业务场景中读取，不作为公开当前报价；
- 旧案例链接不能因为搜索缓存继续提供私密文件或未授权图片。

## 11. 跨端一致性与内容生命周期

### 11.1 统一事实

官网、小程序和后台必须在以下内容上保持一致：

- 品牌名称和正式公开介绍；
- 电话、微信、地址、地图和服务区域；
- 团队成员公开状态和对外资料；
- 作品标题、公开图片、分类、标签和授权结果；
- 摄影业务名称、公开说明和状态；
- 套餐名称、所属业务、当前价格、固定定金、服务项和公开状态；
- 预约、订单、支付和交付的客户可见结果；
- 内容下架、案例授权撤回和套餐版本失效结果。

### 11.2 公开内容生命周期

官网只能读取已发布的公开内容：

| 内容状态 | 官网公开访问 |
|---|---:|
| 草稿 | 否 |
| 待校验/待修复 | 否，除非以受控预览方式访问 |
| 已发布且公开资格有效 | 是 |
| 已下架 | 否，旧链接显示统一不可用结果 |
| 授权过期/撤回 | 否，按 A06/A15 规则隐藏 |
| 版本被替代 | 公开端展示当前有效版本，历史版本仅限有权限业务场景 |
| 已归档 | 否 |

预览链接不能被搜索、公开分享或匿名长期访问。发布失败时保留原公开版本，不出现部分页面更新。

### 11.3 端侧编排

官网可以：

- 使用更长的品牌介绍和服务说明；
- 展示更多案例或更完整的图片集合；
- 提供专题页、分享页和页面级摘要；
- 使用桌面端更适合阅读和比较的布局；
- 将预约主要引导至小程序。

官网不能：

- 自己修改套餐价格或固定定金；
- 把作品分类改成摄影业务；
- 绕过案例授权和公开资格；
- 使用过期活动价或旧联系方式；
- 展示小程序不可见的草稿、未发布内容或客户私密记录；
- 通过独立副本维持已经下架的作品或套餐。

## 12. 状态、空状态与异常体验

### 12.1 页面通用状态

官网每个页面应能区分：

| 状态 | 页面反馈 | 客户行动 |
|---|---|---|
| 加载中 | 当前内容正在加载 | 等待或稍后重试 |
| 暂无内容 | 当前没有已发布的有效内容 | 查看其他栏目或联系工作室 |
| 筛选无结果 | 当前分类/标签没有有效案例或套餐 | 清除条件或返回全部 |
| 已下架 | 当前公开内容已停止展示 | 查看当前内容或联系 |
| 版本替代 | 原内容已被新版本替代 | 查看当前有效版本 |
| 授权失效 | 当前案例不可公开 | 返回作品或联系，不展示内部原因 |
| 网络失败 | 页面暂时无法加载 | 重试或使用联系方式 |
| 服务暂不可用 | 系统无法完成当前读取/提交 | 稍后重试或联系 |
| 需要身份 | 当前任务需要进入小程序确认身份 | 进入小程序或返回公开内容 |
| 不可访问 | 当前页面不允许公开访问 | 返回首页/列表或联系 |

### 12.2 内容为空

- 没有已发布作品时，不显示测试案例或占位图片；
- 某类业务没有有效套餐时，显示暂无标准套餐并提供咨询入口；
- 没有公开团队资料时隐藏团队区块，不显示空卡片；
- 没有真实评价授权时隐藏评价区块；
- 联系渠道未配置时不显示错误图标，但至少保留一个确认过的联系方法；
- 地图无法显示时保留文字地址和电话/微信；
- 首页推荐没有有效内容时隐藏区块或展示简短的可信说明。

### 12.3 公开内容失效

案例、业务、套餐或团队资料被下架后：

- 官网列表和首页不再展示；
- 旧链接得到安全、明确的不可用提示；
- 允许返回上级、查看当前内容或联系工作室；
- 不用旧内容副本维持页面完整性；
- 不将公开内容下架自动解释为客户订单、支付或交付状态变化。

### 12.4 预约导流失败

如果官网到小程序的跳转、预约页面或身份确认暂时不可用：

- 访客仍可浏览公开内容；
- 页面说明当前预约入口暂不可用；
- 提供电话/微信咨询入口；
- 不把跳转失败显示为预约失败或订单失败；
- 不丢失能够安全传递的业务/套餐来源，但不使用客户端旧数据绕过服务端校验。

### 12.5 官网直接预约异常

如果最终选择官网直接预约，客户侧至少需要区分：

- 字段校验错误；
- 未完成身份确认；
- 套餐版本不可用；
- 日期或固定时段不可选；
- 提交成功待确认；
- 申请已失效；
- 确认时段冲突；
- 服务暂不可用；
- 需要联系工作室处理。

官网不应把所有异常都显示为“网络错误”，也不应把服务端拒绝改写成预约成功。

### 12.6 客户业务记录和私密交付

官网不直接展示客户预约、订单、支付和交付记录，除非未来经过身份、权限和业务设计确认。默认体验是：

```text
官网公开页面
  → 进入小程序
  → 身份确认
  → 查看预约/订单/支付/交付
```

尾款未付、交付未发布、权限不足或入口到期等结果在小程序中按 A08/A15 反馈，官网只提供安全的入口和公共帮助说明。

## 13. 访问性、可理解性与可信度要求

### 13.1 可理解性

- 页面标题、导航和行动文案使用客户能理解的名称；
- 作品、业务、套餐、预约申请和订单不使用内部对象名称；
- 价格、固定定金、尾款、服务项和咨询项有清晰关系；
- “联系工作室”“进入小程序”“提交预约申请”使用不同文案；
- 预约说明明确“提交申请后等待工作室确认”；
- 下架、失效和无结果提示不暴露内部原因，但给出可执行下一步。

### 13.2 桌面和移动浏览

官网需要同时考虑：

- 桌面浏览器的横向布局、作品对比和文字阅读；
- 移动浏览器的单列阅读、图片加载、触控操作和分享返回；
- 不同屏幕尺寸下标题、价格、按钮和联系入口不重叠；
- 长标题、长服务项、长地址和多图案例不会破坏页面结构；
- 关键行动在桌面和移动端都可发现；
- 图片展示不牺牲真实内容可辨识性，不用过度裁切隐藏主体。

具体视觉风格、色彩、组件和布局方案不在本专题锁定。

### 13.3 可信度

官网正式公开前应确认：

- 品牌名称、Logo、介绍和服务区域；
- 电话、微信、地址和地图；
- 团队姓名/公开称呼、职位和履历；
- 作品图片的公开资格和授权；
- 套餐价格、固定定金、服务项和交付说明；
- 评价、奖项、从业年限和客户数量等宣传信息。

不能将当前小程序原型中的“枝南影像”、电话、东莞凤岗地址、团队履历、套餐价格或测试评价直接作为官网正式内容。

## 14. 功能需求清单

### 14.1 官网公开页面

- 工作室介绍；
- 团队公开资料；
- 作品分类和案例列表；
- 案例详情和多图浏览；
- 摄影业务列表和详情；

### 14.2 搜索和分享

- 不显示本机路径、内部错误、客户资料和第三方原始响应。

## 15. 验收标准

### 15.1 外部访问与页面独立性

1. 访客可以通过首页、作品、业务、套餐、工作室和联系入口理解 SouthLeaf 的品牌、服务范围和下一步行动。
2. 作品案例、业务和套餐详情可以被直接访问，不要求访客必须先从首页进入。
3. 每个公开深层页面都有工作室品牌识别、页面主题、返回路径、相关内容和联系入口。
4. 通过外部链接进入案例或套餐时，访客落到对应内容，不被无条件送回无关首页。
5. 公开页面在桌面和移动浏览器中均能完成基本浏览和联系任务。

### 15.2 内容与事实一致性

1. 官网只展示 A05-A07 已发布且当前有效的公开内容。
2. 官网与小程序的品牌、联系方式、地址、地图、作品、业务和套餐事实一致。
3. 套餐列表与详情中的名称、图片、所属业务、价格、固定定金和服务项一致。
4. 官网不展示历史 30%/50% 定金比例作为当前规则，不使用未经确认的原型数值。
5. 作品授权撤回、案例下架或套餐失效后，官网列表、首页、详情和分享页面不会继续公开失效内容。
6. 官网不复制旧价格、旧联系方式或私密交付内容来维持失效页面的完整性。

### 15.3 搜索和分享

1. 官网页面具有可理解的品牌标题、页面主题和公开摘要，不再使用空标题或错误文档语言。
2. 作品、业务和套餐分享信息与当前页面事实一致。
3. 公开分享不会暴露客户姓名、联系方式、订单、授权证据、私密文件或永久文件地址。
4. 旧分享链接访问下架或授权撤回内容时，显示安全的不可用结果，并提供当前内容或联系入口。
5. 搜索结果进入深层页面后，访客无需先浏览首页即可理解当前页面和工作室来源。
6. 待确认的 SEO 获客目标和关键词策略不会被伪装成已经验证的用户行为。

### 15.4 联系和预约关系

1. 访客可以在首页、案例、业务、套餐和联系页找到经过确认的电话、微信、地址或小程序入口。
2. 拨号、查看微信、查看地图、进入小程序和提交预约使用不同的文案和反馈。
3. 联系动作不会被显示为预约成功、订单生成或支付成功。
4. 官网预约入口明确申请需要工作室确认；未确定官网直接预约前，不向用户承诺完整在线预约。
5. 如果官网引导小程序，客户可以理解跳转目的，并尽量保留业务/套餐来源上下文。
6. 如果官网直接预约，官网和小程序读取同一预约事实，不形成两套冲突状态。

### 15.5 状态、异常和空状态

1. 没有有效内容时，官网显示可信空状态，不使用测试数据、旧数据或占位图片。
2. 图片、地图、链接、服务或预约暂不可用时，页面提供重试、返回、联系或进入小程序的下一步。
3. 下架、授权失效、版本替代、无结果和网络失败反馈不同，不统一显示为系统故障。
4. 服务端业务拒绝不会被改写为预约成功、支付成功或内容可访问。
5. 官网不暴露数据库字段、内部错误、服务器路径、客户隐私或外部服务原始响应。
6. 发布失败时保留原公开版本，不出现部分页面更新和部分页面回滚的不可解释状态。

### 15.6 公开与私密边界

1. 官网公开案例和客户私密交付在访问目的、页面入口和授权边界上清楚分离。
2. 官网不因客户已支付尾款、存在订单或拥有交付文件而自动公开照片。
3. 官网不直接提供未授权案例图片、精修图、原片或永久下载地址。
4. 客户预约、订单、支付和交付记录默认转入小程序身份受控入口。
5. 官网公开内容下架或授权撤回不会自动改变客户私密交付，除非 A15 产生明确业务结果。

## 16. 验证方式

### 16.1 负责人和内容资料核验

需要工作室负责人确认：

- 官网是否承担自然搜索获客，重点地域和业务范围是什么；
- 是否需要独立官网，还是只需轻量 H5 展示；
- 正式品牌名称、Logo、标语和工作室介绍；
- 六类摄影业务的正式名称、说明和目标客户；
- 当前有效公开案例、授权范围和可分享图片；
- 当前有效套餐、价格、固定定金、服务项和活动规则；
- 电话、微信、地址、地图、服务区域和联系时间；
- 团队成员公开资料、履历和头像授权；
- 是否公开评价、奖项、从业年限和客户数量；
- 官网预约采用小程序引导还是直接提交；
- 官网是否需要文章、拍摄指南、FAQ 或专题页；
- 客户业务记录是否全部回到小程序；
- 官网域名、品牌备案、分享渠道和外部投放来源。

### 16.2 脱敏场景验证

至少准备以下脱敏场景：

1. 从搜索结果直接进入首页；
2. 从搜索结果直接进入案例详情；
3. 从社交分享进入套餐详情；
4. 分享案例后案例公开授权撤回；
5. 分享套餐后套餐价格或固定定金形成新版本；
6. 访问已下架业务、案例和套餐旧链接；
7. 某一摄影业务没有有效套餐；
8. 作品图片部分撤回后剩余图片仍可公开；
9. 地图或图片资源暂时不可用；
10. 官网联系电话发生变更后小程序同步；
11. 访客从案例进入关联套餐再进入小程序预约；
12. 官网预约入口不可用时转电话/微信；
13. 客户从官网进入小程序查看订单；
14. 未登录访客尝试访问私密交付；
15. 页面在桌面和移动浏览器中打开，并通过外部返回继续浏览。

### 16.3 搜索和分享验证

在具备正式内容和测试域名后验证：

- 页面标题、摘要和分享图片是否与当前内容一致；
- 直接访问深层页面是否可理解；
- 公开案例、业务和套餐是否能被安全分享；
- 下架、授权撤回和版本替代后的旧链接是否安全处理；
- 搜索摘要是否包含过期价格、客户信息或内部文案；
- 移动端分享返回和浏览器回退是否保留页面上下文；
- 图片、地图和联系方式不可用时是否有文字降级。

不应在没有真实搜索数据前虚构自然流量、关键词排名、点击率或预约转化率目标。

### 16.4 客户可用性验证

通过目标客户或脱敏访谈观察：

- 访客能否在首屏识别工作室和摄影定位；
- 访客能否从搜索/分享页面理解当前内容，不依赖首页；
- 访客能否区分作品、摄影业务和标准套餐；
- 访客是否能找到可靠电话、微信和地址；
- 访客是否理解官网预约是申请还是已确认；
- 访客是否愿意进入小程序完成后续业务；
- 访客能否理解下架、无结果、价格过期和联系入口不可用；
- 访客是否把公开案例和私密相册区分开；
- 访客在桌面和手机上是否都能完成浏览到联系的主要路径。

## 17. 待确认经营内容与产品决策

以下事项仍需要工作室负责人或后续专题确认：

1. 官网的首要获客来源是自然搜索、社交分享、熟人推荐、广告投放还是其他渠道。
2. 官网是否需要承担 SEO 获客，以及重点地区、摄影业务和内容主题是什么。
3. 官网是独立 Web 体验，还是先采用与小程序高度复用的轻量 H5 展示。
4. 官网首页、作品、业务、套餐、团队、流程和联系页的正式内容规模。
5. 官网是否需要文章、拍摄指南、FAQ、案例专题或其他持续更新内容。
6. 官网是否直接提交完整预约，还是统一引导至微信小程序。
7. 如果引导至小程序，访客是否接受身份确认和环境切换；需要保留哪些来源上下文。
8. 如果官网直接预约，客户身份方式、记录查看和与小程序的统一入口如何处理。
9. 官网是否展示完整价格、价格区间、起始价或只展示咨询入口。
10. 六类摄影业务分别有哪些适合搜索和分享的正式公开说明。
11. 哪些历史作品已经取得公开授权，哪些只能保留在工作室内部。
12. 是否允许公开团队成员的姓名、照片、履历、奖项、从业年限和案例关联。
13. 官网是否允许公开客户评价、客户案例故事和服务数量。
14. 套餐价格、固定定金、活动价、服务项和交付说明的正式公开口径是什么。
15. 业务、案例或套餐下架后的旧链接希望显示不可用、替代内容还是联系工作室。
16. 官网是否需要提供客户进入小程序查看预约、订单、支付和成片的入口。
17. 官网和小程序是否允许不同的作品展示数量、案例排序和摘要长度。
18. 正式域名、品牌名称、备案、分享平台和外部投放渠道是什么。
19. 官网公开访问、图片加载、地图调用和外部分享的合规与隐私要求是什么。
20. 如何获取官网访问、分享、联系、预约和转入小程序的真实基线。

## 18. 后续专题输入

A09 为后续专题提供以下输入：

- A05：官网使用统一品牌、工作室资料、联系方式和内容发布状态；
- A06：官网案例详情、图片公开资格、授权撤回和分享失效处理；
- A07：官网业务/套餐公开字段、价格、固定定金、版本和失效状态；
- A08：官网导入小程序的客户任务、身份触发、预约、订单、支付和交付入口；
- A10：后台维护官网栏目、SEO/分享公开信息、预览、发布、下架和失效链接任务；
- A11：官网公开资料、客户身份切换和隐私边界；
- A12：官网直接预约或小程序导流时的预约字段、固定时段和冲突结果；
- A13：官网不直接复制订单事实，客户业务记录转入统一受控入口；
- A14：官网支付入口只导向受支持的客户交易流程，不自行判定支付事实；
- A15：官网公开案例授权、私密交付和入口到期保持隔离；
- A16：官网访问来源、页面理解、联系和小程序转入的衡量方向。

## 19. 结论

当前工程没有正式独立官网，只有基于 uni-app 的前端/H5 构建入口和面向小程序的页面原型。当前 HTML 标题为空、文档语言不正确，页面缺少独立公开信息架构、深层链接、SEO/分享内容、旧链接处理和官网预约分工；小程序中已有的硬编码、固定详情、联系方式冲突和占位内容也不能直接迁移为官网正式内容。

A09 确立的目标是：建立一个可被搜索、分享和直接访问的品牌官网，让外部访客能够独立理解工作室、浏览有效公开案例、比较摄影业务和套餐、确认联系信息，并清楚进入小程序或预约咨询；官网与小程序共享统一公开事实，但不必复制相同的页面结构和操作路径。

官网是否直接提交预约仍是待确认产品决策。无论最终采用官网直预约还是引导小程序，官网都不能绕过预约确认、订单生成、支付、履约、交付授权和错误处理的统一规则。官网在真实品牌资料、公开案例授权、套餐经营内容、SEO 获客目标和客户可用性被验证前，不应锁定最终页面结构、技术框架、SEO 策略、数据库模型、API 契约或具体编码方案。
