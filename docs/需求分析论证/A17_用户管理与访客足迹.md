## 1. 目的

本期要让工作室认出每一个打开小程序的人，看见他留下的称呼和头像，并看见他打开过哪些页面、把哪张卡片传出去、谁又点开了。

用户管理回答「这个人是谁」。访客足迹回答「这个人看了什么、卡片怎么传下去」。两件共用同一个微信身份。公开预约继续关闭。点赞、留言、手机号不在本期。

## 2. 和已有文档的关系

| 已有说法 | 本期决定 |
|---|---|
| A11：浏览不建立客户档案 | 继续有效。登录建立的是小程序用户，不是预约客户 |
| A11 / D-304：未登录可以浏览公开内容 | 不再作为当前产品决定。打开小程序就必须完成微信登录 |
| P02 Q05：微信身份为基础，手机号不是登录前置，同手机号不自动合并 | 继续有效，并且本期不采集手机号。旧预约只按同一身份指纹接上 |
| D-304：登录成功会成为预约客户 | 不再作为当前产品决定。预约周历只放提交过预约申请的人 |
| A16：页面打开不是业务成功；记录失败不能挡住正式业务 | 继续有效。足迹写失败时，页面照常打开，分享卡片照常发出 |
| 六个页面的分享只返回标题和固定路径 | 本期在路径上增加卡片编号，并回传服务器 |

D-304 第 3 节与本文冲突的地方，以本文为准。Q05「不按手机号、称呼自动合并」不以本文废止。

## 3. 已确认的用户管理

### 3.1 登录

- 进入小程序就登录。成功后直接到首页，不在进门时插入填写资料。
- 使用微信静默登录。没有授权弹窗，没有账号密码，没有退出。
- 登录失败时停在重试页，不进入作品和套餐。使用中会话过期，先自动再登录；再次失败才回到重试页。
- 每次小程序回到前台并成功确认身份，都更新最近登录，包括从微信聊天切回来。
- 服务器保存身份指纹，不保存 openid。短编号是指纹前六位大写。认人用完整指纹。
- 用户只来自小程序。官网不登录，也不写入用户管理。

### 3.2 资料

- 登录和用户信息是两层。登录只认出这个微信。用户信息现在是头像和用户名，两项都有才算齐。手机号以后若要，也归在用户信息里；本期不采集，也不用来拦预约。
- 称呼或头像还空着，人仍然是已登录。看首页、作品、套餐、关于，以及打开预约页看档期，都不要求这两项，也不因此新建预约客户。页面不标「资料未齐」。空称呼仍显示「微信用户」加短编号，头像用默认图。
- 缺任何一项时，「我的」升起一张卡片。卡片上只有要补的项和保存，不写操作说明，没有「以后再说」。只缺一项时，卡片里只留那一项。点卡片上方的暗处可以关上；底栏仍可切换。关上不算跳过，下次再进「我的」如果还缺，卡片再出现。
- 两项都有了，再进「我的」不再自动弹出。点「我的」里的头像和用户名，可以再打开同一张卡片修改。卡片不把空用户名存回去。
- 提交预约申请时，如果还缺头像或用户名，先弹出同一张卡片。两项都保存成功之后，才继续提交。点上方关上时，不提交申请，也不新建预约客户。这张卡片不改变预约开关。
- 称呼：客人和后台都能改，以最后一次保存为准。后台清空后恢复默认称呼，客人下次进「我的」会再看到卡片。
- 头像：只有客人能换。后台只看，不能撤下。
- 备注：只有后台能写、能看。「我的」里不出现。
- 客人填了称呼之后，客人侧只看见称呼。后台始终看见短编号。
- 没有电话、地址、真实姓名。只保留当前资料，用户页不展示修改历史。
- 第一次填写称呼或头像时，使用微信自己的隐私保护指引。小程序里不再做一页协议。

### 3.3 客人与后台

- 「我的」可以改称呼和头像。这个微信如果已经对上预约申请，申请列在下面，沿用现有申请卡片。不放新的预约入口。
- 后台入口叫「用户」，沿用现在的管理员，不新开角色。
- 列表显示头像、称呼、短编号、最近登录、注册时间，按最近登录从新到旧。搜索匹配称呼和短编号。
- 详情可以改称呼和备注。已接上的预约只读，并可转到现有预约处理。不能在用户页新建预约。
- 不能手工新建用户，不能删除，不能停用。
- 已经在预约里的人不等待批量导入。他下次打开小程序并登录成功后，才出现在用户列表，并和他已有的预约接到一起。

## 4. 用户管理还要守住的边界

这些不是新的功能，而是上面那些决定带出来的约束。设计必须守住，不能在实现时重新打开。

- 登录会话和预约会话分开。现有预约登录会新建预约客户，而且预约入口关闭时会直接拒绝。用户登录不能走那条接口。
- 只登录的人不进入预约周历，也不占档期。
- 接上旧预约只认同一套身份指纹。称呼相同、短编号碰巧相同，都不合并。
- 短编号只用于显示和搜索。两个人前六位相同，搜索把两行都列出来，身份仍是完整指纹。
- 用户页不展示称呼和备注的修改历史。工作人员的修改仍写入现有后台审计，审计不在用户页展开。
- 头像不进入公开作品库，也不出现在小程序作品里。
- 上线称呼和头像填写之前，要在微信公众平台的隐私保护指引里声明昵称和头像。未声明时，微信会禁用这两个填写组件。
- 本期不提供注销。用户资料按第 3 节保留。注销和法定保留留到后面的合规专题，不在本期补一个删除按钮。

## 5. 访客足迹

因为进入小程序就必须登录，足迹的主体就是这个用户。没有登录前的匿名足迹。重试页上的失败不写入足迹。

### 5.1 记这三件事

| 事件 | 记下什么 | 不表示 |
|---|---|---|
| 打开页面 | 谁、哪一页、作品或套餐、服务器时间、从哪张卡片来、微信场景号 | 想预约，或已经看完 |
| 发出分享 | 谁、哪一页、新卡片编号、上一张卡片编号 | 对方已经收到。微信只保证客人点开了分享，不保证卡片送出 |
| 从卡片进入 | 谁点开、卡片编号、场景号。场景号只说明单聊、群或朋友圈这一类入口 | 群里还有哪些人 |

同一用户、同一页面、同一内容，30 秒内的重复打开记一次。每次发出分享都保留自己的卡片编号。

记录失败时，页面照常打开，分享照常发出。缺一条足迹，不补写成预约或订单。

### 5.2 传递怎么串

卡片编号由服务器签发，放进分享路径。打开的人带着这个编号进来，就成为下一跳。下一张卡片记下上一张的编号。

能看见的链是：谁发出，谁点开，谁再发出。没点开的人、微信群名称、群成员和聊天内容不进入记录。朋友圈同样只认点开了带编号的页面。

编号对不上任何一张已发出的卡片时，这次打开仍然保留，只是没有上一跳。

### 5.3 后台怎么看

- 用户详情里有这个人的时间线：打开了哪一页，从哪张卡片进来，后来自己发出了哪一张。
- 从一次分享进去，看见这张卡片被谁打开，其中谁又发出了下一张。
- 旁边有三个数：一段时间内的打开次数、发出次数、被打开次数。这三个数用来扫一眼。时间线和卡片传递才是要看的内容。
- 列表本身不铺开足迹。

### 5.4 保留

**已确认**：单条足迹和卡片保留 180 天，到期删除。到期后可以留下不含个人的按天次数。用户资料不随足迹到期删除。

## 6. 本期不做

- 手机号获取、短信登录、地址、真实姓名。
- 手工新建只有姓名或电话的人。
- 官网登录和官网足迹。
- 退出、删除、停用、注销。
- 点赞、留言及其审核。
- 公开预约入口。
- 批量导入旧预约客户。
- 解析微信群，保存 openid，保存分享票据。
- 把打开页面写成预约、订单或付款成功。

## 7. 验收

- 新客人第一次打开小程序，登录成功后进入首页。后台「用户」里出现一行，称呼是「微信用户」加六位短编号。预约周历不新增这一行。
- 关掉网络或服务器拒绝登录时，停在重试页，作品页打不开。
- 客人在「我的」的卡片里保存称呼和头像，后台看到同一份。后台改称呼后，客人下次打开「我的」看到新称呼。客人看不到备注。卡片上没有「以后再说」和操作说明。
- 没有头像或用户名时，打开预约页仍可看档期，预约客户表不增加。按下提交先出现同一张卡片；点上方关上后，申请没有提交。两项都保存后，申请才提交，这时才出现预约客户。
- 后台不能新建、删除、停用用户，不能撤下头像，不能在用户页新建预约。
- 一位已经有预约申请、并且指纹对得上的客人再次进入小程序后，出现在用户列表，「我的」和用户详情都能看到那些已有申请。
- 客人从作品详情发出分享，另一位已登录的客人点开。第一位的时间线有发出，第二位的时间线有打开，卡片传递上是这两跳。
- 足迹接口失败时，作品页仍然打开，分享路径仍然能发出。
- 数据库和日志里没有 openid。公开作品接口不返回用户资料和足迹。
- 超过 180 天的足迹和卡片被删除。对应用户、称呼、头像和备注还在。
