## 1. 这次要收口什么

阶段二的产品目标不变：工作室能维护真实资料，顾客能用微信身份提交预约，工作人员确认后占档并成单。在此之上，2026-11-06 补充的展示要求是：

1. 预约功能对真实顾客开放。
2. 支持微信用户登录。
3. 媒体存储改为腾讯云 COS。
4. 有网络时尽快显示已发布内容，页面不先摆一套占位内容干等。
5. 顾客能读到的字、能看到的图，都由后台发布；字段为空就留白。
6. 公开图片走 COS，并由 CDN 分发。
7. 没有网络、超时或目录接口失败时，内容区什么都不显示。不使用上次缓存，也不用写死的句子顶上。

审阅时先按下面的口径读。若要改，改这一节即可，后面的批次跟着改。

| 口径 | 本文采用 | 若改成另一边 |
|---|---|---|

## 4. 小程序里仍写死、X1 必须收走的句子

下面这些顾客仍能看见，但改后台不会变：

- 首页和关于页的「安娜 & 方女士」
- 作品详情底部的「安娜全程引导 · 含专属定制妆造」
- 预约各状态旁的说明，包括「请提前 15 分钟到店，安娜与方女士期待与你们见面」

- 「当前为演示占位码」「预约服务暂未开放」「公开联系方式暂未配置」

「本阶段不收款」若后台留空，页面不显示这句。代码仍保证没有支付入口，也不把金额写成已支付。

## 5. 五个批次

```text
X1 展示只来自已发布内容
    ↓
X2 公开图片进入 COS，并由 CDN 分发
    ↓
X3 微信身份与预约开关在预发布接通
    ↓
X4 真实资料发布，预约对顾客开放
    ↓
X5 真机验收、备份恢复与发布回退
```

X2 和 X3 可以并行准备账号和域名。X4 必须等 X1、X2、X3 都过了自己的验收：否则正式内容会带着写死的人名，图片仍在本机磁盘上，或者顾客仍是测试身份。

### X1 展示只来自已发布内容

目标：小程序不再自己编工作室内容。有目录就按目录画；没有目录就什么内容都不画。

包含：

- 扩展管理库里的展示文案，并在后台提供编辑、预览和发布。至少覆盖 §4 列出的句子，以及各页仍写在 WXML 里的栏目标题、按钮字和空状态。
- 公开接口随目录版本返回这些字段。未发布的草稿不到小程序。
- 小程序删除写死的替身句子。某个字段为空，那一块不渲染。
- 目录请求失败、超时或无网络：内容区空白。不读本地存储里的旧首页。
- 同一次打开中，已经成功的结果留在内存。切回页面时先显示这份结果，同时再请求；新请求失败则清空。
- `dataMode=demo` 允许保留一行工程标识。`production` 不显示该标识，也不接受 `demo` 数据。

不包含：改颜色和版式、COS、打开正式预约、录入真实品牌。

验收：

- 后台把首页署名改成另一句并发布后，小程序只显示新句子。
- 把该字段清空并发布后，该位置没有字。
- 断网打开小程序，五个内容页都没有工作室文字和图片；底栏仍在。
- 杀进程后再断网打开，仍没有上一次的内容。
- 正式构建遇到 `dataMode=demo` 时拒绝渲染内容。

### X2 公开图片进入 COS，并由 CDN 分发

目标：衍生图不再落在应用服务器磁盘上，小程序也不再向 API 要整段图片字节。

包含：

- 用 COS 实现现有的媒体写入端口和公开读取端口。原图不进入公开地址。对象创建后不覆盖。
- 上传仍先检查类型、体积和像素，只保存缩略图和预览图。
- 管理端预览仍走后台自己的登录来源，不放到公开 CDN。
- 小程序使用的公开图地址指向 CDN。地址对应的是某次处理后的衍生图，不是永久原图。
- 作品或授权撤回之后，新的目录不再给出该图；新的读取不能再拿到字节。已经发出的字节不承诺追回。
- 补上图片文件夹（`V15`）目前缺少的测试。
- 目录 JSON 仍很快返回；图片速度由 CDN 承担，而不是把图片再代理进 API 进程。

不包含：把顾客私密成片放进这个公开桶、在 CDN 上缓存「是否仍有权查看」的结论、用测试桶里的对象直接当正式图片。

验收：

- 隔离环境上传、发布、小程序读取、撤回，字节在 COS，不在本机媒体目录。
- 撤回后新请求不再显示该图。
- 同一张已发布的预览图重复打开时，不再每次都把整文件读进 API 进程。
- 管理端未登录不能通过公开 CDN 看到未发布的图。

### X3 微信身份与预约开关在预发布接通

目标：用真实的微信 `code2session` 跑通「登录 → 选档 → 提交 → 后台确认成单」，数据仍是预发布的虚构或待销毁内容。

包含：

- 预发布的公开预约使用 `WECHAT`。`TEST` 身份只允许配合成数据，生产配置拒绝它。
- AppID、AppSecret、会话密钥放在环境里，不进仓库。仓库里已有的测试 AppID 只说明客户端构建指向哪一个小程序，不代替密钥托管。
- 服务器域名使用 HTTPS。小程序后台把该域名配进合法请求域名。
- 后台保存一套预发布营业规则。未保存规则时，预约继续拒绝，不猜默认值。
- 预发布套餐来自显式发布清单，并与 `admin_package_fact` 对齐。
- 顾客只看自己的申请。同手机号、同微信、姓名相近都不自动合并。

不包含：把预发布内容宣称为正式营业、手机号一键获取、订阅消息、收款。

验收：

- 真机用微信登录后提交一笔申请，页面为待确认，数据库没有占档。
- 管理员在后台指定时段并确认后，占档、订单和快照各一笔，页面显示已确认和「不收款」的已发布文案。文案若被清空，则不显示这句，支付入口仍然不存在。
- 用另一个微信号读不到这一笔。
- 生产配置打开 `TEST` 身份时进程拒绝启动。

### X4 真实资料发布，预约对顾客开放

目标：顾客看到的是工作室核对过的内容，并能提交真实预约。

包含：

- 工作室提供并核验：品牌、成员、地址、营业时间、联系方式、可用二维码、实际开放的套餐和价格、作品图及权属或授权材料、档期规则。
- 全部经后台录入和发布。不手改数据库，不把测试行改个标记当成正式数据。
- 正式环境与预发布数据隔离。正式开放前，演示作品、占位二维码和测试客户不可见。
- 公开预约开关在上述材料就绪后打开。
- 通知渠道登记为人工联系：顾客在「我的」查看状态，工作室用电话或微信跟进。失败任务仍在后台可见、可重试。不宣称消息已经送达顾客。

不包含：订阅消息模板、支付、把未授权的作品先挂到线上。

验收：

- 正式小程序的品牌、价格、作品和关于页都能在后台改完并发布，源码里没有工作室专名。
- 一笔真实身份的申请走完待确认和确认成单，订单快照里的套餐名和金额来自确认当时的事实。
- 抽查公开作品都有当前有效的授权；撤回后新访问看不到。
- 正式库里没有演示种子和 `TEST` 身份产生的顾客。

### X5 真机验收、备份恢复与发布回退

目标：按 P02 的 G2B 和 G3 把阶段二叫做完成。

包含：

- 工作室在真机上走完浏览、断网空白、恢复后看到新内容、预约、确认、取消或改期、授权撤回。
- 数据库和 COS 各做一次隔离的备份恢复，核对目录版本和对象是否一致，并写明保留责任人。
- 做一次应用发布和回退。已执行的数据库迁移不能只靠换回旧程序来假装撤销。
- 密钥只在环境中。日志不出现 AppSecret、会话密钥或数据库口令。
- 复跑非 Web 控制台关闭探针，或者在证据里写明该探针不再作为当前包的门禁。
- 容量只按单工作室的真实预期做一次测量：首页目录时间、CDN 图片时间、上传 30MB 图片的处理时间。不把多实例压测当作本阶段完成条件。

验收：G2B 和 G3 的条目都有记录，且没有未声明的阻断缺陷。到这里，阶段二收口。

## 6. 阶段二完成的定义

同时成立时，阶段二完成：

1. X1 至 X5 的验收都有记录。
2. P02 的 G2A 保持有效，G2B 和 G3 成立。

未完成 X5 时，最多称为预发布，不向真实顾客承诺已经营业。
