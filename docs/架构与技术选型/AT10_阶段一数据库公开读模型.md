# AT10 阶段一数据库公开读模型

## 1. 决策与边界

用户要求：不保留旧兼容，不做 JSON/空实现兜底；按新版架构完成数据库闭环。采用独立 MySQL 库，不迁移或删除旧 southleafdb。此决策更新技术实现，不扩大 P01 的阶段一产品范围：仍然没有预约、订单、支付、私密交付和完整后台。

这是具有端口/适配器边界的公开查询应用，不是把旧 JPA Entity 换个名字，也不为小规模展示引入微服务。

## 2. 依赖方向

```text
小程序：严格 HTTP 契约 → 明确的 Summary/Detail 映射 → 页面状态与展示
                                  ↓
HTTP Controller → PublicQueryService → CatalogReadService
                     ↓                     ↓ 端口
              CatalogProjection      PublishedCatalogRepository
                     ↓                     ↑ 实现
              PublicVisibilityPolicy  JdbcPublishedCatalogRepository → MySQL
                     ↓ 端口
              PublicAuthorizationEvaluator
                     ↑ 实现
              JdbcPublicAuthorizationEvaluator → MySQL 当前授权事实

PublicMediaContentController → PublicMediaService
    → 公开资格 / 前后两次当前性复核
    → MediaObjectStore 端口 ← FileMediaObjectStore → 私有衍生图目录

显式运维入口（不是 Web Bean）：DatabaseMigrationMain → Flyway / 演示导入 / 预制演示图
```

- domain/port 不依赖 JDBC、文件系统、JSON 或适配器；application 只通过端口操作存储。JUnit 架构约束防止反向依赖重新引入。
- 不存在 Json*/Empty* 生产适配器、旧 CRUD Controller、旧 JPA Entity/Repository、legacy-local profile 或从新库失败回落旧库的分支。
- HTTP 响应 DTO 与不可变 CatalogSnapshot、关系表分开。前端不接受旧枚举、数字响应码、旧单独 wechat 字段、notes 别名或详情 options.id 别名。
- 正常的错误响应、页面加载态、用户布局偏好和网络重试不是业务数据兜底；来源错误不能变成成功空列表或虚构业务值。

## 3. 发布一致性

1. 每个公开查询从数据库读取 active_publication 指针及发布身份。
2. 首次读取一个版本，在 REPEATABLE READ 事务中加载完整关系投影；该发布快照为不可变对象。
3. 内存仅缓存最后一个不可变发布快照；每次请求仍查数据库指针，数据库不可用时直接报服务不可用，绝不使用旧快照降级成功。
4. 一个 QueryResult 同时封装 data 与 meta，不再让 Controller 在组装 data 后另查一次版本。
5. 公开授权不进入跨请求快照缓存：每次资格评估读取当前数据库记录。同一查询内仅复用已评估的同一作品结果。
6. 已发布内容不得就地修改：维护工具应创建新 release、完整写入并校验关系及素材后，在一个事务内切换 active_publication。新增版本要有新的 contentVersion；旧版本可保留审计，不代表仍可公开。

当前是受限规模的发布聚合读模型（最多 1000 作品、1000 套餐、100 业务的实现容量保护），不是大图库检索引擎。未来可替换查询端口、增加专用分页投影和发布工具，但不能让性能缓存绕过授权当前性。

## 4. 分页协议

游标携带发布版本、查询条件和最后 ID，不提供授权能力。格式/条件非法为 400 PUBLIC_QUERY_INVALID；版本过期或锚点消失为 **409 PUBLIC_CURSOR_EXPIRED**。

客户端收到该明确冲突，只重启一次首屏查询；不把旧页拼进新版本，不对任意错误自动循环重试。业务目录和列表首屏若来自不同版本，不渲染混合结果，进入明确错误状态供刷新。排版与分类偏好不受重查影响。

## 5. 数据模型（19 张领域表，另加 Flyway 历史表）

| 分组 | 表 |
|---|---|
| 发布身份 | catalog_release、active_publication |
| 品牌与联系 | studio_brand、studio_contact、team_member、team_specialty、contact_channel |
| 业务与套餐 | photography_business、catalog_package、package_line |
| 作品与关系 | public_work、work_business、work_media |
| 媒体 | media_asset、media_variant |
| 首页编排 | home_featured_business、home_featured_package |
| 当前公开授权 | public_authorization、authorization_media |

- 展示实体以 release_id 关联发布版本；子项使用关系表、外键、唯一顺序和 CHECK，不把整份目录塞进数据库 JSON 大字段。
- 媒体绑定从具体领域关系推导，不依赖不能建立外键的任意 owner_id 拼接。
- 套餐服务项/提示/须知支持多行 TEXT；不使用旧 varchar(255) 拼数组或旧 desc 列。
- 时间按 UTC 维护；公开/授权时间使用 DATETIME(6)，支持合法的 2038 年之后期限，JDBC 适配器明确转换成 Instant。
- contentVersion 是发布身份；媒体另有字节级 SHA-256，不把发布版本当作客户同意的证明。

## 6. 授权与媒体

公开列表以批量授权端口读取当前事实；一个 repeatable-read 事务内用两条 SQL 获取整批授权与媒体范围，不按作品触发 N+1。纯单元测试验证单批调用，真实 MySQL 集成测试验证 6 作品仅两条 SQL。批次不完整属于依赖错误，不被当成正常未知授权。

范围包含发布身份 releaseId、作品候选版本、媒体绑定版本、媒体集合、主体范围引用、用途、渠道、有效期、事实修订号和摘要。缺失、撤回、过期、范围不匹配均拒绝公开；数据库依赖失败返回不可用，不能转成“没有作品”。

演示导入 provenance=DEMO_GENERATED、evidence_ref 明示不是客户同意；生产读取要求 VERIFIED_AUTHORITY，且数据发布必须是 production/APPROVED。**这些字段与标记是系统事实载体，不证明外部授权资料真实或已完成运营审查。** 当前没有真实客户授权资料，也没有把外部 A15 系统接入伪称完成。

媒体请求流程：校验参数和绑定 → 读取当前资格戳 → 读取预制内容寻址文件并校验 canonical root、长度、上限和 SHA-256 → 再读当前发布/授权戳 → 一致才返回。HEAD 同资格检查；Range 不支持；不使用 304/长期缓存绕过复核。撤回在最终复核后的极短发送窗口、客户端前台持续显示的正式协议仍需单独验收，不能以此代码宣称网络层绝对原子撤回。

演示图在显式导入阶段生成、完整解码检查尺寸并写入私有目录，接口不再动态绘图。真实照片仍应经过正式衍生图、元数据清理和授权发布流程；不能直接把私密原图丢进此目录。

## 7. 配置、迁移与权限

- 应用只接受环境注入的连接和媒体根目录。缺配置、缺迁移、数据库不可用或发布模式不匹配，启动/读取失败，不创建旧表、不补种子、不降级 JSON。
- Flyway 11.20.3 校验版本/校验和；运行账号不执行 migrate/repair/clean。迁移由独立运维账号显式执行。
- 本机凭据存 Windows Credential Manager，通过启动脚本注入子进程。此为开发便利：生产需区分运行与迁移的 OS/密钥访问身份，不能把同一开发用户的凭据库当作生产权限隔离。
- 运行账号只获新库 SELECT；迁移账号仅获新库必要 DDL/DML；集成测试账号只能操作独立测试库。原 root 和旧库未纳入运行路径。
- schema 迁移不带演示种子。--seed-demo 是显式空公开读模型导入，不接受覆盖/合并/重置现有数据。

## 8. 验证与未交付范围

纯单元/架构测试、真实 MySQL 集成测试和运行中契约检查分开执行。真实库测试验证权限、TLS、持久化、外键、撤回、范围/期限、版本切换与游标冲突；不以 H2、Mock 或跳过测试替代。

当前记录见《阶段一新版架构与数据库交付记录》。正式资料、真实授权核验、部署/真机门禁、备份恢复演练、完整 SCA/容量运维验收仍须独立完成，不因数据库闭环而自动通过。

## 严格复核后补充规范

领域、应用与端口均为 plain Java；Spring 注解与框架装配只在 config/adapter/controller 等外层，架构测试禁止内层反向依赖。运行以 Spring Boot 4.1.1/Spring 7、Tomcat 11.0.27、Jackson 3.1.8 及维护后的传递依赖验证；版本与安全边界以当前严格复核记录和 POM 为准。

启动实际校验账号、直接 SELECT-only 授权及 TLS cipher，拒绝 root/写权限/全局 SELECT/角色/GRANT OPTION。生产还要求 VERIFY_IDENTITY；权限错误不修复、不降级。新发布不能沿用旧 release_id 的范围事实，即使候选/绑定版本字符串相同；真实库回归覆盖此反例。

物理模型、媒体、迁移及本地恢复证据见 D-502/D-503/D-504。OSV 运行依赖 0 匹配不等于完整 SCA；前端已知高危与外部正式门禁仍阻塞。
