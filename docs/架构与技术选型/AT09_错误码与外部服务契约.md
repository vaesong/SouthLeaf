## 1. 文档目的

本文件统一 SouthLeaf 的 HTTP 状态、稳定业务错误码、字段级校验、日志 request id、外部支付/退款/对象存储结果映射和人工补偿边界。

错误响应服务于客户端和运营人员，不暴露 Java 异常、SQL、堆栈、内部路径或第三方原始响应。详细技术字段名可在 API 契约阶段落定，但业务语义和安全边界从本文件开始固定。

## 2. 错误响应原则

统一错误响应至少包含：

- `code`：稳定的业务错误码，不使用 HTTP 状态码代替；
- `message`：面向当前调用方的安全提示；
- `requestId`：用于日志检索和客服/后台排障；
- `details`：可选的字段错误、重试提示或业务上下文，不包含敏感信息。

示例结构：

```json
{
  "code": "RESERVATION_SLOT_CONFLICT",
  "message": "该时间段刚刚被其他预约占用，请重新选择。",
  "requestId": "req-xxxxxxxx",
  "details": {
    "retryable": false
  }
}
```

约束：

- 成功与失败不能只由 `code == 200` 判断；HTTP 状态和业务错误码分别表达协议结果与业务结果。
- 客户侧提示使用稳定、可理解的文案；后台可获得更完整但仍脱敏的处理建议。
- 内部日志记录异常堆栈和上下文，接口响应不返回堆栈。
- 同一个 request id 贯穿入口、应用服务、任务和外部调用日志；异步任务另有 task id 并保留原 request id。
- 错误码一旦对外使用，不随意改变语义；文案可以按端侧调整。

## 3. HTTP 状态映射

| HTTP 状态 | 使用范围 | 业务错误码示例 |
|---:|---|---|
| 400 | 请求格式、字段校验、参数组合错误 | `VALIDATION_ERROR`、`INVALID_REQUEST` |
| 401 | 未认证或客户身份失效 | `UNAUTHENTICATED`、`CUSTOMER_SESSION_EXPIRED` |
| 403 | 已认证但无角色、资源或状态权限 | `FORBIDDEN`、`RESOURCE_ACCESS_DENIED` |
| 404 | 资源不存在或当前调用方不可见 | `RESOURCE_NOT_FOUND` |
| 409 | 状态冲突、并发冲突、重复或版本过期 | `CONFLICT`、`RESERVATION_SLOT_CONFLICT`、`STALE_VERSION` |
| 422 | 请求格式正确但业务规则不允许 | `BUSINESS_STATE_INVALID`、`PAYMENT_AMOUNT_MISMATCH` |
| 429 | 频率、重复尝试或外部渠道限流 | `RATE_LIMITED`、`EXTERNAL_RATE_LIMITED` |
| 500 | 未预期内部错误 | `INTERNAL_ERROR` |
| 502 | 外部服务明确不可用或返回无效结果 | `EXTERNAL_SERVICE_ERROR` |
| 503 | 系统或外部依赖暂时不可用 | `SERVICE_UNAVAILABLE`、`PAYMENT_PROCESSING` |

不要把所有业务失败都返回 500；客户端需要依据状态码和稳定业务码决定展示、重试或引导人工处理。

## 4. 通用错误码目录

| 错误码 | HTTP | 语义 | 客户端动作 |
|---|---:|---|---|
| `VALIDATION_ERROR` | 400 | 字段缺失、格式或范围不合法 | 修正字段后重试 |
| `INVALID_REQUEST` | 400 | 请求结构或参数组合不合法 | 修正请求 |
| `UNAUTHENTICATED` | 401 | 未登录或身份无效 | 重新认证 |
| `CUSTOMER_SESSION_EXPIRED` | 401 | 客户侧身份已过期 | 重新进入身份验证流程 |
| `FORBIDDEN` | 403 | 角色不允许此操作 | 不重试，联系有权限人员 |
| `RESOURCE_ACCESS_DENIED` | 403 | 无资源归属或敏感访问权 | 不暴露资源存在性 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在或不可见 | 刷新或返回列表 |
| `CONFLICT` | 409 | 通用并发或业务冲突 | 刷新资源后重新操作 |
| `STALE_VERSION` | 409 | 客户端使用旧版本操作 | 重新读取最新版本 |
| `RATE_LIMITED` | 429 | 请求过于频繁 | 按提示退避 |
| `INTERNAL_ERROR` | 500 | 未预期内部错误 | 使用 request id 联系处理人员 |
| `EXTERNAL_SERVICE_ERROR` | 502 | 外部服务明确失败 | 按业务提示重试或等待 |
| `SERVICE_UNAVAILABLE` | 503 | 当前服务暂不可用 | 稍后重试 |

## 5. 预约、档期与订单错误码

| 错误码 | HTTP | 适用场景 | 是否可重试 |
|---|---:|---|---:|
| `RESERVATION_SLOT_CONFLICT` | 409 | 确认或改期时固定时段已被占用 | 否，重新选时段 |
| `RESERVATION_NOT_CONFIRMABLE` | 422 | 预约已处理、已失效或套餐条件不满足 | 否，刷新状态 |
| `RESERVATION_EXPIRED` | 422 | 待确认申请超过有效期限 | 否，重新提交 |
| `RESERVATION_NOT_FOUND` | 404 | 预约不存在或调用方不可见 | 否 |
| `RESERVATION_CANCELLATION_INVALID` | 422 | 当前预约状态不允许取消 | 否 |
| `RESCHEDULE_NOT_AVAILABLE` | 422 | 当前订单/预约不满足改期条件 | 否，联系工作室 |
| `ORDER_ALREADY_EXISTS` | 409 | 重复成单请求但已有订单 | 幂等读取既有订单 |
| `ORDER_NOT_FOUND` | 404 | 订单不存在或不可见 | 否 |
| `ORDER_STATE_INVALID` | 422 | 当前订单状态不允许操作 | 否，刷新状态 |
| `ORDER_DEPOSIT_EXPIRED` | 422 | 定金期限已过，订单已失效 | 否，重新预约 |
| `ORDER_REVISION_CONFLICT` | 409 | 订单修订版本冲突 | 读取最新版本后重试 |
| `PACKAGE_VERSION_UNAVAILABLE` | 422 | 套餐已下架、版本无效或不允许成单 | 否，重新选择 |
| `PACKAGE_SNAPSHOT_CHANGED` | 409 | 待确认期间套餐版本发生变化 | 联系工作室重新确认 |

## 6. 支付与退款错误码

| 错误码 | HTTP | 适用场景 | 客户端动作 |
|---|---:|---|---|
| `PAYMENT_NOT_DUE` | 422 | 分期尚未到应付条件 | 等待拍摄完成或状态变化 |
| `PAYMENT_ALREADY_PAID` | 409 | 分期已有成功支付事实 | 刷新支付状态，不重复付款 |
| `PAYMENT_PROCESSING` | 503 | 支付结果未知或查单中 | 不重复创建支付，等待查单 |
| `PAYMENT_AMOUNT_MISMATCH` | 422 | 请求金额、订单金额或回调金额不一致 | 停止应用，进入人工核对 |
| `PAYMENT_ORDER_MISMATCH` | 422 | 支付单与订单/分期不匹配 | 停止应用，记录安全事件 |
| `PAYMENT_DUPLICATE` | 409 | 重复支付或重复成功结果 | 进入待分配/待退款处理 |
| `PAYMENT_OVERPAYMENT` | 409 | 超出当前分期应付金额 | 不自动分配，后台处理 |
| `PAYMENT_PARTIAL_NOT_SUPPORTED` | 422 | 首版不接受任意部分付款 | 补齐应付金额或联系工作室 |
| `PAYMENT_CHANNEL_ERROR` | 502 | 支付渠道明确失败 | 按渠道提示重试 |
| `PAYMENT_QUERY_REQUIRED` | 503 | 下单超时，需要服务端查单 | 等待系统处理 |
| `OFFLINE_PAYMENT_REVIEW_REQUIRED` | 422 | 线下收款尚未核验 | 等待后台复核 |
| `REFUND_NOT_ALLOWED` | 422 | 当前原因、状态或金额不允许退款 | 联系工作室 |
| `REFUND_REVIEW_REQUIRED` | 422 | 退款需负责人审核或金额未确定 | 等待人工处理 |
| `REFUND_PROCESSING` | 503 | 退款已提交但结果未最终确认 | 不重复发起 |
| `REFUND_FAILED_REVIEW` | 503 | 退款失败，转人工跟进 | 等待通知或联系工作室 |
| `REFUND_AMOUNT_INVALID` | 422 | 退款金额超过可退范围或不符合审核事实 | 修正退款申请 |

## 8. 字段级校验规则

字段错误应返回稳定错误码 `VALIDATION_ERROR`，并在 `details.fields` 中给出安全的字段标识和提示。

至少覆盖：

- 日期必须是可预约的有效日期，不能早于业务允许的最早日期；
- 申请失效时间、定金支付期限和小程序交付开放期必须是合法的正数时长；后台配置变化只影响新记录，既有记录使用已保存的实际截止时间；
- 固定时段必须来自当前工作室配置，不能由客户端任意构造；
- 客户联系方式满足格式、长度和脱敏存储要求；
- 套餐 id、套餐版本和业务类型必须存在且可用于申请；
- 定金金额不能小于零或超过订单总额；
- 线下收款金额、方式、时间和凭证信息必须完整；
- 退款金额不能超过已收且可退金额；
- 交付文件类型、大小、哈希和归属必须满足配置；
- 网盘补充交付必须有接收人、交付范围、链接有效期和操作原因。

不在字段错误中返回数据库字段名、Java 类名、对象存储路径或第三方原始参数。

## 9. 外部支付服务契约

### 9.1 发起支付

应用服务必须先生成本地支付意图，保存订单号、分期号、金额快照、幂等键和处理中状态，再调用微信支付适配层。外部调用超时进入 `PAYMENT_PROCESSING` 或待查单，不得直接判定失败并无条件创建新支付单。

### 9.2 支付回调

回调适配层必须完成：

1. 验证签名、通知来源、商户身份和证书/密钥配置；
2. 校验外部支付单号、业务订单号、分期号和金额；
3. 以外部支付单号和通知事件做幂等；
4. 在本地事务中写入支付事实并推进支付分期；
5. 返回渠道要求的成功确认；
6. 后续通知、履约或订单摘要更新通过任务/outbox，不在回调中同步调用其他外部服务。

签名错误、金额不匹配、订单不匹配和重复通知都要记录安全日志；对外响应不得返回内部校验细节。

### 9.3 主动查单

查单任务与回调使用相同的支付事实落库规则和锁顺序。查单结果未知时继续退避；达到阈值后进入人工核对。支付成功事实一旦确认，不因迟到的失败结果覆盖。

## 10. 外部退款服务契约

- 退款前先创建本地退款申请和审核事实，金额、原支付事实、责任原因和幂等号不可缺失。
- 外部退款请求必须复用稳定的幂等号，网络超时不能直接创建第二笔退款。
- 结果未知进入 `REFUND_PROCESSING`，通过查询或回调确认；明确失败超过自动重试阈值后进入 `REFUND_FAILED_REVIEW`。
- 退款成功事实记录外部退款单号、金额、时间和原支付关联；普通订单编辑不得覆盖。
- 退款通知、客户提示和人工补偿异步执行，并保留 task id 与 request id。

## 11. 对象存储契约

- 私密成片使用私有存储，不暴露永久对象地址。
- 上传采用受控上传会话；文件必须绑定订单、交付批次和文件类型。
- 上传成功后仍需完整性、大小、类型和必要的安全校验；未校验文件不得发布。
- 对象不存在、元数据缺失或哈希不一致时，业务文件进入异常/待重传，不向客户开放。
- 客户访问流程为：身份验证 → 订单归属 → 尾款已付清 → 交付已发布 → 授权有效 → 入口未到期 → 按用途生成短期访问地址。
- 尾款付清后，带水印预览和正式下载使用不同的访问用途；正式精修图和原片下载不限次数且不加水印，访问和下载均记录审计。
- 交付入口到期只关闭小程序访问，不自动物理删除工作室原文件；网盘补充交付走独立的负责人授权和审计流程。

## 12. 日志、审计与安全事件

### 12.1 普通运行日志

结构化记录：

- 时间、环境、服务模块；
- request id、trace id、task id；
- 操作类型、资源类型和业务号；
- 结果、耗时、错误码和可重试性；
- 外部调用名称、耗时和脱敏结果。

### 12.2 业务审计

至少审计：

- 预约确认、拒绝、取消、改期和档期释放；
- 订单生成、修订、失效和人工延长定金期限；
- 在线支付回调、查单、线下收款登记和核验；
- 退款申请、审核、发起、成功、失败和人工补偿；
- 确认拍摄完成、缺席、取消、补拍和服务异常；
- 成片上传、校验、发布、撤回、授权和网盘补充交付；
- 公开案例授权、撤回和公开下架；
- 敏感资料访问、角色变更和配置变更。

### 12.3 安全事件

签名错误、支付金额不匹配、订单归属不匹配、越权访问、异常下载和重复退款请求需要单独标记安全事件，并触发告警或人工核查。

## 13. 外部契约待补充

进入实现前仍需补齐：

- 微信支付具体版本、证书/密钥配置方式和回调响应协议；
- 对象存储供应商、上传方式、生命周期和安全扫描能力；
- 网盘补充交付的实际服务、链接有效期和撤回能力；
- 错误码多语言/多端文案和后台诊断信息；
- 重试次数、退避策略、超时和告警阈值；
- 客户身份认证和隐私脱敏的具体实现契约。
