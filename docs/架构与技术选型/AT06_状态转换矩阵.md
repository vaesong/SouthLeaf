# SouthLeaf 状态转换矩阵

> 文档编号：AT06  
> 文档类型：业务状态与转换前置设计  
> 文档状态：第 5 步配套基线稿；基于 AT05 已确认规则  
> 更新日期：2026-10-06  
> 前置文档：[AT04_总体架构设计草案](AT04_总体架构设计草案.md)、[AT05_高风险业务决策矩阵](AT05_高风险业务决策矩阵.md)

## 1. 文档目的

本文件把已确认的业务规则整理成相互独立的状态机，作为权限矩阵、事务/并发/幂等矩阵、错误码目录和后续详细数据库/API设计的共同输入。

本文件不定义最终数据库表、字段名或 API 请求格式。状态机中的“已确认”表示经营规则已经对齐；“技术不变量”表示实现必须保持的约束；“待配置/待补充”表示仍需由运营规则或技术契约补齐。

## 2. 全局原则

- 预约、档期占用、订单、支付分期、支付尝试、退款、履约和交付分别维护状态。
- 订单页面可以展示综合进度，但综合进度是只读投影，不能反向修改领域事实。
- 所有改变业务状态的动作都必须具备操作者、时间、原因或来源，并写入必要的审计记录。
- 外部支付、退款和对象存储没有与 MySQL 共享的分布式事务，外部结果未知时必须进入处理中或待查状态。
- 重复请求、回调和定时任务必须幂等；不能因为重试重复创建订单、重复占档或重复记账。
- 线下电话/微信预约和线上预约共用同一日期与固定时段冲突源。
- 首版只按同一日期和同一固定时段判断冲突，不单独管理摄影师、场地和设备资源。

## 3. 预约状态机

### 3.1 状态

| 状态 | 含义 | 是否占用硬档期 |
|---|---|---:|
| `PENDING_REVIEW` 待确认 | 客户线上提交或后台录入后，等待工作室处理 | 否 |
| `CONFIRMED` 已确认 | 工作室确认并同时完成成单、硬占档 | 是 |
| `REJECTED` 已拒绝 | 工作室因冲突、套餐变化或其他原因拒绝申请 | 否 |
| `CANCELLED` 已取消 | 预约被客户、工作室或系统按规则终止 | 否 |
| `EXPIRED` 已失效 | 待确认申请超过配置期限，未形成订单 | 否 |
| `RESCHEDULED` 已改期 | 原预约不再作为当前履约安排，已关联新的修订预约/订单 | 由新修订记录决定 |

### 3.2 允许转换

| 当前状态 | 动作 | 目标状态 | 前置条件与结果 |
|---|---|---|---|
| 无 | 提交线上申请 | `PENDING_REVIEW` | 记录客户、套餐版本、日期、固定时段和来源；不占硬档期 |
| 无 | 后台录入线下预约 | `PENDING_REVIEW` 或直接进入确认用例 | 记录来源为电话/微信；不得绕过冲突校验 |
| `PENDING_REVIEW` | 确认并成单 | `CONFIRMED` | 同一事务内重新校验冲突、建立硬占档、创建订单并写入快照 |
| `PENDING_REVIEW` | 拒绝 | `REJECTED` | 必须记录拒绝原因；不占档期 |
| `PENDING_REVIEW` | 超时失效 | `EXPIRED` | 仅适用于未处理申请；具体期限由运营配置 |
| `PENDING_REVIEW` | 客户取消 | `CANCELLED` | 记录取消方和原因；不产生退款事实，除非此前存在收款 |
| `CONFIRMED` | 申请并批准改期 | `RESCHEDULED` | 新日期重新校验并建立占用；原记录不可覆盖，定金按协商结果沿用 |
| `CONFIRMED` | 取消 | `CANCELLED` | 释放占用；退款按发起方、原因和已收款项决定 |
| `CONFIRMED` | 订单定金逾期失效 | `CANCELLED` 或关联失效结果 | 以订单失效为主事实，释放对应档期；保留预约和订单历史 |
| `CONFIRMED` | 工作室封档影响已确认安排 | `CANCELLED` 或异常处理 | 不得静默覆盖；需要人工处理、通知和审计 |

### 3.3 预约不变量

- 只有 `CONFIRMED` 预约可以对应有效硬占档和已创建订单。
- `PENDING_REVIEW` 不得阻塞其他申请的提交，也不得对客户承诺成功。
- 同一日期与固定时段最多存在一笔有效硬占档。
- 确认动作必须幂等；重复确认不能创建第二个订单或第二条有效占用。
- 改期保留原预约记录，并通过新修订记录表达新的日期、时段和状态。

## 4. 档期占用状态机

### 4.1 状态

| 状态 | 含义 |
|---|---|
| `HELD` 已占用 | 已确认预约/订单持有该日期与固定时段 |
| `RELEASE_PENDING` 待释放 | 已触发失效、取消或改期，等待释放任务或事务完成 |
| `RELEASED` 已释放 | 不再阻塞该日期与固定时段 |
| `BLOCKED` 后台封档 | 工作室主动关闭该时段，不接受新的确认 |

### 4.2 允许转换

| 当前状态 | 动作 | 目标状态 | 说明 |
|---|---|---|---|
| 无 | 确认并成单 | `HELD` | 与预约确认和订单创建处于同一事务 |
| `HELD` | 订单定金逾期失效 | `RELEASED` | 释放前重新核对支付事实 |
| `HELD` | 取消 | `RELEASED` | 取消、退款和释放需要保持业务顺序与审计一致 |
| `HELD` | 改期 | `RELEASE_PENDING` → `RELEASED` | 新时段占用成功后再释放旧时段，避免中途丢失档期 |
| 无 | 后台封档 | `BLOCKED` | 封档不能静默覆盖已确认占用 |
| `BLOCKED` | 解除封档 | 无 | 允许新的申请和确认，仍需最终冲突校验 |

### 4.3 占用不变量

- 唯一冲突键至少表达工作室、日期、固定时段和有效占用状态。
- 改期必须先确认新时段可用，再释放旧时段；不能先释放旧时段后再尝试新时段而导致业务丢失。
- 后台手工录入、线上确认、定时失效和改期全部使用同一冲突校验服务。

## 5. 订单状态机

### 5.1 状态

| 状态 | 含义 |
|---|---|
| `PENDING_DEPOSIT` 待支付定金 | 订单已由预约确认生成，等待定金结清 |
| `DEPOSIT_PAID` 定金已付 | 定金支付事实已确认，可进入拍摄安排流程 |
| `IN_SERVICE` 服务中 | 已满足履约条件，订单处于拍摄或后续制作流程 |
| `COMPLETED` 已完成 | 约定服务和交付流程已完成，是否仍可访问由交付授权决定 |
| `CANCELLED` 已取消 | 订单被客户、工作室或异常规则终止 |
| `EXPIRED` 已失效 | 待定金订单超过期限且未形成有效收款 |
订单退款不作为订单主状态；退款申请、处理中、成功和失败由独立的退款状态机维护。订单仍保留其原有业务终止或完成状态，并通过关联退款事实表达资金处理进度。

### 5.2 允许转换

| 当前状态 | 动作 | 目标状态 | 说明 |
|---|---|---|---|
| 无 | 确认预约并成单 | `PENDING_DEPOSIT` | 创建不可变套餐、价格、服务内容和时间快照；记录定金截止时间 |
| `PENDING_DEPOSIT` | 定金成功结清 | `DEPOSIT_PAID` | 支付事实经回调验签或查单确认 |
| `PENDING_DEPOSIT` | 定金期限到期 | `EXPIRED` | 24 小时默认；执行前复核支付事实，释放硬占档 |
| `EXPIRED` | 迟到支付且原时段仍可用 | `PENDING_DEPOSIT` 或恢复后状态 | 重新执行排他占档校验；只有重新占档成功才允许恢复 |
| `EXPIRED` | 迟到支付但原时段已占用 | 保持 `EXPIRED` | 不自动恢复，支付事实进入退款或人工处理流程 |
| `PENDING_DEPOSIT` | 客户/工作室取消 | `CANCELLED` | 已有收款时必须进入退款判断，不得直接抹除付款 |
| `DEPOSIT_PAID` | 开始履约 | `IN_SERVICE` | 需满足定金规则；履约状态另行维护 |
| `IN_SERVICE` | 服务和交付结束 | `COMPLETED` | 不能仅凭支付状态自动推导 |
| 任一可取消状态 | 发起退款 | 订单保持原业务终止或完成状态 | 同时创建独立退款申请；订单状态不代替退款状态 |
| 退款申请 | 退款成功 | 不改变订单主状态 | 更新支付分期和退款事实，保留订单历史 |
| 退款申请 | 退款未知/失败 | 不改变订单主状态 | 退款状态进入处理中或失败待处理，执行有限重试和人工跟进 |

### 5.3 订单不变量

- 订单只在预约确认并成单时创建；预约提交本身不创建订单。
- 套餐、价格、服务项、日期和固定时段快照不可被套餐后续编辑回写。
- 订单状态、支付状态、履约状态和交付状态分别维护。
- 订单是否可履约由定金支付和履约规则共同决定，不能只看订单是否存在。
- 改期创建修订版本，原订单和支付事实不可覆盖。

## 6. 支付分期与支付尝试状态机

### 6.1 分期状态

首版至少有两笔支付分期：定金、尾款。两者都按订单生成时的固定金额处理，不允许任意部分付款。

| 状态 | 含义 |
|---|---|
| `NOT_DUE` 未到应付条件 | 例如拍摄完成前的尾款 |
| `DUE` 待支付 | 已满足支付条件，等待结清 |
| `PROCESSING` 支付处理中 | 已发起支付但结果未确定 |
| `PAID` 已结清 | 已有唯一有效成功支付事实 |
| `OVERDUE` 已逾期 | 到期未结清 |
| `CANCELLED` 已取消 | 分期因订单取消或修订不再适用 |
| `REFUNDING` 退款处理中 | 对该分期已发起退款 |
| `REFUNDED` 已退款 | 对该分期的约定款项已退款 |

### 6.2 分期转换

| 当前状态 | 动作 | 目标状态 | 说明 |
|---|---|---|---|
| 无 | 创建订单 | 定金 `DUE`，尾款 `NOT_DUE` | 金额从套餐/订单快照读取并固化 |
| 定金 `DUE` | 发起在线支付 | `PROCESSING` | 生成唯一支付尝试和幂等键 |
| 定金 `PROCESSING` | 回调/查单成功 | `PAID` | 验签、金额、订单和分期均须匹配 |
| 定金 `PROCESSING` | 结果未知 | `PROCESSING` | 进入查单任务，不允许重复创建第二笔有效支付 |
| 定金 `DUE` | 支付期限到期 | `OVERDUE` | 与订单失效动作联动，执行前复核支付事实 |
| 拍摄完成确认 | 尾款激活 | 尾款 `DUE` | 由负责人或管理员显式操作触发 |
| 尾款 `DUE` | 发起支付 | `PROCESSING` | 仍须幂等与金额校验 |
| 尾款 `DUE` | 超过配置期限未支付 | `OVERDUE` | 订单和履约记录保留，不自动取消或退款；成片访问继续关闭 |
| 任一 `PAID` | 发起退款 | `REFUNDING` | 退款范围和金额由审核事实决定 |
| `REFUNDING` | 退款成功 | `REFUNDED` | 记录外部退款单和金额 |
| `REFUNDING` | 失败/未知 | `REFUNDING` | 有限重试后人工跟进 |

### 6.3 支付不变量

- 同一分期只允许一个成功结算结果应用到应付金额；重复、超额或金额不符款项进入待分配/待退款状态。
- 前端支付返回不是唯一事实；回调验签或服务端查单才是支付事实来源。
- 在线支付和线下收款都写入支付事实；线下收款必须记录方式、金额、时间、经办人、凭证/备注和核验状态。
- 支付成功事实不可被普通订单编辑覆盖。

## 7. 退款状态机

### 7.1 状态

| 状态 | 含义 |
|---|---|
| `REQUESTED` 已申请 | 已形成退款申请，等待审核或提交外部渠道 |
| `APPROVED` 已审核 | 有权负责人批准退款金额和范围 |
| `PROCESSING` 处理中 | 已提交外部退款或结果未知 |
| `SUCCEEDED` 成功 | 外部渠道确认退款完成 |
| `FAILED` 失败待处理 | 超过自动重试或明确失败，等待人工处理 |
| `CANCELLED` 已撤销 | 尚未提交外部渠道的申请被撤销 |

### 7.2 退款规则

- 客户主动取消或客户原因无法拍摄时，定金原则上不退；特殊处理必须有权限和审计。
- 工作室原因取消时，已收定金全额退回并释放档期。
- 改期需要协商，已付定金支持沿用；不可归责事件优先协商改期并沿用定金。
- 工作室责任导致尾款已付的服务异常或取消时，按未交付部分协商全额或部分退款，由负责人审核。
- 退款失败或结果未知进入 `PROCESSING` 或 `FAILED`，有限重试后人工跟进并通知客户；不能直接视为成功或未发生。

## 8. 履约状态机

### 8.1 状态

| 状态 | 含义 |
|---|---|
| `NOT_SCHEDULED` 待安排 | 订单已满足基础条件但尚未安排履约 |
| `SCHEDULED` 已安排/待拍摄 | 已确认拍摄安排 |
| `IN_PROGRESS` 拍摄中 | 仅在确有中途操作时使用 |
| `COMPLETED` 已完成 | 负责人或管理员确认拍摄完成 |
| `EXCEPTION` 异常 | 存在需要处理的服务异常 |
| `CANCELLED` 已取消 | 履约安排被终止 |

### 8.2 履约动作

- 负责人或管理员可以确认拍摄完成并触发尾款；摄影师不能直接触发尾款。
- 客户缺席、工作室取消、补拍和服务异常作为独立结果/事件记录，包含原因、操作者和时间。
- 履约状态不由支付状态自动推导；拍摄完成动作必须幂等并写入审计。
- 预约、订单和履约异常不得通过自由文本覆盖原始状态或历史事实。

## 9. 交付状态机

### 9.1 交付任务状态

| 状态 | 含义 |
|---|---|
| `NOT_READY` 未准备 | 尚未进入交付准备 |
| `UPLOADING` 上传中 | 文件正在上传或登记 |
| `VERIFYING` 校验中 | 文件完整性、类型或元数据校验中 |
| `READY` 已准备 | 文件已校验但尚未发布 |
| `PUBLISHED` 已发布 | 满足条件并开放给客户访问 |
| `ACCESS_EXPIRED` 客户入口已到期 | 小程序入口关闭，工作室原文件仍可保留 |
| `REVOKED` 已撤回 | 客户侧访问被撤回 |
| `ARCHIVED` 已归档 | 工作室保留原文件和业务元数据，不代表客户可访问 |

### 9.2 交付规则

- 首版交付精修图片和原片，暂不纳入视频和压缩包。
- 尾款付清前不开放任何成片预览和下载；尾款结清、交付已发布、授权有效且订单归属校验通过后，才开放小程序内带水印预览和正式文件下载。
- 正式精修图和原片下载不限次数且不加水印；系统记录访问和下载审计。
- 默认授权预约联系人；其他家庭成员由后台显式添加并记录授权。
- 小程序交付入口开放期限由后台配置，当前暂定默认 1 周；到期后下架入口，不代表物理删除原文件。
- 到期后如客户确有需要，工作室可人工通过网盘链接补充交付，必须受权限控制并留下记录。
- 公开案例必须取得明确同意，默认不公开；公开授权与私密交付授权分开保存。
- 对象存储只负责文件保存和技术访问地址，业务授权由应用服务判断。
