### 25.3 S5 确认成单接线（W2 首个增量）

此前 `BookingApplication.confirmReservation` 已实现并通过 101 项真实 MySQL 测试，但**没有任何 HTTP 端点**，后台无法在浏览器内确认成单。本次补齐：

| 层 | 变更 |
|---|---|
| 控制器 | `AdminBookingController` 新增 `POST /api/admin/v1/bookings/reservations/{reservationId}/confirm`，要求 `Reservation-Confirm` capability、`If-Match` 当前修订、`Idempotency-Key`，请求体精确为 `{"slotId"}` |

### 25.4 确认成单的已知阻塞：套餐事实缺失（必须先解决）

复核运行时装配时发现：`AdminBookingConfiguration` 目前把套餐事实端口显式接成空实现——

```java
// Package facts are intentionally unavailable in this local operations slice. No create or
// confirm endpoint is exposed until the immutable published-package adapter is wired.
PackageCatalog unavailablePackages = packageVersionRef -> Optional.empty();
```

因此 `confirmReservation` 在运行时必然以 `PACKAGE_NOT_FOUND`（HTTP 404）失败。**新增的 HTTP 端点与页面按钮当前不可用**，不得按"已完成"表述。

根因不在接线，而在**数据事实不存在**：M3 目录的套餐只携带 `priceType` 与 `displayPrice` 展示文案（`FIXED | FROM | INQUIRY | UNDISCLOSED`），没有结构化金额、币种与价格版本；而订单快照要求 `amountMinorUnits`、`currencyCode`、`priceVersion`。D-303 把"结构化金额候选"列为待确认项，Q03 的真实总价与固定定金按 P02 属于 2B。

**状态：已解除。** 阻塞点不在接线，而在数据事实不存在——M3 套餐只有展示文案（`priceType` /
`displayPrice`），订单快照却要求结构化金额。现按 S2-B 已验证的 synthetic 口径补齐事实并接通适配器，
未引入任何真实价格、支付或定金字段。
