## 1. 非 Web 控制台关闭探针不再作为当前包的门禁

2026-11-01 的工程收口没有重跑这项探针。当时从会话向进程发送控制台事件后，进程在 90 秒内没有退出。该事实记在[实施跟踪](阶段二实施跟踪.md) §26。历史 S1-B 的通过记录仍只代表当时的包，不代表现在这个包。

当前包不再把「向非 Web 管理进程独有控制台发送 Ctrl+C，退出码 130」当作门禁。代替它的现行门禁是：

- 单元测试覆盖配置拒绝：媒体 `file` / `cdn` 缺项或混用拒绝，管理媒体 `file` / `cos` 缺项或混用拒绝，生产拒绝 `TEST` 身份，生产拒绝 `TEST_SINK`，未配齐的经营参数拒绝。
- 对接人在已打包的公开 API jar 上执行 `backend/scripts/Test-StartupGuards.ps1`。它检查数据库不可达时拒绝启动，以及生产模式拒绝未校验的数据库 TLS。它不发送控制台关闭事件，也不改已有的 API 或 MySQL 进程。

本文不把上述单元测试或启动脚本写成已经在本次对接里跑过。

## 2. 密钥只在环境中

AppSecret、COS `SecretId` / `SecretKey`、数据库口令和会话密钥只放在进程环境里，不进仓库，不进日志，不进 `toString`。对接时用一段不会出现在正常业务日志里的秘密前缀检索本次启动日志，命中次数必须是 0。检索之后丢掉这段前缀，不要把它写进验收记录。

## 3. 数据库备份与恢复

`backend/scripts/Test-BackupRestore.ps1 -ConfirmIsolatedTestRestore` 只允许动本机 `127.0.0.1:3306` 上的 `southleaf_public_it`。它会改 `studio_brand.english_name`，再从 dump 恢复，并核对 `E:\SouthLeaf-data\public-media` 里的对象。这是隔离演练，不是生产灾难恢复。不要改脚本去指向 `southleaf_public` 或任何生产主机。

生产比对在一份隔离副本上做，不在正在服务的库上做变更探针。

1. 先执行 `SELECT DATABASE();`。结果不是预定库名就停止。
2. 记下公开库的指针和版本：

```sql
SELECT release_id, visible, epoch
FROM active_catalog_publication
WHERE singleton_id = 1;

SELECT release_id, content_version, data_mode
FROM public_catalog_release
WHERE release_id = (
  SELECT release_id FROM active_catalog_publication WHERE singleton_id = 1
);
```

3. 记下行数：`public_catalog_release`、`public_catalog_release_variant`、`flyway_schema_history`，以及管理库的 `admin_media_variant`、`booking_notification_outbox`、`flyway_admin_schema_history`。
4. 对公开库和管理库分别执行：

```text
mysqldump --single-transaction --skip-lock-tables --skip-add-locks --no-tablespaces --set-gtid-purged=OFF
```

5. 记录每个 dump 文件的 SHA-256。把 dump 恢复进一对空的隔离库，而不是覆盖正在服务的库。
6. 比对第 2、3 步的指针、`content_version`、`data_mode` 和行数。公开历史表必须包含恢复前已经成功的版本。管理历史表是 `flyway_admin_schema_history`；一旦 `V16` 已经应用，恢复后的版本里必须有 `16`。

`V16` 只把通知状态约束扩展为 `PENDING`、`LEASED`、`SENT`、`FAILED`、`STAFF`。它不新增表。`MANUAL_CONTACT` 在没有应用 `V16` 时不能把记录写成 `STAFF`，也不能改写成 `SENT` 来绕过。

## 4. COS 对象

公开地址只指向派生对象，键的形式是 `<sha256>.jpg` 或 `<sha256>.png`。原图不进入这个键，也不进入公开 URL。备份读取使用管理侧的 COS 凭据，不使用会过期的 CDN 地址。

```sql
SELECT object_key, sha256, byte_length
FROM admin_media_variant;
```

对每一行：用管理凭据取回该键的字节，计算 SHA-256，必须等于 `sha256`，也必须等于 `object_key` 的前 64 位；字节数必须等于 `byte_length`。再对当前公开指针引用的 `public_catalog_release_variant.object_key` 做同一比对。多出来的公开键，或少掉的公开键，都是失败。

撤回的判定是新目录不再引用该图，并且新的读取拿不到新的签名地址。已经发出的字节不回收。不要把 CDN 缓存当成授权决定。

## 5. 发布回退

发布前记录 `uniapp-api` 与 `admin-runtime` 两个 jar 的 SHA-256，以及当时管理历史表里的最大版本。

回退是换回这两个 jar 并重启。已经应用的迁移留在库里。换回旧程序不能假装 `V16` 被撤销。旧程序不会把 `STAFF` 改写成 `SENT`；对接人也不要手工改这个状态。若需要撤销 `STAFF` 的含义，另写一条向前的迁移，不靠 jar 回退。

## 6. 单工作室计时

只测一次真实预期，不做多实例压测。三次都记录秒数、HTTP 状态和日期。没有测到的项写「未测」，不要填估计值。

1. 首页目录。对 `GET {apiOrigin}/api/v1/public/home` 记录首字节时间。响应头 `Cache-Control` 必须是 `no-store`。这条时间是目录 JSON，不是图片字节。
2. CDN 图片。只从第 1 步响应里取一张 `previewUrl`。它的主机必须等于本次构建配置的 `mediaOrigin`，路径必须是 64 位十六进制加 `.jpg` 或 `.png`，查询串必须带 `q-sign-algorithm=sha1`。记录这张图的首字节时间和总时间。若地址仍是 `/api/v1/public/media/{id}/preview/content`，这次测的是 file 模式，不能写成 CDN 结果。
3. 上传。在后台传一张 31457280 字节的 JPEG，接口是 `POST /api/admin/v1/media/uploads`，表单字段名是 `file`。记录从请求发出到 JSON 返回的时间、HTTP 状态和 `mediaId`。原图不入库；入库的是 `admin_media_variant` 里的派生对象。返回 `MEDIA_TOO_LARGE` 时这次计时无效。
