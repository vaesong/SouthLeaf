## 2. 架构与职责

```text
公开 Controller → PublicQueryService → CatalogProjection / 可见性策略
                         ↓                         ↓
             PublishedCatalogRepository   PublicAuthorizationEvaluator
                         ↓                         ↓
              JDBC 发布快照适配器          JDBC 当前授权事实适配器

媒体 Controller → PublicMediaService → 可见性与资格复核 + MediaObjectStore
                                                         ↓
                                                私有预制衍生图目录
```

- domain：不可变发布聚合与精确范围授权规则，不依赖 Web、JDBC 或 Spring 容器。
- application：一次查询产生同一发布快照的 data/meta，负责排序、过滤、游标与资格协调。
- port：发布读取、批量范围授权事实、预制媒体存储边界。
- adapter：JDBC、私有文件系统与 HTTP，各自承担技术实现；不把 SQL/文件装配塞进 Controller。
- tooling：独立显式迁移和演示准备，不注册成 Web API，不随应用启动补表或补数据。

每次公开读取都从数据库确认当前发布指针；不可变缓存只能复用同一发布，不能掩盖断库。目录内容以新发布及原子指针切换更新，不原地修改已缓存发布。

授权事实不随发布缓存。列表使用**一个批量端口调用，在同一 repeatable-read 事务内以两条 SQL 读取授权与媒体范围**，避免按作品逐个查库；真实库测试已验证 6 作品对应两条查询。当前发布容量上限为 1,000 作品、1,000 套餐、100 业务；这不是生产容量/负载验收承诺。

## 4. 公开契约与媒体

- OpenAPI 为 `0.3.0-db`，保留的是新版 API 路径而不是旧字段兼容。品牌英文、业务、套餐、作品、联系渠道与成员均从关系读模型返回。
- 旧价格枚举、单独微信字段、旧详情参数不再接受。未知字段/值或畸形响应不静默转成页面资料。
- 游标与查询/发布绑定：畸形或查询不匹配为 400；发布变化或锚点失效为 409 `PUBLIC_CURSOR_EXPIRED`。客户端仅对此明确冲突重查首屏一次，不混拼发布、不对任意错误重试。
- 成功 Meta 与错误 ErrorMeta 分开描述，错误中的 null 字段、可空媒体及必需字段已按真实响应校验。
- OpenAPI 3.0 规范校验及 12 份真实 HTTP JSON 响应 schema 校验通过，覆盖 200/400/404/409。该检查在本次审查工具环境执行，不冒充仓库已有 CI 门禁。
- 媒体只返回已准备、已绑定、当前允许公开的衍生图；读取时检查真实路径、大小、SHA-256，缓冲后再次核对发布/授权戳。HEAD 同样检查；不支持 Range；不以 304 或长期缓存跳过资格。
- 最终复核后的网络发送窗口、客户端持续前台显示的强制撤回协议未作绝对原子性承诺。
