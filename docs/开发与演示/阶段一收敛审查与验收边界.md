## 1. 已确认范围

阶段一仅交付演示内容的小程序公开展示和配套工程能力，不要求真实内容、后台、正式发布或生产环境。阶段二必须完成真实内容及后台上传维护、照片权属与客户授权事实及证据、正式 AppID、合法域名、TLS 和生产凭据等交付。用户同意将 uni-app 调整为原生微信小程序；这是一项已批准但尚未完成的实现变更，不等于现有原生稿已验收。

后置真实材料不等于删除现有授权资格判断、撤回下架、演示标识和 production 安全守卫。阶段一不得混入未经核验的真实客户照片，不得把 demo 当作生产发布。阶段二后台不能仅补界面：还需管理写 API、认证权限、校验、审计、上传与受控发布流程。

## 4. 对五项问题的审查结论

### 4.1 文档与编码是否全部完成

否。演示主链路已经建成，真实资料与生产条件按本次确认不再阻塞阶段一；但原生源码正式交付、旧运行链/生成物清理、对应工程规范和运行文档同步、原生完整回归与冻结仍是阶段一工程收尾。不能把旧前端通过记录转算为新前端通过。

### 4.2 专业规范、架构解耦和扩展性

后端分层有实际实现：纯领域/应用/端口、JDBC 与私有文件系统适配器、集中装配、显式迁移、只读运行身份、独立集成库。当前发布指针每次查库，授权不随发布缓存，数据与元信息来自同一查询快照。这是可维护的基础，不是仅有目录命名。

限制：架构测试主要扫描源码依赖，不能证明不存在所有循环或越层调用；PublicMediaService 复用 PublicQueryService 的静态校验/异常工厂，存在模块耦合。领域模型以发布读聚合为中心，适合公开浏览，不应直接扩成预约/订单写模型。后续后台需写模型、发布事务与权限审计，不能直接暴露 Reader 仓储做 CRUD。

### 4.4 硬编码与关键数据

关键展示事实来自数据库经 API 返回：品牌名称/文案、联系方式/渠道、成员、业务、套餐价格与服务项、作品、图片引用。前端映射严格校验契约，没有发现所抽查页面用固定业务数组替代这些接口，也不将网络失败伪装成空列表成功。此结论限于本轮检查范围，不是全工程零硬编码保证。

合理常量包括路由、错误提示、布局枚举、协议字段、分页上限、六页面/八图标构建白名单。数据库演示 seed 和测试 fixture 中固定样例是显式演示数据，不是页面运行时兜底。

确有固定实现：渠道白名单为 wechat/douyin/xiaohongshu（数据库及前端均有限制），首页数量/动作文案、套餐页分享标题等为产品展示规则，logoMedia 固定 null，本机脚本媒体路径固定。新渠道或首页运营规则若需后台可配，要同步 schema/契约/实现，不能承诺后台任意填值即可扩展。服务端 DB URL/用户名/密码与媒体根目录来自环境；客户端 API origin 来自构建配置，秘密不下发客户端。

### 4.5 数据库是否真正对接

是。实际运行采用新演示库 southleaf_public，专用集成库 southleaf_public_it；迁移/演示导入为显式工具，运行账号 SELECT-only，启动验证身份、授权与加密连接。数据失败不回落旧库/JSON/Empty。真实库测试和当前 HTTP 证明公开读取闭环有效。

授权/发布切换/游标失效及只读账号限制由既有集成套件验证；本轮调用此套件成功。没有后台写 API，因此“数据库已接通”不等于“第二阶段内容管理已完成”。既有 V1 不改写，后续 schema 新增迁移。

## 5. 收敛签署条件

1. 原生替换作为唯一正式前端完成交付，保留批准 UI、六页面与公开 API，不长期双轨。
2. 旧运行依赖/生成物清理，安装锁定和安全审计重跑；干净检出可构建。
3. 原生格式、单元、真实 API 契约、发布切换/分页/生命周期及六路模拟器回归通过。
4. 文档统一技术栈、命令、阶段范围；当前限制和第二阶段交接明确；最终差异/诊断复核。
5. 冻结确切候选并记录证据，再宣布阶段一演示工程验收通过。

真实内容、权属/客户授权材料、AppID/域名/TLS/生产凭据、后台上传与管理、正式上线相关验证列第二阶段，不再用它们无限扩大阶段一。当前没有执行正式候选冻结，故不能签署全部完成。
