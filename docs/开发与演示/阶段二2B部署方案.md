# 阶段二 2B 部署方案

> 适用场景：用**测试 AppID + 境外域名 seekway.xyz** 先跑通真机链路，后期替换为备案域名与正式 AppID。
> 本文所有结论来自对当前代码的核对，不是通用经验。

---

## 一、先说缺口：是不是设计有问题？

**设计没错，是“范围没覆盖到”。** 2A 的目标是“用隔离夹具证明功能正确”，所有本地验证都跑在
`127.0.0.1` + 自签证书 + 演示数据上。为此代码里写了几道**刻意的安全闸**——在 2A 阶段它们是优点，
到 2B 就变成必须先打开的门。四处缺口已经全部补齐：第 1 处改为配置驱动（`c05e008`），第 2–4 处见本表。

| # | 位置 | 原状 | 现状 |
|---|---|---|---|
| 1 | 管理端监听与来源 | `SOUTHLEAF_ADMIN_WEB_MODE` 只认 `demo`；origin 必须等于 `localhost:端口`；监听地址写死 `"localhost"`；证书别名写死 `"localhost"` | **已改**：`DeploymentProfile`（`demo` / `release`）+ `SOUTHLEAF_ADMIN_WEB_BIND_ADDRESS` + `SOUTHLEAF_ADMIN_WEB_TRUSTED_PROXIES` + `AdminOriginPolicy`。四类事实全部来自环境变量，证书可按需为空 |
| 2 | `admin_package_fact` | 只有建表语句，全仓库没有写入路径 | **已补**：`AdminPackageFactMain --import <file.json>`。只 INSERT、同值幂等、异值整批拒绝（改价必须换 `version_ref`）、`--dry-run` 只出计划 |
| 3 | 管理端产物打包 | 只有 L5 脚本用 `zipfile` 临时把 `admin-web/dist` 塞进 jar | **已补**：`backend/scripts/build-admin-runtime.py`，重建 jar 后再替换（旧 `static/` 不会被残留）；L5 脚本改为调用它，验证与发布同一条路径 |
| 4 | 套餐标识三处对齐 | `package.id` / `admin_package_fact.version_ref` / `SOUTHLEAF_PUBLIC_BOOKING_PACKAGE_REFS` 靠手工保持一致 | **已补**：`PackageFactCatalogCheck` 在预约入口启动时核对此表；缺 ref 报 `PACKAGE_REF_UNKNOWN`，data_mode 不符报 `PACKAGE_FACT_MODE_MISMATCH`，一律拒绝启动 |

> 第 1 处的改法不是“加一个 release 分支接受固定域名”，而是把**部署事实**从代码里搬出来：
> 档案（profile）决定“能不能绑公网、要不要自己终结 TLS”，地址与信任的代理来自配置，
> 来源校验走 `AdminOriginPolicy`（先规范化再精确比对，扩展来源不必改请求管线）。

## 二、域名与服务器：能不能同一个？

**能，而且推荐同一台服务器。** 但要分清"域名"和"服务"两件事：

| 方案 | 域名 | 端口 | 优缺点 |
|---|---|---|---|
| **A（推荐）** | `api.seekway.xyz` → 公开 API<br>`admin.seekway.xyz` → 管理后台 | 都是 443 | 职责清楚；小程序白名单只填 api 那一个；证书可分开管理（子域名可共用一张泛域名证书） |
| B | 都走 `seekway.xyz` | 443 | nginx 按路径分流：`/api/v1/public/*` → public-api，其余 → admin-runtime。可用，但两个应用抢同一个根路径，排查问题时容易混 |

结论：**同一台服务器、两套进程、两个子域名**。管理后台必须是"同源相对 API"（代码里有边界测试锁死这一点），
而 admin-runtime 自己就同时提供 SPA 和 `/api/admin/v1`，所以它天然满足同源要求——不需要为它单独拆域名。

### 端口硬约束

- 小程序 `wx.request` **只允许 HTTPS，且端口必须是 443**，不能写端口号。
- 所以 nginx 必须占 443，两个后端分别监听 127.0.0.1 的非标端口（如 8090 / 8443）。

### 未备案域名的现实限制（这条会直接影响你的测试计划）

微信要求**加入「服务器域名」白名单的域名必须完成 ICP 备案**。seekway.xyz 是境外域名、未备案，
所以它**无法进入白名单**。可用的路径只剩一条：

| 阶段 | 能做到 | 限制 |
|---|---|---|
| 现在（测试） | 开发版/体验版 + 关闭「校验合法域名」+ 手机能访问 seekway.xyz | 只能自己人或体验成员扫体验版二维码；不能提交审核、不能正式发布 |
| 上线前 | 必须换成已备案的境内域名 | 备案通常 7–20 个工作日，建议现在就去排期 |

补充两点：
- **游客模式（`touristappid`）不能真机预览**，只能在开发者工具里跑。要在手机上测，至少要注册一个**个人主体小程序**（免费、免认证）拿到 AppID，上传体验版。
- 项目里的 `build-native.mjs` 已经是这个行为：demo 模式产出 `urlCheck: false`，release 模式才打开校验。所以测试期不用改代码。

## 三、部署架构

```
                    ┌──────────────── 一台服务器 (Linux) ────────────────┐
  小程序(手机)  ────►│ nginx :443  ──► api.seekway.xyz    → 127.0.0.1:8090  public-api.jar
                    │             └─► admin.seekway.xyz  → 127.0.0.1:8443  admin-runtime.jar (含 SPA)
  运营浏览器    ────►│                                                    │
                    │ MySQL 8.4 (127.0.0.1:3306, TLS)  ← 两个应用          │
                    │ 媒体目录 /var/lib/southleaf/media                    │
                    └────────────────────────────────────────────────────┘
```

两个 jar 都**只监听回环地址**，对外只暴露 nginx 的 443。数据库不进公网。

## 四、部署步骤

### 0. 前置清单

| 项 | 要求 | 现状 |
|---|---|---|
| 服务器 | Ubuntu 24.04 / 2C4G 起，20G 盘 | 待你提供 |
| JDK | 21（代码用 Java 21 特性） | — |
| MySQL | 8.4，必须启用 TLS（生产模式强制 `sslMode=VERIFY_IDENTITY`） | — |
| 域名 | `api.seekway.xyz`、`admin.seekway.xyz` 都解析到该服务器 | 你已有 seekway.xyz |
| 证书 | Let's Encrypt（HTTP-01 需要 80 端口放开） | — |
| 小程序 | 至少个人主体 AppID（免认证），用于上传体验版 | 待定 |

### 1. 建库与最小授权

**不要手写 GRANT。** 三个模块的启动校验会逐表比对授权集，多一条少一条都拒绝启动：
`PublicBookingGrantPolicy`（11 张表）、`AdminRuntimeGrantPolicy`、`AdminOutboxProperties` 的 outbox 授权。

需要 6 个账号：

| 账号 | 用途 | 权力边界 |
|---|---|---|
| `southleaf_admin_migrator` | 跑 admin 迁移 | 仅 `southleaf_admin` schema 内 DDL |
| `southleaf_public_migrator` | 跑 public 迁移 | 仅 `southleaf_public` schema 内 DDL |
| `southleaf_admin_runtime` | 管理后台读写 | 账号/会话/内容/预约/订单/outbox，按策略表 |
| `southleaf_booking_writer` | 后台确认成单写入 | `booking_*` 全权限 + `admin_package_fact` 只读 |
| `southleaf_public_booking_writer` | 小程序提交申请 | 8 张表 INSERT/SELECT，3 张表只读，**无任何占用或订单写权** |
| `southleaf_public_reader` | 小程序读公开内容 | 仅 `southleaf_public` 只读 |

生产模式下 schema 名是固定的：`southleaf_admin` 与 `southleaf_public`（`AdminRuntimePolicy` 硬校验）。

### 2. 迁移（显式，不随应用启动）

```bash
# 管理端 V2–V11
java -cp "admin-migration-cli/target/classes:admin-migration-cli/target/dependency/*" \
  cn.zhinan.adminmigration.AdminDatabaseMigrationMain --migrate
java -cp "..." cn.zhinan.adminmigration.AdminDatabaseMigrationMain --validate

# 公开端 V1–V3 —— 注意：生产不要带 --seed-demo
java -jar uniapp-api.jar -Dloader.main=cn.zhinan.uniapp.tooling.DatabaseMigrationMain \
  org.springframework.boot.loader.launch.PropertiesLauncher
```

`--validate` 必须打印 `ADMIN_SCHEMA_VALIDATION_PASS` 才算过。

价格事实单独导入（同一套 `SOUTHLEAF_ADMIN_MIGRATION_*` 变量，先 `--dry-run` 看计划）：

```bash
java -cp "..." cn.zhinan.adminmigration.AdminPackageFactMain --dry-run --import package-facts.json
java -cp "..." cn.zhinan.adminmigration.AdminPackageFactMain --import package-facts.json
# PACKAGE_FACT_IMPORTED:insert=2:existing=0
```

文件形如 `{"dataMode":"PRODUCTION","facts":[{"versionRef":"<uuid>", ...}]}`；
`versionRef` 必须与 `SOUTHLEAF_PUBLIC_BOOKING_PACKAGE_REFS` 里的 ref 完全一致，
否则预约入口启动即报 `PUBLIC_BOOKING_REFUSED:PACKAGE_REF_UNKNOWN`。

管理端这 9 个键是一个整体，少一个必填项就是启动失败（`ADMIN_RUNTIME_REFUSED:CONFIGURATION`），
不会带着半个配置跑起来：

| 键 | 必填 | 缺省 | 说明 |
|---|---|---|---|
| `SOUTHLEAF_ADMIN_WEB_MODE` | 是 | — | `demo`：只许绑回环、必须自带 keystore、origin 必须等于监听地址；`release`：允许绑任意字面地址，TLS 可由代理终结 |
| `SOUTHLEAF_ADMIN_WEB_ORIGIN` | 是 | — | 浏览器地址栏看到的那个 `https://` 源。必须 scheme=https、无路径/查询/片段/用户信息；`release` 档不接受回环主机名 |
| `SOUTHLEAF_ADMIN_WEB_PORT` | 是 | — | 监听端口，1024–65535 |
| `SOUTHLEAF_ADMIN_WEB_BIND_ADDRESS` | 否 | `127.0.0.1` | 只接受字面地址（`localhost`/IPv4/IPv6）；`demo` 档必须回环 |
| `SOUTHLEAF_ADMIN_WEB_TRUSTED_PROXIES` | 见下 | — | 逗号分隔的字面地址。`release` 档若不提供 keystore，则**必须**提供，否则拒绝启动（不然每个写请求都会被判定为明文而拒绝） |
| `SOUTHLEAF_ADMIN_WEB_KEYSTORE_PATH` / `_PASSWORD` / `_TYPE` | 否 | — | 三个一起给或一起不给；`demo` 档必填。类型支持 `JKS` / `PKCS12` |
| `SOUTHLEAF_ADMIN_WEB_KEYSTORE_ALIAS` | 否 | 由容器选择 | 不给就让容器挑（单条目的 keystore 不需要别名） |

生产建议：`release` + 不给 keystore + `TRUSTED_PROXIES=127.0.0.1`，即 **TLS 终结在 nginx，应用只监听回环**。
这样证书续期只在一处，应用也不需要接触私钥。

管理端的两个业务能力按**事实**判定，不按模式字符串：

| 能力 | 判定规则 | 生产口径 |
|---|---|---|
| 预约与确认成单 | 需要有 Web 管理面；`BOOKING_DATA_MODE` 必须与 `ADMIN_MODE` 一致（production→`PRODUCTION`，demo→`SYNTHETIC`） | **可启用**。它只在事务内写 outbox 行，不依赖投递进程 |
| 通知投递（outbox 调度） | 需要有 Web 管理面；`DELIVERY_MODE` 目前只有 `TEST_SINK`，而测试接收器不产生真实投递 | **不启用**。生产环境配 `TEST_SINK` 会被拒绝启动 |

所以 2B 上线时：**后台能确认预约、能成单**；确认产生的通知任务会**留在 `booking_notification_outbox` 表里不出队**，
等真实通知通道接入后再开 `SOUTHLEAF_ADMIN_OUTBOX_*` 补发或重放。这是"阶段二不发真实通知"的直接后果，不是缺陷。

### 5. nginx（TLS 终结在 nginx，回源到本地 https）

```nginx
# api.seekway.xyz
server {
  listen 443 ssl http2;
  server_name api.seekway.xyz;
  ssl_certificate     /etc/letsencrypt/live/api.seekway.xyz/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.seekway.xyz/privkey.pem;

  client_max_body_size 12m;

  location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 30s;
  }
}

# admin.seekway.xyz
server {
  listen 443 ssl http2;
  server_name admin.seekway.xyz;
  ssl_certificate     /etc/letsencrypt/live/admin.seekway.xyz/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/admin.seekway.xyz/privkey.pem;

  location / {
    proxy_pass http://127.0.0.1:8443;    # 应用只监听回环、明文；TLS 在这一层终结
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;   # 必填：应用据此判定 request.isSecure()
  }
}
```

> `Cache-Control: no-store`、`X-Content-Type-Options`、CSRF、`secure + SameSite=Strict` 都由应用自己发，
> nginx 不要覆盖这些头，否则会把已验证的安全属性改掉。

### 7. 上线自检（缺一不可）

| 检查 | 期望 |
|---|---|
| `curl https://api.seekway.xyz/api/v1/public/home` | 200，`meta.dataMode = "production"` |
| 小程序请求 | 能取到套餐与时段，且**没有任何支付字样** |
| 提交一笔申请 | 201，状态「待确认」，数据库占用为 0 |
| 后台登录 | 能进，CSRF 正常，`PHPSESSID` 类 cookie 为 Secure + SameSite=Strict |
| 后台确认 | 生成唯一订单与快照，金额来自 `admin_package_fact` 的 PRODUCTION 行 |
| 后台改期到已占时段 | 409 `SLOT_UNAVAILABLE`，原档不变 |
| 停掉通知 | 后台可见失败并人工恢复 |
| 服务器重启 | 两个服务自动拉起，数据不丢 |

## 五、风险与不做的事

- **不做支付**：全链路无支付入口，2B 也不引入。
- **通知通道**先用 `TEST_SINK`，真实订阅消息模板拿到再切；切换不承诺 exactly-once。
- **未备案域名不能提交审核**：体验版能跑通 ≠ 能上线。备案请尽早排期。
- **单机部署**没有高可用，数据库与磁盘是单点；G3 才谈备份恢复与容灾。
- TLS 回源用 `proxy_ssl_verify off` 只允许出现在回环地址上；若将来拆分机器，必须改成真实证书校验。
