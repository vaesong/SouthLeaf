## 分拣原则与升级约束

1. **Vite / 开发服务 / WebSocket / Express**：优先限制暴露面。仅在可信本机运行开发服务，不绑定公网/LAN，不把开发服务器当生产服务。旧版开发服务即使在 localhost，也可能受恶意网站访问影响；不要在开启开发服务时浏览不可信页面。默认演示工作流使用静态 build:demo，不需常驻 Vite 开发服务器。
2. **Rollup 等构建工具**：构建过程也有权限，不能以“不在手机运行时”忽略构建风险。此次已单独修复 Rollup，构建输入仍应可信。
3. **Vue/SSR/@intlify**：当前是 mp-weixin，不等于已用到 SSR/危险 HTML；要做产物与调用可达性核查。禁止把可控内容塞入 v-html/动态模板，不能仅凭“看起来没用”接受所有风险。
4. **dcloud 版本矩阵**：当前 3.0.0-5020620260917001 的 vite-plugin-uni 声明精确 Vite 5.2.8（j146）。不能只把顶层 Vite 强行升到不兼容版本，或用 override 跨大版本压住告警；单升 5.4.21 也不能消除本次扫描所列全部 Vite 告警。
5. **选择稳定兼容线**：registry 的 latest 是 uni-app 2.x，vue3 tag 当前指向 alpha；不能机械安装 latest 或 alpha。下一步需要确认上游 Vue3 稳定兼容矩阵，评估官方维护说明，再在受控候选上联动升级。
6. **后端 Java**：尚未完成传递依赖 SCA；当前 Boot 3.4.0 也需要评估受支持的补丁/版本线。不能因 53 项功能测试通过就断言无已知漏洞。

## 后续门禁

- 对上游无法修复/受矩阵约束的条目记录具体受影响入口、可达性、缓解措施、负责人和复查日期；当前未取得正式风险接受，不标 ACCEPTED。
- 兼容矩阵升级后重跑：干净锁文件安装、Node/后端测试、微信构建、公开与安全冒烟、目标设备六页面/排序/排版、授权撤回；另按启用范围验证 H5。
- 归档前后审计原始输出、锁文件及构建版本；不以告警数字降低替代真实兼容和安全验收。
