# 阶段一演示运行指南（原生微信 + 数据库）

> 当前运行说明；旧 uni-app/JSON/legacy-local 命令不再适用。阶段一为演示工程；真实资料、权属/客户授权材料、后台、正式 AppID/域名/TLS/生产凭据在阶段二交付。当前验收见[收敛交付记录](阶段一收敛交付记录.md)。

## 1. 环境与唯一入口

- Java 21、Maven Wrapper、Node >=22、MySQL 8.4；后端 Spring Boot 4.1.1。
- 客户端唯一源码是 `frontend`，原生微信六页面/四 tab。没有 uni-app/Vue/Vite 运行或编译依赖。
- 演示库 `southleaf_public`、专用集成库 `southleaf_public_it`。旧 `southleafdb` 保留、不迁移、不清空、不兜底。
- 演示内容：6 业务/6 套餐/6 作品，虚构成员和平台账号、不能扫码的二维码及生成衍生图；不代表客户真实同意。
- 默认 API 仅监听 127.0.0.1:8090。已有同端口服务时不要重复启动。

## 2. 当前电脑运行

Windows cmd.exe，`backend` 目录：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-PublicApi.ps1
```

本机启动器从当前 Windows 用户 Credential Manager 的 `SouthLeaf/PublicDatabase/Reader` 获取账号密码，只临时注入子进程，不写项目或打印密码。Java 服务本身依赖环境变量，不依赖 Windows 凭据 API。

本机脚本优先使用显式 `SOUTHLEAF_MEDIA_ROOT`；未配置时采用仓库旁的 `<仓库路径>-data/public-media`，当前为 `E:\SouthLeaf-data\public-media`。该目录私有，非静态 HTTP 根。其他部署显式提供已准备好的媒体目录。

`frontend` 目录：

```bat
npm ci --ignore-scripts --registry=https://registry.npmjs.org
npm run verify
npm audit --registry=https://registry.npmjs.org
set SOUTHLEAF_API_ORIGIN=http://127.0.0.1:8090
npm run build:demo
npm run test:contract
```

构建必须显式给 origin，没有隐式网络端点。导入微信开发者工具的目录是 `frontend/dist/build/mp-weixin`；源目录缺少生成的 runtime.js，不能直接导入。游客 AppID 仅为 demo，域名检查仅在 demo 关闭。

构建先校验暂存内容，再替换输出子项，保留 DevTools 持有的目录根及工具私有设置；这是本地构建，不是生产原子部署协议。发现额外静态素材、框架运行码、未解析依赖或非法模板编码会失败。

## 3. 新电脑初始化（当前电脑不要重复执行）

`Initialize-PublicDatabase.ps1` 仅在两个目标库和三个目标账号均不存在时执行，不重置已有库。PowerShell 在 backend 目录：

```powershell
$admin = Get-Credential -Message 'MySQL administrator for new isolated databases'
$env:SOUTHLEAF_ADMIN_USERNAME = $admin.UserName
$env:SOUTHLEAF_ADMIN_PASSWORD = $admin.GetNetworkCredential().Password
try {
  & ./scripts/Initialize-PublicDatabase.ps1 -MySqlClientPath 'YOUR_MYSQL_BIN/mysql.exe'
} finally {
  Remove-Item Env:SOUTHLEAF_ADMIN_PASSWORD
  $admin = $null
}
```

随机新凭据存系统凭据库。后续显式迁移/首轮演示导入：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-DatabaseMigration.ps1 -SeedDemo
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-DatabaseMigration.ps1 -TestDatabase -SeedDemo
```

SeedDemo 只允许 `catalog_release` 无记录的数据库；已有发布会拒绝，不是更新/合并/重置命令。正常升级只迁移：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-DatabaseMigration.ps1
```

MySQL DDL 不保证事务回滚；不能改写已应用 V1、自动 repair/clean 或重建已使用库。后续 schema 新增 V2 等迁移。当前演示库不要重复初始化。


真实集成脚本执行完整 Maven verify，必须有独立测试库；会在测试库提交测试变更并在 finally 恢复，不用 H2 或静默跳过。启动守卫检查不停止已有 API/MySQL。

模拟器使用已安装微信开发者工具和本机隔离自动化依赖 `.trellis/.runtime/wechat-automation`，并非应用依赖：

```bat
rem 替换为本机 CLI 与工程绝对路径；自动化端口应先就绪
"YOUR_WECHAT_DEVTOOLS/cli.bat" auto --project "YOUR_REPOSITORY/frontend/dist/build/mp-weixin" --auto-port 9420 --trust-project
node backend/scripts/render-wechat.cjs
```

最后一条从仓库根执行。脚本只连接本机 9420，完整验证六路和排序/直接布局控件；截图在 `frontend/dist/wechat-native-render`，不提交。CLI 返回不代表 WebSocket 和页面已就绪；端口未就绪/编译报错的运行不得记为通过。游客模式和模拟器不能证明手机联系/分享/扫码和正式发布。

## 5. 配置、安全与发布边界

- 运行服务：`SOUTHLEAF_DB_URL / USERNAME / PASSWORD`、`SOUTHLEAF_MEDIA_ROOT`，可选 `SOUTHLEAF_BIND_ADDRESS / PORT`。只读账号，不传迁移凭据。
- 独立迁移：`SOUTHLEAF_MIGRATION_URL / USERNAME / PASSWORD`，不注入 Web 服务。
- 当前本地数据库 TLS 为 REQUIRED；生产仍必须 VERIFY_IDENTITY 和真实独立身份，后置阶段二不意味着放宽守卫。
- 客户端 `build:release` 读取 `config/release.json` 的 appId/apiOrigin；当前未配置，故应失败，不填假值绕过。配置中不得写秘密。
- 发布内容不可原地修改已缓存发布；准备新关系/衍生图后以事务切换 active_publication。授权撤回独立更新事实与修订号。
- 正式后台尚未实现，阶段二需管理 API、认证、上传、审计和发布，不只是表单。
- root 历史密码轮换沿用 j275 证据；不再使用或输出旧秘密，应用仍用 Reader。

备份恢复脚本仅用于固定隔离测试库，需显式确认且无其他测试写入：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-BackupRestore.ps1 -ConfirmIsolatedTestRestore
```

本地恢复证据不是生产灾备承诺。真实材料、生产部署、手机和正式容量/灾备/持续显示撤回验收在阶段二完成。
